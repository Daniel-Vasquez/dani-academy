Casi todos los datos de una app web son **listas de objetos**: lo que llega de una API, lo que guardas en MongoDB y lo que pintas con `.map()` en React. Aquí modelas un día de tu app de entrenamiento, de menos a más.

**Requisitos:** el `ts-playground` de las secciones anteriores, con `strict` y `noUncheckedIndexedAccess` activos.

## Paso 1: tipar arrays

**Qué es:** un array tipado garantiza que **todos** sus elementos son del mismo tipo.

**Cómo se usa:** crea `src/03-arrays.ts`.

```ts
// Archivo: src/03-arrays.ts
const pesos: number[] = [80.5, 79.8, 79.2];
const ejercicios: Array<string> = ["sentadilla", "press banca", "peso muerto"];
const mezcla: (string | number)[] = ["series", 4, "repeticiones", 8];

pesos.push(78.9);
console.log(`Registros de peso: ${pesos.length}`);
console.log(`Ejercicios en mayúsculas: ${ejercicios.map((e) => e.toUpperCase()).join(", ")}`);
console.log(`Valores mezclados: ${mezcla.join(" ")}`);

const ultimoPeso = pesos[pesos.length - 1];
if (ultimoPeso !== undefined) {
  console.log(`Último peso registrado: ${ultimoPeso.toFixed(1)} kg`);
}
```

```bash
npm start -- src/03-arrays.ts
```

```text
Registros de peso: 4
Ejercicios en mayúsculas: SENTADILLA, PRESS BANCA, PESO MUERTO
Valores mezclados: series 4 repeticiones 8
Último peso registrado: 78.9 kg
```

- **`number[]` y `Array<number>` son lo mismo.** En este curso, `number[]`.
- **`(string | number)[]`:** elementos de texto o número. Sin paréntesis, `string | number[]` sería "un texto, o un array de números".
- **El `if (ultimoPeso !== undefined)` es obligatorio** por `noUncheckedIndexedAccess`: leer por índice da `number | undefined`. Sin él: `error TS18048: 'ultimoPeso' is possibly 'undefined'.`

<Callout type="risk">

- **Sin `noUncheckedIndexedAccess`,** `pesos[10].toFixed(1)` compila y revienta con `Cannot read properties of undefined`. Es la primera fuente de errores con listas: mantén la opción activa.
- **`.find()` puede no encontrar nada:** devuelve `T | undefined` siempre. Comprueba el resultado.
- **`.find()` e `.includes()` recorren todo el array:** con miles de búsquedas sobre miles de elementos, usa un `Map` o un `Set`.

</Callout>

## Paso 2: tuplas para pares de valores

**Qué es:** un array de **longitud fija** donde **cada posición tiene su tipo**. Sirve cuando el orden significa algo: una coordenada, un rango.

**Cómo se usa:** crea `src/03-tuplas.ts`.

```ts
// Archivo: src/03-tuplas.ts
type Coordenada = [latitud: number, longitud: number];
type RangoFechas = [inicio: string, fin: string];

const gimnasio: Coordenada = [19.4326, -99.1332];
const semana: RangoFechas = ["2026-10-05", "2026-10-11"];

const [lat, lng] = gimnasio;
console.log(`Gimnasio en ${lat}, ${lng}`);
console.log(`Semana del ${semana[0]} al ${semana[1]}`);

// Object.entries devuelve un array de tuplas [clave, valor]
const aguaPorDia: Record<string, number> = { lunes: 8, martes: 6, miercoles: 9 };
for (const [dia, vasos] of Object.entries(aguaPorDia)) {
  console.log(`${dia}: ${vasos} vasos`);
}

// useState de React devuelve una tupla: [valor, función para cambiarlo]
function crearContador(inicial: number): [number, (nuevo: number) => void] {
  let valor = inicial;
  return [valor, (nuevo) => {
    valor = nuevo;
    console.log(`Contador actualizado a ${valor}`);
  }];
}

const [vasos, setVasos] = crearContador(0);
console.log(`Vasos iniciales: ${vasos}`);
setVasos(1);
```

```bash
npm start -- src/03-tuplas.ts
```

```text
Gimnasio en 19.4326, -99.1332
Semana del 2026-10-05 al 2026-10-11
lunes: 8 vasos
martes: 6 vasos
miercoles: 9 vasos
Vasos iniciales: 0
Contador actualizado a 1
```

- **Las etiquetas `[latitud: number, longitud: number]`** solo documentan: salen en el autocompletado.
- **`semana[0]` es `string`, sin `undefined`:** TypeScript sabe qué posiciones existen. `semana[2]` da `error TS2493: Tuple type 'RangoFechas' of length '2' has no element at index '2'.`
- **`crearContador` imita a `useState`:** `const [vasos, setVasos] = useState(0)` es desestructurar una tupla. `Record<string, number>` es un objeto de claves de texto y valores numéricos.

<Callout type="risk">

- **Las tuplas no son inmutables:** `gimnasio.push(5)` compila. Para garantizarlo, `readonly [number, number]` (Paso 4).
- **A partir de tres posiciones, usa un objeto:** `[string, number, boolean, string]` obliga a recordar qué es cada una.
- **Orden de coordenadas:** Google Maps usa `[latitud, longitud]`; GeoJSON y MongoDB, `[longitud, latitud]`. Los tipos no lo detectan: los dos son `number`.

</Callout>

## Paso 3: objetos y propiedades opcionales

**Qué es:** un tipo en línea describe la **forma** del objeto. Con `?`, una propiedad puede faltar, y su tipo real pasa a ser `T | undefined`.

**Cómo se usa:** crea `src/03-objetos.ts`.

```ts
// Archivo: src/03-objetos.ts
const entreno: {
  tipo: string;
  minutos: number;
  intensidad: "baja" | "media" | "alta";
  notas?: string;
} = {
  tipo: "running",
  minutos: 30,
  intensidad: "media",
};

console.log(`${entreno.tipo}: ${entreno.minutos} min (${entreno.intensidad})`);

// notas es opcional: su tipo es string | undefined
const largoNotas = entreno.notas?.length ?? 0;
console.log(`Caracteres en notas: ${largoNotas}`);

entreno.notas = "Rodaje suave por el parque";
console.log(`Notas: ${entreno.notas}`);
console.log(`Caracteres en notas: ${entreno.notas?.length ?? 0}`);
```

```bash
npm start -- src/03-objetos.ts
```

```text
running: 30 min (media)
Caracteres en notas: 0
Notas: Rodaje suave por el parque
Caracteres en notas: 26
```

- **`notas?: string`:** el objeto se crea sin `notas` y no hay error.
- **`entreno.notas?.length ?? 0`:** `?.` (_optional chaining_) da `undefined` sin lanzar error si `notas` falta, y `??` (_nullish coalescing_) pone `0` en ese caso.

<Callout type="risk">

- **`??` no es `||`:** `||` sustituye también `0` y `""`. Con `minutos: 0`, `entreno.minutos || 30` da 30; `??` da 0.
- **Abusar de `?.` esconde bugs:** un dato que nunca debería faltar desaparece en silencio. Úsalo solo donde faltar sea normal.
- **`notas?: string` no es `notas: string | undefined`:** el primero permite omitir la propiedad; el segundo obliga a escribirla, aunque sea `undefined`.

</Callout>

## Paso 4: proteger datos con `readonly`

**Qué es:** `readonly` impide, al compilar, cambiar una propiedad tras crear el objeto: un identificador, una fecha de creación.

**Cómo se usa:** crea `src/03-readonly.ts`.

```ts
// Archivo: src/03-readonly.ts
const registro: {
  readonly id: string;
  readonly creadoEn: string;
  pesoKg: number;
} = {
  id: "reg_001",
  creadoEn: "2026-10-09T07:30:00Z",
  pesoKg: 80.5,
};

registro.pesoKg = 80.1; // permitido: no es readonly
console.log(`Registro ${registro.id}: ${registro.pesoKg} kg`);

const CATEGORIAS: readonly string[] = ["trabajo", "personal", "salud", "estudio"];
console.log(`Categorías disponibles: ${CATEGORIAS.join(", ")}`);
console.log(`¿Existe "salud"? ${CATEGORIAS.includes("salud")}`);
```

```bash
npm start -- src/03-readonly.ts
```

```text
Registro reg_001: 80.1 kg
Categorías disponibles: trabajo, personal, salud, estudio
¿Existe "salud"? true
```

Añade estas dos líneas, ejecuta `npm run typecheck` y bórralas:

```ts
registro.id = "reg_002";
CATEGORIAS.push("ocio");
```

```text
error TS2540: Cannot assign to 'id' because it is a read-only property.
error TS2339: Property 'push' does not exist on type 'readonly string[]'.
```

- **Un `readonly string[]` no tiene `push`, `pop`, `splice` ni `sort`.** Sí tiene los que crean un array nuevo: `map`, `filter`, `slice`, `toSorted`.

<Callout type="risk">

- **`readonly` solo existe en TypeScript:** en ejecución, nada impide cambiar `id`. Para eso, `Object.freeze()`.
- **Es superficial:** en `readonly entrenos: Entreno[]` no reasignas la lista, pero sí puedes cambiar un entreno de dentro.
- **`const` no es `readonly`:** impide asignar otro objeto a la variable, no cambiar sus propiedades.

</Callout>

## Paso 5: por qué se rechazan propiedades de más

**Qué es:** TypeScript usa **tipado estructural**: un objeto encaja en un tipo si tiene **al menos** sus propiedades. Pero a un **objeto literal** escrito directamente le aplica el _excess property checking_: una propiedad de más ahí es casi seguro una errata.

**Cómo se usa:** crea `src/03-exceso.ts`.

```ts
// Archivo: src/03-exceso.ts
type Ejercicio = { nombre: string; series: number };

function describir(ejercicio: Ejercicio): string {
  return `${ejercicio.nombre}: ${ejercicio.series} series`;
}

// Caso A: objeto en variable con propiedades de más → se acepta
const desdeVariable = { nombre: "dominadas", series: 4, descanso: 90 };
console.log(describir(desdeVariable));

// Caso B: objeto literal escrito directamente con las propiedades exactas → se acepta
console.log(describir({ nombre: "fondos", series: 3 }));
```

```text
dominadas: 4 series
fondos: 3 series
```

Añade este caso C, con una errata, y ejecuta `npm run typecheck`:

```ts
console.log(describir({ nombre: "remo", serie: 3 }));
```

```text
error TS2561: Object literal may only specify known properties, but 'serie' does not exist in type 'Ejercicio'. Did you mean to write 'series'?
```

- **El caso A pasa:** `desdeVariable` tiene `nombre` y `series`, y `descanso` sobra sin molestar.
- **El caso C no:** el objeto literal solo se usa ahí, así que `serie` es una errata. Borra la línea antes de seguir.

<Callout type="risk">

- **La comprobación desaparece con variables intermedias:** con campos opcionales, `const opciones = { minutos: 5, notass: "x" }` se acepta y la nota se pierde. Anota la variable (`const opciones: Opciones = {…}`) o escribe el objeto en la llamada.
- **Lo que sobra llega a la base de datos:** como el caso A se acepta, MongoDB guarda todas las propiedades. Zod (I1) elimina lo que sobra.

</Callout>

## Paso 6: modelar un día de entreno completo

**Qué es:** el objetivo de la sección: un día con fecha, ejercicios y agua, y una función que calcula el **volumen total** (series × repeticiones × peso).

**Cómo se usa:** crea `src/03-dia-entreno.ts`.

```ts
// Archivo: src/03-dia-entreno.ts
type EjercicioDelDia = {
  readonly nombre: string;
  series: number;
  repeticiones: number;
  pesoKg: number;
  notas?: string;
};

type DiaEntreno = {
  readonly fecha: string; // formato AAAA-MM-DD
  ejercicios: EjercicioDelDia[];
  aguaMl: number;
  duracionMin?: number;
};

function volumenEjercicio(ejercicio: EjercicioDelDia): number {
  return ejercicio.series * ejercicio.repeticiones * ejercicio.pesoKg;
}

function volumenTotal(dia: DiaEntreno): number {
  return dia.ejercicios.reduce((total, ejercicio) => total + volumenEjercicio(ejercicio), 0);
}

function ejercicioMasPesado(dia: DiaEntreno): EjercicioDelDia | undefined {
  return dia.ejercicios.toSorted((a, b) => b.pesoKg - a.pesoKg)[0];
}

const jueves: DiaEntreno = {
  fecha: "2026-10-08",
  ejercicios: [
    { nombre: "sentadilla", series: 4, repeticiones: 8, pesoKg: 70 },
    { nombre: "press banca", series: 4, repeticiones: 10, pesoKg: 50, notas: "Última serie al fallo" },
    { nombre: "remo con barra", series: 3, repeticiones: 12, pesoKg: 40 },
  ],
  aguaMl: 2250,
};

console.log(`Entreno del ${jueves.fecha}`);
for (const ejercicio of jueves.ejercicios) {
  const nota = ejercicio.notas ? ` (${ejercicio.notas})` : "";
  console.log(`- ${ejercicio.nombre}: ${volumenEjercicio(ejercicio)} kg${nota}`);
}
console.log(`Volumen total: ${volumenTotal(jueves)} kg`);
console.log(`Agua: ${(jueves.aguaMl / 1000).toFixed(2)} L`);
console.log(`Duración: ${jueves.duracionMin ?? "sin registrar"}`);

const masPesado = ejercicioMasPesado(jueves);
console.log(`Ejercicio con más peso: ${masPesado?.nombre ?? "ninguno"}`);

const diaVacio: DiaEntreno = { fecha: "2026-10-09", ejercicios: [], aguaMl: 0 };
console.log(`Volumen de un día sin ejercicios: ${volumenTotal(diaVacio)} kg`);
console.log(`Ejercicio con más peso en un día vacío: ${ejercicioMasPesado(diaVacio)?.nombre ?? "ninguno"}`);
```

```bash
npm run typecheck
npm start -- src/03-dia-entreno.ts
```

```text
Entreno del 2026-10-08
- sentadilla: 2240 kg
- press banca: 2000 kg (Última serie al fallo)
- remo con barra: 1440 kg
Volumen total: 5680 kg
Agua: 2.25 L
Duración: sin registrar
Ejercicio con más peso: sentadilla
Volumen de un día sin ejercicios: 0 kg
Ejercicio con más peso en un día vacío: ninguno
```

- **Dos tipos en lugar de uno gigante:** `DiaEntreno` usa `EjercicioDelDia[]`, y `volumenEjercicio` recibe solo lo que necesita.
- **`aguaMl` en mililitros enteros:** sin decimales (Paso 1 de B1.2), y la unidad va en el nombre.
- **`reduce` con valor inicial `0`:** sin él, un día vacío lanza `TypeError: Reduce of empty array with no initial value`.
- **`ejercicioMasPesado` devuelve `EjercicioDelDia | undefined`,** y obliga a quien llama a manejarlo. `toSorted` no desordena el original, a diferencia de `sort`.

<Callout type="risk">

- **Fechas como texto:** `fecha: string` acepta `"ayer"`. El comentario `// formato AAAA-MM-DD` es una promesa, no una comprobación: Zod (I1) y `Date` en MongoDB (B5.5).
- **Ordenar para quedarte con el primero** es O(n log n) y copia el array. Con miles de elementos, un `reduce` de una pasada.
- **`toSorted` es de ES2023:** con `"target": "ES2022"` da `error TS2550: Property 'toSorted' does not exist on type 'EjercicioDelDia[]'. Do you need to change your target library?`. Por eso B1.1 usa `ES2023`.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Copia `src/03-dia-entreno.ts` como `src/03-ejercicio.ts` y añade a `DiaEntreno` una propiedad opcional `comidas`: un array de objetos con `nombre` (texto), `kcal` (número) y `momento` (`"desayuno" | "comida" | "cena" | "snack"`).
2. Escribe `kcalTotales(dia)` que devuelva la suma de calorías, y que devuelva `0` si el día no tiene comidas registradas.
3. Escribe `resumenDia(dia)` que devuelva una tupla `[volumenKg: number, kcal: number]` y úsala con desestructuración.
4. Prueba con un día con comidas y otro sin la propiedad `comidas`, y ejecuta `npm run typecheck`.

</Callout>

Solución completa:

```ts
// Archivo: src/03-ejercicio.ts
type EjercicioDelDia = {
  readonly nombre: string;
  series: number;
  repeticiones: number;
  pesoKg: number;
  notas?: string;
};

type Comida = {
  nombre: string;
  kcal: number;
  momento: "desayuno" | "comida" | "cena" | "snack";
};

type DiaEntreno = {
  readonly fecha: string;
  ejercicios: EjercicioDelDia[];
  aguaMl: number;
  duracionMin?: number;
  comidas?: Comida[];
};

function volumenTotal(dia: DiaEntreno): number {
  return dia.ejercicios.reduce((total, e) => total + e.series * e.repeticiones * e.pesoKg, 0);
}

function kcalTotales(dia: DiaEntreno): number {
  return (dia.comidas ?? []).reduce((total, comida) => total + comida.kcal, 0);
}

function resumenDia(dia: DiaEntreno): [volumenKg: number, kcal: number] {
  return [volumenTotal(dia), kcalTotales(dia)];
}

const conComidas: DiaEntreno = {
  fecha: "2026-10-08",
  ejercicios: [{ nombre: "sentadilla", series: 4, repeticiones: 8, pesoKg: 70 }],
  aguaMl: 2000,
  comidas: [
    { nombre: "Avena con plátano", kcal: 420, momento: "desayuno" },
    { nombre: "Pollo con arroz", kcal: 650, momento: "comida" },
    { nombre: "Yogur griego", kcal: 150, momento: "snack" },
  ],
};

const sinComidas: DiaEntreno = {
  fecha: "2026-10-09",
  ejercicios: [],
  aguaMl: 1500,
};

for (const dia of [conComidas, sinComidas]) {
  const [volumenKg, kcal] = resumenDia(dia);
  console.log(`${dia.fecha}: ${volumenKg} kg de volumen, ${kcal} kcal`);
}
```

```text
2026-10-08: 2240 kg de volumen, 1220 kcal
2026-10-09: 0 kg de volumen, 0 kcal
```

<Callout type="risk">

- **`dia.comidas ?? []`:** sin él, `error TS18048: 'dia.comidas' is possibly 'undefined'.` TypeScript te obliga a decidir qué pasa sin comidas, algo que en JavaScript verías en producción.
- **`EjercicioDelDia` está duplicado** en dos archivos. En B1.4 lo conviertes en un tipo reutilizable, y en B1.7 lo mueves a un módulo.

</Callout>

<Callout type="mastery">

Puedes tipar cualquier objeto JSON que ya uses en tus proyectos sin consultar la documentación: arrays con `[]`, pares fijos con tuplas, campos opcionales con `?`, campos inmutables con `readonly`, y sabes por qué TypeScript se queja de una propiedad de más en un objeto literal.

</Callout>

## Resumen

- `number[]` es `Array<number>`; con `noUncheckedIndexedAccess`, leer por índice da `T | undefined`.
- Tuplas: longitud fija y un tipo por posición. `useState` devuelve una.
- `?` marca lo opcional; `?.` lee sin romper; `??` solo sustituye `null` y `undefined`.
- `readonly` protege al compilar, es superficial y no existe en ejecución.
- Un objeto literal con propiedades de más da error; uno en una variable, no.
