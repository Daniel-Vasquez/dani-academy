Escribir el tipo de **todo** da código más largo y más frágil. Aquí ves qué deduce TypeScript solo, dónde conviene anotar y cómo leer datos externos con `unknown` en lugar de `any`.

**Requisitos:** el proyecto `ts-playground` de B1.1, con su `tsconfig.json` y los _scripts_ `typecheck` y `start`.

## Paso 1: los tipos primitivos

**Qué es:** los valores más básicos de JavaScript, que no son objetos. TypeScript los nombra en minúscula.

**Cómo se usa:** crea `src/02-primitivos.ts`.

```ts
// Archivo: src/02-primitivos.ts
const nombre: string = "Dani";
const kmSemana: number = 23.5; // enteros y decimales: todo es number
const entrenoHecho: boolean = true;
const notas: null = null; // "no hay valor, a propósito"
const lesion: undefined = undefined; // "no se ha asignado ningún valor"
const pasosAnuales: bigint = 9_007_199_254_740_993n; // enteros enormes y exactos
const idUnico: symbol = Symbol("id"); // un valor único e irrepetible

console.log(typeof nombre, typeof kmSemana, typeof entrenoHecho);
console.log(typeof notas, typeof lesion, typeof pasosAnuales, typeof idUnico);
```

```bash
npm start -- src/02-primitivos.ts
```

```text
string number boolean
object undefined bigint symbol
```

| Tipo                 | Para qué                                                          |
| -------------------- | ----------------------------------------------------------------- |
| `string`             | Texto: nombres, correos, identificadores como `"B1.3"`            |
| `number`             | Todos los números: no hay `int` ni `float` separados              |
| `boolean`            | `true` o `false`                                                  |
| `null` y `undefined` | "Vacío a propósito" y "nunca se asignó", por convención           |
| `bigint` y `symbol`  | Enteros enormes e identificadores únicos: rara vez en una app web |

<Callout type="risk">

- **`typeof null` devuelve `"object"`:** un error histórico de JavaScript. Para comprobar `null`, compara: `valor === null`.
- **`String`, `Number` y `Boolean` con mayúscula** son objetos envoltorio, no los primitivos. `let x: String` compila, pero es incorrecto.
- **`0.1 + 0.2` da `0.30000000000000004`:** `number` es binario. Para dinero, trabaja en céntimos enteros.

</Callout>

## Paso 2: la inferencia

**Qué es:** TypeScript **deduce el tipo a partir del valor**, y una vez deducido, el tipo queda fijado.

**Cómo se usa:** crea `src/02-inferencia.ts` sin una sola anotación, predice cada tipo y compruébalo con el ratón.

```ts
// Archivo: src/02-inferencia.ts
let nombre = "Dani";
let vasosDeAgua = 0;
let completado = false;
const pesos = [80.5, 79.8, 79.2];
const hoy = new Date();
const entreno = { tipo: "running", km: 5.2 };

function totalKm(distancias: number[]) {
  return distancias.reduce((acumulado, km) => acumulado + km, 0);
}

const total = totalKm([5, 3.2, 10]);

vasosDeAgua = vasosDeAgua + 1;
console.log(nombre, vasosDeAgua, completado, pesos.length, hoy instanceof Date, entreno.km, total);
```

| Variable      | Tipo inferido                                     |
| ------------- | ------------------------------------------------- |
| `nombre`      | `string`                                          |
| `vasosDeAgua` | `number`                                          |
| `completado`  | `boolean`                                         |
| `pesos`       | `number[]`                                        |
| `hoy`         | `Date`                                            |
| `entreno`     | `{ tipo: string; km: number; }`                   |
| `total`       | `number` (lo deduce de lo que devuelve `totalKm`) |

Añade esta línea al final, ejecuta `npm run typecheck` y bórrala:

```ts
vasosDeAgua = "tres";
```

```text
error TS2322: Type 'string' is not assignable to type 'number'.
```

<Callout type="risk">

- **Arrays vacíos:** `const lista = []` tiene un tipo provisional que cambia con cada `push`. Si un array empieza vacío, anótalo: `const lista: number[] = []`.
- **Objetos que crecerán:** con `const entreno = { tipo: "running" }`, hacer luego `entreno.km = 5` da error. Define el tipo completo desde el principio (B1.4).
- **No anotes por inercia:** `const vasos: number = 0` no aporta nada, y al cambiar el valor tendrás que cambiar dos cosas.

</Callout>

## Paso 3: anotar solo donde aporta

**Qué es:** hay tres sitios donde **sí** debes escribir el tipo: parámetros, variables sin valor inicial y el retorno de funciones que otros usan. La regla: **anota en los bordes y deja inferir dentro**.

**Cómo se usa:** crea `src/02-anotar.ts` y ejecútalo con `npm start -- src/02-anotar.ts`. El objetivo es 6 vasos los domingos y 8 el resto.

```ts
// Archivo: src/02-anotar.ts

// 1. PARÁMETROS: TypeScript no puede adivinar qué te van a pasar
function saludar(nombre: string) {
  return `Hola, ${nombre}`;
}

// 2. VARIABLES SIN VALOR INICIAL: se asignarán más tarde
let objetivoVasos: number;
const esDiaDeDescanso = new Date().getDay() === 0;
if (esDiaDeDescanso) {
  objetivoVasos = 6;
} else {
  objetivoVasos = 8;
}

// 3. RETORNO DE FUNCIONES IMPORTANTES: fija el contrato
export function volumenEntreno(series: number, repeticiones: number, pesoKg: number): number {
  return series * repeticiones * pesoKg;
}

console.log(saludar("Dani"));
console.log(`Objetivo de hoy: ${objetivoVasos} vasos`);
console.log(`Volumen: ${volumenEntreno(4, 8, 70)} kg`);
```

```text
Hola, Dani
Objetivo de hoy: 8 vasos
Volumen: 2240 kg
```

- **Parámetros:** sin `: string`, `npm run typecheck` da `error TS7006: Parameter 'nombre' implicitly has an 'any' type.` Es `strict`, a través de `noImplicitAny`.
- **Retorno de `volumenEntreno`:** se exporta. Si alguien rompe la implementación, el error sale **aquí**, no en los diez archivos que la usan.

<Callout type="risk">

- **Usar una variable antes de asignarla:** sin el `if/else`, `console.log(objetivoVasos)` da `error TS2454: Variable 'objetivoVasos' is used before being assigned.` En JavaScript habría impreso `undefined`.
- **Retornos inferidos en funciones exportadas:** un cambio interno altera su tipo y rompe a quien la usa sin avisar. En funciones públicas, anota.

</Callout>

## Paso 4: por qué `any` es peligroso

**Qué es:** `any` **desactiva** el compilador: acepta cualquier valor y te deja hacer cualquier cosa con él.

**Cómo se usa:** crea `src/02-any.ts`.

```ts
// Archivo: src/02-any.ts
function formatearKm(valor: any) {
  return valor.toFixed(1) + " km";
}

console.log(formatearKm(5.25));
console.log(formatearKm("5.25"));
```

```bash
npm run typecheck
```

Sin errores: TypeScript confía ciegamente en `any`. Ahora ejecútalo:

```bash
npm start -- src/02-any.ts
```

```text
5.3 km
…/src/02-any.ts:3
  return valor.toFixed(1) + " km";
               ^

TypeError: valor.toFixed is not a function
    at formatearKm (…/src/02-any.ts:3:16)
```

- **La segunda llamada rompe el programa en ejecución,** justo lo que TypeScript debía evitar. Debajo verás más líneas del _stack trace_.
- **`any` se contagia:** lo que sale de un `any` también es `any`, y el agujero se extiende sin que lo veas.

<Callout type="risk">

- **`any` aparece sin que lo escribas:** `res.json()`, `JSON.parse()` y muchas librerías antiguas lo devuelven. Conviértelo en un tipo concreto o todo lo que sigue queda sin protección.
- **Si de verdad lo necesitas** (una librería sin tipos), limítalo a una línea con un comentario que explique por qué. Nunca "para que se quite el error".

</Callout>

## Paso 5: sustituir `any` por `unknown`

**Qué es:** `unknown` también acepta cualquier valor, pero **no te deja usarlo hasta que compruebes qué es**. Es el tipo correcto para lo que viene de fuera.

**Cómo se usa:** leer unas preferencias guardadas como texto, como las de `localStorage`. Crea `src/02-unknown.ts`.

```ts
// Archivo: src/02-unknown.ts
type Tema = "light" | "dark";

interface Preferencias {
  tema: Tema;
  objetivoVasos: number;
}

const PREFERENCIAS_POR_DEFECTO: Preferencias = { tema: "light", objetivoVasos: 8 };

function leerPreferencias(texto: string): Preferencias {
  let datos: unknown;
  try {
    datos = JSON.parse(texto); // JSON.parse devuelve any: lo guardamos como unknown
  } catch {
    return PREFERENCIAS_POR_DEFECTO; // el texto ni siquiera es JSON válido
  }

  // Comprobación 1: tiene que ser un objeto (y no null)
  if (typeof datos !== "object" || datos === null) {
    return PREFERENCIAS_POR_DEFECTO;
  }

  // Comprobación 2: cada campo con el tipo y los valores esperados
  const tema = "tema" in datos ? datos.tema : undefined;
  const objetivo = "objetivoVasos" in datos ? datos.objetivoVasos : undefined;

  return {
    tema: tema === "dark" || tema === "light" ? tema : PREFERENCIAS_POR_DEFECTO.tema,
    objetivoVasos:
      typeof objetivo === "number" && objetivo > 0 ? objetivo : PREFERENCIAS_POR_DEFECTO.objetivoVasos,
  };
}

// Casos que pueden llegar desde localStorage
console.log(leerPreferencias('{"tema":"dark","objetivoVasos":10}'));
console.log(leerPreferencias('{"tema":"sepia","objetivoVasos":"diez"}'));
console.log(leerPreferencias("esto no es JSON"));
console.log(leerPreferencias("null"));
```

```bash
npm start -- src/02-unknown.ts
```

```text
{ tema: 'dark', objetivoVasos: 10 }
{ tema: 'light', objetivoVasos: 8 }
{ tema: 'light', objetivoVasos: 8 }
{ tema: 'light', objetivoVasos: 8 }
```

- **`const datos: unknown = JSON.parse(…)`:** desde aquí, TypeScript no deja usar `datos` sin comprobarlo.
- **`typeof datos !== "object" || datos === null`:** descarta lo que no es un objeto. Después, TypeScript **sabe** que lo es: es el _narrowing_ (B1.6).
- **`"tema" in datos`** comprueba que la propiedad existe. Cada valor se valida con su tipo **y** su rango, con un valor por defecto si no encaja.

Dos pruebas con `npm run typecheck` (borra cada línea antes de la siguiente):

1. Tras la primera comprobación, `datos.tema.toUpperCase();`:

   ```text
      error TS2339: Property 'tema' does not exist on type 'object'.
   ```

   Sabe que es un objeto, no que tenga `tema`.

2. Antes del `return` final, `tema.toUpperCase();`:

   ```text
      error TS18046: 'tema' is of type 'unknown'.
   ```

   Sabe que `tema` existe, no qué es.

Con `any`, las dos habrían compilado y roto la app.

<Callout type="risk">

- **Este código es largo a propósito:** en proyectos reales, Zod (I1) hace esta validación en una línea y genera el tipo.
- **`localStorage` puede lanzar errores** (modo privado, almacenamiento lleno). Envuelve `getItem` en `try/catch`.
- **Tus propios datos antiguos también son externos:** si cambias la forma de las preferencias, los usuarios conservan el formato viejo. Los valores por defecto te protegen.

</Callout>

## Paso 6: `never`, lo que no puede ocurrir

**Qué es:** el tipo de un valor que **nunca existe**: una función que siempre lanza un error o una rama imposible.

**Cómo se usa:** crea `src/02-never.ts`.

```ts
// Archivo: src/02-never.ts
function fallar(mensaje: string): never {
  throw new Error(mensaje);
}

function dividir(a: number, b: number): number {
  if (b === 0) {
    fallar("No se puede dividir entre 0");
  }
  return a / b;
}

console.log(dividir(10, 4));
try {
  dividir(1, 0);
} catch (error) {
  console.log(error instanceof Error ? error.message : error);
}
```

```text
2.5
No se puede dividir entre 0
```

- **`: never` en `fallar`:** TypeScript sabe que el código no continúa tras la llamada. Su uso más importante llega en B1.6: que el compilador avise si olvidas un caso de un `switch`.

<Callout type="risk">

- **`void` no es `never`:** `void` termina sin devolver nada útil; `never` no termina con normalidad. Anotar `: never` en una función que puede terminar da error.
- **`catch (error)` es `unknown`** con `strict`. Comprueba `error instanceof Error` antes de leer `.message`.

</Callout>

## Paso 7: tipos literales y uniones

**Qué es:** un tipo puede ser **un valor concreto**, como `"dark"`. Con `|` unes varios en un conjunto cerrado de valores permitidos.

**Cómo se usa:** crea `src/02-literales.ts`.

```ts
// Archivo: src/02-literales.ts
let temaVariable = "dark"; // string: con let el valor puede cambiar
const temaFijo = "dark"; // "dark": con const nunca cambiará

type Tema = "light" | "dark";
type Categoria = "trabajo" | "personal" | "salud" | "estudio";

let tema: Tema = "light";
tema = "dark";

function colorDeCategoria(categoria: Categoria): string {
  if (categoria === "trabajo") return "#0284c7";
  if (categoria === "personal") return "#d97706";
  if (categoria === "salud") return "#0d9488";
  return "#f25c76";
}

console.log(temaVariable, temaFijo, tema);
console.log(colorDeCategoria("salud"));
```

```text
dark dark dark
#0d9488
```

- **`let` frente a `const`:** `temaVariable` es `string`; `temaFijo` es `"dark"`. Con `const`, el valor no puede cambiar, así que TypeScript infiere el **literal**.
- **Unión de literales:** `tema = "sepia";` da `Type '"sepia"' is not assignable to type 'Tema'.` Y al escribir `colorDeCategoria("`, el editor ofrece las cuatro categorías.

<Callout type="risk">

- **Los valores del exterior no son literales:** un `<select>` da un `string`, no una `Categoria`. Compruébalo contra la lista permitida, como en el Paso 5.
- **Una categoría nueva cae en el último `return` sin avisar.** En B1.6 harás que el compilador te obligue a manejarla.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Crea `src/02-ejercicio.ts` con una función `leerObjetivoKm(texto: string): number` que reciba el contenido de un campo de formulario y devuelva los kilómetros objetivo de la semana.
2. El parámetro es texto; conviértelo y valida: si no es un número, es negativo o supera 200, devuelve 20 como valor por defecto.
3. Usa `unknown` en algún punto intermedio en lugar de `any`.
4. Prueba la función con `"35"`, `"-5"`, `"mucho"`, `""` y `"1000"`, y ejecuta `npm run typecheck` y `npm start -- src/02-ejercicio.ts`.

</Callout>

Solución completa:

```ts
// Archivo: src/02-ejercicio.ts
const OBJETIVO_POR_DEFECTO = 20;
const OBJETIVO_MAXIMO = 200;

function esNumeroValido(valor: unknown): valor is number {
  return typeof valor === "number" && Number.isFinite(valor);
}

function leerObjetivoKm(texto: string): number {
  const limpio = texto.trim();
  if (limpio === "") return OBJETIVO_POR_DEFECTO;

  const convertido: unknown = Number(limpio);
  if (!esNumeroValido(convertido)) return OBJETIVO_POR_DEFECTO;
  if (convertido < 0 || convertido > OBJETIVO_MAXIMO) return OBJETIVO_POR_DEFECTO;

  return convertido;
}

for (const entrada of ["35", "-5", "mucho", "", "1000"]) {
  console.log(`"${entrada}" → ${leerObjetivoKm(entrada)} km`);
}
```

```text
"35" → 35 km
"-5" → 20 km
"mucho" → 20 km
"" → 20 km
"1000" → 20 km
```

`valor is number` es un **type guard** propio: "si devuelve `true`, el valor es un `number`" (B1.6).

<Callout type="risk">

- **`Number("")` vale `0`, no `NaN`:** sin comprobar el texto vacío, un campo en blanco sería un objetivo de 0 km.
- **`Number.isFinite`, no `isFinite`:** el global convierte antes de comprobar (`isFinite("5")` es `true`).

</Callout>

<Callout type="mastery">

Sabes qué tipo inferirá TypeScript antes de pasar el ratón por encima, anotas solo parámetros, variables sin valor y retornos públicos, y nunca usas `any` para datos externos: usas `unknown` y compruebas.

</Callout>

## Resumen

- Primitivos en minúscula: `string`, `number`, `boolean`, `null`, `undefined`, `bigint`, `symbol`.
- La inferencia deduce el tipo y lo fija: no anotes lo evidente.
- Anota en los bordes: parámetros, variables sin valor y retornos públicos.
- `any` apaga el compilador; `unknown` acepta todo, pero obliga a comprobar.
- `never` marca lo imposible; `const` da literales; `|` crea conjuntos cerrados.
