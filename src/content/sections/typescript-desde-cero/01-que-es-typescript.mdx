TypeScript ya está en tus proyectos: el `tsconfig.json` de Astro, los `.ts`, los subrayados rojos de VS Code. Aquí montas `ts-playground`, la carpeta que usarás en todas las secciones de este curso.

**Requisitos:** Node.js 22 o superior (`node -v`) y VS Code.

## Paso 1: crear el proyecto de práctica

**Qué es:** un proyecto de Node con TypeScript instalado como dependencia de desarrollo. Así cada proyecto fija su propia versión.

**Cómo se usa:**

```bash
mkdir ts-playground
cd ts-playground
npm init -y
npm install --save-dev typescript tsx
mkdir src
code .
```

- **`--save-dev`:** `typescript` (el compilador, `tsc`) y `tsx` (ejecuta `.ts` sin compilar) no van a producción.
- **`code .`** abre la carpeta en VS Code. Si el comando no existe: `Cmd` + `Shift` + `P` → _Shell Command: Install 'code' command in PATH_.

Sustituye `package.json` por este, completo:

```json
{
  "name": "ts-playground",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "typecheck": "tsc --noEmit",
    "build": "tsc",
    "start": "tsx"
  },
  "devDependencies": {
    "tsx": "^4.23.15",
    "typescript": "^7.0.2"
  }
}
```

- **`"type": "module"`:** el proyecto usa `import`/`export`, como Astro.
- **Los tres _scripts_:** `npm run typecheck` comprueba tipos, `npm run build` compila y `npm start -- archivo.ts` ejecuta.

<Callout type="risk">

- **Versiones:** las de `devDependencies` son las de esta lección (TypeScript 7.0). Si npm te instala otras más nuevas, **conserva las tuyas**. Tu proyecto de Astro puede usar otra versión, y es normal.
- **Nada de `npm install -g typescript`:** una versión global rompe proyectos antiguos al actualizarla. Usa `npx tsc` o los _scripts_.
- **Sin `"type": "module"`,** los `import` compilados fallan con `SyntaxError: Cannot use import statement outside a module`.

</Callout>

## Paso 2: configurar el compilador con `tsconfig.json`

**Qué es:** el archivo que dice al compilador **qué archivos** revisar y **con qué reglas**. Admite comentarios (es `jsonc`).

**Cómo se usa:** créalo en la raíz del proyecto.

```jsonc
// Archivo: tsconfig.json
{
  "compilerOptions": {
    // Versión de JavaScript que se genera y métodos disponibles (ES2023 incluye toSorted, findLast…)
    "target": "ES2023",
    // Formato de módulos de salida: import/export estándar
    "module": "ESNext",
    // Cómo se resuelven los imports: igual que Vite y Astro (sin exigir extensiones)
    "moduleResolution": "Bundler",
    // Trata cada archivo como un módulo independiente aunque no tenga import/export
    "moduleDetection": "force",
    // Activa todas las comprobaciones estrictas (la opción más importante)
    "strict": true,
    // Acceder a lista[0] devuelve "valor | undefined" (lo verás en B1.3)
    "noUncheckedIndexedAccess": true,
    // Obliga a escribir "import type" cuando solo importas tipos (lo verás en B1.7)
    "verbatimModuleSyntax": true,
    // No revisa los tipos internos de las librerías de node_modules (más rápido)
    "skipLibCheck": true,
    // Dónde están los .ts y dónde se escriben los .js compilados
    "rootDir": "src",
    "outDir": "dist"
  },
  "include": ["src"]
}
```

- **`strict: true`:** activa las comprobaciones serias. Son, en lo esencial, las reglas de tu proyecto de Astro; en B1.7 verás cada línea.

<Callout type="risk">

- **`moduleDetection: "force"`:** sin él, un archivo sin `import` ni `export` es un _script_ global, y dos funciones con el mismo nombre en archivos distintos dan `Duplicate function implementation`.
- **No desactives `strict`** para quitarte errores: siguen en tu código, solo dejas de verlos.
- **`include` mal puesto:** si tus archivos no están en `src/`, `tsc` dice `No inputs were found in config file`.

</Callout>

## Paso 3: un bug real en JavaScript

**Qué es:** JavaScript tiene **tipado dinámico**: nadie comprueba los tipos hasta que el código se ejecuta. Y los valores de un formulario **siempre llegan como texto**.

**Cómo se usa:** crea `src/01-suma.js`.

```js
// Archivo: src/01-suma.js
function sumarKm(a, b) {
  return a + b;
}

// Simulamos lo que llega de un formulario: siempre texto
const kmLunes = "5";
const kmMartes = 3;

const total = sumarKm(kmLunes, kmMartes);
console.log(`Total de la semana: ${total} km`);
console.log(`¿Supera los 10 km? ${total > 10}`);
```

```bash
node src/01-suma.js
```

```text
Total de la semana: 53 km
¿Supera los 10 km? true
```

- **El programa no falla, miente:** con `+`, si un valor es texto, JavaScript concatena (`"5" + 3` → `"53"`). Luego compara `"53" > 10` convirtiendo el texto a número.

<Callout type="risk">

- **Errores silenciosos:** el peor bug no rompe la app, guarda datos erróneos sin avisar. Esos 53 km contaminarían tus estadísticas.
- **Formularios, `URLSearchParams` y `localStorage` devuelven texto.** Convierte (`Number(valor)`) y valida antes de operar.

</Callout>

## Paso 4: el mismo código en TypeScript

**Qué es:** TypeScript es JavaScript con anotaciones de tipo. El compilador (`tsc`) comprueba que encajan **sin ejecutar nada**, y luego las borra: se ejecuta JavaScript normal.

**Cómo se usa:** crea `src/01-suma.ts`.

```ts
// Archivo: src/01-suma.ts
function sumarKm(a: number, b: number): number {
  return a + b;
}

const kmLunes = Number("5"); // convertimos el texto del formulario a número
const kmMartes = 3;

const total = sumarKm(kmLunes, kmMartes);
console.log(`Total de la semana: ${total} km`);
console.log(`¿Supera los 10 km? ${total > 10}`);
```

```bash
npm run typecheck
```

Sin salida significa sin errores. Cambia `Number("5")` por `"5"` y repite:

```text
src/01-suma.ts:9:23 - error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.

9 const total = sumarKm(kmLunes, kmMartes);
                        ~~~~~~~

Found 1 error in src/01-suma.ts:9
```

Vuelve a poner `Number("5")` y ejecútalo:

```bash
npm start -- src/01-suma.ts
```

```text
Total de la semana: 8 km
¿Supera los 10 km? false
```

- **`a: number`:** el parámetro debe ser un número. **`): number`:** lo que devuelve.
- **`9:23` y `TS2345`:** línea, columna (la 1 es el comentario `// Archivo:`) y código del error. VS Code lo subraya con el mismo motor.

<Callout type="risk">

- **`tsx` no comprueba tipos:** con `"5"`, `npm start` vuelve a decir 53 km. Usa `npm run typecheck` (o `tsc --noEmit`) antes de cada _commit_ y en el CI.
- **`Number("cinco")` es `NaN`, y sigue siendo un `number`:** los tipos comprueban la forma, no el valor. Los valores se validan con Zod (I1).

</Callout>

## Paso 5: los tipos desaparecen al compilar

**Qué es:** compilar es borrar los tipos y dejar JavaScript. TypeScript **no añade comprobaciones en ejecución**.

**Cómo se usa:** compila sin `--noEmit` y abre `dist/01-suma.js`.

```bash
npm run build
```

```js
// Archivo: src/01-suma.ts
function sumarKm(a, b) {
    return a + b;
}
const kmLunes = Number("5"); // convertimos el texto del formulario a número
const kmMartes = 3;
const total = sumarKm(kmLunes, kmMartes);
console.log(`Total de la semana: ${total} km`);
console.log(`¿Supera los 10 km? ${total > 10}`);
export {};
```

- **No queda ni rastro de `number`.** El código es casi el que escribirías a mano, comentarios incluidos.
- **`export {};`** lo añade TypeScript por `moduleDetection: "force"`, para que el archivo sea un módulo.
- **Dos conclusiones:** TypeScript **no hace tu código más lento**, porque se ejecuta el mismo JavaScript. Y **no protege en ejecución**: un dato con otra forma que llegue en producción pasa sin control.

Crea el `.gitignore`:

```gitignore
node_modules/
dist/
```

<Callout type="risk">

- **No subas `dist/` a Git:** es código generado.
- **En Astro no compilas con `tsc`:** Vite borra los tipos al vuelo, como `tsx`. Quien **comprueba** es `npm run check` (`astro check`). Si nunca lo ejecutas, los errores de tipos solo están en el editor.

</Callout>

## Paso 6: el editor como herramienta

**Qué es:** VS Code usa el mismo motor que `tsc`, así que el editor te da los tipos mientras escribes. Practica estos gestos en `src/01-suma.ts`:

| Gesto                | Qué hace                                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Hover sobre `total`  | Muestra `const total: number`, aunque no lo escribiste (es la _inferencia_, B1.2)                                  |
| `total.`             | Autocompleta solo métodos de número (`toFixed`, `toString`…)                                                       |
| `F12` o `Cmd` + clic | Va a la definición. Sobre `console.log`, abre el `.d.ts` de Node: así se lee la documentación real de una librería |

<Callout type="risk">

- **Versión del editor:** VS Code trae su propio TypeScript. Si sus errores no coinciden con `npm run typecheck`: `Cmd` + `Shift` + `P` → _TypeScript: Select TypeScript Version_ → _Use Workspace Version_.
- **Subrayados desfasados** tras cambiar `tsconfig.json`: `Cmd` + `Shift` + `P` → _TypeScript: Restart TS Server_.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. En `ts-playground`, crea `src/01-ejercicio.ts` con una función `ritmoMedio(km, minutos)` que devuelva el ritmo en minutos por kilómetro, con tipos en parámetros y retorno.
2. Simula que los dos valores llegan de un formulario como texto, conviértelos y muestra el resultado con un decimal.
3. Ejecuta `npm run typecheck`; después quita la conversión de uno de los valores y lee el error completo.
4. Ejecuta el archivo con `npm start -- src/01-ejercicio.ts`, compila con `npm run build` y busca el resultado en `dist/`.

</Callout>

Solución completa:

```ts
// Archivo: src/01-ejercicio.ts
function ritmoMedio(km: number, minutos: number): number {
  if (km <= 0) {
    throw new Error("La distancia debe ser mayor que 0");
  }
  return minutos / km;
}

// Lo que llega de un formulario: texto
const kmFormulario = "5";
const minutosFormulario = "28";

const ritmo = ritmoMedio(Number(kmFormulario), Number(minutosFormulario));
console.log(`Ritmo medio: ${ritmo.toFixed(1)} min/km`);
```

```text
Ritmo medio: 5.6 min/km
```

<Callout type="risk">

- **División por cero:** sin `km <= 0`, `28 / 0` da `Infinity`, que sigue siendo un `number`. Los tipos no sustituyen a validar valores.
- **`toFixed` devuelve texto:** sumar `ritmo.toFixed(1)` con un número es el bug del Paso 3, y esta vez TypeScript sí avisa.

</Callout>

<Callout type="mastery">

Puedes montar un proyecto de TypeScript desde una carpeta vacía y explicar con tus palabras por qué TypeScript no hace tu código más lento y por qué, aun así, no protege contra datos inesperados en ejecución.

</Callout>

## Resumen

- TypeScript = JavaScript + tipos que `tsc` comprueba **antes** de ejecutar.
- `tsconfig.json` fija qué se revisa y con qué reglas: `strict: true`, siempre.
- `tsc --noEmit` comprueba, `tsx` ejecuta sin comprobar y `tsc` compila a `dist/`.
- Los tipos se borran al compilar: sin coste, pero sin protección en ejecución.
- Hover, autocompletado y `F12` son la mitad del valor de TypeScript.
