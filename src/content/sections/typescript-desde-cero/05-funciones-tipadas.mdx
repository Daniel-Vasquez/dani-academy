Una función bien tipada dice qué necesita, qué devuelve y qué puede fallar. Aquí construyes un pequeño cliente de tareas que termina llamando a una API real con `fetch` y `Promise<T>`.

**Requisitos:** el `ts-playground` y conexión a internet: usarás `https://jsonplaceholder.typicode.com`, una API pública de pruebas sin registro.

## Paso 1: parámetros obligatorios, opcionales y con valor por defecto

**Qué es:** tres clases de parámetros. Los obligatorios se pasan siempre, los opcionales (`?`) pueden faltar y los que tienen valor por defecto (`=`) toman ese valor si faltan.

**Cómo se usa:** crea `src/05-parametros.ts`.

```ts
// Archivo: src/05-parametros.ts
// 1. Obligatorio: siempre hay que pasarlo
// 2. Opcional (?): puede omitirse; dentro de la función vale undefined
// 3. Con valor por defecto (=): puede omitirse; dentro de la función nunca es undefined
function formatearEntreno(tipo: string, notas?: string, minutos = 30): string {
  const base = `${tipo} · ${minutos} min`;
  return notas ? `${base} · ${notas}` : base;
}

console.log(formatearEntreno("running"));
console.log(formatearEntreno("fuerza", "Pierna"));
console.log(formatearEntreno("yoga", undefined, 45));

// Parámetro rest: un número variable de argumentos, que llegan como array
function sumarKm(...distancias: number[]): number {
  return distancias.reduce((total, km) => total + km, 0);
}

console.log(`Total: ${sumarKm(5, 3.2, 10)} km`);
console.log(`Sin datos: ${sumarKm()} km`);
```

```bash
npm start -- src/05-parametros.ts
```

```text
running · 30 min
fuerza · 30 min · Pierna
yoga · 45 min
Total: 18.2 km
Sin datos: 0 km
```

Su firma, con el ratón encima de `formatearEntreno`:

```text
function formatearEntreno(tipo: string, notas?: string, minutos?: number): string
```

- **`minutos = 30`:** desde fuera es `minutos?: number`, pero **dentro** es `number`, nunca `undefined`.
- **`notas?: string`:** dentro es `string | undefined`, y por eso se comprueba antes de usarla.
- **`...distancias: number[]`** recoge los argumentos sueltos en un array: `sumarKm()` recibe `[]`.

<Callout type="risk">

- **Los opcionales van al final:** `function f(a?: string, b: number)` da `error TS1016: A required parameter cannot follow an optional parameter.` Para saltarte uno del medio hay que pasar `undefined`.
- **Con más de tres parámetros, usa un objeto:** `formatearEntreno("yoga", undefined, 45)` obliga a recordar el orden. Es el patrón de las _props_ de React (Paso 2).
- **El valor por defecto solo se aplica con `undefined`,** no con `null`. Con `strict`, TypeScript no deja pasar `null` a un `number`.

</Callout>

## Paso 2: el patrón del objeto de opciones

**Qué es:** con varios opcionales, la función recibe **un solo objeto** y lo desestructura en la firma. El orden deja de importar.

**Cómo se usa:** crea `src/05-opciones.ts`.

```ts
// Archivo: src/05-opciones.ts
interface OpcionesFormato {
  tipo: string;
  minutos?: number;
  notas?: string;
  unidad?: "min" | "h";
}

function formatearEntreno({ tipo, minutos = 30, notas, unidad = "min" }: OpcionesFormato): string {
  const duracion = unidad === "h" ? `${(minutos / 60).toFixed(1)} h` : `${minutos} min`;
  return notas ? `${tipo} · ${duracion} · ${notas}` : `${tipo} · ${duracion}`;
}

console.log(formatearEntreno({ tipo: "running" }));
console.log(formatearEntreno({ tipo: "yoga", minutos: 45 }));
console.log(formatearEntreno({ tipo: "senderismo", minutos: 150, unidad: "h", notas: "Desierto de los Leones" }));
```

```bash
npm start -- src/05-opciones.ts
```

```text
running · 30 min
yoga · 45 min
senderismo · 2.5 h · Desierto de los Leones
```

- **`{ tipo, minutos = 30, notas, unidad = "min" }: OpcionesFormato`:** saca cada propiedad, aplica los valores por defecto, y el tipo va **después** del patrón completo.

<Callout type="risk">

- **`function f({ tipo: string })` no tipa nada:** renombra `tipo` a una variable llamada `string`. El error lo delata: `error TS7031: Binding element 'string' implicitly has an 'any' type.` Lo correcto: `function f({ tipo }: { tipo: string })`.
- **Erratas en las opciones:** `{ tipo: "yoga", minuto: 45 }` da error por el _excess property checking_ (B1.3), salvo que el objeto venga de una variable sin anotar.

</Callout>

## Paso 3: funciones como tipos

**Qué es:** las funciones son valores que se pasan como argumentos (`.filter`, `addEventListener`, el `onClick` de React). Su tipo es su firma con una flecha: `(tarea: Tarea) => boolean`.

**Cómo se usa:** crea `src/05-callbacks.ts`.

```ts
// Archivo: src/05-callbacks.ts
interface Tarea {
  id: number;
  titulo: string;
  hecha: boolean;
}

// El tipo de una función: recibe una Tarea y devuelve boolean
type Filtro = (tarea: Tarea) => boolean;

const pendientes: Filtro = (t) => !t.hecha; // t ya es Tarea: no hay que anotarlo
const completadas: Filtro = (t) => t.hecha;
const contiene =
  (texto: string): Filtro =>
  (t) =>
    t.titulo.toLowerCase().includes(texto.toLowerCase());

function filtrar(tareas: Tarea[], ...filtros: Filtro[]): Tarea[] {
  return tareas.filter((tarea) => filtros.every((filtro) => filtro(tarea)));
}

const tareas: Tarea[] = [
  { id: 1, titulo: "Correr 5 km", hecha: true },
  { id: 2, titulo: "Correr series de 400 m", hecha: false },
  { id: 3, titulo: "Leer sección B1.5", hecha: false },
];

console.log("Pendientes:", filtrar(tareas, pendientes).map((t) => t.titulo));
console.log("Completadas:", filtrar(tareas, completadas).map((t) => t.titulo));
console.log("Pendientes de correr:", filtrar(tareas, pendientes, contiene("correr")).map((t) => t.titulo));
```

```bash
npm start -- src/05-callbacks.ts
```

```text
Pendientes: [ 'Correr series de 400 m', 'Leer sección B1.5' ]
Completadas: [ 'Correr 5 km' ]
Pendientes de correr: [ 'Correr series de 400 m' ]
```

- **Tipado contextual:** en `const pendientes: Filtro = (t) => !t.hecha` no anotas `t`: TypeScript lo deduce de `Filtro`. Igual en `.filter((tarea) => …)` o en `onClick={(e) => …}`.
- **`contiene` es una fábrica:** una función que devuelve un `Filtro`. Es habitual en React y en los _middleware_.

<Callout type="risk">

- **Un callback puede usar menos parámetros de los declarados:** `(t) => true` es un `Filtro` válido. Por eso `forEach((x) => …)` funciona aunque pase tres argumentos.
- **`["1", "2", "3"].map(parseInt)` da `[1, NaN, NaN]`:** `map` pasa el índice y `parseInt` lo toma como base. Los tipos encajan, así que TypeScript no avisa: escribe `.map((s) => Number.parseInt(s, 10))`.
- **Con muchos filtros y miles de elementos,** pon primero el que más descarta: `every` se detiene en el primer `false`.

</Callout>

## Paso 4: `void` frente a `undefined`

**Qué es:** `void` en un tipo de función significa "**ignoraré** lo que devuelvas". `undefined` es un valor concreto: una función `(): undefined` debe devolverlo.

**Cómo se usa:** crea `src/05-void.ts`.

```ts
// Archivo: src/05-void.ts
type AlCambiar = (valor: number) => void;

function registrarCambio(valor: number): void {
  console.log(`Nuevo valor: ${valor}`);
}

const historial: number[] = [];

// push devuelve un number (la nueva longitud), pero un callback de tipo void puede devolver cualquier cosa:
// quien lo llama promete ignorar el resultado
const guardarEnHistorial: AlCambiar = (valor) => historial.push(valor);

function crearContador(alCambiar: AlCambiar) {
  let valor = 0;
  return () => {
    valor += 1;
    alCambiar(valor);
  };
}

const incrementar = crearContador(registrarCambio);
incrementar();
incrementar();

const incrementarYGuardar = crearContador(guardarEnHistorial);
incrementarYGuardar();
incrementarYGuardar();
incrementarYGuardar();
console.log(`Historial: ${historial.join(", ")}`);
```

```bash
npm start -- src/05-void.ts
```

```text
Nuevo valor: 1
Nuevo valor: 2
Historial: 1, 2, 3
```

- **`(valor: number) => void` acepta `historial.push(valor)`,** aunque devuelve un número. Por eso escribes `onClick={() => setContador(c + 1)}` en React sin preocuparte del retorno.
- **En una declaración, `void` es estricto:** `function registrarCambio(): void` con `return 5` da error.

<Callout type="risk">

- **No uses el resultado de un callback `void`:** `const r = alCambiar(valor)` es `void` y no sirve de nada. Si necesitas un resultado, declara su tipo real.
- **Callbacks asíncronos:** `onClick={async () => { await guardar(); }}` compila, pero nadie espera la promesa. Si `guardar` falla, queda una promesa rechazada sin manejar: usa `try/catch` dentro.

</Callout>

## Paso 5: funciones asíncronas y `Promise<T>`

**Qué es:** una función `async` **siempre devuelve una promesa**. Si devuelve un `Tarea[]`, su tipo es `Promise<Tarea[]>`.

**Cómo se usa:** primero, mira lo que devuelve la API.

```bash
curl "https://jsonplaceholder.typicode.com/todos?userId=1&_limit=3"
```

```json
[
  { "userId": 1, "id": 1, "title": "delectus aut autem", "completed": false },
  { "userId": 1, "id": 2, "title": "quis ut nam facilis et officia qui", "completed": false },
  { "userId": 1, "id": 3, "title": "fugiat veniam minus", "completed": false }
]
```

La respuesta real tiene más saltos de línea; aquí va compactada. Los textos en latín son de relleno. Con esa forma, crea `src/05-api-tareas.ts`:

```ts
// Archivo: src/05-api-tareas.ts
const API = "https://jsonplaceholder.typicode.com";

// Forma de cada tarea tal como la devuelve la API (nombres en inglés)
interface TareaApi {
  userId: number;
  id: number;
  title: string;
  completed: boolean;
}

// Forma que usa nuestra app
interface Tarea {
  id: number;
  titulo: string;
  hecha: boolean;
}

type Filtro = (tarea: Tarea) => boolean;

function aTarea(t: TareaApi): Tarea {
  return { id: t.id, titulo: t.title, hecha: t.completed };
}

async function obtenerTareas(usuarioId: number, limite = 5): Promise<Tarea[]> {
  const url = `${API}/todos?userId=${usuarioId}&_limit=${limite}`;
  const res = await fetch(url);
  if (!res.ok) {
    throw new Error(`HTTP ${res.status} al pedir ${url}`);
  }
  const datos = (await res.json()) as TareaApi[]; // promesa al compilador, NO una comprobación
  return datos.map(aTarea);
}

const pendientes: Filtro = (t) => !t.hecha;

try {
  const tareas = await obtenerTareas(1);
  console.log(`Descargadas ${tareas.length} tareas`);
  for (const tarea of tareas.filter(pendientes)) {
    console.log(`[ ] #${tarea.id} ${tarea.titulo}`);
  }
  for (const tarea of tareas.filter((t) => t.hecha)) {
    console.log(`[x] #${tarea.id} ${tarea.titulo}`);
  }
} catch (error) {
  console.error("No se pudieron cargar las tareas:", error instanceof Error ? error.message : error);
}
```

```bash
npm run typecheck
npm start -- src/05-api-tareas.ts
```

```text
Descargadas 5 tareas
[ ] #1 delectus aut autem
[ ] #2 quis ut nam facilis et officia qui
[ ] #3 fugiat veniam minus
[ ] #5 laboriosam mollitia et enim quasi adipisci quia provident illum
[x] #4 et porro tempora
```

La tarea #4 sale la última porque primero se imprimen las pendientes.

- **`if (!res.ok)`:** `fetch` **no lanza error** con un 404 o un 500, solo sin conexión. `res.ok` es `true` para los códigos 200–299.
- **`await res.json()` devuelve `any`,** y `as TareaApi[]` le dice al compilador "confía en mí". **No comprueba nada.**
- **`aTarea`** traduce la forma de la API a la de tu app: si la API cambia, solo tocas esa función. El `await` fuera de una función funciona porque el archivo es un módulo ES.

<Callout type="risk">

- **`as` es una promesa, no una verificación:** con la URL de `/users`, TypeScript no se queja y el programa imprime `[ ] #1 undefined`. Si una API cambia de formato, tu app muestra datos rotos sin error. Se valida con Zod (I1).
- **Sin `if (!res.ok)`,** un 404 acaba en `datos.map is not a function`, un error que no dice nada del problema real.
- **Sin límite de tiempo ni en paralelo:** añade `signal: AbortSignal.timeout(5000)` a `fetch`, y pide varias cosas a la vez con `Promise.all([…])`.

</Callout>

## Paso 6: sobrecargas, solo para reconocerlas

**Qué es:** varias firmas para una misma implementación, cuando el tipo de retorno depende de los argumentos. Las verás en librerías, como `document.createElement`.

**Cómo se usa:** crea `src/05-sobrecargas.ts`.

```ts
// Archivo: src/05-sobrecargas.ts
// Firmas públicas: lo que ve quien llama a la función
function convertir(valor: string): number;
function convertir(valor: number): string;
// Implementación: no se puede llamar directamente con esta firma
function convertir(valor: string | number): string | number {
  return typeof valor === "string" ? Number(valor) : String(valor);
}

const comoNumero = convertir("42"); // TypeScript sabe que es number
const comoTexto = convertir(42); // TypeScript sabe que es string

console.log(comoNumero + 1, comoTexto.padStart(5, "0"));
```

```text
43 00042
```

- **`comoNumero` es `number` y `comoTexto` es `string`.** Sin sobrecargas, los dos serían `string | number`.

<Callout type="risk">

- **La implementación no se comprueba contra cada firma:** si siempre devolviera `String(valor)`, TypeScript seguiría diciendo que `convertir("42")` es `number`.
- **Casi siempre hay algo mejor:** dos funciones con nombres claros (`aNumero`, `aTexto`) o un genérico.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Crea `src/05-ejercicio.ts` con una función `obtenerUsuario(id: number): Promise<Usuario | null>` que llame a `https://jsonplaceholder.typicode.com/users/:id`.
2. Debe devolver `null` si la respuesta es un 404 y lanzar un error con cualquier otro estado distinto de 200.
3. `Usuario` solo necesita `id`, `nombre`, `email` y `ciudad` (en la API: `id`, `name`, `email` y `address.city`).
4. Pruébala con el id `1` (existe) y el `999` (no existe).
5. Añade un comentario explicando por qué el `as` no es una verificación.

</Callout>

Solución completa:

```ts
// Archivo: src/05-ejercicio.ts
const API = "https://jsonplaceholder.typicode.com";

interface UsuarioApi {
  id: number;
  name: string;
  email: string;
  address: { city: string };
}

interface Usuario {
  id: number;
  nombre: string;
  email: string;
  ciudad: string;
}

async function obtenerUsuario(id: number): Promise<Usuario | null> {
  const res = await fetch(`${API}/users/${id}`, { signal: AbortSignal.timeout(5000) });

  if (res.status === 404) return null;
  if (!res.ok) throw new Error(`HTTP ${res.status} al pedir el usuario ${id}`);

  // El "as" solo le dice al compilador qué forma ESPERAMOS. Si la API devuelve otra cosa,
  // TypeScript no lo sabrá: el error aparecerá más tarde, lejos de aquí. Se resuelve validando (Zod, curso I1).
  const datos = (await res.json()) as UsuarioApi;

  return { id: datos.id, nombre: datos.name, email: datos.email, ciudad: datos.address.city };
}

for (const id of [1, 999]) {
  try {
    const usuario = await obtenerUsuario(id);
    if (usuario === null) {
      console.log(`Usuario ${id}: no existe`);
    } else {
      console.log(`Usuario ${id}: ${usuario.nombre} <${usuario.email}> de ${usuario.ciudad}`);
    }
  } catch (error) {
    console.error(`Usuario ${id}: error`, error instanceof Error ? error.message : error);
  }
}
```

```bash
npm start -- src/05-ejercicio.ts
```

```text
Usuario 1: Leanne Graham <Sincere@april.biz> de Gwenborough
Usuario 999: no existe
```

<Callout type="risk">

- **`null` para lo esperado, un error para lo inesperado:** un id que no existe es normal y `Usuario | null` obliga a manejarlo. Devolver `null` también ante un 500 esconde una caída del servidor.
- **`AbortSignal.timeout`** lanza un `TimeoutError` a los 5 segundos, y lo captura el mismo `try/catch`.
- **`datos.address.city` asume que `address` existe:** si faltara, `Cannot read properties of undefined` en ejecución, aunque TypeScript no se queje.

</Callout>

<Callout type="mastery">

Tipas cualquier función asíncrona de tus proyectos con su `Promise<T>` correcto, usas un objeto de opciones cuando hay varios parámetros opcionales, sabes por qué un callback `void` puede devolver un valor y puedes explicar por qué un `as` no protege de una API que cambia.

</Callout>

## Resumen

- Opcionales (`?`) al final; con valor por defecto, nunca `undefined` dentro.
- Más de tres parámetros: un objeto de opciones.
- `(t: Tarea) => boolean` tipa funciones como valores; los callbacks infieren sus parámetros.
- `void` en un tipo de función ignora el resultado; `undefined` es un valor.
- `async` devuelve `Promise<T>`; `fetch` no falla con un 404, y `as` no verifica nada.
