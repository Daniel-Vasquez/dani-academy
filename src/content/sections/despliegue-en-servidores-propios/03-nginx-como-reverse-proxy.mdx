Tu contenedor solo escucha en `127.0.0.1:4321` (A4.2), así que falta quien reciba a los visitantes en el puerto 80. Eso es un **_reverse proxy_**, y **Nginx** es el más usado. Aquí lo pones delante, haces que formularios, registro y límite de intentos sigan funcionando, añades compresión y estáticos precomprimidos y lo comparas con Caddy.

**Requisitos:** `entrenos-app` con el `Dockerfile` y el `compose.yaml` de A4.2, en el servidor de I6, con `ufw` activo (I6.5) y los puertos 80 y 443 permitidos. En las salidas, la IP del servidor es `192.168.64.2` (I6.5): usa la tuya.

## Paso 1: por qué no exponer Node en el puerto 80

**Qué es:** en Linux, los puertos por debajo de 1024 son **privilegiados**: solo `root` los abre.

**Cómo se usa:** con un usuario normal:

```bash
node -e 'require("http").createServer((q, r) => r.end("hola")).listen(80, "0.0.0.0")'
```

```text
Error: listen EACCES: permission denied 0.0.0.0:80
```

```bash
sysctl net.ipv4.ip_unprivileged_port_start
```

```text
net.ipv4.ip_unprivileged_port_start = 1024
```

- **Node como `root` entregaría el servidor** al primer fallo de la app o de sus dependencias (por eso `USER node` en A4.2). Nginx lo resuelve así:

```bash
sudo apt-get install -y nginx
ps -o user,args -C nginx
```

```text
USER     COMMAND
root     nginx: master process /usr/sbin/nginx -g daemon on; master_pr…
www-data nginx: worker process
www-data nginx: worker process
```

- **El proceso principal es `root` solo para abrir puertos;** atienden trabajadores `www-data` sin privilegios, uno por núcleo (aquí, dos). Node usa un solo hilo (A4.1).
- **Lo demás lo medirás:** Nginx comprime fuera del hilo de la app (Paso 5), sirve un JavaScript tres veces más rápido (Paso 6), gestiona HTTPS (A4.4), sigue en pie si la app cae (A4.5) y rechaza cuerpos enormes (Paso 7).

<Callout type="risk">

- **Comprueba el valor en tu servidor:** con `ip_unprivileged_port_start = 0` (máquinas de Lima, contenedores) no verás `EACCES`; en un VPS suele ser 1024. Para repetir la prueba, `sudo sysctl net.ipv4.ip_unprivileged_port_start=1024` hasta reiniciar.
- **`setcap` o `authbind` solo resuelven el puerto:** siguen faltando compresión, HTTPS y lo demás.

</Callout>

## Paso 2: el primer `proxy_pass`

**Qué es:** en Ubuntu, `sites-available` guarda las configuraciones y `sites-enabled` enlaza las activas. `proxy_pass` reenvía las peticiones a tu app.

**Cómo se usa:** recién instalado, responde la bienvenida:

```bash
curl -sI http://127.0.0.1/ | grep -iE "^(HTTP|server)"
```

```text
HTTP/1.1 200 OK
Server: nginx/1.28.3 (Ubuntu)
```

Levanta la app (`docker compose up -d`) y la configuración más corta, con `sudo nano /etc/nginx/sites-available/entrenos`:

```nginx
# Archivo: /etc/nginx/sites-available/entrenos (primera versión: solo proxy_pass)
server {
  listen 80 default_server;
  listen [::]:80 default_server;
  server_name _;

  location / {
    proxy_pass http://127.0.0.1:4321;
  }
}
```

- **`server`** es un sitio; **`listen 80 default_server`** escucha en IPv4 e IPv6 y atiende lo que no sea de otro sitio; **`server_name _`**, sin dominio aún (A4.4); **`location /`**, todas las rutas.

Activa el sitio, quita el de bienvenida y recarga:

```bash
sudo rm /etc/nginx/sites-enabled/default
sudo ln -s /etc/nginx/sites-available/entrenos /etc/nginx/sites-enabled/entrenos
sudo nginx -t
sudo systemctl reload nginx
```

```text
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

- **`nginx -t` revisa sin aplicar,** y `reload` aplica sin cortar conexiones.

Desde **tu equipo**, como un visitante:

```bash
curl -s -m 3 -o /dev/null -w "4321 directo -> %{http_code}\n" http://192.168.64.2:4321/
curl -s -o /dev/null -w "GET / -> %{http_code}\n" http://192.168.64.2/
curl -s -o /dev/null -w "GET /entrar -> %{http_code}\n" http://192.168.64.2/entrar
```

```text
4321 directo -> 000
GET / -> 200
GET /entrar -> 200
```

El 4321 no responde desde fuera y el 80 sí. Ahora un registro y un formulario, con el `Origin` que enviaría el navegador:

```bash
B=http://192.168.64.2
curl -s -w " -> %{http_code}\n" -H "origin: $B" -H "content-type: application/json" \
  -d '{"email":"prueba@prueba.test","password":"una-clave-de-prueba-larga","name":"Prueba"}' $B/api/auth/sign-up/email
curl -s -w " -> %{http_code}\n" -H "origin: $B" -H "content-type: application/x-www-form-urlencoded" -d "a=1" $B/nuevo-accion
```

```text
{"message":"Invalid origin","code":"INVALID_ORIGIN"} -> 403
Cross-site POST form submissions are forbidden -> 403
```

- **Las páginas cargan y nadie puede registrarse ni enviar un formulario.** Un `curl` a la portada no lo habría visto.

<Callout type="risk">

- **Comprueba siempre desde fuera:** en el servidor, `curl` se salta _firewall_ y red.
- **Si `nginx -t` falla, no recargues:** `reload` mantendría la configuración anterior, pero un `restart` dejaría Nginx parado.
- **Un enlace en `sites-enabled` a un archivo borrado** hace fallar `nginx -t` (`open() … failed`): quítalo también.

</Callout>

## Paso 3: que la app sepa dónde está

**Qué es:** contra CSRF (I5.2), Astro y Better Auth comparan el `Origin` con su propia dirección, que deducen de lo que les llega. `proxy_pass` manda como `Host` `127.0.0.1:4321`, y `http://192.168.64.2` les parece otra web. Son **tres arreglos**, y hacen falta los tres.

**Cómo se usa:** **primero, las cabeceras,** dentro de `location /`:

```nginx
  location / {
    proxy_pass http://127.0.0.1:4321;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
```

- **`Host`** es el dominio del visitante; **`X-Forwarded-Proto`**, `http` o `https` (A4.4); **`X-Forwarded-For`**, su IP (Paso 4).
- **Tras `nginx -t` y `reload`, lo mismo: 403 y 403.** Llegan, pero nadie se fía aún.

**Segundo, `BETTER_AUTH_URL`,** que en tu `.env` sigue siendo `http://localhost:4321`. En el `.env` **del servidor**:

```bash
BETTER_AUTH_URL=http://192.168.64.2
```

Con `docker compose up -d`, el registro ya funciona:

```text
{"token":"…","user":{"name":"Prueba","email":"prueba@prueba.test",…}} -> 200
Cross-site POST form submissions are forbidden -> 403
```

**Tercero, `allowedDomains`.** Astro no se fía de `Host` ni de `X-Forwarded-*`, que cualquiera puede inventar, salvo para los dominios de `security.allowedDomains`. En `astro.config.mjs`, tras el adaptador:

```js
  adapter: node({
    mode: "standalone",
  }),

  security: {
    // Detrás de un proxy: los únicos dominios por los que Astro acepta Host y X-Forwarded-* (A4.3).
    // Se fija en el build; sin esto, la app se cree en localhost y rechaza los formularios
    allowedDomains: process.env.APP_HOSTNAME ? [{ hostname: process.env.APP_HOSTNAME }] : [],
  },
```

Se fija en el _build_, como `PUBLIC_NOMBRE_APP` (A4.2). En la etapa `build` del `Dockerfile`:

```dockerfile
ARG PUBLIC_NOMBRE_APP="Mi entreno"
ARG OBJETIVO_SEMANAL_MINUTOS=150
ARG APP_HOSTNAME
```

En `build.args` de `compose.yaml`:

```yaml
    build:
      context: .
      args:
        PUBLIC_NOMBRE_APP: "Mi entreno"
        APP_HOSTNAME: ${APP_HOSTNAME:?Añade APP_HOSTNAME a .env} # dominio o IP pública, sin http
```

Y en el `.env` del servidor, que Compose usa para `${…}`:

```bash
APP_HOSTNAME=192.168.64.2
```

- **`${APP_HOSTNAME:?…}`** impide construir sin él, en vez de dar una imagen que rechaza todos los formularios:

```text
error while interpolating services.app.build.args.APP_HOSTNAME: required variable APP_HOSTNAME is missing a value: Añade APP_HOSTNAME a .env
```

Con `docker compose up -d --build`, las pruebas más un dominio falso y una web ajena:

```bash
curl -s -o /dev/null -w "formulario, Origin de la web -> %{http_code}\n" -H "origin: $B" \
  -H "content-type: application/x-www-form-urlencoded" -d a=1 $B/nuevo-accion
curl -s -o /dev/null -w "formulario, Host y Origin falsos -> %{http_code}\n" -H "host: malo.com" -H "origin: http://malo.com" \
  -H "content-type: application/x-www-form-urlencoded" -d a=1 $B/nuevo-accion
```

```text
formulario, Origin de la web -> 302
formulario, Host y Origin falsos -> 403
```

- **302 es la redirección a `/entrar`** (sin sesión): el formulario pasa, y el dominio falso sigue en 403. Con sesión, todo el flujo:

```text
registro 200
entreno 201
estadisticas con sesión 200
```

<Callout type="risk">

- **El `.env` del servidor no es el tuyo:** `BETTER_AUTH_URL` y `APP_HOSTNAME` cambian. `APP_HOSTNAME` exige reconstruir; `BETTER_AUTH_URL`, solo recrear el contenedor.
- **Solo tus dominios en `allowedDomains`:** un comodín (`**.tudominio.com`) amplía lo que se puede falsificar.
- **Astro ya confía en `X-Forwarded-Proto`** (con `https`, el formulario pasa: 302), lo que necesitarás en A4.4. Por eso Node solo debe recibir tráfico de Nginx: publicar en `127.0.0.1` no es opcional.

</Callout>

## Paso 4: `X-Forwarded-For` y la IP del visitante

**Qué es:** para Node, todo viene de Nginx. La IP real viaja en `X-Forwarded-For`, y Better Auth la usa para limitar intentos de inicio de sesión (I5.5): tres fallos y el siguiente, 429.

**Cómo se usa:** un atacante falla cinco veces desde una IP y luego otro usuario intenta entrar desde otra:

```text
sin X-Forwarded-For
  atacante: 401 401 401 429 429
  otro usuario (otra IP): 429

con X-Forwarded-For $remote_addr
  atacante: 401 401 401 429 429
  otro usuario (otra IP): 401
```

- **Sin la cabecera, un atacante deja sin entrar a todos:** un único contador compartido, como avisa la app:

```text
WARN [Better Auth]: Rate limiting could not determine a client IP and is falling back to a single shared per-path bucket.
```

- **Con ella, el 401 del otro usuario es el correcto:** tiene su propio contador.
- **`$proxy_add_x_forwarded_for` añade la IP a lo que mande el cliente:** con su propia cabecera quedan dos (`1.2.3.4, 192.168.64.1`), y Better Auth, que solo acepta una, vuelve al contador común (401 401 401 429 429).
- **`$remote_addr`** sustituye la cabecera por la IP real de la conexión:

```nginx
    proxy_set_header X-Forwarded-For $remote_addr;
```

Y el registro de Nginx ya tiene la IP de cada visitante:

```text
192.168.64.1 - - [05/Nov/2026:19:35:52 -0600] "POST /api/auth/sign-in/email HTTP/1.1" 429 67 "-" "curl/8.7.1"
```

<Callout type="risk">

- **`$remote_addr` solo vale si Nginx habla directamente con internet:** tras Cloudflare o un balanceador, sería su IP. Entonces `$proxy_add_x_forwarded_for` con `advanced.ipAddress.trustedProxies` de Better Auth.
- **En desarrollo no se ve:** sin `NODE_ENV=production`, Better Auth usa `127.0.0.1`.
- **Busca `could not determine a client IP`** en `docker compose logs app` tras cada cambio de Nginx: es la única señal.

</Callout>

## Paso 5: compresión

**Qué es:** Nginx comprime con gzip y, con un módulo, con Brotli. `nginx.conf` trae `gzip on`, pero solo para `text/html`.

**Cómo se usa:** desde tu equipo:

```bash
JS=$(curl -s $B/entrar | grep -oE '/_astro/client\.[^"]+\.js' | head -n 1)
curl -s -o /dev/null -w "%{size_download} bytes\n" -H "accept-encoding: gzip, br" "$B$JS"
```

```text
212892 bytes
```

- **Sin comprimir:** `gzip_types` viene comentada. El HTML sí bajaba (6686 → 2910 bytes en `/entrar`); lo más pesado, no.

Ubuntu incluye Brotli:

```bash
sudo apt-get install -y libnginx-mod-http-brotli-filter libnginx-mod-http-brotli-static
```

`conf.d` se aplica a todos los sitios. `/etc/nginx/conf.d/compresion.conf`:

```nginx
# Archivo: /etc/nginx/conf.d/compresion.conf
# gzip on ya viene en nginx.conf, pero solo para text/html
gzip_vary on;
gzip_proxied any;
gzip_comp_level 5;
gzip_min_length 1024;
gzip_types text/css text/javascript application/javascript application/json image/svg+xml;

brotli on;
brotli_comp_level 5;
brotli_min_length 1024;
brotli_types text/css text/javascript application/javascript application/json image/svg+xml;
```

- **`gzip_vary on`** añade `Vary: Accept-Encoding` para que una caché no sirva la versión comprimida a quien no la entiende; **`gzip_proxied any`** comprime lo que viene de Node.
- **`gzip_comp_level 5`** equilibra tamaño y CPU, y **`gzip_min_length 1024`** evita lo que no compensa. En **`*_types`**, nunca JPEG ni WebP.

```text
/_astro/client.XI9U0KhD.js   sin comprimir  212892 B
                             gzip            66546 B   Content-Encoding: gzip
                             Brotli          62495 B   Content-Encoding: br
/entrar (SSR)                sin comprimir    6686 B
                             gzip             2747 B   Content-Encoding: gzip
                             Brotli           2511 B   Content-Encoding: br
```

- **Brotli deja un 29 % del original,** y el navegador elige con `Accept-Encoding`: lo que medías en Vercel (A4.1).

<Callout type="risk">

- **`gzip on` no significa «comprimido»:** compruébalo con `curl`, `Accept-Encoding` y los bytes recibidos.
- **No mezcles secretos con texto del atacante en una respuesta comprimida:** el tamaño puede delatarlos (BREACH). Nada de tokens en páginas que repiten parámetros de la URL.

</Callout>

## Paso 6: servir los estáticos con Nginx

**Qué es:** los archivos de `_astro/` llevan _hash_ y no cambian (A4.1): Nginx puede leerlos del disco, ya comprimidos, en vez de pedirlos a Node.

**Cómo se usa:** medido en el servidor (2 núcleos, medidor en la misma máquina: valen las proporciones):

```text
                                                 pet/s    p99
JS sin comprimir, Node directo                    3944   18 ms
JS sin comprimir, Nginx desde el disco           12562   13 ms
JS con Brotli, comprimiendo en cada petición       578   70 ms
JS con Brotli, precomprimido                      2884   15 ms
```

- **Sin compresión, Nginx triplica a Node.** Con Brotli al vuelo, 578 pet/s: 212 kB comprimidos una y otra vez. (No compares entre grupos: la cifra baja con `Accept-Encoding` por motivos que esta medición no aísla).
- **Precomprimido una vez, al nivel máximo,** es cinco veces más rápido y más pequeño: 56 771 bytes frente a 62 495.

`scripts/publicar-estaticos.sh`, en el servidor, con la orden `brotli` (`sudo apt-get install -y brotli`):

```bash
#!/usr/bin/env bash
# Archivo: scripts/publicar-estaticos.sh
# En el servidor: saca _astro de la imagen, lo precomprime y lo deja donde lo sirve Nginx.
# Uso: bash scripts/publicar-estaticos.sh [imagen]   (por defecto, entrenos:local)
set -euo pipefail

IMAGEN="${1:-entrenos:local}"
DESTINO=/var/www/entrenos/_astro
TEMPORAL="$(mktemp -d)"
CONTENEDOR="$(docker create "$IMAGEN")"
trap 'docker rm "$CONTENEDOR" >/dev/null; rm -rf "$TEMPORAL"' EXIT

docker cp "$CONTENEDOR:/app/dist/client/_astro/." "$TEMPORAL/"

# Nivel máximo: se comprime una vez aquí, no en cada petición
find "$TEMPORAL" -type f \( -name '*.js' -o -name '*.css' -o -name '*.svg' \) -size +1k \
  -exec brotli -q 11 -k -f {} \; -exec gzip -9 -k -f {} \;

# Sin borrar lo anterior: una pestaña abierta aún pide los archivos de la versión previa
sudo mkdir -p "$DESTINO"
sudo cp -r "$TEMPORAL/." "$DESTINO/"
sudo chmod -R a+rX "$DESTINO"
echo "✓ $(find "$TEMPORAL" -type f | wc -l | tr -d ' ') archivos en $DESTINO ($IMAGEN)"
```

```bash
bash scripts/publicar-estaticos.sh
```

```text
✓ 37 archivos en /var/www/entrenos/_astro (entrenos:local)
```

- **`docker create`** crea un contenedor sin arrancarlo, solo para copiar de él, y el `trap` lo borra.
- **`brotli -q 11` y `gzip -9`,** al máximo porque es una vez; `-k` conserva el original.
- **No borra lo anterior:** una pestaña abierta tiene un HTML que pide los archivos de la versión previa.

La configuración completa. Sustituye `/etc/nginx/sites-available/entrenos`:

```nginx
# Archivo: /etc/nginx/sites-available/entrenos
upstream entrenos_app {
  server 127.0.0.1:4321;
  keepalive 16; # conexiones abiertas con Node: no abre una nueva por petición
}

server {
  listen 80 default_server;
  listen [::]:80 default_server;
  server_name _;

  server_tokens off;
  client_max_body_size 1m;

  # Lo que llega a Node: los location heredan estas cabeceras de server
  proxy_http_version 1.1;
  proxy_set_header Connection "";
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header X-Forwarded-For $remote_addr;

  # Recursos con hash: los sirve Nginx. Si falta alguno, se lo pide a Node
  location /_astro/ {
    root /var/www/entrenos;
    add_header Cache-Control "public, max-age=31536000, immutable";
    access_log off;
    brotli_static on;
    gzip_static on;
    try_files $uri @app;
  }

  location / {
    proxy_pass http://entrenos_app;
  }

  location @app {
    proxy_pass http://entrenos_app;
  }
}
```

- **`upstream` con `keepalive 16`** reutiliza conexiones con Node: 2110–2602 pet/s SSR frente a 1577–1895 sin ella. Exige `proxy_http_version 1.1` y `Connection ""`.
- **Cabeceras en `server`,** heredadas por todas las `location`, salvo una con su propio `proxy_set_header`, que pierde **todas**.
- **`location /_astro/`** gana a `/` por ser más específica: `root` sirve de `/var/www/entrenos`, con el `Cache-Control` de Astro (un año, `immutable`), y **`brotli_static`/`gzip_static`** envían el `.br` o `.gz` si existe.
- **`try_files $uri @app`:** si falta el archivo, lo pide a Node en vez de dar 404.
- **`server_tokens off`** deja `Server: nginx`, sin versión que dé pistas.

```bash
sudo nginx -t && sudo systemctl reload nginx
curl -s -o /dev/null -D - -H "accept-encoding: br" "$B$JS" | grep -iE "^(HTTP|server|content-encoding|content-length|cache-control)"
```

```text
HTTP/1.1 200 OK
Server: nginx
Content-Length: 56771
Content-Encoding: br
Cache-Control: public, max-age=31536000, immutable
```

<Callout type="risk">

- **Publica los estáticos en cada despliegue:** si no, `try_files` lo salva y solo lo notas en el rendimiento. En A4.5 irá en el despliegue.
- **`add_header` tampoco se hereda** en una `location` con el suyo: las cabeceras de seguridad de `server` desaparecen de `/_astro/` (A5).
- **`keepalive` y el cierre de Node a los 5 s:** 12 intentos al caducar no dieron error, pero si ves 502 sueltos con `upstream prematurely closed`, sospecha de esto. Pasar por Nginx cuesta poco (unas 2600 pet/s frente a 2833 directo); mide en tu máquina.

</Callout>

## Paso 7: cuando algo falla

**Qué es:** lo que responde Nginx cuando la petición o la app no están bien.

**Cómo se usa:** `client_max_body_size 1m` rechaza lo que lo supera antes de llegar a Node:

```bash
head -c 2000000 /dev/zero | curl -s -o /dev/null -w "POST 2 MB -> %{http_code}\n" \
  -H "origin: $B" -H "content-type: application/json" --data-binary @- $B/api/auth/sign-in/email
```

```text
POST 2 MB -> 413
```

Con `docker compose stop app`:

```text
GET /entrar -> 502      <title>502 Bad Gateway
GET / -> 502
GET /_astro/client.XI9U0KhD.js -> 200
```

- **Nginx sigue en pie y responde 502** (_Bad Gateway_), y lo que sirve él sigue en 200. La causa, en `/var/log/nginx/error.log`:

```text
2026/11/05 19:40:08 [error] 129386#129386: *1137 connect() failed (111: Connection refused) while connecting to upstream, client: 192.168.64.1, server: _, request: "GET /…
```

- **`docker compose start app` lo arregla.** Un reinicio da 502 unos segundos: lo resuelve A4.5.

<Callout type="risk">

- **502, 504 y 413 son de Nginx, no de la app:** Node no responde, tarda más de 60 s (`proxy_read_timeout`) o el cuerpo es grande. Mira primero `error.log`.
- **Para subidas de archivos, sube `client_max_body_size`** solo en esa `location`.
- **`/` también da 502:** aunque prerenderizada, la sirve Node. Copiar los HTML a Nginx obligaría a publicarlos y saltaría el _middleware_: no compensa.

</Callout>

## Paso 8: la alternativa más simple, Caddy

**Qué es:** **Caddy**, otro _reverse proxy_ en el que lo habitual viene hecho.

**Cómo se usa:** este `Caddyfile` equivale a tus dos archivos de Nginx (en el 8080, para probarlo junto a Nginx):

```text
# Archivo: /etc/caddy/Caddyfile
:8080 {
	encode zstd gzip

	handle /_astro/* {
		root * /var/www/entrenos
		header Cache-Control "public, max-age=31536000, immutable"
		file_server {
			precompressed br gzip
		}
	}

	handle {
		reverse_proxy 127.0.0.1:4321
	}
}
```

```bash
docker run -d --rm --name caddy --network host \
  -v "$PWD/Caddyfile:/etc/caddy/Caddyfile:ro" -v /var/www/entrenos:/var/www/entrenos:ro caddy:2-alpine
```

Contra la misma app:

```text
JS:         Content-Encoding: br, Content-Length: 56771, Cache-Control: public, max-age=31536000, immutable
/entrar:    Content-Encoding: zstd
formulario -> 302
registro -> 200
sign-in con X-Forwarded-For propio: 401 401 401 429 429
```

- **Sin configurar cabeceras:** `reverse_proxy` manda `Host` y `X-Forwarded-*` correctos y comprime con **zstd** si se acepta.
- **Con un dominio en lugar de `:8080`, obtiene y renueva el certificado HTTPS solo** (lo que harás a mano en A4.4).

| Aspecto                  | Nginx                                  | Caddy                                         |
| ------------------------ | -------------------------------------- | --------------------------------------------- |
| Cabeceras del proxy      | Las escribes tú                        | Correctas por defecto                         |
| HTTPS                    | Certbot y configuración (A4.4)         | Automático con un dominio                     |

- **El curso sigue con Nginx** porque lo heredarás en casi cualquier servidor y obliga a entender cada pieza; en un proyecto propio, Caddy es razonable.

<Callout type="risk">

- **El `caddy` de `apt` va muy atrás** (2.6.2 frente a 2.11.9): usa la imagen o su repositorio. **`--network host`** le deja llegar a `127.0.0.1:4321`; en Compose, `reverse_proxy app:4321`.

## Ejercicio práctico

<Callout type="exercise">

1. Sirve tu app en el VPS de I6 detrás de Nginx en el puerto 80, con la configuración del Paso 6, y comprueba que el puerto 4321 no responde desde fuera.
2. Escribe `scripts/comprobar-proxy.sh`, para ejecutar **desde tu equipo**, que reciba la IP del servidor y compruebe: que Node no responde desde fuera; que Nginx no enseña su versión; que cada tipo de ruta responde con su código; que un formulario con `Origin` de la web pasa y uno de otra web no; que el registro funciona; que el JS principal llega con Brotli y caché de un año; y que un cuerpo de 2 MB se rechaza.
3. Comprueba que detecta fallos: quita `proxy_set_header Host` y publica el puerto de Compose sin `127.0.0.1`.

</Callout>

Solución. El punto 1 son los Pasos 2 a 6. `scripts/comprobar-proxy.sh`:

```bash
#!/usr/bin/env bash
# Archivo: scripts/comprobar-proxy.sh
# Desde tu equipo, nunca desde el servidor: comprueba lo que ve alguien de fuera.
# Uso: bash scripts/comprobar-proxy.sh 203.0.113.10
set -uo pipefail

SERVIDOR="${1:?Indica la IP o el dominio del servidor}"
BASE="http://$SERVIDOR"
FALLOS=0

bien() { echo "  ok    $1"; }
mal() { echo "  FALLO $1"; FALLOS=1; }
comprobar() { # descripción, valor obtenido, valor esperado
  if [ "$2" = "$3" ]; then bien "$1"; else mal "$1: $2 (esperaba $3)"; fi
}
cabecera() { tr -d '\r' | grep -i "^$1:" | cut -d' ' -f2- | head -n 1; }

echo "== Lo que no debe verse"
if curl -s -m 3 -o /dev/null "http://$SERVIDOR:4321/"; then
  mal "Node responde desde fuera en el puerto 4321"
else
  bien "Node no responde desde fuera en el puerto 4321"
fi
comprobar "Nginx no enseña su versión" "$(curl -s -I "$BASE/entrar" | cabecera server)" "nginx"

echo "== Rutas a través de Nginx"
comprobar "/ (prerenderizada)" "$(curl -s -o /dev/null -w '%{http_code}' "$BASE/")" 200
comprobar "/entrar (SSR)" "$(curl -s -o /dev/null -w '%{http_code}' "$BASE/entrar")" 200
comprobar "/estadisticas (privada)" "$(curl -s -o /dev/null -w '%{http_code}' "$BASE/estadisticas")" 302
comprobar "/api/resumen (sin sesión)" "$(curl -s -o /dev/null -w '%{http_code}' "$BASE/api/resumen")" 401

echo "== El dominio y las cabeceras llegan bien a la app"
comprobar "formulario con Origin de la web" "$(curl -s -o /dev/null -w '%{http_code}' \
  -H "origin: $BASE" -H 'content-type: application/x-www-form-urlencoded' -d a=1 "$BASE/nuevo-accion")" 302
comprobar "formulario con Origin de otra web" "$(curl -s -o /dev/null -w '%{http_code}' \
  -H 'origin: http://otra-web.test' -H 'content-type: application/x-www-form-urlencoded' -d a=1 "$BASE/nuevo-accion")" 403
comprobar "registro" "$(curl -s -o /dev/null -w '%{http_code}' -H "origin: $BASE" -H 'content-type: application/json' \
  -d "{\"email\":\"proxy-$(date +%s)@prueba.test\",\"password\":\"$(openssl rand -hex 12)\",\"name\":\"Prueba\"}" \
  "$BASE/api/auth/sign-up/email")" 200

echo "== Estáticos y compresión"
JS="$(curl -s "$BASE/entrar" | grep -oE '/_astro/client\.[^"]+\.js' | head -n 1)" # el mayor; los de < 1 kB no se comprimen
CABECERAS="$(curl -s -o /dev/null -D - -H 'accept-encoding: br' "$BASE$JS")"
comprobar "$JS comprimido" "$(cabecera content-encoding <<< "$CABECERAS")" "br"
comprobar "caché de un año" "$(cabecera cache-control <<< "$CABECERAS")" "public, max-age=31536000, immutable"
comprobar "cuerpo de 2 MB rechazado" "$(head -c 2000000 /dev/zero | curl -s -o /dev/null -w '%{http_code}' \
  -H "origin: $BASE" -H 'content-type: application/json' --data-binary @- "$BASE/api/auth/sign-in/email")" 413

[ "$FALLOS" = 0 ] && echo "Todo correcto"
exit "$FALLOS"
```

- **Código de salida 0.** Con los dos fallos del punto 3 (`Host` comentado y `"4321:4321"` en `compose.yaml`):

```text
  FALLO Node responde desde fuera en el puerto 4321
  FALLO formulario con Origin de la web: 403 (esperaba 302)
```

- **`set -uo pipefail`, sin `-e`:** cada fallo se anota y sigue, para tener la lista completa. **`<<<`** pasa `$CABECERAS` a la función sin pedir dos veces el archivo.
- **El JS `client.*`, el mayor:** uno de menos de 1 kB no se comprime y daría un fallo falso, como en la primera versión.
- **También se prueba un `Origin` ajeno:** una configuración que deja pasar todo daría ok en la primera prueba.

<Callout type="risk">

- **Crea un usuario en cada ejecución** (`proxy-<fecha>@prueba.test`): en un servidor con datos reales, bórralos o quita esa comprobación.
- **Desde fuera:** en el servidor, el 4321 respondería y el primer «ok» sería falso.

</Callout>

<Callout type="mastery">

Sabes explicar por qué Node no debe exponerse en el puerto 80: abrirlo exige privilegios que tu app no debe tener, y Nginx lo hace con un proceso `root` mínimo y trabajadores sin privilegios; además comprime, sirve los archivos tres veces más rápido, limita lo que entra y sigue en pie cuando la app no lo está. Y sabes lo que exige estar detrás de un proxy: `Host`, `BETTER_AUTH_URL` y `allowedDomains` para que funcionen formularios y registro, y `X-Forwarded-For` para que un atacante no bloquee a todos tus usuarios.

</Callout>

## Resumen

- Un usuario normal no abre el 80 (`EACCES`); Nginx lo abre como `root` y atiende con `www-data`.
- Solo con `proxy_pass`, registro y formularios dan **403**.
- Tres arreglos: `Host`, `BETTER_AUTH_URL` y `allowedDomains` (con `APP_HOSTNAME` en el _build_).
- Sin `X-Forwarded-For`, **un atacante bloquea el inicio de sesión de todos**; con un proxy, `$remote_addr`.
- `gzip_types` para el JavaScript; Brotli 212 892 → 62 495 bytes, precomprimido 56 771.
- Nginx sirve archivos 3 veces más rápido; precomprimir multiplica por cinco; `try_files … @app` evita 404.
- 413, 502 y 504 son de Nginx (`error.log`); `nginx -t` antes de `reload` y pruebas desde fuera.
- Caddy: cabeceras correctas y HTTPS automático.
