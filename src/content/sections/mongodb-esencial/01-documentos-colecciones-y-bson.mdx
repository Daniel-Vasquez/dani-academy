Llevas meses usando MongoDB a través de Better Auth sin tocarlo directamente. Aquí te conectas a tu clúster con `mongosh`, creas documentos en una base de datos de práctica, desmontas un `ObjectId` y exploras, sin tocar nada, las colecciones reales de tu proyecto.

**Requisitos:** tu clúster de MongoDB Atlas, con su usuario y contraseña, y Homebrew.

## Paso 1: la jerarquía de MongoDB

**Qué es:** cinco niveles, de lo más grande a lo más pequeño.

| Nivel             | Qué es                                       | En tu proyecto             | Equivalente en SQL (B4)      |
| ----------------- | -------------------------------------------- | -------------------------- | ---------------------------- |
| **Clúster**       | Los servidores (tres réplicas en Atlas)      | Tu clúster de Atlas        | El servidor de base de datos |
| **Base de datos** | Un espacio con nombre que agrupa colecciones | `dani_academy`             | Una base de datos            |
| **Colección**     | Un grupo de documentos del mismo tipo        | `user`, `section_progress` | Una tabla                    |
| **Documento**     | Un registro con forma de JSON                | Un usuario, una lectura    | Una fila                     |
| **Campo**         | Un par clave-valor dentro de un documento    | `email`, `readAt`          | Una columna                  |

- **Un clúster aloja varias bases de datos:** practicarás en **`academy_lab`**, separada por completo de los datos reales de `dani_academy`.

## Paso 2: instalar `mongosh` y conectarte a Atlas

**Qué es:** `mongosh` es la consola oficial de MongoDB: un intérprete de JavaScript conectado a la base de datos.

**Cómo se usa:**

```bash
brew install mongosh
mongosh --version
```

Copia la cadena de conexión de Atlas → _Clusters_ → **Connect** → **Shell**:

```bash
mongosh "mongodb+srv://tu-cluster.abc123.mongodb.net/" --apiVersion 1 --username tu-usuario
```

Escribe la contraseña cuando te la pida:

```text
Atlas atlas-xxxxxx-shard-0 [primary] test>
```

- **`test>`** es la base de datos actual; **`[primary]`**, el servidor del _replica set_ que acepta escrituras (B4.5). En las salidas siguientes solo se muestra `academy_lab>`.

<Callout type="risk">

- **No pongas la contraseña en el comando:** quedaría en el historial (`~/.zsh_history`). Con `--username` sin `--password`, `mongosh` la pide sin mostrarla.
- **"Server selection timed out"** es casi siempre _Network Access_: añade tu IP con _Add Current IP Address_. Si cambias de red, tu IP cambia.
- **Practica con un usuario de permisos justos:** en _Database Access_, uno con `readWrite` solo sobre `academy_lab`, para que un error no toque `dani_academy`.

</Callout>

## Paso 3: tus primeros documentos

**Qué es:** MongoDB crea bases de datos y colecciones **la primera vez que escribes en ellas**, y los documentos de una colección no tienen por qué tener la misma forma.

**Cómo se usa:** cámbiate a la base de datos de práctica, que aún no existe.

```js
use academy_lab
```

```text
switched to db academy_lab
```

```js
db.usuarios.insertOne({ nombre: "Dani", email: "dani@ejemplo.com", creado: new Date("2026-10-09T15:00:00Z") })
```

```text
{
  acknowledged: true,
  insertedId: ObjectId('6ac9621f275ed63c4f14fc68')
}
```

- **`db.usuarios`** es la colección, creada en este momento. **`acknowledged: true`:** el servidor confirmó. **`insertedId`:** el `_id` generado (Paso 4).

```js
db.usuarios.find()
```

```text
[
  {
    _id: ObjectId('6ac9621f275ed63c4f14fc68'),
    nombre: 'Dani',
    email: 'dani@ejemplo.com',
    creado: ISODate('2026-10-09T15:00:00.000Z')
  }
]
```

```js
show dbs
show collections
```

```text
academy_lab   32.00 KiB
admin         48.00 KiB
config        68.00 KiB
local        236.00 KiB
usuarios
```

En Atlas verás también `dani_academy`, y no `config`. Ahora un documento con **otra forma**, con un objeto anidado y un array:

```js
db.usuarios.insertOne({ nombre: "Ana", email: "ana@ejemplo.com", preferencias: { tema: "dark", objetivoVasos: 8 }, etiquetas: ["running", "yoga"] })
db.usuarios.find({ "preferencias.tema": "dark" }, { _id: 0, nombre: 1, preferencias: 1 })
db.usuarios.find({ etiquetas: "yoga" }, { _id: 0, nombre: 1 })
```

```text
[ { nombre: 'Ana', preferencias: { tema: 'dark', objetivoVasos: 8 } } ]
[ { nombre: 'Ana' } ]
```

- **Dani no tiene `preferencias` y Ana sí,** y nadie se queja.
- **`"preferencias.tema"`,** entre comillas, consulta dentro de un objeto anidado. **`etiquetas: "yoga"`** encuentra los arrays que **contienen** ese valor.
- **`{ _id: 0, nombre: 1 }`** es una **proyección**: los campos a devolver (B5.3).

<Callout type="risk">

- **Una errata crea una colección nueva en silencio:** `db.usarios.insertOne(...)` crea `usarios`, y luego no encuentras el documento. Revisa `show collections`.
- **La flexibilidad tiene un precio:** sin `preferencias`, `usuario.preferencias.tema` revienta en JavaScript. Los tipos de TypeScript (B5.2) y `$jsonSchema` (como en esta plataforma) controlan la forma.

</Callout>

## Paso 4: el `_id` y la anatomía de un `ObjectId`

**Qué es:** todo documento tiene **`_id`**, su clave primaria: única en la colección e inmutable. Si no la das, el _driver_ genera un **`ObjectId`** de 12 bytes con estructura.

**Cómo se usa:**

```text
6ac9621f  275ed63c4f  14fc68
└──┬───┘  └────┬───┘  └──┬─┘
 marca     aleatorio  contador
 de tiempo (5 bytes)  (3 bytes)
 (4 bytes)
```

- **Los 4 primeros bytes son la fecha de creación,** en segundos desde 1970:

```js
const id = db.usuarios.findOne({ nombre: "Dani" })._id
id.getTimestamp()
```

```text
ISODate('2026-10-09T21:52:31.000Z')
```

- **Los 5 siguientes son aleatorios,** uno por proceso. **Los 3 últimos, un contador:** dos seguidos solo cambian al final.

```js
new ObjectId()
new ObjectId()
```

```text
ObjectId('6ac9621f275ed63c4f14fc69')
ObjectId('6ac9621f275ed63c4f14fc6a')
```

- **Se generan sin consultar al servidor,** sin contador central como el de SQLite, y se ordenan aproximadamente por antigüedad.

También puedes elegir tú el `_id`, con una clave natural estable (B4.2):

```js
db.cursos.insertOne({ _id: "B1", titulo: "TypeScript desde cero" })
db.cursos.insertOne({ _id: "B1", titulo: "Repetido" })
```

```text
{ acknowledged: true, insertedId: 'B1' }
MongoServerError: E11000 duplicate key error collection: academy_lab.cursos index: _id_ dup key: { _id: "B1" }
```

- **`E11000` es el error de clave duplicada,** el `UNIQUE constraint failed` de SQLite. Dice la colección, el índice (`_id_`) y el valor repetido.

<Callout type="risk">

- **Un `ObjectId` revela cuándo se creó algo:** en una URL pública, cualquiera ve la fecha. Casi nunca importa; a veces, sí.
- **`ObjectId` no es un `string`:** `{ _id: "6ac9621f…" }` no encuentra el `ObjectId('6ac9621f…')`, y falla en silencio. Es el error más común (B5.5).
- **No son secretos ni impredecibles:** en parte son secuenciales. Nunca como token de seguridad.

</Callout>

## Paso 5: BSON, más tipos que JSON

**Qué es:** MongoDB guarda **BSON** (_Binary JSON_), con tipos que JSON no tiene: fechas, varios números, `ObjectId`.

**Cómo se usa:** el mismo dato de varias formas, y el tipo de cada campo con `$type`.

```js
db.tipos.insertOne({
  fechaTexto: "09/10/2026",
  fechaDate: new Date("2026-10-09T15:00:00Z"),
  precioDouble: 0.1 + 0.2,
  precioDecimal: Decimal128("0.30"),
  entero: 5,
  largo: NumberLong("9007199254740993"),
})
db.tipos.findOne({}, { _id: 0 })
```

```text
{
  fechaTexto: '09/10/2026',
  fechaDate: ISODate('2026-10-09T15:00:00.000Z'),
  precioDouble: 0.30000000000000004,
  precioDecimal: Decimal128('0.30'),
  entero: 5,
  largo: Long('9007199254740993')
}
```

```js
db.tipos.aggregate([{ $project: { _id: 0, fechaTexto: { $type: "$fechaTexto" }, fechaDate: { $type: "$fechaDate" }, precioDouble: { $type: "$precioDouble" }, precioDecimal: { $type: "$precioDecimal" }, entero: { $type: "$entero" }, largo: { $type: "$largo" } } }])
```

```text
[
  {
    fechaTexto: 'string',
    fechaDate: 'date',
    precioDouble: 'double',
    precioDecimal: 'decimal',
    entero: 'int',
    largo: 'long'
  }
]
```

Las fechas como texto se ordenan carácter a carácter:

```js
db.fechas.insertMany([{ f: "09/10/2026" }, { f: "10/01/2026" }, { f: "28/02/2026" }])
db.fechas.find({}, { _id: 0 }).sort({ f: 1 })
```

```text
[ { f: '09/10/2026' }, { f: '10/01/2026' }, { f: '28/02/2026' } ]
```

- **El 9 de octubre sale antes que el 10 de enero.** `Date` guarda un instante exacto en UTC, ordena bien y permite operar con fechas.
- **`Decimal128`** guarda decimales exactos: en un `double`, `0.1 + 0.2` es `0.30000000000000004` (B1.2). Para dinero, `Decimal128` o céntimos enteros.
- **`int`, `long` y `double`:** JavaScript solo tiene `double`, y `NumberLong("9007199254740993")` conserva un entero que un `double` no puede.

<Callout type="risk">

- **El tipo puede variar entre documentos:** con `km: "5"` en unos y `km: 5` en otros, `{ km: { $gte: 5 } }` solo encuentra los numéricos. Pasa con formularios sin convertir (B1.1).
- **`mongosh` y Node no muestran lo mismo:** `mongosh` enseña `ISODate(…)`; el _driver_ da `Date`, `ObjectId` o `Long`, y `JSON.stringify` los pasa a texto perdiendo el tipo (B5.5).

</Callout>

## Paso 6: las herramientas, y tus colecciones reales

**Qué es:** tres formas de trabajar con tu clúster.

| Herramienta                       | Qué es                            | Para qué la usarás                                                                        |
| --------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------- |
| **Atlas** (web) → _Data Explorer_ | La interfaz web de tu clúster     | Mirar datos rápidamente, gestionar usuarios, IPs, índices y métricas                      |
| **Compass**                       | Aplicación de escritorio gratuita | Explorar colecciones con comodidad, construir consultas visualmente, ver `explain` (B5.6) |
| **`mongosh`**                     | Consola                           | Probar consultas exactas, scripts, tareas repetibles                                      |

Compass se instala desde [mongodb.com/products/tools/compass](https://www.mongodb.com/products/tools/compass), con la cadena de _Connect_ → _Compass_.

**Cómo se usa:** explora tu proyecto **sin modificar nada**.

```js
use dani_academy
show collections
db.user.findOne({}, { name: 1, email: 1, createdAt: 1 })
db.session.countDocuments()
db.account.findOne({}, { password: 0 })
```

| Colección          | Quién la crea   | Campos (tipos)                                                                                                                                    |
| ------------------ | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user`             | Better Auth     | `_id` (ObjectId), `name`, `email`, `emailVerified` (Boolean), `createdAt`, `updatedAt` (Date)                                                     |
| `session`          | Better Auth     | `_id`, `token`, `userId` (**ObjectId**), `expiresAt`, `ipAddress`, `userAgent`, `createdAt`, `updatedAt`                                          |
| `account`          | Better Auth     | `_id`, `accountId`, `providerId` (`"credential"` para correo y contraseña), `userId` (ObjectId), `password` (el _hash_), `createdAt`, `updatedAt` |
| `section_progress` | Esta plataforma | `userId` (**string**), `courseId`, `sectionId`, `readAt` (Date)                                                                                   |
| `quiz_attempts`    | Esta plataforma | `userId`, `courseId`, `answers`, `results`, `score`, `total`, `passed`, `submittedAt`                                                             |
| `study_sessions`   | Esta plataforma | `userId`, `startedAt`, `lastSeenAt`, `sectionIds`, `courseIds`                                                                                    |

- **Better Auth guarda `userId` como `ObjectId`; la plataforma, como texto.** Las dos valen, pero no se mezclan en una consulta: es el error del Paso 4. Decídelo una vez por proyecto.

<Callout type="risk">

- **Excluye lo sensible al explorar:** `{ password: 0 }` oculta el _hash_. Un `token` de `session` es una sesión iniciada: nunca en capturas ni en _issues_.
- **No edites a mano las colecciones de Better Auth:** un `userId` cambiado o una `account` borrada deja usuarios sin poder entrar. Usa su API.
- **`mongosh` no avisa de en qué base de datos estás antes de borrar:** mira el _prompt_, y vuelve a `use academy_lab` para practicar.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Conéctate a tu clúster con `mongosh` y con Compass.
2. En `academy_lab`, crea una colección `entrenos` con tres documentos: uno de running (`tipo`, `km`, `minutos`, `fecha` como `Date`), uno de fuerza (`tipo`, `ejercicios` como array de objetos con `nombre`, `series` y `repeticiones`, y `fecha`) y uno de hidratación (`tipo`, `ml`, `fecha`).
3. Comprueba con `$type` que todas las fechas son de tipo `date`.
4. Averigua, a partir del `_id` de cada uno, en qué segundo se crearon.
5. Explora `user`, `session` y `account` en tu proyecto (sin modificar nada) y apunta qué campo relaciona cada sesión con su usuario y de qué tipo es.

</Callout>

Solución de los puntos 2, 3 y 4:

```js
use academy_lab
db.entrenos.insertMany([
  { tipo: "running", km: 5.2, minutos: 28, fecha: new Date("2026-10-07T07:30:00Z") },
  {
    tipo: "fuerza",
    ejercicios: [
      { nombre: "sentadilla", series: 4, repeticiones: 8 },
      { nombre: "press banca", series: 4, repeticiones: 10 },
    ],
    fecha: new Date("2026-10-08T18:00:00Z"),
  },
  { tipo: "hidratacion", ml: 500, fecha: new Date("2026-10-08T12:00:00Z") },
])
db.entrenos.aggregate([{ $project: { _id: 0, tipo: 1, tipoDeFecha: { $type: "$fecha" } } }])
db.entrenos.find().toArray().map((e) => ({ tipo: e.tipo, creado: e._id.getTimestamp() }))
```

```text
{
  acknowledged: true,
  insertedIds: {
    '0': ObjectId('6ac9628d75670bffb56fbcd0'),
    '1': ObjectId('6ac9628d75670bffb56fbcd1'),
    '2': ObjectId('6ac9628d75670bffb56fbcd2')
  }
}
[
  { tipo: 'running', tipoDeFecha: 'date' },
  { tipo: 'fuerza', tipoDeFecha: 'date' },
  { tipo: 'hidratacion', tipoDeFecha: 'date' }
]
[
  { tipo: 'running', creado: ISODate('2026-10-09T21:54:21.000Z') },
  { tipo: 'fuerza', creado: ISODate('2026-10-09T21:54:21.000Z') },
  { tipo: 'hidratacion', creado: ISODate('2026-10-09T21:54:21.000Z') }
]
```

- **Los tres se crearon en el mismo segundo** con `insertMany`, y solo cambia el contador. La fecha del `_id` es cuándo se guardó; `fecha`, cuándo ocurrió el entreno.
- **El punto 5:** el campo es **`userId`**, de tipo **`ObjectId`**, en `session` y `account`. Las sesiones de un usuario: `db.session.find({ userId: db.user.findOne({ email: "tu-correo" })._id }, { token: 0 })`.

<Callout type="risk">

- **`insertMany` es ordenado por defecto:** si falla el segundo, el tercero no entra y el primero sí. Con `{ ordered: false }`, lo intenta con todos.
- **`db.dropDatabase()` borra la base de datos actual sin confirmación:** perfecto para limpiar `academy_lab` al final, y una catástrofe en `dani_academy`.

</Callout>

<Callout type="mastery">

Sabes qué es un `ObjectId` y qué información contiene (fecha de creación, parte aleatoria y contador), distingues la jerarquía clúster → base de datos → colección → documento, eliges `Date` para fechas y `Decimal128` (o céntimos enteros) para dinero, y exploras las colecciones reales de tu proyecto sin modificar nada ni exponer datos sensibles.

</Callout>

## Resumen

- Clúster → base de datos → colección → documento; se crean al primer `insert`.
- Formas distintas por documento; notación de punto para anidados.
- `_id` es la clave: un `ObjectId` (fecha, aleatorio, contador) o un valor tuyo. Duplicado: `E11000`.
- BSON: `Date` para fechas, `Decimal128` o céntimos para dinero.
- Atlas, Compass y `mongosh`. Better Auth guarda `userId` como `ObjectId`.
