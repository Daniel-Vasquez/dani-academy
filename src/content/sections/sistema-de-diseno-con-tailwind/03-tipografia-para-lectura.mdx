Esta plataforma es sobre todo texto que se lee durante media hora, y la tipografía decide si se lee con gusto o se abandona. Lo deciden la **fuente**, el **largo de línea**, el **interlineado** y que la fuente llegue a tiempo sin mover el texto. Aquí montas la tipografía de una lección en `tw-lab` y mides cada decisión.

**Requisitos:** el proyecto `tw-lab` de I7.2, con los _tokens_ claros y oscuros.

```bash
npm install @fontsource-variable/jetbrains-mono
```

## Paso 1: tres fuentes y cómo se cargan

**Qué es:** una familia por uso, y **Fontsource**, que empaqueta cada fuente en npm con su CSS y la sirve desde tu dominio, sin Google Fonts.

| Uso                | Familia       | En esta plataforma | Por qué                                                                                     |
| ------------------ | ------------- | ------------------ | ------------------------------------------------------------------------------------------- |
| Texto largo        | Serif         | Source Serif 4     | Los remates guían el ojo a lo largo de la línea; cansa menos en lecturas largas             |
| Interfaz y títulos | Sans-serif    | Inter              | Limpia y legible en tamaños pequeños (botones, menús, etiquetas)                            |
| Código             | Monoespaciada | JetBrains Mono     | Todos los caracteres miden lo mismo: el código se alinea, y `0`/`O` y `1`/`l` se distinguen |

- **`font-display: swap`:** mientras descarga, el texto se pinta con la de reserva (Georgia, `system-ui`…) y se cambia al llegar.
- **Subconjuntos con `unicode-range`:** Inter viene en 7 archivos (latín, cirílico, griego…) y solo se descargan los que usa la página; para el español basta `latin`, con ñ y acentos (`node_modules/@fontsource-variable/inter/index.css`).

**Cómo se usa:** las fuentes se cargan en `src/styles/global.css` (forma final en el Paso 3; respecto a I7.2, el `@import` de JetBrains Mono y `--font-mono`). Para el texto principal, además, **precarga**: con `<link rel="preload">` se pide a la vez que el CSS, no después. Añade un hueco para el `<head>` en `src/layouts/Layout.astro`:

```astro
---
// Archivo: src/layouts/Layout.astro
import "../styles/global.css";
import { ClientRouter } from "astro:transitions";
import BotonTema from "../components/BotonTema.astro";

interface Props {
  titulo: string;
}
const { titulo } = Astro.props;
---

<html lang="es">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width" />
    <title>{titulo} · Tailwind lab</title>
    <!-- 1. El tema, ANTES de que el navegador pinte nada. is:inline: Astro no lo aplaza ni lo empaqueta -->
    <script is:inline>
      (() => {
        const aplicarTema = () => {
          let guardado = null;
          try {
            guardado = localStorage.getItem("tema");
          } catch {
            // Almacenamiento bloqueado: se sigue la preferencia del sistema
          }
          const oscuro = guardado ? guardado === "dark" : matchMedia("(prefers-color-scheme: dark)").matches;
          document.documentElement.dataset.theme = oscuro ? "dark" : "light";
        };
        aplicarTema();
        // 2. View Transitions: al navegar, el <html> nuevo llega sin data-theme. Se reaplica antes de pintarlo
        if (!window.__temaEscuchando) {
          window.__temaEscuchando = true;
          document.addEventListener("astro:after-swap", aplicarTema);
        }
      })();
    </script>
    <ClientRouter />
    <slot name="head" />
  </head>
  <body class="bg-bg font-sans text-fg">
    <div class="flex justify-end p-3"><BotonTema /></div>
    <slot />
  </body>
</html>
```

Y crea el _layout_ de las lecciones, `src/layouts/LayoutLectura.astro`, que precarga Source Serif 4:

```astro
---
// Archivo: src/layouts/LayoutLectura.astro
// Para lecciones en Markdown: tipografía de lectura y la fuente del texto precargada
import Layout from "./Layout.astro";
import serif from "@fontsource-variable/source-serif-4/files/source-serif-4-latin-wght-normal.woff2?url";

const { frontmatter } = Astro.props;
---

<Layout titulo={frontmatter.title}>
  <!-- preload: el navegador pide la fuente ya, sin esperar a descubrirla en el CSS -->
  <link slot="head" rel="preload" href={serif} as="font" type="font/woff2" crossorigin />
  <main class="px-4 py-10">
    <article class="prose prose-lg mx-auto max-w-[68ch] font-serif prose-headings:font-sans prose-headings:tracking-tight">
      <slot />
    </article>
  </main>
</Layout>
```

- **`?url`** importa la **dirección** del archivo con el mismo nombre con _hash_ que usa el CSS (`source-serif-4-latin-wght-normal.DMe4EKeb.woff2`); si no coincidieran, se descargaría dos veces.
- **`crossorigin` es obligatorio** en la precarga de fuentes, aunque sean del mismo dominio, o el navegador la pide otra vez.

En el _build_, con 300 ms de latencia y 400 KB/s:

```text
Con preload de Source Serif 4:
  Layout.css                                   12.2 KB · empieza   317 ms · termina   706 ms
  source-serif-4-latin-wght-normal.woff2       49.7 KB · empieza   317 ms · termina   802 ms
  inter-latin-wght-normal.woff2                47.1 KB · empieza   724 ms · termina  1260 ms
  jetbrains-mono-latin-wght-normal.woff2       39.5 KB · empieza   724 ms · termina  1241 ms
Sin preload:
  Layout.css                                   12.2 KB · empieza   320 ms · termina   680 ms
  source-serif-4-latin-wght-normal.woff2       49.7 KB · empieza   691 ms · termina  1358 ms
  inter-latin-wght-normal.woff2                47.1 KB · empieza   696 ms · termina  1350 ms
  jetbrains-mono-latin-wght-normal.woff2       39.5 KB · empieza   696 ms · termina  1312 ms
```

- **Con la precarga, la fuente llega 556 ms antes** (802 frente a 1358 ms): empieza a la vez que el CSS.
- **Solo bajan los 3 archivos `latin`** (unos 136 KB) de los 19 subconjuntos declarados. Inter y JetBrains Mono esperan al CSS, y está bien: precargarlas competiría por la red.

<Callout type="risk">

- **Precarga solo la fuente principal y su subconjunto:** cada precarga se descarga **siempre**, la use o no la página.
- **`swap` mueve el texto al llegar la fuente** (CLS) si la de reserva tiene otras proporciones. Georgia para la serif, `system-ui` para la sans, y la principal precargada.
- **Las fuentes variables traen todos los pesos en un archivo** por subconjunto; con `@fontsource/inter` (estático), cada peso es otro.

</Callout>

## Paso 2: medida, interlineado y escala

**Qué es:** la **medida** (caracteres por línea) es más cómoda entre 60 y 75: con más, cuesta volver al principio de la siguiente; con menos, se salta demasiado. El **interlineado** de un texto largo, entre 1,6 y 1,8.

**Cómo se usa:** una página de prueba en Markdown con lo típico de una lección (títulos, párrafos, listas, cita, código y tabla), con el _layout_ en el _frontmatter_. `src/pages/lectura.md`:

````md
---
layout: ../layouts/LayoutLectura.astro
title: "B5.4 · Update y Delete"
---

# Update y Delete

En la sección anterior creaste y leíste entrenos. Ahora toca **cambiarlos**: marcar una sección como leída, corregir una fecha o borrar un entreno duplicado. MongoDB tiene una operación para cada caso, y elegir la correcta evita errores que no se ven hasta que hay dos usuarios a la vez.

## Paso 1: actualizar un documento

`updateOne` busca **un** documento y le aplica unos cambios. Los cambios no son el documento nuevo, sino *operadores*: instrucciones sobre qué campo tocar y cómo.

```ts
const resultado = await progreso.updateOne(
  { userId: "u_ana", cursoId: "B5" },
  { $addToSet: { seccionesLeidas: "B5.4" }, $set: { actualizado: new Date() } },
  { upsert: true },
);
console.log(resultado.modifiedCount); // 1
```

Los operadores más usados:

- `$set` cambia el valor de un campo, o lo crea si no existe.
- `$inc` suma una cantidad a un número, sin leerlo antes.
- `$addToSet` añade un valor a un array, solo si no estaba.
- `$unset` borra un campo del documento.

> Un `updateOne` sin operadores (`{ titulo: "Nuevo" }` en lugar de `{ $set: { titulo: "Nuevo" } }`) da un error: así MongoDB evita que sustituyas el documento entero por accidente.

## Paso 2: borrar

1. `deleteOne` borra el primer documento que coincide.
2. `deleteMany` borra **todos** los que coinciden: con un filtro vacío, la colección entera.
3. Un borrado lógico (`$set: { borradoEn: new Date() }`) permite deshacerlo.

| Operación | Borra | Se puede deshacer |
| --- | --- | --- |
| `deleteOne` | Uno | No |
| `deleteMany` | Todos los que coinciden | No |
| Borrado lógico | Ninguno (los marca) | Sí |
````

En Chrome, contando los caracteres de cada línea del primer párrafo:

```text

  artículo de 647 px · caracteres por línea: 73, 70, 67 (media 70)
  h1    Inter Variable · 48px / 48px (1.00)
  h2    Inter Variable · 30px / 40px (1.33)
  p     Source Serif 4 Variable · 18px / 32px (1.78)
  li    Source Serif 4 Variable · 18px / 32px (1.78)
  code  JetBrains Mono Variable · 14.2222px / 24.8889px (1.75)

  artículo de 358 px · caracteres por línea: 40, 40, 37, 37, 38, 45, 42 (media 40)

  artículo de 1248 px · caracteres por línea: 143 (media 143)
```

- **70 caracteres por línea con `max-w-[68ch]`:** `ch` es el ancho del `0`, algo mayor que la media de un texto. Sin límite, 143 a 1280 px; en el móvil, 40, con 18 px de letra.
- **Interlineado 1,78:** `prose-lg` da 18 px de letra y 32 de línea; los títulos, cortos, más apretados (1,33 en `h2`).
- **Escala 48, 30 y 18 px** para `h1`, `h2` y texto; el código baja a 14,2 px porque la monoespaciada es más ancha.

<Callout type="risk">

- **`prose-headings:font-sans` cambia solo los títulos:** serif para el texto e Inter para títulos, como esta plataforma. Dos familias como mucho, más la del código.
- **`h1` con interlineado 1,0** va bien en una línea; un título largo en dos queda apretado: `prose-h1:leading-tight`.

</Callout>

## Paso 3: `prose` y Shiki con los _tokens_

**Qué es:** `@tailwindcss/typography` (B7.5) define sus colores con variables (`--tw-prose-body`, `--tw-prose-links`…); apuntadas a tus _tokens_, el mismo `prose` sirve en los dos temas sin `dark:prose-invert`. **Shiki**, integrado en Astro, colorea el código: con `themes` y `defaultColor: false`, cada palabra lleva sus dos colores (`--shiki-light` y `--shiki-dark`) y el CSS elige.

**Cómo se usa:** sustituye `astro.config.mjs`.

```js
// @ts-check
import { defineConfig } from "astro/config";
import tailwindcss from "@tailwindcss/vite";
import react from "@astrojs/react";

// https://astro.build/config
export default defineConfig({
  vite: {
    plugins: [tailwindcss()],
  },
  integrations: [react()],
  markdown: {
    // Shiki, el resaltado de código que trae Astro: un tema para claro y otro para oscuro
    shikiConfig: {
      themes: { light: "github-light", dark: "github-dark" },
      defaultColor: false, // sin color por defecto: lo elige el CSS según data-theme
    },
  },
});
```

Y `src/styles/global.css`:

<Callout type="risk">

- **Con `defaultColor: false`, sin CSS no hay color:** las reglas `.astro-code span { color: var(--shiki-light) }` y su versión `[data-theme="dark"]` son obligatorias.
- **El `!important` del fondo** gana al `style` que Shiki pone en cada bloque, y todos usan `--surface`, como el código en línea.
- **Los temas de Shiki no siempre llegan al AA sobre tu fondo:** esta plataforma ajusta cuatro colores de GitHub claro en su `global.css` (I7.4).

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Diseña la tipografía de una sección del temario: títulos, párrafos, listas, citas y bloques de código, en claro y en oscuro.
2. Comprueba la medida (entre 60 y 75 caracteres por línea en escritorio), el interlineado del texto (entre 1,6 y 1,8) y que cada elemento cambia de color con el tema.

</Callout>

Solución: la página `/lectura` de los pasos; la medida y el interlineado están en el Paso 2. Los colores de cada elemento, con el tema claro y el oscuro guardados:

```text
light:
  fondo        rgb(250, 250, 250)
  texto        rgb(15, 23, 42)
  titulo       rgb(15, 23, 42)
  cita         rgb(13, 148, 136)
  codigoLinea  rgb(234, 237, 242)
  bloque       rgb(234, 237, 242)
  await        rgb(215, 58, 73)
dark:
  fondo        rgb(13, 17, 23)
  texto        rgb(230, 237, 243)
  titulo       rgb(230, 237, 243)
  cita         rgb(45, 212, 191)
  codigoLinea  rgb(22, 27, 34)
  bloque       rgb(22, 27, 34)
  await        rgb(249, 117, 131)
```

- **Todo cambia con el tema sin una sola clase `dark:`:** fondo, texto, títulos, el borde de la cita, el código en línea y el fondo de los bloques.
- **El código cambia de paleta:** `await` pasa del rojo de `github-light` (`rgb(215, 58, 73)`) al de `github-dark` (`rgb(249, 117, 131)`), más claro.
- **El texto oscuro no es blanco puro** (`rgb(230, 237, 243)`) sobre `rgb(13, 17, 23)`: esa diferencia menor hace llevadera la lectura larga.

<Callout type="risk">

- **Lee tú la página 20 minutos:** las medidas dicen si está en rango, no si es cómoda; según la fuente, 1,78 puede sentirse apretado o separado.
- **Mide el contraste de cada color,** no solo el del texto: enlaces (`--accent-strong`), texto secundario y código, a 4,5:1 (I7.4).

</Callout>

<Callout type="mastery">

Puedes leer 20 minutos seguidos en tu página sin fatiga: el texto va en serif a 18 px, con unos 70 caracteres por línea y un interlineado de 1,78; las fuentes se cargan con `swap`, solo en los subconjuntos que se usan y con la principal precargada; y `prose` y Shiki usan tus _tokens_, así que la lectura es igual de cuidada en claro y en oscuro.

</Callout>

## Resumen

- Serif para leer, sans-serif para interfaz y títulos, monoespaciada para código.
- Fontsource con `swap` y `unicode-range`; precargar la principal la adelantó 556 ms.
- Medida de 60 a 75 caracteres (`max-w-[68ch]` ≈ 70) e interlineado de 1,6 a 1,8.
- `prose` ligado a los _tokens_ con `--tw-prose-*`, sin `prose-invert`.
- Shiki con `themes` y `defaultColor: false`, y CSS que elige el color por `data-theme`.
