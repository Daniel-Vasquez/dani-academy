Una página accesible la puede usar cualquiera: quien necesita contraste, quien usa un lector de pantalla, quien navega con el teclado, quien se marea con las animaciones. Es calidad y, en muchos países, una obligación legal, y casi todo se resuelve con HTML bien escrito y algo de CSS. Aquí mides el contraste de tus _tokens_, auditas `tw-lab` con dos herramientas que no siempre coinciden y lo recorres con el teclado.

**Requisitos:** el proyecto `tw-lab` de I7.3, Chrome con la extensión axe DevTools (gratuita) y Lighthouse, incluido en las DevTools.

## Paso 1: el contraste, medido

**Qué es:** WCAG (_Web Content Accessibility Guidelines_) define el **contraste** como una relación de 1:1 (colores iguales) a 21:1 (negro sobre blanco), calculada con la luminancia. El nivel AA es el que se exige normalmente.

| Contenido                                    | Mínimo AA | Mínimo AAA |
| -------------------------------------------- | --------- | ---------- |
| Texto normal                                 | 4,5:1     | 7:1        |
| Texto grande (24 px, o 18,7 px en negrita)   | 3:1       | 4,5:1      |
| Iconos, bordes de campos y otros componentes | 3:1       | —          |

**Cómo se usa:** `scripts/contraste.ts` aplica la fórmula a cada par de _tokens_ en los dos temas.

```ts
// Archivo: scripts/contraste.ts
// Relación de contraste WCAG 2.x entre pares de tokens, en claro y en oscuro
// Uso: node scripts/contraste.ts
type Hex = `#${string}`;

/** Luminancia relativa de un color (fórmula de WCAG 2.x) */
function luminancia(hex: Hex): number {
  const canales = [1, 3, 5].map((i) => parseInt(hex.slice(i, i + 2), 16) / 255);
  const lineal = canales.map((c) => (c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4));
  return 0.2126 * lineal[0]! + 0.7152 * lineal[1]! + 0.0722 * lineal[2]!;
}

/** De 1:1 (iguales) a 21:1 (negro sobre blanco) */
export function contraste(a: Hex, b: Hex): number {
  const [claro, oscuro] = [luminancia(a), luminancia(b)].sort((x, y) => y - x);
  return (claro! + 0.05) / (oscuro! + 0.05);
}

const TEMAS = {
  claro: { bg: "#fafafa", surface: "#eaedf2", fg: "#0f172a", muted: "#475569", accent: "#0d9488", "accent-strong": "#0f766e", "accent-contrast": "#ffffff", danger: "#f25c76", "danger-strong": "#be123c" },
  oscuro: { bg: "#0d1117", surface: "#161b22", fg: "#e6edf3", muted: "#9aa4b2", accent: "#2dd4bf", "accent-strong": "#5eead4", "accent-contrast": "#04201d", danger: "#f87191", "danger-strong": "#fda4af" },
} as const;

// [texto, fondo, uso]
const PARES = [
  ["fg", "bg", "texto normal"],
  ["muted", "bg", "texto secundario"],
  ["muted", "surface", "texto secundario en tarjeta"],
  ["accent", "bg", "acento como TEXTO"],
  ["accent-strong", "bg", "enlaces y texto de acento"],
  ["accent-contrast", "accent", "texto de un botón"],
  ["danger", "bg", "error como TEXTO"],
  ["danger-strong", "bg", "texto de error"],
] as const;

for (const [tema, t] of Object.entries(TEMAS)) {
  console.log(`${tema}:`);
  for (const [texto, fondo, uso] of PARES) {
    const r = contraste(t[texto] as Hex, t[fondo] as Hex);
    const nota = r >= 7 ? "AAA" : r >= 4.5 ? "AA" : r >= 3 ? "solo texto grande (AA ≥ 18,7 px negrita o 24 px)" : "✗ no pasa";
    console.log(`  ${`${texto} sobre ${fondo}`.padEnd(30)} ${r.toFixed(2).padStart(5)}:1  ${nota.padEnd(10)} ${uso}`);
  }
}
```

- **El acento `#0d9488` sobre `#fafafa` da 3,59:1:** vale para fondos, bordes, iconos y texto grande, **no** para texto normal. Por eso existe `--accent-strong` (`#0f766e`, 5,24:1) para enlaces y texto de acento.
- **El blanco sobre un botón de acento también falla** (3,74:1): los botones con texto van sobre `accent-strong` (5,47:1, Paso 5).
- **En oscuro todo pasa con holgura** (`#2dd4bf` sobre fondo oscuro, 10,17:1): un color sirve en un tema y no en el otro.

<Callout type="risk">

- **Mide sobre el fondo real:** el texto secundario da 7,26:1 sobre `bg` y 6,46:1 en una tarjeta (`surface`).
- **La opacidad engaña:** `text-fg/60` se mezcla con el fondo y pierde contraste. Para texto, un _token_ con valor propio (`muted`).
- **El color no basta:** un enlace sin subrayado no se distingue para quien no ve ese color. `prose` los subraya; mantenlo.

</Callout>

## Paso 2: HTML semántico, _landmarks_ y títulos

**Qué es:** un lector de pantalla recorre la estructura de la página: salta entre **landmarks** (zonas) y se hace un índice con los títulos.

| Elemento   | Zona (_landmark_)   | Uso                                                   |
| ---------- | ------------------- | ----------------------------------------------------- |
| `<header>` | Cabecera (`banner`) | La barra superior. **Una por página**                 |
| `<nav>`    | Navegación          | Los menús. Si hay varios, cada uno con `aria-label`   |
| `<main>`   | Contenido principal | **Una por página**. Lo que no se repite entre páginas |
| `<aside>`  | Complementario      | El índice lateral del curso                           |
| `<footer>` | Pie (`contentinfo`) | El pie de página                                      |

**Cómo se usa:** un único `<h1>` por página y, debajo, `<h2>`, `<h3>`… sin saltar niveles. El nivel lo decide la estructura, no el tamaño: para un `<h2>` pequeño, cambia la clase.

<Callout type="risk">

- **Un `<div>` con `onClick` no es un botón:** no llega con Tab, no responde a Enter ni Espacio y no se anuncia. `<button>` para acciones, `<a href>` para navegar.
- **Las imágenes necesitan `alt`:** lo que aporta la imagen, o `alt=""` si es decorativa.

</Callout>

## Paso 3: foco visible, teclado y enlace para saltar

**Qué es:** quien usa Tab necesita **ver** dónde está, y no recorrer la misma barra de enlaces en cada página. Las soluciones: **foco visible** en todo y un **enlace para saltar al contenido**, oculto hasta que recibe el foco.

**Cómo se usa:** crea `src/components/SaltarAlContenido.astro`.

```astro
---
// Archivo: src/components/SaltarAlContenido.astro
// El primer elemento con foco: oculto hasta que se llega con Tab, y salta al <main id="contenido">
---

<a
  href="#contenido"
  class="sr-only rounded-lg bg-accent-strong px-4 py-2 text-accent-contrast focus:not-sr-only focus:absolute focus:top-3 focus:left-3 focus:z-50"
>
  Saltar al contenido
</a>
```

Va en el _layout_ como primer elemento con foco, dentro de la cabecera; las páginas con cabecera propia (las de curso de B7) no reciben la del _layout_, para no tener dos `<header>`. Sustituye `src/layouts/Layout.astro`:

```astro
---
// Archivo: src/layouts/Layout.astro
import "../styles/global.css";
import { ClientRouter } from "astro:transitions";
import BotonTema from "../components/BotonTema.astro";
import SaltarAlContenido from "../components/SaltarAlContenido.astro";

interface Props {
  titulo: string;
  /** Para las páginas que traen su propia cabecera (y ponen en ella el botón de tema) */
  sinCabecera?: boolean;
}
const { titulo, sinCabecera = false } = Astro.props;
---

<html lang="es">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width" />
    <title>{titulo} · Tailwind lab</title>
    <!-- 1. El tema, ANTES de que el navegador pinte nada. is:inline: Astro no lo aplaza ni lo empaqueta -->
    <script is:inline>
      (() => {
        const aplicarTema = () => {
          let guardado = null;
          try {
            guardado = localStorage.getItem("tema");
          } catch {
            // Almacenamiento bloqueado: se sigue la preferencia del sistema
          }
          const oscuro = guardado ? guardado === "dark" : matchMedia("(prefers-color-scheme: dark)").matches;
          document.documentElement.dataset.theme = oscuro ? "dark" : "light";
        };
        aplicarTema();
        // 2. View Transitions: al navegar, el <html> nuevo llega sin data-theme. Se reaplica antes de pintarlo
        if (!window.__temaEscuchando) {
          window.__temaEscuchando = true;
          document.addEventListener("astro:after-swap", aplicarTema);
        }
      })();
    </script>
    <ClientRouter />
    <slot name="head" />
  </head>
  <body class="bg-bg font-sans text-fg">
    {
      !sinCabecera && (
        <header class="flex justify-end p-3">
          <SaltarAlContenido />
          <BotonTema />
        </header>
      )
    }
    {sinCabecera && <SaltarAlContenido />}
    <slot />
  </body>
</html>
```

- **Cada `<main>` lleva `id="contenido"`,** el destino del enlace.
- **`curso.astro` y `curso-responsive.astro`** pasan `sinCabecera`, importan `BotonTema` y lo ponen en su `<nav>`.

<Callout type="risk">

- **Nunca `outline: none` sin otro contorno igual de visible:** `:focus-visible` (Paso 5) lo muestra con el teclado y no al hacer clic.
- **`sr-only` oculta a la vista, no al lector:** `focus:not-sr-only` lo muestra con el foco. Con `display: none` o `hidden`, nadie podría usarlo.

</Callout>

## Paso 4: ARIA, solo cuando el HTML no basta

**Qué es:** **ARIA** son atributos que dan a los lectores de pantalla información que el HTML no tiene. Su primera regla: **no usarlo** si el HTML ya lo resuelve; `role="button"` en un `<div>` es peor que un `<button>`.

**Cómo se usa:**

| Necesitas…                                | HTML       | ARIA, solo si no hay HTML           |
| ----------------------------------------- | ---------- | ----------------------------------- |
| Un botón                                  | `<button>` | —                                   |
| Un botón que se activa y desactiva        | `<button>` | `aria-pressed="true"` / `"false"`   |
| Nombrar algo sin texto visible (un icono) | —          | `aria-label="Cerrar"`               |
| Enlazar un campo con su error             | —          | `aria-describedby` (I5.5)           |
| Avisar de un cambio                       | —          | `role="alert"` o `aria-live` (I5.5) |
| La página actual en un menú               | —          | `aria-current="page"` (B7.4)        |

- **`BotonTema` (I7.2) es el caso de `aria-pressed`:** un interruptor cuyo texto no cambia, pero su estado sí: "Modo oscuro, botón, activado".

<Callout type="risk">

- **`aria-pressed` es para interruptores:** "Guardar" no tiene estado, y "Ver más" / "Ver menos" ya lo dice con el texto.
- **ARIA no añade comportamiento:** `role="button"` no hace que un `<div>` responda a Enter; solo cambia lo que se anuncia.

</Callout>

## Paso 5: movimiento reducido y los cambios en `global.css`

**Qué es:** quien se marea con las animaciones lo indica en su sistema, y CSS lo recibe como **`prefers-reduced-motion: reduce`**.

- **Reducir no es quitar la información:** una barra de progreso tiene que seguir cambiando, aunque sea de golpe.

</Callout>

Las correcciones:

- **"Continuar"** y los botones de `flex.astro` y `grid.astro` pasan a `bg-accent-strong`: 5,47:1.
- **Shiki:** tres colores de GitHub no llegan a 4,5:1 sobre `--surface` y se cambian por el mismo tono ajustado: palabras clave `#d73a49` → `#b31d28` (de 3,90 a 5,73:1), comentarios en claro `#6a737d` → `#4b5563` (de 4,10 a 6,44:1) y en oscuro `#6a737d` → `#8b949e` (de 3,59 a 5,62:1), como hace esta plataforma.
- **`componentes.astro` y `estados.astro`** reciben su `<h1>` (`page-has-heading-one`).

Corregir también rompió tres cosas:

- **`landmark-no-duplicate-banner`:** el _layout_ ponía un `<header>` y las páginas de curso ya tenían el suyo; de ahí `sinCabecera` (Paso 3).
- **`heading-order`:** el `<h1>` nuevo de `/estados` iba seguido de un `<h3>`, que pasó a `<h2>`.
- **`region`:** el enlace de salto quedaba fuera de toda zona; dentro del `<header>`, se resolvió.

## Resumen

- AA: 4,5:1 para texto normal, 3:1 para texto grande e iconos. `#0d9488` sobre `#fafafa`, 3,59:1: para texto, `accent-strong`.
- Un `<header>`, un `<main>`, títulos en orden y un `<h1>`; `<button>` y `<a>` en su sitio.
- `:focus-visible` y un enlace "Saltar al contenido" el primero.
- ARIA solo si el HTML no basta: `aria-pressed` para interruptores.
- `prefers-reduced-motion` y dos auditores (Lighthouse y axe), en los dos temas.
