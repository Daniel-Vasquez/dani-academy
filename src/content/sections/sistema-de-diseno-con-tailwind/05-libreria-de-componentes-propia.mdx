Con los _tokens_ (I7.1), el tema (I7.2), la tipografía (I7.3) y la accesibilidad (I7.4), lo que falta es no repetir. Cada botón de la app debería ser **el** botón: mismas formas, mismos estados, mismo foco, sin que cada página reinvente sus clases. Una **librería de componentes** es ese conjunto de piezas, cada una con sus variantes (primario o secundario, pequeño o grande), y una página donde verlas todas juntas. En esta sección vas a definir las variantes con `cva`, de forma que TypeScript avise si alguien pide una que no existe, vas a escribir siete componentes y vas a montar la página `/ui`, revisada en los dos temas.

**Lo que tendrás al terminar:** `src/components/ui/variantes.ts` con las variantes de todos los componentes; `Button`, `Badge`, `Card`, `Checkbox`, `ProgressBar`, `Alerta` y `Tabs`, y la página `/ui`.

**Requisitos:** el proyecto `tw-lab` de I7.4, con `cn()` de B7.5.

```bash
npm install class-variance-authority
```

## Paso 1: el inventario y `cva`

| Componente    | Para qué                              | Variantes                                                                    |
| ------------- | ------------------------------------- | ---------------------------------------------------------------------------- |
| `Button`      | Acciones                              | `variante` (primario, secundario, fantasma, peligro) y `tamano` (sm, md, lg) |
| `Badge`       | Estados cortos ("Completado")         | `tono` (neutral, accent, warning, danger)                                    |
| `Card`        | Agrupar contenido                     | `relieve` (plana, contorno); interactiva si es un enlace                     |
| `Checkbox`    | Marcar una opción                     | —                                                                            |
| `ProgressBar` | Progreso de un curso                  | `tamano` (sm, md)                                                            |
| `Alerta`      | Mensajes de la interfaz               | `tipo` (info, exito, warning, danger)                                        |
| `Tabs`        | Alternar contenidos en el mismo sitio | —                                                                            |

En B7.5 escribiste las variantes con un objeto (`VARIANTES[variante]`). **`cva`** (_class-variance-authority_) hace lo mismo con una estructura fija: unas clases base, las variantes y sus valores por defecto, y devuelve una función que da las clases de cada combinación. Crea `src/components/ui/variantes.ts`, con las de todos los componentes:

```ts
// Archivo: src/components/ui/variantes.ts
// Las variantes de cada componente, en un solo sitio: las usan tanto los .astro como los .tsx
import { cva, type VariantProps } from "class-variance-authority";

export const boton = cva(
  "inline-flex items-center justify-center gap-2 rounded-xl font-semibold transition disabled:cursor-not-allowed disabled:opacity-50",
  {
    variants: {
      variante: {
        primario: "bg-accent-strong text-accent-contrast hover:bg-accent", // 5,47:1 (I7.4)
        secundario: "bg-surface text-fg ring-1 ring-surface-2 ring-inset hover:bg-surface-2",
        fantasma: "text-fg hover:bg-surface",
        peligro: "bg-danger-strong text-danger-contrast hover:opacity-90",
      },
      tamano: {
        sm: "px-3 py-1.5 text-sm",
        md: "px-5 py-2.5 text-sm",
        lg: "px-6 py-3 text-base",
      },
    },
    defaultVariants: { variante: "primario", tamano: "md" },
  },
);
export type VariantesBoton = VariantProps<typeof boton>;

export const insignia = cva("inline-flex items-center rounded-full px-2.5 py-0.5 text-xs font-medium ring-1 ring-inset", {
  variants: {
    tono: {
      neutral: "bg-surface text-fg ring-surface-2",
      accent: "bg-accent/10 text-accent-strong ring-accent/30",
      warning: "bg-warning/10 text-fg ring-warning/40",
      danger: "bg-danger/10 text-danger-strong ring-danger/30",
    },
  },
  defaultVariants: { tono: "neutral" },
});
export type VariantesInsignia = VariantProps<typeof insignia>;

export const tarjeta = cva("rounded-2xl border border-surface-2 p-5", {
  variants: {
    relieve: {
      plana: "bg-surface",
      contorno: "bg-bg",
    },
    // Una tarjeta que es un enlace: se nota al pasar por encima y al enfocarla
    interactiva: {
      true: "transition hover:border-accent hover:shadow-sm",
      false: "",
    },
  },
  defaultVariants: { relieve: "plana", interactiva: false },
});
export type VariantesTarjeta = VariantProps<typeof tarjeta>;

export const alerta = cva("rounded-r-xl border-l-4 px-5 py-3", {
  variants: {
    tipo: {
      info: "border-info bg-info/10",
      exito: "border-accent bg-accent/10",
      warning: "border-warning bg-warning/10",
      danger: "border-danger bg-danger/10",
    },
  },
  defaultVariants: { tipo: "info" },
});
export type VariantesAlerta = VariantProps<typeof alerta>;
```

```text
secundario sm:     inline-flex items-center justify-center gap-2 rounded-xl font-semibold transition disabled:cursor-not-allowed disabled:opacity-50 bg-surface text-fg ring-1 ring-surface-2 ring-inset hover:bg-surface-2 px-3 py-1.5 text-sm

```

- **`defaultVariants`:** sin argumentos, `boton()` es primario y mediano.
- **`VariantProps<typeof boton>`** saca el tipo de las propiedades a partir de las variantes: `{ variante?: "primario" | "secundario" | …; tamano?: … }`. No hay que escribirlo a mano ni mantenerlo.
- **Todo en un archivo `.ts`:** las variantes valen igual para componentes de Astro (`.astro`) y de React (`.tsx`). Hay que poder usar el mismo `boton()` en un enlace de Astro y en un botón de React.

<Callout type="risk">

- **Los nombres de clase, completos y literales:** `cva` funciona con Tailwind porque las clases están escritas enteras en el archivo (`"bg-accent-strong"`), y Tailwind las encuentra al escanear (B7.1). Nunca construyas una clase con plantillas (`` `bg-${color}` ``): Tailwind no la generaría.
- **Una variante, una decisión de diseño:** si un botón necesita algo que ninguna variante tiene, piensa si es una variante nueva (para toda la app) o una excepción. Con `className` desde fuera, la excepción queda en esa página y no ensucia la librería.

</Callout>

## Paso 2: `Button` y `Badge`

Sustituye `src/components/ui/Button.tsx`:

```tsx
// Archivo: src/components/ui/Button.tsx
import type { ButtonHTMLAttributes } from "react";
import { cn } from "../../lib/cn";
import { boton, type VariantesBoton } from "./variantes";

interface ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement>, VariantesBoton {}

export function Button({ variante, tamano, className, type = "button", ...resto }: ButtonProps) {
  // cn() deja que una clase de fuera gane a la de la variante (px-2 sobre px-5), como en B7.5
  return <button type={type} className={cn(boton({ variante, tamano }), className)} {...resto} />;
}
```

Y `src/components/ui/Badge.astro`:

```astro
---
// Archivo: src/components/ui/Badge.astro
import { cn } from "../../lib/cn";
import { insignia, type VariantesInsignia } from "./variantes";

interface Props extends VariantesInsignia {
  class?: string;
}
const { tono, class: className } = Astro.props;
---

<span class={cn(insignia({ tono }), className)}><slot /></span>
```

Los dos componentes heredan sus propiedades de las variantes, así que TypeScript conoce los valores válidos. Prueba con una variante que no existe, `<Button variante="enorme">`:

```text
src/pages/prueba.astro:5:9 - error ts(2322): Type '"enorme"' is not assignable to type '"primario" | "secundario" | "fantasma" | "peligro" | null | undefined'.
```

El error sale al escribirlo (y en `npm run check`), no en el navegador. Al hacer este cambio en `tw-lab`, `astro check` encontró, de la misma forma, tres usos antiguos con variantes que ya no existían en otra página.

<Callout type="risk">

- **`cn()` sigue siendo necesario:** `cva` junta las clases, pero no resuelve conflictos. Sin `cn()`, `<Button className="px-2">` dejaría `px-5 px-2` en el HTML, y ganaría la que Tailwind haya escrito después en el CSS, no la tuya.
- **No metas lógica de negocio en un componente de la librería:** un `Button` no sabe qué es una sección leída. Los componentes de la librería reciben datos y pintan; los de la app (`MarcarLeida`) los usan.

</Callout>

Y `src/components/ui/Alerta.astro`, para los mensajes de la interfaz. Con `vivo`, los lectores de pantalla lo anuncian al aparecer: `role="alert"` para los errores (interrumpe) y `role="status"` para lo demás (espera a que el usuario termine):

```astro
---
// Archivo: src/components/ui/Alerta.astro
// Un mensaje de la interfaz. Con "vivo", los lectores de pantalla lo anuncian al aparecer (role="alert" o "status")
import { cn } from "../../lib/cn";
import { alerta, type VariantesAlerta } from "./variantes";

const TITULOS = { info: "Nota", exito: "Hecho", warning: "Atención", danger: "Error" } as const;

interface Props extends VariantesAlerta {
  titulo?: string;
  vivo?: boolean;
  class?: string;
}
const { tipo = "info", titulo, vivo = false, class: className } = Astro.props;
const rol = vivo ? (tipo === "danger" ? "alert" : "status") : undefined;
---

<div role={rol} class={cn(alerta({ tipo }), className)}>
  <p class="text-xs font-semibold tracking-wider text-muted uppercase">{titulo ?? TITULOS[tipo ?? "info"]}</p>
  <div class="mt-1 text-sm text-fg"><slot /></div>
</div>
```

- **`accent-accent-strong`** es la utilidad de Tailwind para la propiedad CSS `accent-color`: colorea la casilla nativa sin rehacerla. Una casilla dibujada con `<div>` habría que hacerla accesible a mano (teclado, estado, etiqueta).
- **`role="progressbar"`** con `aria-valuenow`, `aria-valuemax` y `aria-valuetext`: el lector de pantalla dice "Progreso de TypeScript desde cero, 3 de 8".
- **`Alerta` es distinto del `Aviso` de B7.5:** `Aviso` son los bloques de una lección (Nota, Ejercicio, Riesgos); `Alerta`, los mensajes de la app (guardado, error). Mezclarlos en un componente con siete variantes lo haría inmanejable.

<Callout type="risk">

- **`role="alert"` solo para lo urgente:** el lector de pantalla interrumpe lo que esté leyendo. Un "Guardado" que interrumpe en cada cambio es insoportable; para eso está `role="status"`.
- **El `h3` de `Card` supone que va dentro de una sección con `h2`:** si la usas directamente bajo el `h1` de una página, el orden de los títulos se rompe (I7.4). Una librería más completa recibiría el nivel como propiedad.

</Callout>

## Paso 4: `Tabs`, con el teclado de verdad

Las pestañas son el componente más fácil de hacer mal: con un `<div>` por pestaña, no se pueden usar con el teclado ni las entiende un lector de pantalla. El patrón de WAI-ARIA dice cómo deben comportarse: `role="tablist"`, `tab` y `tabpanel`, Tab para **entrar** en la pestaña activa y las flechas para **cambiar** de pestaña. Crea `src/components/ui/Tabs.tsx`:

```tsx
// Archivo: src/components/ui/Tabs.tsx
// Pestañas accesibles (patrón WAI-ARIA): Tab entra en la pestaña activa, las flechas cambian de pestaña
import { useId, useRef, useState, type KeyboardEvent, type ReactNode } from "react";
import { cn } from "../../lib/cn";

interface Pestana {
  id: string;
  titulo: string;
  contenido: ReactNode;
}

export function Tabs({ pestanas, etiqueta }: { pestanas: Pestana[]; etiqueta: string }) {
  const [activa, setActiva] = useState(0);
  const botones = useRef<(HTMLButtonElement | null)[]>([]);
  const base = useId();

  function alPulsar(evento: KeyboardEvent<HTMLButtonElement>) {
    const ultima = pestanas.length - 1;
    const destino = { ArrowRight: activa === ultima ? 0 : activa + 1, ArrowLeft: activa === 0 ? ultima : activa - 1, Home: 0, End: ultima }[evento.key];
    if (destino === undefined) return;
    evento.preventDefault();
    setActiva(destino);
    botones.current[destino]?.focus();
  }

  return (
    <div>
      <div role="tablist" aria-label={etiqueta} className="flex gap-1 border-b border-surface-2">
        {pestanas.map((p, i) => (
          <button
            key={p.id}
            ref={(el) => {
              botones.current[i] = el;
            }}
            type="button"
            role="tab"
            id={`${base}-tab-${p.id}`}
            aria-selected={i === activa}
            aria-controls={`${base}-panel-${p.id}`}
            tabIndex={i === activa ? 0 : -1} // solo la activa entra en el orden de Tab
            onClick={() => setActiva(i)}
            onKeyDown={alPulsar}
            className={cn(
              "-mb-px border-b-2 px-4 py-2 text-sm font-medium",
              i === activa ? "border-accent-strong text-accent-strong" : "border-transparent text-muted hover:text-fg",
            )}
          >
            {p.titulo}
          </button>
        ))}
      </div>
      {pestanas.map((p, i) => (
        <div key={p.id} role="tabpanel" id={`${base}-panel-${p.id}`} aria-labelledby={`${base}-tab-${p.id}`} hidden={i !== activa} tabIndex={0} className="py-4 text-sm text-fg">
          {p.contenido}
        </div>
      ))}
    </div>
  );
}
```

- **`tabIndex` móvil:** solo la pestaña activa tiene `tabIndex={0}`; las demás, `-1`. Así, Tab entra en el grupo una sola vez y el siguiente Tab sale al panel, en lugar de recorrer todas las pestañas.
- **Las flechas cambian la pestaña y mueven el foco a la vez;** Inicio y Fin van a la primera y a la última; las flechas dan la vuelta al llegar a un extremo.
- **`aria-selected`, `aria-controls` y `aria-labelledby`** enlazan cada pestaña con su panel; `useId()` da _ids_ únicos aunque haya dos grupos de pestañas en la página.

<Callout type="risk">

- **Si la isla de React deja de funcionar tras instalar un paquete** (en la consola del servidor, `_jsxDEV is not a function` o `Invalid hook call`), es la caché de Vite: para el servidor y arráncalo con `npm run dev -- --force` (I5.2).
- **Las pestañas no sustituyen a la navegación:** si cada pestaña es una página distinta con su propia URL, son enlaces (`<nav>` con `aria-current`), no pestañas.

</Callout>

- **Tab entra en la pestaña activa** (`tabindex` 0/-1/-1), las flechas cambian a la vez el foco, la selección y el panel visible, y dan la vuelta al llegar a un extremo.

<Callout type="risk">

- **Revisa `/ui` en los dos temas cada vez que añadas una variante:** el fallo del botón de peligro solo existía en oscuro, y ninguna otra página tenía un botón de peligro.
- **La página `/ui` es interna:** si no quieres que sea pública en producción, ponle `prerender = false` y protégela con el _middleware_ (I5.3), o no la incluyas en el _build_.

</Callout>

<Callout type="mastery">

Construyes una página nueva solo combinando tus componentes: cada pieza tiene sus variantes definidas con `cva` y tipadas con `VariantProps` (TypeScript avisa de una variante que no existe), usa los _tokens_ para funcionar en los dos temas, es accesible con el teclado y con un lector de pantalla, y la página `/ui` te deja verlas y revisarlas todas a la vez.

</Callout>

## Resumen

- Un inventario de componentes y sus variantes, en un solo `variantes.ts` que comparten Astro y React.
- `cva(base, { variants, defaultVariants })` da las clases de cada combinación; `VariantProps` da sus tipos.
- `cn()` sigue haciendo falta para que una clase de fuera gane a la de la variante.
- Componentes nativos siempre que se pueda (`<input type="checkbox">`, `<button>`); ARIA para lo que el HTML no trae (`role="progressbar"`, `role="tab"`).
- Pestañas con el patrón WAI-ARIA: `tabIndex` móvil, flechas, Inicio y Fin.
- Una página `/ui` con todo, revisada con axe en claro y en oscuro.
