Las listas largas de clases se resuelven **extrayendo componentes**, no volviendo a las clases semánticas. Aquí extraes componentes de Astro y React, mides por qué una clase pasada desde fuera a veces no funciona (y cómo lo arregla `cn()`), creas una utilidad con `@utility` y estilizas contenido largo con `prose`.

**Requisitos:** el proyecto `tw-lab` de B7.4 y React (curso B6).

## Paso 1: un componente en lugar de una lista repetida

**Qué es:** si copias la misma lista de clases en tres sitios, no crees una clase CSS: crea un **componente**, y cambiarás el diseño en un solo archivo.

**Cómo se usa:** añade React y las librerías de la sección.

```bash
npx astro add react --yes
npm install clsx tailwind-merge @tailwindcss/typography
```

Crea `src/components/ui/Badge.astro`:

```astro
---
// Archivo: src/components/ui/Badge.astro
type Tono = "neutral" | "accent" | "warning";
interface Props {
  tono?: Tono;
  class?: string;
}
const { tono = "neutral", class: className } = Astro.props;

// Nombres de clase completos: Tailwind los encuentra (B7.1)
const TONOS: Record<Tono, string> = {
  neutral: "bg-slate-100 text-slate-700 ring-slate-200",
  accent: "bg-accent/10 text-accent-strong ring-accent/30",
  warning: "bg-amber-50 text-amber-900 ring-amber-200",
};
---

<span
  class:list={[
    "inline-flex items-center rounded-full px-2.5 py-0.5 text-xs font-medium ring-1 ring-inset",
    TONOS[tono],
    className,
  ]}
>
  <slot />
</span>
```

- **Las clases están completas en `TONOS`** (la trampa de B7.1): la _prop_ `tono` elige una entrada, sin construir nombres.
- **`class:list`** une cadenas, ignora valores falsos y acepta objetos `{ "clase": condición }`.
- **`class` desde fuera** (`<Badge class="px-4">`) se renombra al desestructurar, `class: className`, porque `class` es palabra reservada.

<Callout type="risk">

- **Extrae a la tercera repetición, no antes:** un componente de un solo uso solo añade un archivo.
- **Los tipos de las _props_ son documentación:** con `tono?: Tono`, `tono="verde"` sale en rojo. Sin tipo, es una insignia sin color.

</Callout>

## Paso 2: el conflicto de clases y `cn()`

**Qué es:** cuando dos clases dan valor a la misma propiedad, **gana la que aparece más tarde en el CSS**, no en el atributo. **`tailwind-merge`** entiende las clases y elimina las que se contradicen, quedándose con la última escrita; con `clsx` (clases condicionales), forma **`cn()`**.

**Cómo se usa:** crea `src/pages/componentes.astro` (crea antes `Button.tsx`, del Paso 3, o no compilará).

```astro
---
// Archivo: src/pages/componentes.astro
import Layout from "../layouts/Layout.astro";
import Badge from "../components/ui/Badge.astro";
import { Button } from "../components/ui/Button";
---

<Layout titulo="B7.5 · Componentes">
  <main class="mx-auto max-w-2xl space-y-8 p-8">
    <p class="flex gap-2">
      <Badge>Sin empezar</Badge>
      <Badge tono="accent">Completado</Badge>
      <Badge tono="warning">En curso</Badge>
      <Badge tono="accent" class="px-4">px-4 desde fuera</Badge>
      <Badge tono="accent" class="px-2">px-2 desde fuera</Badge>
    </p>

    <div class="flex flex-wrap items-center gap-3">
      <Button>Marcar como leído</Button>
      <Button variante="secundario">Ver temario</Button>
      <Button variante="fantasma" tamano="sm">Cancelar</Button>
      <Button className="px-2">px-2 desde fuera</Button>
      <Button disabled>Guardando…</Button>
    </div>
  </main>
</Layout>
```

Las dos últimas insignias reciben `px-4` y `px-2` desde fuera, sobre el `px-2.5` del componente. Con `class:list`:

```text
px-4 desde fuera     relleno 16px
px-2 desde fuera     relleno 10px
```

- **`px-4` gana; `px-2` pierde** y se queda en 10 px. El HTML tiene las dos clases, pero en el CSS generado (en `dist/_astro/` tras `npm run build`) el orden es:

```text
orden en el CSS: .px-2 → .px-2.5 → .px-4 → .px-5
```

- **`px-4` va después de `px-2.5`, y `px-2` antes:** el resultado depende de un orden que no controlas.

Crea `src/lib/cn.ts`:

```ts
// Archivo: src/lib/cn.ts
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

/** Une clases condicionales y resuelve conflictos de Tailwind (la última gana). */
export function cn(...inputs: ClassValue[]): string {
  return twMerge(clsx(inputs));
}
```

Y un _script_ de prueba, `src/lib/prueba-cn.ts`, que se ejecuta con `node src/lib/prueba-cn.ts` (Node 23.6+ ejecuta TypeScript):

```ts
// Archivo: src/lib/prueba-cn.ts
import { clsx } from "clsx";
import { twMerge } from "tailwind-merge";
import { cn } from "./cn.ts";

const leido = false;

console.log("clsx:      ", clsx("px-5 py-3", leido && "bg-accent/10", !leido && "bg-accent", { "opacity-50": false }));
console.log("solo unir: ", clsx("px-5 py-3", "px-2"));
console.log("cn:        ", cn("px-5 py-3", "px-2"));
console.log("cn colores:", cn("bg-accent text-white", "bg-slate-100"));
console.log("cn lados:  ", cn("p-4", "px-2"));
console.log("cn al revés:", cn("px-2", "p-4"));
console.log("cn tema:   ", cn("text-accent-strong text-lg", "text-sm"));
```

```text
clsx:       px-5 py-3 bg-accent
solo unir:  px-5 py-3 px-2
cn:         py-3 px-2
cn colores: text-white bg-slate-100
cn lados:   p-4 px-2
cn al revés: p-4
cn tema:    text-accent-strong text-sm
```

- **`clsx` une y descarta condiciones falsas,** pero deja `px-5` y `px-2` juntos. **`cn`** quita `px-5`; con colores, quita `bg-accent` y mantiene `text-white`.
- **Entiende los lados:** `p-4` + `px-2` conserva las dos; `px-2` + `p-4`, sobra `px-2`. Y distingue tamaño de color: `text-accent-strong` se queda y `text-lg` cede ante `text-sm`.

`Badge.astro` con `cn()` en lugar de `class:list`:

```astro
---
// Archivo: src/components/ui/Badge.astro
import { cn } from "../../lib/cn";

type Tono = "neutral" | "accent" | "warning";
interface Props {
  tono?: Tono;
  class?: string;
}
const { tono = "neutral", class: className } = Astro.props;

// Nombres de clase completos: Tailwind los encuentra (B7.1)
const TONOS: Record<Tono, string> = {
  neutral: "bg-slate-100 text-slate-700 ring-slate-200",
  accent: "bg-accent/10 text-accent-strong ring-accent/30",
  warning: "bg-amber-50 text-amber-900 ring-amber-200",
};
---

<span
  class={cn(
    "inline-flex items-center rounded-full px-2.5 py-0.5 text-xs font-medium ring-1 ring-inset",
    TONOS[tono],
    className,
  )}
>
  <slot />
</span>
```

De nuevo con `componentes.astro`:

```text
px-4 desde fuera     relleno 16px
px-2 desde fuera     relleno 8px
```

- **Las dos funcionan.** Es el `Badge.astro` y el `cn.ts` de esta plataforma.

<Callout type="risk">

- **El fallo es silencioso e intermitente:** funciona con `px-4`, falla con `px-2`, y cambia si cambia el CSS. Todo componente que acepte `class` o `className` las une con `cn()`.
- **`tailwind-merge` adivina las clases de tu tema:** un tamaño propio (`--text-titulo` → `text-titulo`) puede tomarlo por un color. Se configura con `extendTailwindMerge`.
- **No concatenes con `+` ni plantillas:** `"px-5 " + className` deja el conflicto y, con `undefined`, añade la clase `"undefined"`.

</Callout>

## Paso 3: un componente de React con variantes

**Qué es:** un botón con variantes y tamaños como mapas de clases completas, y el tipo de la _prop_ derivado del propio mapa.

**Cómo se usa:** crea `src/components/ui/Button.tsx`. `componentes.astro` ya lo usa.

```tsx
// Archivo: src/components/ui/Button.tsx
import type { ButtonHTMLAttributes } from "react";
import { cn } from "../../lib/cn";

const VARIANTES = {
  primario: "bg-accent-strong text-white hover:bg-accent",
  secundario: "bg-white text-slate-900 ring-1 ring-slate-300 ring-inset hover:bg-slate-100",
  fantasma: "text-slate-700 hover:bg-slate-100",
} as const;

const TAMANOS = {
  sm: "px-3 py-1.5 text-sm",
  md: "px-5 py-2.5 text-sm",
} as const;

interface ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  variante?: keyof typeof VARIANTES;
  tamano?: keyof typeof TAMANOS;
}

export function Button({ variante = "primario", tamano = "md", className, type = "button", ...resto }: ButtonProps) {
  return (
    <button
      type={type}
      className={cn(
        "inline-flex items-center gap-2 rounded-xl font-semibold transition focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent-strong disabled:cursor-not-allowed disabled:opacity-50",
        VARIANTES[variante],
        TAMANOS[tamano],
        className,
      )}
      {...resto}
    />
  );
}
```

```text
Marcar como leído    relleno 20px · fondo rgb(15, 118, 110) · texto rgb(255, 255, 255)
Ver temario          relleno 20px · fondo rgb(255, 255, 255) · texto oklch(0.208 0.042 265.755)
Cancelar             relleno 12px · fondo rgba(0, 0, 0, 0) · texto oklch(0.372 0.044 257.287)
px-2 desde fuera     relleno 8px · fondo rgb(15, 118, 110) · texto rgb(255, 255, 255)
Guardando…           relleno 20px · fondo rgb(15, 118, 110) · texto rgb(255, 255, 255)
```

- **`VARIANTES` y `TAMANOS`** son mapas como `TONOS`, de solo lectura con `as const`. **`keyof typeof VARIANTES`** da `"primario" | "secundario" | "fantasma"`: una variante nueva es una línea (I1.2).
- **`extends ButtonHTMLAttributes<HTMLButtonElement>`** acepta todo lo de un `<button>` vía `...resto`, y **`className` al final de `cn()`** tiene la última palabra (`px-2` → 8 px).
- **`type = "button"` por defecto:** sin `type`, dentro de un formulario lo enviaría.

<Callout type="risk">

- **Sin `client:`, el botón es HTML estático:** el `onClick` no existe en el navegador (B6.7). Para un enlace o el botón de un formulario, no hace falta hidratar.
- **Pocas variantes:** tres y dos tamaños cubren casi todo; con diez, son componentes distintos. En I7, `cva` formaliza el patrón.

</Callout>

## Paso 4: `@utility`, con moderación

**Qué es:** **`@utility`** define una utilidad propia para una propiedad que Tailwind no cubre. Funciona con variantes, como cualquier otra.

**Cómo se usa:** sustituye `src/styles/global.css` (también añade `@plugin "@tailwindcss/typography";`, para el Paso 5).

```css
/* Archivo: src/styles/global.css */
@import "tailwindcss";
@import "@fontsource-variable/inter";
@import "@fontsource-variable/source-serif-4";
@plugin "@tailwindcss/typography";

@theme {
  --color-accent: #0d9488;
  --color-accent-strong: #0f766e;
  --font-sans: "Inter Variable", system-ui, sans-serif;

  /* Planificador 2026: un color por categoría */
  --color-trabajo: #0284c7;
  --color-personal: #d97706;
  --color-salud: #0d9488;
  --color-estudio: #f25c76;
  --font-serif: "Source Serif 4 Variable", Georgia, serif;
}

/* Una utilidad propia: funciona con variantes (lg:scrollbar-fino) */
@utility scrollbar-fino {
  scrollbar-width: thin;
  scrollbar-color: var(--color-slate-300) transparent;
}
```

Para probarla, `src/pages/prose.astro`, cuyo panel final usa `scrollbar-fino`:

```astro
---
// Archivo: src/pages/prose.astro
import Layout from "../layouts/Layout.astro";
---

<Layout titulo="B7.5 · Prose">
  <main class="grid gap-8 p-8 lg:grid-cols-2">
    <!-- 1. Sin prose: el HTML de Markdown, sin clases, no tiene estilo -->
    <article id="sin-prose">
      <h2>Arrays, tuplas y objetos</h2>
      <p>Casi todos los datos de una app web son <a href="#">listas de objetos</a>.</p>
      <ol><li>Declara el tipo</li><li>Recorre con <code>map</code></li></ol>
    </article>

    <!-- 2. Con prose: una sola clase estiliza todo el contenido -->
    <article id="con-prose" class="prose prose-slate prose-headings:font-serif prose-a:text-accent-strong">
      <h2>Arrays, tuplas y objetos</h2>
      <p>Casi todos los datos de una app web son <a href="#">listas de objetos</a>.</p>
      <ol><li>Declara el tipo</li><li>Recorre con <code>map</code></li></ol>

      <!-- 3. La trampa: prose dentro de not-prose no recupera los estilos -->
      <div id="trampa" class="not-prose rounded-xl border border-amber-300 p-4">
        <p class="text-xs font-semibold uppercase">Ejercicio (mal)</p>
        <div class="prose">
          <ol><li>Paso uno</li><li>Paso dos</li></ol>
        </div>
      </div>

      <!-- 4. La solución: not-prose solo en el título -->
      <div id="solucion" class="rounded-xl border border-accent/40 px-4">
        <p class="not-prose pt-4 text-xs font-semibold uppercase">Ejercicio (bien)</p>
        <ol><li>Paso uno</li><li>Paso dos</li></ol>
      </div>
    </article>

    <aside id="lateral" class="scrollbar-fino h-32 overflow-y-auto rounded-xl bg-white p-4 lg:col-span-2">
      <p class="h-96">Un panel con su propio scroll y una barra fina (@utility scrollbar-fino).</p>
    </aside>
  </main>
</Layout>
```

En el CSS generado, una regla normal:

```css
.scrollbar-fino{scrollbar-width:thin;scrollbar-color:var(--color-slate-300) transparent}
```

- **En Chrome, el panel tiene `scrollbar-width: thin`,** y admite `lg:scrollbar-fino` o `hover:scrollbar-fino`.

<Callout type="risk">

- **Si cabe en un componente, va en un componente:** `@utility boton` con quince propiedades es volver al CSS semántico. `@utility` es para una o dos propiedades.
- **`@apply` existe, pero úsalo poco:** sirve para HTML que no controlas (un _plugin_, un CMS); en tu código, un componente es más claro.

</Callout>

## Paso 5: contenido largo con `prose`

**Qué es:** el HTML de Markdown o de un CMS no tiene clases, y los estilos base de Tailwind (B7.1) le quitan el formato. **`prose`**, del _plugin_ de tipografía, se lo devuelve con una clase y limita el ancho a 65ch.

**Cómo se usa:** `prose.astro` muestra el mismo contenido sin y con `prose`:

```text
#sin-prose h2 16px 400 "Inter Variable" · enlace oklch(0.208 0.042 265.755) subrayado none · ol none margen-izq 0px · párrafo interlineado 24px
#con-prose h2 24px 700 "Source Serif 4 Variable" · enlace rgb(15, 118, 110) subrayado underline · ol decimal margen-izq 26px · párrafo interlineado 28px
max-width prose: 656.094px
```

- **Sin `prose`, el título parece un párrafo,** el enlace no se distingue y la lista no tiene números.
- **Modificadores:** `prose-slate` (grises), `prose-headings:font-serif`, `prose-a:text-accent-strong`, `max-w-none` y `prose-lg`. Esta plataforma, en su lugar, conecta las variables del _plugin_ (`--tw-prose-body`, `--tw-prose-links`…) con sus colores, para que funcionen en claro y oscuro.

### La trampa de `not-prose`

`not-prose` excluye un bloque del estilo, pero excluye **todo** lo que contiene, **aunque vuelvas a poner `prose` dentro**. Las dos cajas de `prose.astro`:

```text
#trampa ol none · relleno 0px
#solucion ol decimal · relleno 26px
```

- **La caja "mal" pierde los números de su lista:** `not-prose` en el contenedor y `prose` en el contenido. Cada regla del _plugin_ excluye lo que esté dentro de un `not-prose`:

```css
.prose :where(ol):not(:where([class~=not-prose],[class~=not-prose] *)){
```

- **Esta plataforma lo sufrió** en los cuadros de "Ejercicio". La solución, la caja "bien": `not-prose` **solo en el título**.

<Callout type="risk">

- **`prose` pone comillas invertidas al código en línea:** se quitan con `prose-code:before:content-none prose-code:after:content-none`.
- **Botones y tarjetas dentro de `prose`** heredan márgenes y colores de texto: envuélvelos en `not-prose`.
- **`prose` da estilo, no seguridad:** HTML ajeno con `set:html` o `dangerouslySetInnerHTML` sin sanear permite XSS (B3.1).

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Crea `src/components/ui/Aviso.astro`, un cuadro como los de estas lecciones, con tres tipos (`nota`, `ejercicio`, `riesgo`), cada uno con su título y sus colores, que acepte `class` desde fuera y lo una con `cn()`.
2. Su contenido debe heredar los estilos de `prose` del artículo (listas numeradas, código, negritas) sin caer en la trampa de `not-prose`.
3. Monta `src/pages/leccion.astro` con un artículo `prose`, insignias de metadatos, un aviso de cada tipo (uno con un borde más grueso pasado desde fuera) y el `Button` al final.

</Callout>

Solución. `src/components/ui/Aviso.astro`:

```astro
---
// Archivo: src/components/ui/Aviso.astro
import { cn } from "../../lib/cn";

type Tipo = "nota" | "ejercicio" | "riesgo";
interface Props {
  tipo?: Tipo;
  class?: string;
}
const { tipo = "nota", class: className } = Astro.props;

const ESTILOS: Record<Tipo, { titulo: string; caja: string }> = {
  nota: { titulo: "Nota", caja: "border-sky-500 bg-sky-50" },
  ejercicio: { titulo: "Ejercicio", caja: "border-accent bg-accent/10" },
  riesgo: { titulo: "Complicaciones y riesgos", caja: "border-rose-500 bg-rose-50" },
};
const { titulo, caja } = ESTILOS[tipo];
---

<aside class={cn("my-6 rounded-r-xl border-l-4 px-5 py-1", caja, className)}>
  <!-- Solo el título sale de prose: el contenido hereda listas, código y enlaces del artículo -->
  <p class="not-prose mt-3 mb-1 text-xs font-semibold tracking-wider text-slate-600 uppercase">{titulo}</p>
  <slot />
</aside>
```


- **Las listas conservan números y viñetas** porque solo el título lleva `not-prose`; el código en línea hereda la negrita (600) sin comillas.

- **`ESTILOS`** guarda título y clases de cada tipo: un tipo nuevo es una línea. Es, en pequeño, el `Callout.astro` de estas lecciones.

<Callout type="risk">

- **Un aviso es un `<aside>`,** contenido complementario. Para uno urgente que aparece de pronto, además `role="alert"`.
- **El color no puede ser la única pista:** cada aviso lleva su **título escrito**, para quien no distingue el rojo del verde.

</Callout>

<Callout type="mastery">

No repites la misma lista de clases en más de dos sitios: extraes un componente con un mapa de clases completas. Unes las clases que llegan desde fuera con `cn()` (`clsx` + `tailwind-merge`) porque sabes que, si no, el resultado depende del orden del CSS. Usas `@utility` solo para lo que Tailwind no trae, y estilizas contenido largo con `prose`, poniendo `not-prose` solo donde de verdad quieres salir de él.

</Callout>

## Resumen

- Ante la repetición, un componente con un mapa de clases completas.
- Gana la clase que va después **en el CSS**; `cn()` se queda con la última escrita.
- `class:list` no resuelve conflictos: con `class` desde fuera, `cn()`.
- `@utility` para una o dos propiedades que Tailwind no trae.
- `prose` estiliza contenido sin clases; `not-prose`, solo en el título.
