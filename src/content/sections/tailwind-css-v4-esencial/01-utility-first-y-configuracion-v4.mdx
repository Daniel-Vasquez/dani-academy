Tailwind CSS pone en el HTML **clases pequeñas que hacen una sola cosa** (`p-6`, `rounded-xl`, `bg-white`), en lugar de nombres inventados con sus reglas aparte. La versión 4 se configura en CSS, sin `tailwind.config.js`. Aquí defines tu tema, abres el CSS que genera y provocas la trampa de las clases construidas con texto.

**Requisitos:** Node.js 22.12 o superior y CSS básico (selectores, propiedades, `margin`, `padding`, `display`).

## Paso 1: crear el proyecto con Tailwind v4

**Qué es:** `tw-lab`, un proyecto Astro con Tailwind v4, que usarás en todo B7.

**Cómo se usa:**

```bash
npm create astro@latest tw-lab -- --template minimal --install --no-git --yes
cd tw-lab
npx astro add tailwind --yes
npm install @fontsource-variable/inter
npm install --save-dev @astrojs/check typescript @types/node
code .
```

- **`npx astro add tailwind`** instala `tailwindcss` y `@tailwindcss/vite`, y deja así `astro.config.mjs`:

```js
// @ts-check
import { defineConfig } from 'astro/config';

import tailwindcss from '@tailwindcss/vite';

// https://astro.build/config
export default defineConfig({
  vite: {
    plugins: [tailwindcss()]
  }
});
```

- **En v4, Tailwind es un plugin de Vite,** no una integración de Astro. También crea `src/styles/global.css` con `@import "tailwindcss";`, que hay que importar en un layout.
- **Instala la extensión _Tailwind CSS IntelliSense_:** autocompleta, muestra el CSS de cada clase y avisa de clases contradictorias.

<Callout type="risk">

- **Los tutoriales de Tailwind 3 no sirven tal cual:** `tailwind.config.js`, `@tailwind base;` y `npx tailwindcss init` no existen en v4. Las clases son casi las mismas; la configuración, no.
- **Sin `import "../styles/global.css"` en un layout,** las clases están en el HTML pero sin reglas detrás: todo sin estilos.

</Callout>

## Paso 2: el tema, en CSS

**Qué es:** **`@theme`** es donde vive tu tema. Cada variable sigue un **espacio de nombres**: `--color-accent` crea **todas** las utilidades de color con ese nombre (`bg-accent`, `text-accent`, `border-accent`, `ring-accent`…), y `--font-sans` cambia `font-sans`.

**Cómo se usa:** sustituye `src/styles/global.css` por:

```css
/* Archivo: src/styles/global.css */
@import "tailwindcss";
@import "@fontsource-variable/inter";

@theme {
  --color-accent: #0d9488;
  --color-accent-strong: #0f766e;
  --font-sans: "Inter Variable", system-ui, sans-serif;
}
```

- **`@import "tailwindcss"`** trae los estilos base (sin márgenes por defecto, entre otras cosas) y el generador de utilidades.
- **`@import "@fontsource-variable/inter"`** sirve la fuente desde tu proyecto, sin Google Fonts.

El layout que importa el CSS, `src/layouts/Layout.astro`:

```astro
---
// Archivo: src/layouts/Layout.astro
import "../styles/global.css";

interface Props {
  titulo: string;
}
const { titulo } = Astro.props;
---

<html lang="es">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width" />
    <title>{titulo} · Tailwind lab</title>
  </head>
  <body class="bg-slate-50 font-sans text-slate-900">
    <slot />
  </body>
</html>
```

- **El `@theme` de esta plataforma** (`src/styles/global.css`) define colores que cambian entre modo claro y oscuro (`accent`, `info`, `warning`, `danger`…) y tres fuentes. Lo verás en I7.

<Callout type="risk">

- **El nombre decide la utilidad:** `--color-accent` crea `bg-accent`; `--accent`, nada. Los principales: `--color-*`, `--font-*`, `--text-*`, `--spacing`, `--radius-*`, `--shadow-*` y `--breakpoint-*`.
- **`@theme` añade, no sustituye:** tus colores se suman a la paleta. Para usar **solo** los tuyos, `--color-*: initial;`.

</Callout>

## Paso 3: semántico frente a utilidades

**Qué es:** dos formas de escribir estilos: inventar clases con significado y escribir sus reglas, o componer utilidades en el propio elemento.

**Cómo se usa:** sustituye `src/pages/index.astro` por la misma tarjeta de las dos formas.

```astro
---
// Archivo: src/pages/index.astro
import Layout from "../layouts/Layout.astro";
---

<Layout titulo="B7.1 · Utility-first">
  <main class="mx-auto max-w-2xl p-8">
    <h1 class="text-3xl font-bold">La misma tarjeta, dos formas</h1>

    <!-- 1. CSS "semántico": un nombre de clase y sus reglas en otro sitio -->
    <article class="tarjeta-curso">
      <h2 class="tarjeta-curso__titulo">TypeScript desde cero</h2>
      <p class="tarjeta-curso__texto">3 de 8 secciones leídas</p>
    </article>

    <!-- 2. Utilidades: cada clase hace una sola cosa, y se leen en el propio HTML -->
    <article class="mt-6 rounded-xl border border-slate-200 bg-white p-6 shadow-sm">
      <h2 class="text-xl font-semibold text-accent-strong">TypeScript desde cero</h2>
      <p class="mt-2 text-slate-600">3 de 8 secciones leídas</p>
      <a href="#" class="mt-4 inline-block rounded-lg bg-accent px-4 py-2 font-medium text-white">Continuar</a>
    </article>
  </main>
</Layout>

<style>
  .tarjeta-curso {
    margin-top: 1.5rem;
    padding: 1.5rem;
    border: 1px solid #e2e8f0;
    border-radius: 0.75rem;
    background: white;
  }
  .tarjeta-curso__titulo {
    font-size: 1.25rem;
    font-weight: 600;
    color: #0f766e;
  }
  .tarjeta-curso__texto {
    margin-top: 0.5rem;
    color: #475569;
  }
</style>
```

Con `npm run dev`, se ven prácticamente iguales. La diferencia está en el trabajo:

| Aspecto                | CSS semántico                                  | Utilidades                                                     |
| ---------------------- | ---------------------------------------------- | -------------------------------------------------------------- |
| Nombres                | Hay que inventarlos (`tarjeta-curso__titulo`)  | No hay que inventar nada                                       |
| Dónde se lee el estilo | En otro bloque o archivo                       | En el propio elemento                                          |
| Cambiar un componente  | Riesgo de romper otros que usen la misma clase | Solo afecta a ese elemento                                     |
| Tamaño del CSS         | Crece con cada componente nuevo                | Las utilidades se reutilizan: crece muy poco                   |
| Valores                | Cualquiera (`margin-top: 13px`)                | Una escala común (`mt-3`, `mt-4`): diseño más consistente      |
| Lo malo                | Archivos de CSS que nadie se atreve a tocar    | El HTML se llena de clases; se resuelve con componentes (B7.5) |

<Callout type="risk">

- **Una lista larga de clases no es el problema; repetirla, sí.** La solución es un componente (B7.5), no volver a las clases semánticas.
- **Las utilidades no sustituyen al HTML correcto:** un `<div>` con aspecto de botón no es un botón para el teclado ni el lector de pantalla. `<button>`, `<a>`, `<nav>`, y utilidades encima.

</Callout>

## Paso 4: qué CSS genera Tailwind

**Qué es:** Tailwind **lee tus archivos** (`.astro`, `.tsx`, `.md`…), encuentra los nombres de clase escritos y genera **solo esas reglas**.

**Cómo se usa:** compila y abre el CSS.

```bash
npm run build
ls -l dist/_astro/*.css
```

Pesa unos **10 KB (3 KB comprimido)**. Busca estas reglas:

```css
.bg-accent{background-color:var(--color-accent)}
.text-accent-strong{color:var(--color-accent-strong)}
.rounded-xl{border-radius:var(--radius-xl)}
.p-6{padding:calc(var(--spacing) * 6)}
```

Y estas variables:

```css
--color-accent:#0d9488;
--color-slate-600:oklch(44.6% .043 257.281);
--font-sans:"Inter Variable", system-ui, sans-serif;
--spacing:.25rem;
```

- **Cada utilidad es una regla mínima que lee una variable:** `p-6` es `calc(var(--spacing) * 6)`, 6 × 0,25 rem = **1,5 rem**. Toda la escala sale de una variable.
- **`bg-red-500` no está:** ninguna página la usa. De toda la paleta, solo las 7 variables `--color-*` usadas. Los colores de Tailwind van en `oklch`; tu hexadecimal funciona igual.
- **`.tarjeta-curso` no aparece:** el `<style>` de Astro va aparte, con su propio ámbito.

<Callout type="risk">

- **Tailwind no lee lo ignorado por Git ni `node_modules`:** una librería con clases de Tailwind necesita `@source "../../node_modules/mi-libreria";`. Al revés, `@source not "../content";` excluye una carpeta: esta plataforma excluye las lecciones, y el CSS bajó de 69,9 KB a 62,3 KB.
- **Tailwind solo lee texto:** cualquier palabra que parezca una clase, aunque esté en un comentario, genera su regla. Es inofensivo y explica las clases "de más".

</Callout>

## Paso 5: la trampa de las clases construidas con texto

**Qué es:** como Tailwind solo **lee**, no sabe qué clases se **construirán** al ejecutar. **Los nombres de clase deben aparecer completos en el código.**

**Cómo se usa:** crea `src/components/InsigniaRota.astro`.

```astro
---
// Archivo: src/components/InsigniaRota.astro
// ❌ El nombre de la clase se construye al ejecutar: Tailwind nunca lo ve escrito
interface Props {
  color: "emerald" | "amber" | "rose" | "sky";
  texto: string;
}
const { color, texto } = Astro.props;
---

<span class={`rounded-full px-2 py-0.5 text-sm bg-${color}-100 text-${color}-800`}>{texto}</span>
```

La versión correcta, `src/components/Insignia.astro`:

```astro
---
// Archivo: src/components/Insignia.astro
// ✅ Los nombres completos están escritos en el código: Tailwind los encuentra
interface Props {
  color: "emerald" | "amber" | "rose";
  texto: string;
}
const { color, texto } = Astro.props;

const CLASES: Record<Props["color"], string> = {
  emerald: "bg-emerald-100 text-emerald-800",
  amber: "bg-amber-100 text-amber-800",
  rose: "bg-rose-100 text-rose-800",
};
---

<span class:list={["rounded-full px-2 py-0.5 text-sm", CLASES[color]]}>{texto}</span>
```

En `src/pages/insignias.astro`:

```astro
---
// Archivo: src/pages/insignias.astro
import Layout from "../layouts/Layout.astro";
import InsigniaRota from "../components/InsigniaRota.astro";
import Insignia from "../components/Insignia.astro";
---

<Layout titulo="Clases dinámicas">
  <main class="mx-auto max-w-2xl space-y-4 p-8">
    <p>Rotas: <InsigniaRota color="emerald" texto="Completado" /> <InsigniaRota color="amber" texto="En curso" /> <InsigniaRota color="sky" texto="Nuevo" /></p>
    <p>Bien: <Insignia color="emerald" texto="Completado" /> <Insignia color="amber" texto="En curso" /></p>
  </main>
</Layout>
```

Con `npm run build` y `npm run preview`, en `http://localhost:4321/insignias`, el fondo de cada insignia rota:

```text
Completado: fondo oklch(0.95 0.052 163.051)
En curso: fondo oklch(0.962 0.059 95.617)
Nuevo: fondo rgba(0, 0, 0, 0)
```

- **"Nuevo" no tiene fondo:** el HTML dice `bg-sky-100`, pero ese texto no está escrito en ningún archivo, solo `bg-${color}-100`. No hay regla.
- **Esmeralda y ámbar funcionan por casualidad:** `Insignia.astro` escribe `bg-emerald-100` y `bg-amber-100` completos. Si la borras, las "rotas" se rompen sin tocarlas.
- **Para elegir según una variable,** un objeto con las clases completas, como `CLASES`.

<Callout type="risk">

- **Ninguna herramienta avisa:** ni `npm run check`, ni TypeScript, ni la consola. Si una clase "no funciona", comprueba si su nombre aparece completo en algún archivo.
- **`class:list` (Astro) y `className` condicional (React) son seguros** con cadenas completas: `class:list={["p-4", leida && "bg-accent"]}`.
- **Para valores de verdad dinámicos** (un color elegido por el usuario), una variable CSS en línea, `style={{ "--color": colorElegido }}`, y una clase que la lea: `bg-(--color)`.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Añade al `@theme` de `tw-lab` los cuatro colores de las categorías del Planificador 2026 (trabajo `#0284c7`, personal `#d97706`, salud `#0d9488`, estudio `#f25c76`) y una fuente con serifa, Source Serif 4 (`npm install @fontsource-variable/source-serif-4`).
2. Crea `src/pages/ejercicio-b71.astro` con un título en la fuente con serifa y una leyenda con un punto de color por categoría.
3. Usa uno de los colores también como color de texto y de borde, para comprobar que se generan todas las utilidades.

</Callout>

Solución. `src/styles/global.css` completo:

```css
/* Archivo: src/styles/global.css */
@import "tailwindcss";
@import "@fontsource-variable/inter";
@import "@fontsource-variable/source-serif-4";

@theme {
  --color-accent: #0d9488;
  --color-accent-strong: #0f766e;
  --font-sans: "Inter Variable", system-ui, sans-serif;

  /* Planificador 2026: un color por categoría */
  --color-trabajo: #0284c7;
  --color-personal: #d97706;
  --color-salud: #0d9488;
  --color-estudio: #f25c76;
  --font-serif: "Source Serif 4 Variable", Georgia, serif;
}
```

`src/pages/ejercicio-b71.astro`:

```astro
---
// Archivo: src/pages/ejercicio-b71.astro
import Layout from "../layouts/Layout.astro";
---

<Layout titulo="Ejercicio B7.1">
  <main class="mx-auto max-w-2xl p-8">
    <h1 class="font-serif text-4xl font-semibold">Planificador 2026</h1>
    <p class="mt-2 text-slate-600">Leyenda de categorías</p>
    <ul class="mt-6 space-y-2">
      <li class="flex items-center gap-3"><span class="size-4 rounded-full bg-trabajo"></span> Trabajo</li>
      <li class="flex items-center gap-3"><span class="size-4 rounded-full bg-personal"></span> Personal</li>
      <li class="flex items-center gap-3"><span class="size-4 rounded-full bg-salud"></span> Salud</li>
      <li class="flex items-center gap-3"><span class="size-4 rounded-full bg-estudio"></span> Estudio</li>
    </ul>
    <p class="mt-6 border-l-4 border-estudio pl-4 text-estudio">Las clases nuevas existen para todo: bg-, text-, border-…</p>
  </main>
</Layout>
```

Comprobado con `npm run build` y `npm run preview`:

```text
h1: "Source Serif 4 Variable", Georgia, serif · fuente cargada: true
Trabajo: rgb(2, 132, 199)
Personal: rgb(217, 119, 6)
Salud: rgb(13, 148, 136)
Estudio: rgb(242, 92, 118)
aviso: rgb(242, 92, 118) · borde rgb(242, 92, 118)
```

- **Cuatro variables `--color-*` crean `bg-trabajo`, `text-estudio`, `border-estudio`…,** y `--font-serif` cambia `font-serif`, sin otro archivo de configuración. `size-4` abrevia `w-4 h-4`.

<Callout type="risk">

- **Los nombres del tema son tu API:** renombrar `--color-salud` obliga a cambiar cada `bg-salud`. Nombra por significado (`salud`, `danger`), no por color (`verde`).
- **Cada familia de fuente se descarga** (unos 20–60 KB por familia y estilo): importa solo las que uses. Esta plataforma precarga las principales para que el texto no salte.

</Callout>

<Callout type="mastery">

Sabes dónde se configura cada cosa en v4 sin buscar un `tailwind.config.js`: el plugin en `astro.config.mjs`, el tema en `@theme` dentro de tu CSS (con los espacios de nombres `--color-*`, `--font-*`…), y las rutas extra con `@source`. Entiendes que Tailwind genera solo las clases que **lee escritas** en tus archivos, y por eso nunca construyes nombres de clase con plantillas de texto.

</Callout>

## Resumen

- Utility-first: clases de una sola cosa, en el HTML, con una escala común.
- v4 se configura en CSS: `@import "tailwindcss"`, `@theme` y el plugin `@tailwindcss/vite`.
- `--color-accent` crea `bg-accent`, `text-accent`…; `--font-*` cambia las fuentes.
- Solo se generan las clases escritas en tus archivos; `@source` añade o excluye carpetas.
- `bg-${color}-100` no se genera: objeto con nombres completos.
