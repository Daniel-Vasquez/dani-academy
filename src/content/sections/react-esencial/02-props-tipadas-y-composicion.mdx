Un componente que siempre muestra lo mismo sirve de poco. Aquí construyes `Badge`, `Button` y `Card` con sus **props** tipadas, los compones con `children` y descubres un error de Astro que no da ningún aviso.

**Requisitos:** el proyecto `react-lab` de B6.1, B1.4 (interfaces) y B1.5 (funciones como tipos).

## Paso 1: props tipadas y valores por defecto

**Qué es:** las **props** son los parámetros de un componente. React lo llama con **un único objeto** con todas: `<Badge tono="exito">Completado</Badge>` es `Badge({ tono: "exito", children: "Completado" })`.

**Cómo se usa:** crea `src/components/ui/Badge.tsx`.

```tsx
// Archivo: src/components/ui/Badge.tsx
import type { ReactNode } from "react";

type Tono = "neutro" | "exito" | "aviso";

interface BadgeProps {
  tono?: Tono;
  children: ReactNode;
}

const COLORES: Record<Tono, { fondo: string; texto: string }> = {
  neutro: { fondo: "#e2e8f0", texto: "#334155" },
  exito: { fondo: "#ccfbf1", texto: "#115e59" },
  aviso: { fondo: "#fef3c7", texto: "#92400e" },
};

export function Badge({ tono = "neutro", children }: BadgeProps) {
  const { fondo, texto } = COLORES[tono];
  return (
    <span className="insignia" style={{ background: fondo, color: texto }}>
      {children}
    </span>
  );
}
```

- **`interface BadgeProps`** tipa ese objeto: `<Badge tono="peligro">` da error.
- **`{ tono = "neutro", children }`** aplica un valor por defecto, y por eso `tono?:` es opcional.
- **`Record<Tono, …>`** (B1.4) obliga a un color por tono: añadir uno sin color da error.

<Callout type="risk">

- **Las props son de solo lectura:** son del padre. Si un componente necesita cambiar un valor, es **estado** (B6.3).
- **`?` sin valor por defecto** deja `tono` en `undefined`, y `COLORES[tono]` fallaría. `noUncheckedIndexedAccess` lo avisa; sin él, falla en ejecución.

</Callout>

## Paso 2: `children`, el contenido entre etiquetas

**Qué es:** `children` es lo que escribes **entre** las etiquetas. Su tipo es **`ReactNode`**: texto, números, JSX, listas, `null` o `undefined`. La idea central de React es la **composición**: componentes pequeños con huecos donde el padre pone otros.

**Cómo se usa:** crea `src/components/ui/Card.tsx`.

```tsx
// Archivo: src/components/ui/Card.tsx
import type { ReactNode } from "react";

interface CardProps {
  titulo: string;
  nivel?: "basico" | "intermedio" | "avanzado";
  acciones?: ReactNode;
  children: ReactNode;
}

export function Card({ titulo, nivel = "basico", acciones, children }: CardProps) {
  return (
    <section className="tarjeta" data-nivel={nivel}>
      <h2 style={{ marginTop: 0 }}>{titulo}</h2>
      {children}
      {acciones && <footer style={{ marginTop: "1rem", display: "flex", gap: "0.5rem" }}>{acciones}</footer>}
    </section>
  );
}
```

- **`Card` no sabe qué contiene:** solo pone el marco. **`acciones`** es otro hueco `ReactNode`; sin él, el `<footer>` no se pinta.

<Callout type="risk">

- **Si añades props como `mostrarX`, `textoX` o `colorX`,** ese "X" debería ser un hueco. Las props de configuración crecen sin límite; los huecos, no.
- **`{cantidad && <p>…</p>}` pinta un `0`** cuando la cantidad es 0. Con `ReactNode` no pasa, porque falta como `undefined` (B6.4).

</Callout>

## Paso 3: heredar las props de una etiqueta HTML

**Qué es:** un botón necesita **todas** las props de un `<button>`: `onClick`, `disabled`, `type`, `aria-label`. Se heredan, no se declaran una a una.

**Cómo se usa:** crea `src/components/ui/Button.tsx`.

```tsx
// Archivo: src/components/ui/Button.tsx
import type { ButtonHTMLAttributes } from "react";

interface ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  variante?: "principal" | "secundario";
}

export function Button({ variante = "secundario", type = "button", style, ...resto }: ButtonProps) {
  const principal = variante === "principal";
  return (
    <button
      type={type}
      style={{
        background: principal ? "#0f766e" : "#f8fafc",
        color: principal ? "#ffffff" : "#0f172a",
        ...style,
      }}
      {...resto}
    />
  );
}
```

- **`extends ButtonHTMLAttributes<HTMLButtonElement>`** hereda las props nativas con sus tipos y añade `variante`.
- **`...resto`** recoge lo que no desestructuras, y **`{...resto}`** lo pasa al `<button>`: estilo sin perder capacidades.
- **`type = "button"`** por defecto (Paso 6), y **`...style`** al final deja al padre añadir o sobrescribir estilos.

<Callout type="risk">

- **El orden de `{...resto}` importa:** antes de una prop, gana tu valor; después, gana el del padre.
- **Una prop propia dentro de `resto` acaba en el HTML** como `<button variante="principal">`, sin aviso. Sácalas siempre de `resto`.

</Callout>

## Paso 4: componer las piezas y pasar funciones como props

**Qué es:** una prop de tipo función, como `(cursoId: string) => void` (B1.5), permite al hijo **avisar** al padre. El padre decide qué hacer. Por convención, empiezan por `on`.

**Cómo se usa:** crea `src/components/CatalogoCursos.tsx`.

```tsx
// Archivo: src/components/CatalogoCursos.tsx
import { Badge } from "./ui/Badge";
import { Button } from "./ui/Button";
import { Card } from "./ui/Card";

interface Curso {
  id: string;
  titulo: string;
  nivel: "basico" | "intermedio" | "avanzado";
  leidas: number;
  total: number;
}

interface CatalogoCursosProps {
  cursos: Curso[];
  onEmpezar?: (cursoId: string) => void; // prop de tipo función (callback)
}

export function CatalogoCursos({ cursos, onEmpezar }: CatalogoCursosProps) {
  return (
    <div>
      {cursos.map((curso) => {
        const completado = curso.leidas === curso.total;
        return (
          <Card
            key={curso.id}
            titulo={`${curso.id} · ${curso.titulo}`}
            nivel={curso.nivel}
            acciones={
              <Button variante={completado ? "secundario" : "principal"} onClick={() => onEmpezar?.(curso.id)}>
                {completado ? "Repasar" : curso.leidas > 0 ? "Continuar" : "Empezar"}
              </Button>
            }
          >
            <p>
              {curso.leidas} de {curso.total} secciones{" "}
              <Badge tono={completado ? "exito" : curso.leidas > 0 ? "aviso" : "neutro"}>
                {completado ? "Completado" : curso.leidas > 0 ? "En curso" : "Sin empezar"}
              </Badge>
            </p>
          </Card>
        );
      })}
    </div>
  );
}
```

La isla que lo usa, `src/components/CatalogoInteractivo.tsx`:

```tsx
// Archivo: src/components/CatalogoInteractivo.tsx
// Una isla que decide qué hacer cuando se pulsa un botón de la tarjeta
import { CatalogoCursos } from "./CatalogoCursos";

const CURSOS = [
  { id: "B1", titulo: "TypeScript desde cero", nivel: "basico" as const, leidas: 8, total: 8 },
  { id: "B2", titulo: "Git y flujo de trabajo", nivel: "basico" as const, leidas: 2, total: 4 },
  { id: "B6", titulo: "React esencial", nivel: "basico" as const, leidas: 0, total: 7 },
];

export function CatalogoInteractivo() {
  return (
    <CatalogoCursos
      cursos={CURSOS}
      onEmpezar={(cursoId) => {
        console.log(`Ir al curso ${cursoId}`);
      }}
    />
  );
}
```

- **Cada pieza decide una cosa:** `Badge`, el color; `Button`, el estilo; `Card`, el marco; `CatalogoCursos`, el texto y el tono de cada curso. El `key={curso.id}` del `.map()` se explica en B6.4.

<Callout type="risk">

- **`onEmpezar?.()`:** opcional significa que puede ser `undefined`, y llamarla sin `?.` lanzaría `TypeError: onEmpezar is not a function`.
- **Una función nueva en cada render** (`() => onEmpezar?.(curso.id)`) es normal y casi nunca un problema. No la optimices sin una medición.

</Callout>

## Paso 5: la trampa de las funciones desde Astro

**Qué es:** para que una isla funcione en el navegador, Astro **serializa sus props como texto** en el HTML. Los datos se pueden convertir en texto; **una función, no**: llega como `null`, sin aviso.

**Cómo se usa:** crea temporalmente `src/pages/funcion.astro`, que pasa la función desde la página.

```astro
---
import Base from "../layouts/Base.astro";
import { CatalogoCursos } from "../components/CatalogoCursos";
import { Card } from "../components/ui/Card";

const cursos = [{ id: "B1", titulo: "TypeScript desde cero", nivel: "basico" as const, leidas: 0, total: 8 }];
---

<Base titulo="Función como prop">
  <CatalogoCursos client:load cursos={cursos} onEmpezar={(id: string) => console.log(id)} />
  <Card client:load titulo="Con children desde Astro"><p>Este párrafo viene de Astro.</p></Card>
</Base>
```

En `http://localhost:4321/funcion`, "Empezar" **no hace nada**, sin error. En el código fuente (`Cmd` + `Option` + `U`), el `props=` de la `<astro-island>`, descodificado:

```json
{"cursos":[1,[[0,{"id":[0,"B1"],"titulo":[0,"TypeScript desde cero"],"nivel":[0,"basico"],"leidas":[0,0],"total":[0,8]}]]],"onEmpezar":[0,null]}
```

- **`"onEmpezar":[0,null]`:** la función se perdió. En cambio, "Este párrafo viene de Astro." sí aparece: los `children` llegan como HTML renderizado.
- **La regla: de Astro a una isla, solo datos.** Las funciones se definen **dentro** de la isla, como en `CatalogoInteractivo`. Borra `funcion.astro`.

<Callout type="risk">

- **El fallo es silencioso:** con `?.` no pasa nada; sin él, `TypeError` en el navegador. Ni el _build_ ni `npm run check` avisan.
- **Tampoco se serializan** instancias de clases propias ni referencias circulares. Astro admite `Date`, `Map`, `Set`, `URL` o `BigInt`, pero lo seguro son objetos simples.
- **Las props de una isla son visibles en el HTML:** nunca pases datos que el usuario no deba ver. Es el principio de los DTO de B5.5.

</Callout>

## Paso 6: el `type="button"` que evita envíos fantasma

**Qué es:** dentro de un `<form>`, un `<button>` es **`submit` por defecto**. Sin `type = "button"` en `Button`, un "Mostrar contraseña" o un "Añadir otro campo" **enviaría el formulario**. Así, el envío solo ocurre si lo pides: `<Button type="submit">Guardar</Button>`.

## Ejercicio práctico

<Callout type="exercise">

1. Crea `src/components/TarjetaEntreno.tsx`, que muestre un entreno (tipo, minutos y, si los tiene, kilómetros) usando `Card`, `Badge` (con el texto "Intenso" si dura 60 minutos o más) y `Button`, con una prop `onEliminar(id)`.
2. Crea una isla `ListaEntrenos.tsx` con tres entrenos de ejemplo que registre en la consola qué entreno se quiere eliminar.
3. Úsala en `src/pages/ejercicio-b62.astro` y comprueba que no hay errores con `npm run check`.

</Callout>

Solución. `src/components/TarjetaEntreno.tsx`:

```tsx
// Archivo: src/components/TarjetaEntreno.tsx
import { Badge } from "./ui/Badge";
import { Button } from "./ui/Button";
import { Card } from "./ui/Card";

export interface Entreno {
  id: string;
  tipo: "running" | "fuerza" | "yoga";
  minutos: number;
  km?: number;
}

interface TarjetaEntrenoProps {
  entreno: Entreno;
  onEliminar: (id: string) => void;
}

const ETIQUETAS: Record<Entreno["tipo"], string> = { running: "Running", fuerza: "Fuerza", yoga: "Yoga" };

export function TarjetaEntreno({ entreno, onEliminar }: TarjetaEntrenoProps) {
  const intenso = entreno.minutos >= 60;
  return (
    <Card
      titulo={ETIQUETAS[entreno.tipo]}
      acciones={
        <Button onClick={() => onEliminar(entreno.id)} aria-label={`Eliminar entreno ${entreno.id}`}>
          Eliminar
        </Button>
      }
    >
      <p>
        {entreno.minutos} min
        {entreno.km !== undefined && ` · ${entreno.km} km`}{" "}
        {intenso && <Badge tono="aviso">Intenso</Badge>}
      </p>
    </Card>
  );
}
```

`src/components/ListaEntrenos.tsx`:

```tsx
// Archivo: src/components/ListaEntrenos.tsx

const ENTRENOS: Entreno[] = [

  { id: "e2", tipo: "fuerza", minutos: 65 },

];

export function ListaEntrenos() {
  return (
    <>
      {ENTRENOS.map((entreno) => (
        <TarjetaEntreno key={entreno.id} entreno={entreno} onEliminar={(id) => console.log(`Eliminar ${id}`)} />
      ))}
    </>
  );
}
```


- **`export interface Entreno`** vive junto al componente, y la lista lo importa con `type` (B1.7). **`Entreno["tipo"]`** (B1.4) reutiliza la unión en `ETIQUETAS`.
- **`entreno.km !== undefined`, no `entreno.km &&`:** con `km: 0`, la segunda pintaría un `0` suelto (B6.4).
- **`aria-label`** llega al `<button>` por `...resto`: tres "Eliminar" se distinguen con un lector de pantalla.

<Callout type="risk">

- **Este "eliminar" todavía no elimina:** solo avisa. Para que desaparezca, el padre guarda la lista en **estado** (B6.3 y B6.4).
- **Nunca el índice como `id`:** al eliminar uno, cambiarían los de todos los siguientes.

</Callout>

<Callout type="mastery">

Usas `children` (y props de tipo `ReactNode`) en lugar de multiplicar props: tipas las props con una `interface`, das valores por defecto en la desestructuración, heredas las props de una etiqueta HTML con `extends` y `...resto`, avisas al padre con props de función `on…`, y sabes que de Astro a una isla solo viajan datos, nunca funciones.

</Callout>

## Resumen

- Las props llegan como un objeto tipado, con valores por defecto, y son de solo lectura.
- `children: ReactNode` y otros huecos: composición en lugar de configuración.
- `extends ButtonHTMLAttributes<…>` + `{...resto}` heredan las props nativas.
- Una prop `on…` avisa al padre; con `?.` si es opcional.
- De `.astro` a una isla, las funciones llegan como `null`. Botones con `type="button"`.
