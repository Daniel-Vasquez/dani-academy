React es una librería para construir interfaces a partir de **componentes**: funciones que devuelven lo que se ve en pantalla. En tus proyectos con Astro ya lo usas en las partes interactivas (esta plataforma tiene el formulario de login, el botón "Marcar como leído" y la evaluación hechos con React). En esta sección vas a empezar desde cero: crearás un proyecto Astro con React, escribirás tus primeros componentes, verás **en qué se convierte el JSX** cuando se compila (la clave para entender sus reglas) y convertirás una tarjeta de `.astro` a React atributo por atributo, provocando los errores típicos. Al final comprobarás algo que sorprende: un componente de React en Astro, por defecto, **no envía ni un byte de JavaScript** al navegador.

**Lo que tendrás al terminar:** un proyecto `react-lab` (lo usarás en todo el curso B6) con tus primeros componentes `.tsx`, y una tabla mental de las diferencias entre JSX y HTML.

**Requisitos:** Node.js 22.12 o superior y lo visto en B1 (TypeScript y Astro).

## Paso 1: crear el proyecto con React

```bash
npm create astro@latest react-lab -- --template minimal --install --no-git --yes
cd react-lab
npx astro add react --yes
npm install --save-dev @astrojs/check typescript @types/node
code .
```

`npx astro add react` hace tres cosas por ti: instala `react`, `react-dom`, `@astrojs/react` y sus tipos (`@types/react`, `@types/react-dom`); registra la integración en `astro.config.mjs`; y configura TypeScript para JSX. Comprueba los dos archivos:

```js
// @ts-check
import { defineConfig } from 'astro/config';

import react from '@astrojs/react';

// https://astro.build/config
export default defineConfig({
  integrations: [react()]
});
```

```json
{
  "extends": "astro/tsconfigs/strict",
  "include": [".astro/types.d.ts", "**/*"],
  "exclude": ["dist"],
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "react"
  }
}
```

- **`integrations: [react()]`**: Astro sabe ahora renderizar componentes `.tsx` de React.
- **`"jsx": "react-jsx"`** y **`"jsxImportSource": "react"`**: TypeScript transforma el JSX con el _runtime_ automático de React (Paso 3). Por eso no hace falta `import React from "react"` en cada archivo.

Crea un layout sencillo para todas las páginas del curso, `src/layouts/Base.astro`:

```astro

// Archivo: src/layouts/Base.astro

const { titulo } = Astro.props;
---

<html lang="es">
  <head>

    <meta name="viewport" content="width=device-width" />
    <title>{titulo} · React lab</title>
    <style is:global>
      body { font-family: system-ui, sans-serif; max-width: 42rem; margin: 2rem auto; padding: 0 1rem; line-height: 1.5; }
      .tarjeta { border: 1px solid #cbd5e1; border-radius: 0.75rem; padding: 1rem; margin: 1rem 0; }
      .insignia { font-size: 0.75rem; padding: 0.1rem 0.5rem; border-radius: 999px; background: #e2e8f0; }
      button { font: inherit; padding: 0.4rem 0.9rem; border-radius: 0.5rem; border: 1px solid #94a3b8; background: #f8fafc; cursor: pointer; }
      button:disabled { opacity: 0.5; cursor: not-allowed; }
      .error { color: #b91c1c; }
    </style>
  </head>
  <body>
    <slot />
  </body>

```

<Callout type="risk">

- **No mezcles versiones de React:** `react` y `react-dom` deben tener exactamente la misma versión, y `@types/react` la misma versión mayor. Si un día ves errores raros de tipos con `children` o con eventos, revisa `npm ls react react-dom @types/react`.
- **Una sola librería de componentes por isla:** Astro admite React, Vue, Svelte y otras a la vez, pero cada integración añade su propio _runtime_ al navegador. En un proyecto, elige una.

</Callout>

## Paso 2: tu primer componente

Un componente de React es **una función que devuelve JSX**. Crea `src/components/Saludo.tsx`:

```tsx
// Archivo: src/components/Saludo.tsx
export function Saludo() {
  const nombre = "Dani";
  const hoy = new Date().toLocaleDateString("es-MX", { timeZone: "America/Mexico_City", dateStyle: "full" });
  return (
    <>
      <h1>Hola, {nombre}</h1>
      <p>Hoy es {hoy}</p>
    </>
  );
}
```

Tres reglas que ya aparecen aquí:

1. **El nombre empieza por mayúscula** (`Saludo`). Para JSX, `<saludo>` sería una etiqueta HTML desconocida y `<Saludo>`, tu componente.
2. **Se exporta con nombre** (`export function`), para importarlo con `import { Saludo } from "…"`.
3. **Las llaves `{}` insertan expresiones de JavaScript** dentro del JSX: variables (`{nombre}`), llamadas a funciones, operaciones. No sentencias: un `if` o un `for` no caben entre llaves (B6.4).

Úsalo en una página, `src/pages/index.astro` (que ampliarás en el Paso 4):

```astro
---
import Base from "../layouts/Base.astro";
import { Saludo } from "../components/Saludo";
---

<Base titulo="B6.1 · JSX y componentes">
  <Saludo />
</Base>
```

Arranca con `npm run dev` y abre `http://localhost:4321`. Verás "Hola, Dani" y la fecha de hoy, por ejemplo `Hoy es viernes, 9 de octubre de 2026`.

<Callout type="risk">

- **La fecha se calcula en el servidor:** como el componente no es interactivo (Paso 5), `new Date()` se ejecuta al generar la página. En una página estática (la opción por defecto de Astro), se ejecuta **al compilar**, y "hoy" será siempre el día del último despliegue. Para una fecha que cambie, la página debe renderizarse en cada petición (`prerender = false`) o calcularse en el navegador.
- **Siempre `timeZone` al formatear fechas** (B5.5): el servidor de Vercel está en UTC, y sin ella la fecha puede ser la del día anterior o la del siguiente.

</Callout>

## Paso 3: qué es JSX de verdad

JSX **no es HTML**. Es una sintaxis que el compilador convierte en llamadas a funciones de JavaScript. Compruébalo compilando tu componente con `esbuild` (el compilador que usa Vite por debajo, ya instalado con Astro):

```bash
npx esbuild src/components/Saludo.tsx --jsx=automatic --format=esm
```

```js
import { Fragment, jsxs } from "react/jsx-runtime";
function Saludo() {
  const nombre = "Dani";
  const hoy = (/* @__PURE__ */ new Date()).toLocaleDateString("es-MX", { timeZone: "America/Mexico_City", dateStyle: "full" });
  return /* @__PURE__ */ jsxs(Fragment, { children: [
    /* @__PURE__ */ jsxs("h1", { children: [
      "Hola, ",
      nombre
    ] }),
    /* @__PURE__ */ jsxs("p", { children: [
      "Hoy es ",
      hoy
    ] })
  ] });
}
export {
  Saludo
};
```

Cada etiqueta se convierte en una llamada a `jsx` o `jsxs` (del _runtime_ de React) con dos argumentos: **el tipo** (`"h1"`, un texto, para HTML; o tu función, para un componente) y **un objeto de propiedades** (las _props_), donde el contenido va en `children`. En versiones antiguas de React, la función se llamaba `React.createElement`; la idea es la misma.

Esto explica **todas** las reglas de JSX:

- **Un solo elemento raíz:** una función solo puede devolver un valor. `return (<h1/> <p/>)` serían dos valores. Por eso se envuelven en un **fragmento**, `<>…</>`, que se compila a `Fragment` y no añade ninguna etiqueta al HTML.
- **Atributos con nombres de JavaScript:** los atributos son las claves de un objeto, así que usan los nombres de las propiedades del DOM: `className` (porque `class` es una palabra reservada de JavaScript), `htmlFor` (porque `for` también lo es), `tabIndex`, `maxLength`…
- **Expresiones, no sentencias:** lo que va entre llaves acaba como un valor dentro de un array (`children: ["Hola, ", nombre]`). Un `if` no es un valor; un ternario (`a ? b : c`) sí.

<Callout type="risk">

- **Un fragmento no es un `<div>`:** `<>…</>` no aparece en el HTML. Si necesitas una etiqueta contenedora para dar estilos, usa un elemento real. Al revés, no añadas `<div>` innecesarios solo para cumplir la regla del elemento raíz: rompen el diseño de rejillas y _flexbox_.
- **JSX escapa el texto automáticamente:** `{textoDelUsuario}` se inserta como texto, nunca como HTML, así que un `<script>` escrito por un usuario no se ejecuta. La única forma de insertar HTML sin escapar es `dangerouslySetInnerHTML`, y su nombre ya avisa: úsala solo con contenido que controlas por completo (B3.1).

</Callout>

## Paso 4: de `.astro` a `.tsx`, atributo por atributo

Para ver las diferencias en la práctica, escribe la misma tarjeta de curso en los dos formatos. Primero en Astro, `src/components/TarjetaCurso.astro`:

```astro
---
// Archivo: src/components/TarjetaCurso.astro
const titulo = "TypeScript desde cero";
const secciones = 8;
const leidas = 3;
---

<article class="tarjeta">
  <h2>{titulo}</h2>
  <p>{leidas} de {secciones} secciones leídas</p>
  <label for="nota-ts">Nota personal</label>
  <input id="nota-ts" type="text" placeholder="Escribe algo" />
  <img src="/favicon.svg" alt="" width="16" height="16" style="vertical-align: middle; margin-left: 0.5rem" />
</article>
```

Y en React, `src/components/TarjetaCurso.tsx`:

```tsx
// Archivo: src/components/TarjetaCurso.tsx
export function TarjetaCurso() {
  const titulo = "TypeScript desde cero";
  const secciones = 8;
  const leidas = 3;
  const porcentaje = Math.round((leidas / secciones) * 100);

  return (
    <article className="tarjeta">
      <h2>{titulo}</h2>
      <p>
        {leidas} de {secciones} secciones leídas ({porcentaje} %)
      </p>
      <label htmlFor="nota-ts-react">Nota personal</label>
      <input id="nota-ts-react" type="text" placeholder="Escribe algo" />
      <img src="/favicon.svg" alt="" width={16} height={16} style={{ verticalAlign: "middle", marginLeft: "0.5rem" }} />
    </article>
  );
}
```

Muéstralas una debajo de otra. Sustituye `src/pages/index.astro` por:

```astro
---
// Archivo: src/pages/index.astro
import Base from "../layouts/Base.astro";
import TarjetaCursoAstro from "../components/TarjetaCurso.astro";
import { Saludo } from "../components/Saludo";
import { TarjetaCurso } from "../components/TarjetaCurso";
---

<Base titulo="B6.1 · JSX y componentes">
  <Saludo />
  <TarjetaCursoAstro />
  <TarjetaCurso />
</Base>
```

Las diferencias, una por una:

| En HTML / `.astro`               | En JSX / `.tsx`                       | Por qué                                                                 |
| -------------------------------- | ------------------------------------- | ----------------------------------------------------------------------- |
| `class="tarjeta"`                | `className="tarjeta"`                 | `class` es palabra reservada en JavaScript                              |
| `for="nota-ts"`                  | `htmlFor="nota-ts-react"`             | `for` también lo es                                                     |
| `<input …>`                      | `<input … />`                         | En JSX, toda etiqueta se cierra                                         |
| `width="16"`                     | `width={16}`                          | Los números van entre llaves                                            |
| `style="vertical-align: middle"` | `style={{ verticalAlign: "middle" }}` | `style` es un objeto con propiedades en _camelCase_                     |
| `stroke-width="2"` (SVG)         | `strokeWidth={2}`                     | Los atributos con guion pasan a _camelCase_ (salvo `aria-*` y `data-*`) |

Las dobles llaves de `style={{ … }}` no son una sintaxis especial: las de fuera significan "aquí va una expresión de JavaScript" y las de dentro son el objeto.

Provoca los errores típicos. Crea temporalmente estos componentes en `src/components/` y ejecuta `npx tsc --noEmit -p .`:

```tsx
export function Dos() {
  return (
    <h1>Hola</h1>
    <p>Adiós</p>
  );
}
```

```text
error TS2657: JSX expressions must have one parent element.
```

```tsx
export function SinCerrar() {
  return <img src="/favicon.svg" alt="">;
}
```

```text
error TS17008: JSX element 'img' has no corresponding closing tag.
```

```tsx
export function Estilo() {
  return <p style="color: red">Hola</p>;
}
```

```text
error TS2559: Type 'string' has no properties in common with type 'Properties<string | number, string & {}>'.
```

```tsx
export function Clase() {
  return <p class="tarjeta">Hola</p>;
}
```

```text
error TS2322: Type '{ children: string; class: string; }' is not assignable to type 'DetailedHTMLProps<HTMLAttributes<HTMLParagraphElement>, HTMLParagraphElement>'.
```

(Los errores de sintaxis de los dos primeros impiden que TypeScript revise el resto de archivos: pruébalos de uno en uno). Borra los cuatro archivos al terminar.

<Callout type="risk">

- **Los atributos con guion no dan error de TypeScript:** `<path stroke-width="2" />` compila sin quejas, porque JSX acepta cualquier atributo con guion (para que funcionen `data-*` y `aria-*`). El aviso solo aparece en la consola del servidor de desarrollo: ``Invalid DOM property `stroke-width`. Did you mean `strokeWidth`?``. Lo mismo con `class` si silencias el error de tipos: ``Invalid DOM property `class`. Did you mean `className`?``. Al copiar SVG de una web de iconos, revisa los atributos con guion.
- **Los `id` deben ser únicos en la página:** las dos tarjetas usan `nota-ts` y `nota-ts-react`. Si repites un `id` (por ejemplo, al usar dos veces el mismo componente), `htmlFor` apuntará al primero y el clic en la etiqueta enfocará el campo equivocado. React tiene `useId()` para generar identificadores únicos por instancia (B6.5).

</Callout>

## Paso 5: cuánto JavaScript llega al navegador

Compila el proyecto y mira qué ha generado:

```bash
npm run build
grep -c "<script" dist/index.html
```

```text
0
```

**Cero etiquetas `<script>`.** Mira el HTML de las dos tarjetas en `dist/index.html`:

```html
<article class="tarjeta"><h2>TypeScript desde cero</h2><p>3 de 8 secciones leídas</p><label for="nota-ts">Nota personal</label><input id="nota-ts" type="text" placeholder="Escribe algo"><img src="/favicon.svg" alt="" width="16" height="16" style="vertical-align: middle; margin-left: 0.5rem"></article>
<article class="tarjeta"><h2>TypeScript desde cero</h2><p>3<!-- --> de <!-- -->8<!-- --> secciones leídas (<!-- -->38<!-- --> %)</p><label for="nota-ts-react">Nota personal</label><input id="nota-ts-react" type="text" placeholder="Escribe algo"/><img src="/favicon.svg" alt="" width="16" height="16" style="vertical-align:middle;margin-left:0.5rem"/></article>
```

(Se han eliminado los atributos `data-astro-cid` que añade Astro para los estilos). El componente de React se ha convertido en **HTML puro**, casi idéntico al de Astro. Los comentarios `<!-- -->` los usa React para separar los fragmentos de texto. Astro ejecuta tus componentes de React **en el servidor** (o al compilar) y solo envía el resultado.

Para que un componente sea **interactivo** en el navegador (que responda a clics, que cambie), hay que pedirlo con una **directiva** `client:*`. Crea `src/pages/isla.astro`:

```astro
---
// Archivo: src/pages/isla.astro
import Base from "../layouts/Base.astro";
import { Saludo } from "../components/Saludo";
---

<Base titulo="Saludo como isla">
  <Saludo client:load />
</Base>
```

```bash
npm run build
ls -l dist/_astro/*.js
```

Ahora `dist/isla/index.html` contiene una etiqueta `<astro-island … client="load">` y el navegador descarga:

| Archivo       | Tamaño        | Comprimido (gzip) | Qué es            |
| ------------- | ------------- | ----------------- | ----------------- |
| `client.*.js` | 220 735 bytes | 68 264 bytes      | React y React DOM |
| `Saludo.*.js` | 671 bytes     | 449 bytes         | Tu componente     |

**Unos 68 KB comprimidos solo para que React exista en el navegador**, aunque el componente no haga nada interactivo. Esa es la idea de la arquitectura de **islas** de Astro (la verás a fondo en B6.7): la página es HTML estático y solo las "islas" que lo necesitan cargan JavaScript.

<Callout type="risk">

- **No pongas `client:load` "por si acaso":** un componente que solo muestra datos (como `Saludo` o `TarjetaCurso`) no necesita JavaScript. Cada isla innecesaria hace la página más pesada y más lenta en el móvil.
- **Un componente sin directiva no reacciona a nada:** si le pones un `onClick` y lo usas sin `client:*`, el botón se pinta pero el clic no hace nada, sin ningún error. Si algo "no responde" en Astro, lo primero que debes mirar es la directiva.

</Callout>

<Callout type="risk">

- **`viewBox` ya es _camelCase_ en HTML** y se queda igual. No todo atributo cambia: los que ya tienen mayúsculas en SVG (`viewBox`, `preserveAspectRatio`) se escriben tal cual.
- **Convertir a React no siempre es buena idea:** un componente sin interactividad está mejor en `.astro`, que es más simple y nunca envía JavaScript. Convierte a React solo lo que vaya a necesitar estado o eventos (B6.3).

</Callout>

<Callout type="mastery">

Escribes JSX válido sin errores de sintaxis: sabes que se compila a llamadas `jsx(tipo, props)`, y de ahí deduces sus reglas (un elemento raíz o un fragmento, `className` y `htmlFor`, `style` como objeto, atributos en _camelCase_, todo cerrado y expresiones entre llaves). También sabes que en Astro un componente de React sin directiva es solo HTML.

</Callout>

## Resumen

- Un componente es una función con nombre en mayúscula que devuelve JSX; `npx astro add react` configura el proyecto.
- JSX se compila a `jsx(tipo, props)` del _runtime_ de React: un solo elemento raíz (`<>…</>`) y expresiones, no sentencias, entre llaves.
- Diferencias con HTML: `className`, `htmlFor`, `style={{ … }}`, atributos en _camelCase_, números entre llaves y todas las etiquetas cerradas.
- Los atributos con guion no dan error de TypeScript, pero React avisa en la consola del servidor.
- Sin directiva `client:*`, React en Astro genera HTML y 0 KB de JavaScript; con `client:load` se descargan unos 68 KB comprimidos de React.
