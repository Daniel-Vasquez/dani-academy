Los formularios son el punto donde el usuario **escribe datos en tu app**: registrarse, apuntar un entreno, cambiar un objetivo. En React hay dos formas de manejarlos, y elegir mal (o mezclarlas) produce errores difíciles de seguir. En esta sección vas a construir el mismo formulario de las dos formas para ver la diferencia, vas a provocar los dos avisos que React muestra cuando algo está mal montado, vas a hacer un formulario de entreno con un único estado y mensajes de error accesibles, y terminarás con un formulario de registro que valida cada campo sin ninguna librería.

**Lo que tendrás al terminar:** una página `/formularios` con las demostraciones, `FormEntreno` (reutilizable, con validación) y `Registro`.

**Requisitos:** el proyecto `react-lab` de B6.4.

## Paso 1: controlado frente a no controlado

Un campo de formulario guarda un valor (lo que has escrito). La pregunta es **quién es el dueño** de ese valor:

- **Controlado:** el dueño es **React**. El valor vive en un estado, el campo lo muestra (`value={estado}`) y cada pulsación lo actualiza (`onChange`). En todo momento sabes qué hay escrito.
- **No controlado:** el dueño es **el navegador** (el DOM), como en un formulario HTML de toda la vida. React no se entera de lo que escribes; lees el valor al final, normalmente al enviar.

Crea `src/components/formularios/DosFormularios.tsx` con el mismo formulario de las dos formas:

```tsx
// Archivo: src/components/formularios/DosFormularios.tsx
// El mismo formulario, controlado (React guarda el valor) y no controlado (lo guarda el DOM)
import { useState, type FormEvent } from "react";

export function Controlado() {
  const [nombre, setNombre] = useState("");
  const [enviado, setEnviado] = useState("");

  function enviar(evento: FormEvent<HTMLFormElement>) {
    evento.preventDefault();
    setEnviado(nombre);
  }

  return (
    <form onSubmit={enviar} id="controlado">
      <label htmlFor="nombre-c">Nombre (controlado): </label>
      <input id="nombre-c" value={nombre} onChange={(e) => setNombre(e.target.value.toUpperCase())} />{" "}
      <button type="submit">Enviar</button>
      <p>
        Mientras escribes: <span className="eco">{nombre}</span> · Enviado: <span className="enviado">{enviado}</span>
      </p>
    </form>
  );
}

export function NoControlado() {
  const [enviado, setEnviado] = useState("");

  function enviar(evento: FormEvent<HTMLFormElement>) {
    evento.preventDefault();
    const datos = new FormData(evento.currentTarget); // lee los campos por su atributo name
    setEnviado(String(datos.get("nombre") ?? ""));
  }

  return (
    <form onSubmit={enviar} id="no-controlado">
      <label htmlFor="nombre-nc">Nombre (no controlado): </label>
      <input id="nombre-nc" name="nombre" defaultValue="" />{" "}
      <button type="submit">Enviar</button>
      <p>
        Enviado: <span className="enviado">{enviado}</span>
      </p>
    </form>
  );
}
```

En `http://localhost:4321/formularios`, escribe `dani` en los dos campos y pulsa los dos "Enviar":

```text
Controlado:     campo: DANI · mientras escribes: DANI · enviado: DANI
No controlado:  campo: dani · enviado: dani
```

- **En el controlado, el texto aparece en mayúsculas mientras escribes**, porque `onChange` hace `toUpperCase()` antes de guardarlo y el campo muestra lo que hay en el estado. Como el valor está en el estado, puedes transformarlo, validarlo letra a letra o mostrarlo en otra parte de la página ("Mientras escribes: DANI").
- **En el no controlado, React no sabe nada hasta el envío.** Al enviar, `new FormData(evento.currentTarget)` lee **todos** los campos del formulario por su atributo **`name`**. `defaultValue` da el valor inicial, pero después el navegador manda.

|                     | Controlado                                                             | No controlado                                                 |
| ------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------- |
| Dónde vive el valor | Estado de React (`value` + `onChange`)                                 | El DOM (`defaultValue` + `name`)                              |
| Lo lees             | En cualquier momento, del estado                                       | Al enviar, con `FormData`                                     |
| Ideal para          | Validar mientras se escribe, transformar, campos que dependen de otros | Formularios simples, envíos al servidor sin lógica intermedia |

<Callout type="risk">

- **`FormData` necesita el atributo `name`:** un campo sin `name` no aparece en `FormData`, sin ningún error. Si al enviar te falta un dato, lo primero que debes comprobar es el `name`.
- **`FormData.get` devuelve `FormDataEntryValue | null`** (un texto, un archivo o `null`), nunca un número. Convierte y valida igual que con `target.value` (B6.3).
- **`evento.currentTarget` frente a `evento.target`:** en `onSubmit`, `currentTarget` es siempre el `<form>` (donde está el manejador); `target` puede ser otro elemento. Para `FormData`, usa `currentTarget`.

</Callout>

## Paso 2: los dos avisos clásicos

Crea `src/components/formularios/AvisosFormulario.tsx`, con dos errores típicos a propósito:

```tsx
// Archivo: src/components/formularios/AvisosFormulario.tsx
// Dos errores que React avisa en la consola
import { useState } from "react";

export function AvisosFormulario() {
  const [apodo, setApodo] = useState<string | undefined>(undefined); // ❌ empieza sin valor
  return (
    <p>
      <label htmlFor="apodo">Apodo: </label>
      <input id="apodo" value={apodo} onChange={(e) => setApodo(e.target.value)} />{" "}
      <label htmlFor="solo-lectura">Bloqueado: </label>
      <input id="solo-lectura" value="no puedes cambiarme" /> {/* ❌ value sin onChange */}
    </p>
  );
}
```

Con la consola abierta, carga la página: aparece el primer aviso. Escribe una letra en "Apodo": aparece el segundo.

```text
You provided a `value` prop to a form field without an `onChange` handler. This will render a read-only field. If the field should be mutable use `defaultValue`. Otherwise, set either `onChange` or `readOnly`.
A component is changing an uncontrolled input to be controlled. This is likely caused by the value changing from undefined to a defined value, which should not happen. Decide between using a controlled or uncontrolled input element for the lifetime of the component.
```

1. **`value` sin `onChange`:** el campo "Bloqueado" muestra un valor fijo y **no puedes escribir en él** (pruébalo). React lo controla, pero nadie actualiza el estado. Si querías un valor inicial editable, es `defaultValue`; si querías un campo de solo lectura, añade `readOnly` para dejarlo claro.
2. **De no controlado a controlado:** `apodo` empieza como `undefined`, y `value={undefined}` es lo mismo que no poner `value`, así que el campo empieza **no controlado**. Al escribir, `apodo` pasa a ser un texto y el campo se vuelve **controlado**. React no sabe quién es el dueño. La solución: empezar siempre con un texto, `useState("")`.

<Callout type="risk">

- **El caso más frecuente es con datos que llegan de una API:** `value={usuario.nombre}` cuando `usuario` todavía no ha cargado (o el campo es opcional y viene como `undefined`). Usa `value={usuario.nombre ?? ""}`.
- **Estos avisos solo salen en desarrollo:** en producción, React no muestra nada y el campo simplemente se comporta mal. Revisa la consola mientras desarrollas.

</Callout>

## Paso 3: un formulario real, con un estado y validación accesible

Para un formulario con varios campos, lo práctico es **un solo estado con un objeto**, en lugar de un `useState` por campo. Crea `src/components/formularios/FormEntreno.tsx`:

```tsx
// Archivo: src/components/formularios/FormEntreno.tsx
import { useState, type FormEvent } from "react";

interface Entreno {
  tipo: "running" | "fuerza" | "yoga";
  minutos: number;
  km: number | null;
}

interface FormEntrenoProps {
  onGuardar: (entreno: Entreno) => void;
}

// Un solo estado con todos los campos, como texto (así llegan de los inputs)
const VACIO = { tipo: "running", minutos: "", km: "" };
type Campos = typeof VACIO;
type Errores = Partial<Record<keyof Campos, string>>;

function validar(campos: Campos): Errores {
  const errores: Errores = {};
  const minutos = Number(campos.minutos);
  if (campos.minutos.trim() === "" || !Number.isInteger(minutos) || minutos < 1 || minutos > 600) {
    errores.minutos = "Indica los minutos: un número entero entre 1 y 600";
  }
  if (campos.tipo === "running") {
    const km = Number(campos.km.replace(",", "."));
    if (campos.km.trim() === "" || Number.isNaN(km) || km <= 0 || km > 100) {
      errores.km = "Indica los kilómetros: un número mayor que 0";
    }
  }
  return errores;
}

export function FormEntreno({ onGuardar }: FormEntrenoProps) {
  const [campos, setCampos] = useState<Campos>(VACIO);
  const [errores, setErrores] = useState<Errores>({});

  function cambiar(campo: keyof Campos, valor: string) {
    setCampos((anteriores) => ({ ...anteriores, [campo]: valor }));
  }

  function enviar(evento: FormEvent<HTMLFormElement>) {
    evento.preventDefault();
    const encontrados = validar(campos);
    setErrores(encontrados);
    if (Object.keys(encontrados).length > 0) return;

    onGuardar({
      tipo: campos.tipo as Entreno["tipo"],
      minutos: Number(campos.minutos),
      km: campos.tipo === "running" ? Number(campos.km.replace(",", ".")) : null,
    });
    setCampos(VACIO);
  }

  return (
    <form onSubmit={enviar} noValidate>
      <p>
        <label htmlFor="tipo">Tipo: </label>
        <select id="tipo" value={campos.tipo} onChange={(e) => cambiar("tipo", e.target.value)}>
          <option value="running">Running</option>
          <option value="fuerza">Fuerza</option>
          <option value="yoga">Yoga</option>
        </select>
      </p>
      <p>
        <label htmlFor="minutos">Minutos: </label>
        <input
          id="minutos"
          inputMode="numeric"
          value={campos.minutos}
          onChange={(e) => cambiar("minutos", e.target.value)}
          aria-invalid={errores.minutos ? true : undefined}
          aria-describedby={errores.minutos ? "error-minutos" : undefined}
        />
        {errores.minutos && (
          <span id="error-minutos" role="alert" className="error">
            {" "}
            {errores.minutos}
          </span>
        )}
      </p>
      {campos.tipo === "running" && (
        <p>
          <label htmlFor="km">Kilómetros: </label>
          <input
            id="km"
            inputMode="decimal"
            value={campos.km}
            onChange={(e) => cambiar("km", e.target.value)}
            aria-invalid={errores.km ? true : undefined}
            aria-describedby={errores.km ? "error-km" : undefined}
          />
          {errores.km && (
            <span id="error-km" role="alert" className="error">
              {" "}
              {errores.km}
            </span>
          )}
        </p>
      )}
      <button type="submit">Guardar</button>
    </form>
  );
}
```

```tsx
  id: string;
  texto: string;
}

export function RegistroEntrenos() {
  const [guardados, setGuardados] = useState<Guardado[]>([]);
  return (
    <section className="tarjeta">

      <FormEntreno
        onGuardar={(e) =>
```

```text
Vacío:            Indica los minutos: un número entero entre 1 y 600 · Indica los kilómetros: un número mayor que 0
30 min y 5,5 km:  guardados: running · 30 min · 5.5 km · errores: 0 · campos vaciados
Fuerza:           el campo de kilómetros desaparece
700 minutos:      Indica los minutos: un número entero entre 1 y 600 · aria-invalid="true"
45 minutos:       guardados: running · 30 min · 5.5 km | fuerza · 45 min
```

Las decisiones del componente:

- **Un estado `campos` con todos los valores como texto**, que es como llegan de los inputs. Se convierten a números **solo al guardar**. Así, el usuario puede escribir `5,` sin que el campo "salte".
- **`cambiar(campo, valor)`** actualiza una sola propiedad con `[campo]: valor` (una propiedad calculada) sobre una copia del objeto (B6.3).
- **`validar` es una función pura**, fuera del componente: recibe los campos y devuelve los errores. Se puede probar sola (curso A3) y reutilizar.
- **`noValidate`** en el `<form>` desactiva los globos de validación del navegador, para mostrar tus mensajes de forma coherente.
- **Accesibilidad:** cada error tiene un `id`, y el campo apunta a él con `aria-describedby`; `aria-invalid` marca el campo erróneo; y `role="alert"` hace que los lectores de pantalla anuncien el mensaje en cuanto aparece.
- **`inputMode="numeric"` y `"decimal"`** muestran el teclado numérico en el móvil, sin las rarezas de `type="number"` (que acepta `e` y cambia el valor con la rueda del ratón).
- **`replace(",", ".")`** acepta la coma decimal que escribe cualquier persona en México o en España.

<Callout type="risk">

- **La validación del navegador no es seguridad:** cualquiera puede enviar datos a tu API sin pasar por el formulario (B3.3). Valida también en el servidor. Lo ideal es **un mismo esquema** compartido por el cliente y el servidor, que es lo que hace esta plataforma con Zod (`src/schemas/auth.ts`) y lo que verás en el curso I1.
- **Los campos que desaparecen conservan su valor:** al cambiar a "Fuerza", el campo de kilómetros se oculta, pero `campos.km` sigue teniendo lo que escribiste. Por eso `enviar` solo usa `km` si el tipo es running. Ten en cuenta los valores de campos ocultos al guardar.
- **Para formularios grandes, una librería ayuda:** con veinte campos, validación entre campos y envíos asíncronos, `react-hook-form` (la que usan el login y el registro de esta plataforma) ahorra mucho código. Pero entender cómo se hace a mano es lo que te permite usarla bien.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Crea `src/components/formularios/Registro.tsx`, un formulario de registro con nombre (mínimo 2 caracteres), correo (con formato válido) y contraseña (mínimo 8 caracteres).
2. Cada error debe aparecer **solo cuando el usuario sale del campo** (no mientras escribe por primera vez), y desaparecer en cuanto lo corrige.
3. El botón "Crear cuenta" debe estar deshabilitado mientras haya algún campo no válido.
4. Usa `useId` para que el formulario se pueda poner dos veces en la misma página sin `id` repetidos, y los `autoComplete` adecuados para que el gestor de contraseñas funcione.
5. Al enviar, muestra "Cuenta lista para crear: Nombre &lt;correo&gt;" (todavía sin llamar a ninguna API).

</Callout>

Solución. `src/components/formularios/Registro.tsx`:

```tsx
// Archivo: src/components/formularios/Registro.tsx
import { useId, useState, type FormEvent } from "react";

interface Campos {
  nombre: string;
  correo: string;
  contrasena: string;
}
type Campo = keyof Campos;

const CORREO = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

function validar({ nombre, correo, contrasena }: Campos): Partial<Record<Campo, string>> {
  const errores: Partial<Record<Campo, string>> = {};
  if (nombre.trim().length < 2) errores.nombre = "Mínimo 2 caracteres";
  if (!CORREO.test(correo.trim())) errores.correo = "Introduce un correo válido";
  if (contrasena.length < 8) errores.contrasena = "Mínimo 8 caracteres";
  return errores;
}

export function Registro() {
  const id = useId(); // prefijo único: el formulario se puede usar varias veces en la misma página
  const [campos, setCampos] = useState<Campos>({ nombre: "", correo: "", contrasena: "" });
  const [tocados, setTocados] = useState<Partial<Record<Campo, boolean>>>({});
  const [resultado, setResultado] = useState("");

  const errores = validar(campos); // se calcula en cada render: no es estado
  const valido = Object.keys(errores).length === 0;

  const cambiar = (campo: Campo, valor: string) => setCampos((a) => ({ ...a, [campo]: valor }));
  const tocar = (campo: Campo) => setTocados((a) => ({ ...a, [campo]: true }));

  function enviar(evento: FormEvent<HTMLFormElement>) {
    evento.preventDefault();
    if (!valido) return;
    setResultado(`Cuenta lista para crear: ${campos.nombre.trim()} <${campos.correo.trim().toLowerCase()}>`);
  }

  function campo(nombre: Campo, etiqueta: string, tipo: string, autoComplete: string) {
    const visible = tocados[nombre] && errores[nombre];
    return (
      <p>
        <label htmlFor={`${id}-${nombre}`}>{etiqueta}</label>
        <br />
        <input
          id={`${id}-${nombre}`}
          name={nombre}
          type={tipo}
          autoComplete={autoComplete}
          value={campos[nombre]}
          onChange={(e) => cambiar(nombre, e.target.value)}
          onBlur={() => tocar(nombre)}
          aria-invalid={visible ? true : undefined}
          aria-describedby={visible ? `${id}-${nombre}-error` : undefined}
        />
        {visible && (
          <span id={`${id}-${nombre}-error`} className="error" role="alert">
            {" "}
            {errores[nombre]}
          </span>
        )}
      </p>
    );
  }

  return (
    <form onSubmit={enviar} noValidate className="tarjeta">
      <h2 style={{ marginTop: 0 }}>Crear cuenta</h2>
      {campo("nombre", "Nombre", "text", "name")}
      {campo("correo", "Correo", "email", "email")}
      {campo("contrasena", "Contraseña", "password", "new-password")}
      <button type="submit" disabled={!valido}>
        Crear cuenta
      </button>
      {resultado && <p id="resultado">{resultado}</p>}
    </form>
  );
}
```

```text
Inicio                           → errores: [] · botón deshabilitado
Escribe «D» (sin salir)          → errores: [] · botón deshabilitado
Sale del nombre                  → errores: [Mínimo 2 caracteres] · botón deshabilitado
Correo «dani@» y sale            → errores: [Mínimo 2 caracteres | Introduce un correo válido] · botón deshabilitado
Corrige; contraseña de 4         → errores: [Mínimo 8 caracteres] · botón deshabilitado
Contraseña de 8                  → errores: [] · botón activo
resultado: Cuenta lista para crear: Dani <dani@ejemplo.com>
```

Las claves:

- **Los errores no son estado:** `validar(campos)` se calcula en cada render (B6.3). El único estado nuevo es `tocados`, que recuerda qué campos ha abandonado el usuario (`onBlur`). Un error se muestra si el campo está tocado **y** tiene error.
- **El botón usa `valido`**, que no depende de `tocados`: está deshabilitado desde el principio, aunque todavía no se vea ningún mensaje.
- **`useId()`** genera un prefijo único por cada uso del componente (aquí `_r1R_0_`, aunque el formato exacto puede cambiar entre versiones de React). Úsalo como prefijo, nunca lo escribas a mano en el código.
- **La función `campo(…)`** pinta los tres campos con la misma estructura sin repetir el JSX.
- **`autoComplete="new-password"`** le dice al gestor de contraseñas que proponga una nueva; `"email"` y `"name"` permiten el autocompletado. Es lo que hace el formulario de registro de esta plataforma.

<Callout type="risk">

- **Un botón deshabilitado no explica por qué:** si el usuario no sabe qué falta, se frustra. Por eso, aquí los errores aparecen al salir de cada campo. Otra opción común es dejar el botón siempre activo y, al pulsarlo, marcar todos los campos como tocados para mostrar todos los errores a la vez.
- **La expresión del correo es deliberadamente sencilla:** comprueba que hay algo, una `@` y un dominio con punto. Ninguna expresión regular valida de verdad un correo; la única comprobación real es enviar un correo de confirmación.
- **Nunca guardes la contraseña en `localStorage` ni la registres en la consola**, ni siquiera en desarrollo: viaja en el cuerpo de la petición (por HTTPS) y el servidor guarda solo su _hash_ (B3.4).

</Callout>

<Callout type="mastery">

Construyes un formulario con validación sin librerías: eliges entre controlado (`value` + `onChange`, el estado es el dueño) y no controlado (`defaultValue` + `name` + `FormData`), nunca empiezas un campo controlado con `undefined`, guardas los campos en un objeto y calculas los errores en cada render, y los muestras de forma accesible (`aria-invalid`, `aria-describedby`, `role="alert"`).

</Callout>

## Resumen

- Controlado: React es el dueño del valor (`value` + `onChange`). No controlado: el DOM es el dueño (`defaultValue`, y se lee con `FormData` por el `name`).
- `value` sin `onChange` deja el campo bloqueado; pasar de `undefined` a un texto mezcla los dos modos. Empieza siempre con `""`.
- Un formulario con varios campos: un estado con un objeto de textos, convertido a números solo al guardar, y `evento.preventDefault()` en `onSubmit`.
- Los errores se calculan con una función pura; `tocados` decide cuándo mostrarlos. Errores accesibles con `aria-invalid`, `aria-describedby` y `role="alert"`.
- `useId` para identificadores únicos y `autoComplete` para el gestor de contraseñas. La validación del cliente es comodidad; la seguridad está en el servidor.
