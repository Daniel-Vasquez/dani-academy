Casi todas las páginas mezclan lo que es igual para todos (el texto de una lección) con lo que es de una persona (si ya la leyó). Tratadas como un bloque, el texto espera a la base de datos o el dato espera a React. Aquí decides dónde vive cada trozo: el contenido en caché y el estado «leído» aparte, con un criterio para justificar cada isla.

**Requisitos:** _server islands_ (I3.1), directivas de cliente (B6.7), cabeceras de caché (A6) y Nginx (A4). Medido en un navegador real con Astro 7.4.7, `@astrojs/node` 11 y Nginx 1.28 en la VM de A4. La base de datos está **simulada** (un `Map` con espera fija) y Nginx está en la red local: sin CDN ni latencia de internet.

La «base de datos»:

```ts
// Archivo: src/lib/datos.ts
// Simula una base de datos: guarda en memoria y tarda 150 ms en responder
export const ajustes = { retardo: 150, fallo: false };

const leidas = new Map<string, Set<string>>();

async function consulta() {
  await new Promise((resuelve) => setTimeout(resuelve, ajustes.retardo));
  if (ajustes.fallo) throw new Error("La base de datos no responde");
}

export async function estaLeida(usuario: string, seccionId: string) {
  await consulta();
  return leidas.get(usuario)?.has(seccionId) ?? false;
}

export async function marcar(usuario: string, seccionId: string, leida: boolean) {
  await consulta();
  const conjunto = leidas.get(usuario) ?? new Set<string>();
  if (leida) conjunto.add(seccionId);
  else conjunto.delete(seccionId);
  leidas.set(usuario, conjunto);
}
```

<Callout type="risk">

- **No copies esta «sesión» a una app real:** cualquiera puede escribir la _cookie_ que quiera. Usa Better Auth (I5).
- **La espera fija de 150 ms no es una base real:** las cifras sirven para comparar formas, no para predecir tu app.

## Paso 2: todo en el servidor

**Qué es:** renderizar la página entera en cada petición.

**Cómo se usa:**

```astro
---
// Archivo: src/pages/ssr/[id].astro
// Toda la página se renderiza en cada petición
import Pagina from "../../layouts/Pagina.astro";
import { estaLeida } from "../../lib/datos";
import { seccionPorId } from "../../lib/secciones";

export const prerender = false;

const seccion = seccionPorId(Astro.params.id);
if (!seccion) return Astro.rewrite("/404");
const usuario = Astro.cookies.get("sesion")?.value;
const leida = usuario ? await estaLeida(usuario, seccion.id) : false;
---

<Pagina titulo={seccion.titulo}>
  <p id="estado" slot="estado">
    {usuario ? (leida ? `✓ Leída por ${usuario}` : `Sin leer por ${usuario}`) : "Entra"}
  </p>
</Pagina>
```

- **Simple y sin JavaScript,** pero el texto, igual para todos, espera a la consulta. Si falla, cae todo:

```text
base de datos caída: 500, y ningún párrafo en la respuesta
```

<Callout type="risk">

- **Un fallo en un dato secundario tumba la página entera:** sin `try/catch`, 500 y ningún párrafo.
- **No se puede cachear:** lleva datos de cada persona.

</Callout>

## Paso 3: todo en el cliente

**Qué es:** página estática y una isla que pide el dato al cargar.

**Cómo se usa:** la API:

```ts
// Archivo: src/pages/api/progreso/[id].ts
import type { APIRoute } from "astro";
import { estaLeida, marcar } from "../../../lib/datos";

export const prerender = false;

const sinCache = { "Content-Type": "application/json", "Cache-Control": "private, no-store" };

export const GET: APIRoute = async ({ params, cookies }) => {
  const usuario = cookies.get("sesion")?.value;
  if (!usuario) return new Response(null, { status: 401 });
  const leida = await estaLeida(usuario, params.id!);
  return new Response(JSON.stringify({ usuario, leida }), { headers: sinCache });
};

export const PUT: APIRoute = async ({ params, cookies }) => {
  const usuario = cookies.get("sesion")?.value;
  if (!usuario) return new Response(null, { status: 401 });
  await marcar(usuario, params.id!, true);
  return new Response(null, { status: 204 });
};

export const DELETE: APIRoute = async ({ params, cookies }) => {
  const usuario = cookies.get("sesion")?.value;
  if (!usuario) return new Response(null, { status: 401 });
  await marcar(usuario, params.id!, false);
  return new Response(null, { status: 204 });
};

// Un <form> sin JavaScript: guarda y vuelve a la página de origen
export const POST: APIRoute = async ({ params, cookies, request, redirect }) => {
  const usuario = cookies.get("sesion")?.value;
  if (!usuario) return new Response(null, { status: 401 });
  const datos = await request.formData();
  await marcar(usuario, params.id!, datos.get("leida") === "1");
  return redirect(request.headers.get("referer") ?? "/", 303);
};
```

La isla, con el _spinner_ de siempre:

```tsx
// Archivo: src/components/EstadoCliente.tsx
import { useEffect, useState } from "react";

export default function EstadoCliente({ seccionId }: { seccionId: string }) {
  const [texto, setTexto] = useState("Cargando…");
  useEffect(() => {
    fetch(`/api/progreso/${seccionId}`)
      .then((r) => r.json())
      .then((d) => setTexto(d.leida ? `✓ Leída por ${d.usuario}` : `Sin leer por ${d.usuario}`))
      .catch(() => setTexto("Progreso no disponible"));
  }, [seccionId]);
  return <p id="estado">{texto}</p>;
}
```

```astro
---
// Archivo: src/pages/spinner/[id].astro
// Página estática; la isla pide el dato al cargar
import EstadoCliente from "../../components/EstadoCliente";
import Pagina from "../../layouts/Pagina.astro";
import { rutasEstaticas } from "../../lib/secciones";

export const getStaticPaths = rutasEstaticas;
const { seccion } = Astro.props;
---

<Pagina titulo={seccion.titulo}>
  <EstadoCliente slot="estado" client:load seccionId={seccion.id} />
</Pagina>
```

- **La página llega enseguida,** pero para mostrar una frase has descargado React.

<Callout type="risk">

- **El _spinner_ añade peticiones** (7 frente a 2 de la _server island_, Paso 4) y un salto cuando llega el dato.
- **La API es pública por su URL:** valida la sesión en ella, no en la isla.

</Callout>

## Paso 4: la server island

**Qué es:** el periódico impreso para todos con una nota pegada: un componente de servidor que la página estática pide aparte con `server:defer`.

**Cómo se usa:** el componente lee la _cookie_ y consulta:

```astro
---
// Archivo: src/components/ProgresoUsuario.astro
import { estaLeida } from "../lib/datos";

const { seccionId } = Astro.props;
Astro.response.headers.set("Cache-Control", "private, no-store"); // lo que sigue es de una persona
const usuario = Astro.cookies.get("sesion")?.value;

let leida = false;
let fallo = false;
if (usuario) {
  try {
    leida = await estaLeida(usuario, seccionId);
  } catch {
    fallo = true;
  }
}
---

<p id="estado" style="min-height: 2rem">
  {
    !usuario
      ? "Entra para guardar tu progreso"
      : fallo
        ? "Progreso no disponible"
        : leida
          ? `✓ Leída por ${usuario}`
          : `Sin leer por ${usuario}`
  }
</p>
```

La página, estática:

```astro
---
// Archivo: src/pages/defer/[id].astro
// Página estática; solo el progreso se pide al servidor
import ProgresoUsuario from "../../components/ProgresoUsuario.astro";
import Pagina from "../../layouts/Pagina.astro";
import { rutasEstaticas } from "../../lib/secciones";

export const getStaticPaths = rutasEstaticas;
const { seccion } = Astro.props;
---

<Pagina titulo={seccion.titulo}>
  <ProgresoUsuario slot="estado" server:defer seccionId={seccion.id}>
    <p slot="fallback" style="min-height: 2rem">Cargando progreso…</p>
  </ProgresoUsuario>
</Pagina>
```

- **El HTML lleva el `fallback`** y un _script_ que pide `/_server-islands/ProgresoUsuario`. Con 150 ms de consulta, mediana de cinco cargas:

| Forma                  | TTFB   | LCP    | Dato visible | JS (gzip) |
| ---------------------- | ------ | ------ | ------------ | --------- |
| Todo en el servidor    | 154 ms | 176 ms | 160 ms       | 0         |
| Isla con dato (Paso 7) | 154 ms | 180 ms | 162 ms       | 70 KB     |
| Isla con _spinner_     | 1 ms   | 16 ms  | 181 ms       | 70 KB     |
| _Server island_        | 1 ms   | 16 ms  | 158 ms       | 0         |

Con una consulta de 800 ms:

| Forma               | LCP    | Dato visible |
| ------------------- | ------ | ------------ |
| Todo en el servidor | 824 ms | 804 ms       |
| Isla con _spinner_  | 16 ms  | 822 ms       |
| _Server island_     | 16 ms  | 800 ms       |

- **El dato tarda casi lo mismo en todas** (depende de la consulta); cambia qué hace la persona mientras.
- **La página en caché no espera a la base:** el LCP siguió en 16 ms con una consulta cinco veces más lenta, y la _server island_ no envía JavaScript de framework.
- **Si la base cae, la página sigue en pie:** el texto con 200 y la isla con `Progreso no disponible`, por el `try/catch`.

<Callout type="risk">

- **Da al `fallback` la altura final:** con `min-height`, CLS 0; sin él, 0,017, más cuanto más alta la isla. Sin `fallback`, no se ve nada hasta que llega.
- **Sin JavaScript, la isla no llega nunca** (`Cargando progreso…`): si el dato es imprescindible, en el servidor (Paso 2).

</Callout>

## Paso 5: la caché, y lo que puede salir mal

**Qué es:** el TTFB de 1 ms venía de Nginx en caché: lo que hace valer la pena todo, y lo más peligroso.

**Cómo se usa:** separa lo cacheable de lo demás:

```nginx
proxy_cache_path /var/cache/nginx/app keys_zone=app:1m max_size=50m inactive=5m use_temp_path=off;

server {
  # listen, server_name y TLS como en A4

  # Solo las páginas sin datos de nadie
  location ~ ^/defer/ {
    proxy_pass http://127.0.0.1:4390;
    proxy_cache app;
    proxy_cache_valid 200 1m;
    proxy_ignore_headers Cache-Control;
    proxy_set_header Host $http_host;
    add_header X-Cache $upstream_cache_status always;
  }

  # Todo lo demás, sin caché
  location / {
    proxy_pass http://127.0.0.1:4390;
    proxy_set_header Host $http_host;
  }
}
```

- **`proxy_ignore_headers`** porque Astro sirve las estáticas con `public, max-age=0` y Nginx no las guardaría: solo en esta ruta.

Primero entra `ana` (ya la leyó) y después `bob` (no). Lo que ve `bob`:

| Configuración                                | Lo que ve `bob`      |
| -------------------------------------------- | -------------------- |
| Separando rutas: página con `X-Cache: HIT`   | `Sin leer por bob` ✓ |
| Página SSR con `Cache-Control: public`       | `✓ Leída por ana` ✗  |
| Microcaché global, ignorando `Cache-Control` | `✓ Leída por ana` ✗  |
| Lo mismo, pero en la propia _server island_  | `✓ Leída por ana` ✗  |

- **La _server island_ tampoco está a salvo:** su URL es igual para todos y por defecto solo lleva `content-type: text/html`. Por eso `ProgresoUsuario.astro` declara su cabecera:

```astro
Astro.response.headers.set("Cache-Control", "private, no-store"); // lo que sigue es de una persona
```

- **Avisa a cualquier caché que la respete,** pero lo importante es el `location`: una regla que ignora `Cache-Control` no debe alcanzar nada personal.

<Callout type="risk">

- **Una caché compartida no conoce a tus usuarios:** con la URL como clave, Bob recibe lo de Ana; aquí un texto, pero podría ser su correo.
- **Comprueba con dos usuarios reales:** con uno, todo parece correcto.
- **Vacía la caché tras un cambio:** Nginx la conserva hasta que caduca.

</Callout>

## Paso 6: los límites de una server island

**Qué es:** tres comportamientos que sorprenden en producción.

**Cómo se usa:** **cada _build_ usa otra clave.** Las _props_ van cifradas, y una página en caché de la versión anterior pide su isla a un servidor que no puede descifrarla:

```text
misma build:                 200
build nueva, página antigua: 400
misma fuente, otra build:    400
```

- **Queda en `Cargando progreso…` para siempre,** con el 400 solo en la consola, en cada despliegue. Fija la clave:

```bash
npx astro create-key    # guarda el resultado como secreto
ASTRO_KEY=<tu-clave> npm run build
```

- **Con la misma `ASTRO_KEY` en dos _builds_, 200;** basta tenerla al compilar. Cambiarla exige vaciar la caché.

**No redirijas desde una isla:** la página ya se envió. `Astro.redirect` dio un 200 con esto **en mitad de tu página**:

```text
Internal server error
```

- **El `!usuario` de `ProgresoUsuario.astro` lo evita** con un aviso o un enlace. Y **`Astro.url` no es la página** (`/_server-islands/ProgresoUsuario`): pásala como _prop_ o lee `Referer`.

<Callout type="risk">

- **Las _props_ van cifradas** (no se vieron en claro, y manipuladas dieron 400), pero la URL se puede repetir: el usuario sale de la sesión, nunca de una _prop_. Con _props_ grandes (5000 caracteres) la petición pasa a `POST`, el HTML sube de 3,9 a 10,2 KB y no se cachea.
- **Tras un proxy, prueba `PUT` y `POST`:** sin `allowedDomains`, `403 Cross-site PUT form submissions are forbidden` (con `GET` no se notaba). Con TLS, `X-Forwarded-Proto` y repite la prueba (no medido).

</Callout>

## Paso 7: datos iniciales, sin _spinner_

**Qué es:** una isla de verdad (un botón que responde al momento) no obliga al _spinner_: el servidor le pasa el dato como _prop_.

**Cómo se usa:**

```tsx
// Archivo: src/components/BotonLeida.tsx
import { useState } from "react";

interface Props {
  seccionId: string;
  usuario: string;
  inicial: boolean;
}

export default function BotonLeida({ seccionId, usuario, inicial }: Props) {
  const [leida, setLeida] = useState(inicial);

  async function cambiar() {
    const siguiente = !leida;
    setLeida(siguiente); // se pinta ya, y se deshace si el servidor falla
    const r = await fetch(`/api/progreso/${seccionId}`, { method: siguiente ? "PUT" : "DELETE" });
    if (!r.ok) setLeida(!siguiente);
  }

  return (
    <button id="estado" type="button" onClick={cambiar}>
      {leida ? `✓ Leída por ${usuario}` : `Marcar como leída (${usuario})`}
    </button>
  );
}
```

```astro
---
// Archivo: src/pages/inicial/[id].astro
// El servidor consulta y la isla nace con el dato: sin spinner y sin petición extra
import BotonLeida from "../../components/BotonLeida";
import Pagina from "../../layouts/Pagina.astro";
import { estaLeida } from "../../lib/datos";
import { seccionPorId } from "../../lib/secciones";

export const prerender = false;

const seccion = seccionPorId(Astro.params.id);
if (!seccion) return Astro.rewrite("/404");
const usuario = Astro.cookies.get("sesion")?.value ?? "invitado";
const leida = await estaLeida(usuario, seccion.id);
---

<Pagina titulo={seccion.titulo}>
  <BotonLeida slot="estado" client:load seccionId={seccion.id} usuario={usuario} inicial={leida} />
</Pagina>
```

- **El dato viene en el HTML,** sin petición extra ni pantalla de carga: a los 162 ms, y visible sin JavaScript (la segunda fila del Paso 4). A cambio, la página no se cachea.
- **Se combina todo:** una isla de React **dentro** de una _server island_. Página en caché, consulta en el servidor y botón con su dato; un clic dio `PUT 204` y siguió al recargar. Es la solución del ejercicio.

<Callout type="risk">

- **Si la página es pública,** pasar datos personales como _prop_ los mete en un HTML que no debe cachearse.
- **El estado inicial puede quedar viejo:** tras un clic, confía en la respuesta del servidor, no solo en la _prop_.

</Callout>

## Paso 8: cuando React sobra

**Qué es:** muchas interacciones no necesitan un _framework_.

**Cómo se usa:** un índice plegable tres veces en la página, con React y con `<script>` nativo:

```astro
---
// Archivo: src/components/IndiceNativo.astro
const { titulo } = Astro.props;
---

<div>
  <button type="button" data-alternar aria-expanded="true">{titulo}</button>
  <ul data-panel>
    <li>Primer apartado</li>
    <li>Segundo apartado</li>
  </ul>
</div>

<script>
  document.querySelectorAll("[data-alternar]").forEach((boton) => {
    boton.addEventListener("click", () => {
      const abierto = boton.getAttribute("aria-expanded") === "true";
      boton.setAttribute("aria-expanded", String(!abierto));
      const panel = boton.nextElementSibling as HTMLElement;
      panel.hidden = abierto;
    });
  });
</script>
```

| Versión    | Archivos JS | Peso                      | Funciona |
| ---------- | ----------- | ------------------------- | -------- |
| `<script>` | 0           | 221 bytes dentro del HTML | Sí       |
| React      | 5           | 214 KB, unos 70 KB gzip   | Sí       |

- **Astro incluyó el `<script>` una vez,** aunque el componente aparezca tres, y también funcionó dentro de una _server island_.

Guardar un cambio con un formulario, que vuelve solo a la página:

```astro
---
// Archivo: src/components/ProgresoNativo.astro
import { estaLeida } from "../lib/datos";

const { seccionId } = Astro.props;
const usuario = Astro.cookies.get("sesion")?.value;
const leida = usuario ? await estaLeida(usuario, seccionId) : false;
---

{
  usuario && (
    <form method="post" action={`/api/progreso/${seccionId}`}>
      <input type="hidden" name="leida" value={leida ? "0" : "1"} />
      <button id="estado">{leida ? `✓ Leída por ${usuario}` : "Marcar como leída"}</button>
    </form>
  )
}
```

- **`POST` con 303 y el estado al volver,** aunque dentro de una _server island_ tampoco funciona sin JavaScript.
- **React compensa con estado que cambia a menudo** (editor, evaluación de varios pasos, actualización optimista), no para abrir y cerrar: `<details>` lo hace solo.

<Callout type="risk">

- **React se paga una vez por página:** con una isla, otra apenas pesa 0,3 KB; sin ninguna, la primera cuesta 70. La pregunta es si la página puede quedarse sin React.
- **Con _View Transitions_ (A6), un `<script>` no se repite:** escucha `astro:page-load` (no probado aquí).

</Callout>

## Paso 9: decidir

**Qué es:** dónde vive cada dato.

| El dato es…                                | Dónde vive                      |
| ------------------------------------------ | ------------------------------- |
| Igual para todos                           | HTML estático, en caché         |
| Personal, y la página es pública           | _Server island_                 |
| Personal e imprescindible                  | Servidor, sin caché             |
| Personal, e interactivo                    | Isla con dato inicial           |
| Solo del navegador, como un `localStorage` | `<script>` o isla, sin servidor |

**Cómo se usa:** auditando esta plataforma. Tiene `output: "server"` y **ninguna _server island_:** toda sección exige sesión, la comprobación va al servidor en cada petición y no hay página estática que proteger. Las secciones se renderizan en el servidor y las islas nacen con su dato.

- **`LoginForm` y `RegisterForm`, con `client:load`:** validación y errores, que son el fin de la página.
- **`Quiz`, con `client:load`:** estado de varios pasos.
- **`MarkAsReadButton`, con `client:visible`:** optimista, y al final de la página.
- **`NotesIsland`, con `client:idle`:** editor con autoguardado, que no es urgente.
- **`SidebarToggle`, con `client:load`:** discutible: solo abre un panel y podría ser un `<script>`, pero esas páginas ya cargan React. El tema, el índice lateral y el seguimiento de estudio son `<script>` nativos.

<Callout type="risk">

- **Estas cifras son del laboratorio:** no se ha medido la plataforma en producción.
- **Una isla «discutible» crece:** revisa cada `client:*` cuando una página deje de cargar React por otra razón.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

Rediseña la página de una sección para que el contenido sea cacheable y el estado "leído" llegue con una _server island_.

</Callout>

Solución, con un botón de verdad: la _server island_ consulta y la isla de React nace con el dato:

```astro
---
// Archivo: src/components/ProgresoInteractivo.astro
import { estaLeida } from "../lib/datos";
import BotonLeida from "./BotonLeida";

const { seccionId } = Astro.props;
Astro.response.headers.set("Cache-Control", "private, no-store");
```

## Resumen

- **Lo común se cachea y lo personal llega aparte.**
- **`server:defer`:** LCP de 176 a 16 ms sin JavaScript de _framework_, también con 800 ms de consulta; el dato no llega antes.
- **Con la base caída,** SSR da 500 y la _server island_ deja el texto.
- **`private, no-store` en cada isla personal** y `location` separados: si no, Bob vio los datos de Ana.
- **`ASTRO_KEY` fija,** sin `Astro.redirect` ni datos de usuario en _props_; sin JavaScript, la isla no llega.
- **Datos iniciales como _prop_,** sin _spinner_; `<script>` nativo: 221 bytes frente a 70 KB.
- **Sin página pública,** una _server island_ no aporta.
