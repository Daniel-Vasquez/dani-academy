Un sitio con contenido suele empezar con archivos sueltos leídos como se puede, hasta que un `orden: "2"` desordena el índice en producción. Una **colección de contenido** trata esos archivos como una tabla, con un esquema que fija sus campos y tipos. Aquí construyes un sitio de cursos en MDX con cada dato validado, ves qué errores rompen el _build_ y cuáles no, y cubres los segundos.

**Requisitos:** React intermedio (I2), Backend con Astro (I3) y TypeScript avanzado (A1). Medido con Astro 7.4.7, `@astrojs/mdx` 8.1.3 y `@astrojs/react` 7.1.4, en un Mac con Node 26; los tiempos dependen de la máquina.

## Paso 1: el proyecto

**Qué es:** un proyecto de Astro con MDX y React, y un `verificar` que comprueba tipos antes de compilar.

**Cómo se usa:**

```bash
mkdir contenido && cd contenido
npm init -y
npm pkg set type=module scripts.build="astro build" scripts.verificar="astro check && astro build"
npm i astro @astrojs/mdx @astrojs/react react react-dom
npm i -D @astrojs/check typescript @types/react
```

`astro.config.mjs`:

```js
import mdx from "@astrojs/mdx";
import react from "@astrojs/react";
import { defineConfig } from "astro/config";

export default defineConfig({ integrations: [mdx(), react()] });
```

`tsconfig.json`:

```json
{ "extends": "astro/tsconfigs/strict", "compilerOptions": { "jsx": "react-jsx", "jsxImportSource": "react" } }
```

<Callout type="risk">

- **`verificar` es `astro check && astro build`:** el Paso 6 muestra errores que solo ve `astro check`. Úsalo también en el CI (A7).
- **Fija las versiones:** los comportamientos medidos aquí son de las versiones de arriba.

</Callout>

## Paso 2: el esquema

**Qué es:** `src/content.config.ts`, el contrato de todo el contenido.

**Cómo se usa:**

```ts
// Archivo: src/content.config.ts
import { defineCollection, reference } from "astro:content";
import { file, glob } from "astro/loaders";
import { z } from "astro/zod";

const cursos = defineCollection({
  loader: file("src/content/cursos.json"),
  schema: z.object({
    titulo: z.string(),
    nivel: z.enum(["basico", "intermedio", "avanzado"]),
  }),
});

const secciones = defineCollection({
  // Lo que empieza por "_", sea archivo o carpeta, es un borrador
  loader: glob({
    pattern: ["**/*.mdx", "!**/_*.mdx", "!**/_*/**"],
    base: "./src/content/secciones",
  }),
  schema: z.object({
    titulo: z.string().min(1),
    curso: reference("cursos"),
    orden: z.number().int().positive(),
    minutos: z.number().int().positive().default(60),
    resumen: z.string().max(120),
  }),
});

export const collections = { cursos, secciones };
```

- **`file()`** lee un archivo con muchas entradas, cada una con su `id`; **`glob()`** lee muchos archivos, con el `id` sacado de la ruta.
- **`schema` es Zod:** lo que no cumple, no entra. **`.default(60)`** rellena `minutos`, que en tus páginas siempre es un número.
- **`reference("cursos")`** apunta a otra colección, como una clave foránea.

<Callout type="risk">

- **`z` se importa de `astro/zod`:** `import { z } from "astro:content"` funciona pero está obsoleto (9 avisos _hint_ de `astro check`, nada en el _build_).
- **El archivo es `src/content.config.ts`,** no `src/content/config.ts`: con el antiguo, `LegacyContentConfigError` te dice dónde moverlo.
- **`.max(120)` es una decisión de diseño:** si `resumen` va en una tarjeta, el esquema hace cumplir el límite.

</Callout>

## Paso 3: el contenido

**Qué es:** un JSON con los cursos y un MDX por sección, con sus datos en el _frontmatter_ (entre las líneas `---`).

**Cómo se usa:** `src/content/cursos.json`:

```json
[
  { "id": "git", "titulo": "Git desde cero", "nivel": "basico" },
  { "id": "docker", "titulo": "Docker", "nivel": "intermedio" }
]
```

`src/content/secciones/git/02-commits.mdx`:

```mdx
---
titulo: "Commits"
curso: git
orden: 2
resumen: "Una sección de prueba."
---

## Commits

Texto de la sección 2.
```

- **Crea también `git/01-que-es.mdx`, `git/10-ramas.mdx` y `docker/01-imagenes.mdx`,** con el mismo formato y su `orden`.

<Callout type="risk">

- **El `id` de cada curso en `cursos.json` es lo que referencia `curso:`** en cada sección: una errata no rompe el _build_ (Paso 6).
- **El nombre del archivo forma el `id`:** cambiarlo cambia la URL de la página.

</Callout>

## Paso 4: las páginas

**Qué es:** dos rutas dinámicas cuyas páginas decide `getStaticPaths`.

**Cómo se usa:** el índice de un curso:

```astro
---
// Archivo: src/pages/cursos/[curso]/index.astro
import { getCollection } from "astro:content";

export async function getStaticPaths() {
  const cursos = await getCollection("cursos");
  return cursos.map((curso) => ({ params: { curso: curso.id }, props: { curso } }));
}

const { curso } = Astro.props;
const secciones = await getCollection("secciones", ({ data }) => data.curso.id === curso.id);
secciones.sort((a, b) => a.data.orden - b.data.orden); // getCollection no garantiza el orden
---

<h1>{curso.data.titulo}</h1>
<ol>
  {
    secciones.map((s) => (
      <li>
        <a href={`/cursos/${curso.id}/${s.id.split("/").pop()}`}>{s.data.titulo}</a>
      </li>
    ))
  }
</ol>
```

Cada sección:

```astro
---
// Archivo: src/pages/cursos/[curso]/[seccion].astro
import { getCollection, getEntry, render } from "astro:content";

export async function getStaticPaths() {
  const secciones = await getCollection("secciones");
  return secciones.map((seccion) => ({
    params: { curso: seccion.data.curso.id, seccion: seccion.id.split("/").pop() },
    props: { seccion },
  }));
}

const { seccion } = Astro.props;
const curso = await getEntry(seccion.data.curso); // un reference se resuelve aquí
if (!curso) throw new Error(`La sección ${seccion.id} apunta a un curso que no existe`);

const { Content, headings } = await render(seccion);
---

<p>{curso.data.titulo} · {seccion.data.minutos} min</p>
<h1>{seccion.data.titulo}</h1>
<nav>{headings.map((h) => <a href={`#${h.slug}`}>{h.text}</a>)}</nav>
<Content />
```

| Función                              | Qué devuelve                         |
| ------------------------------------ | ------------------------------------ |
| `getCollection("secciones", filtro)` | Las entradas, todas o las filtradas  |
| `getEntry("cursos", "git")`          | Una entrada, o `undefined` si no hay |
| `render(entrada)`                    | `Content` y `headings`, entre otros  |

```bash
npm run verificar
```

```text
6 page(s) built
cursos/docker/01-imagenes  cursos/docker  cursos/git/01-que-es
cursos/git/02-commits  cursos/git/10-ramas  cursos/git
```

- **Seis páginas, y sabes por qué:** dos cursos y cuatro secciones. `headings` da el índice de la página con profundidad y `slug`; con tres títulos:

```json
[[2, "qué-es-git"], [3, "un-detalle"], [2, "otra-idea"]]
```

<Callout type="risk">

- **`getCollection` no garantiza el orden,** y `[1, 2, 10].sort()` da `1 10 2` (compara texto): ordena siempre tú con `(a, b) => a - b`.
- **El `id` incluye la carpeta** (`git/02-commits`, por eso `.split("/").pop()`) y se normaliza (`Dos Palabras.mdx` → `docker/dos-palabras`).
- **`slug` en el _frontmatter_ reemplaza el `id` entero** (`mis-commits`, sin `git/`): es un campo reservado.

</Callout>

## Paso 5: que el build se rompa

**Qué es:** lo que has ganado: un dato mal escrito detiene el _build_ con un mensaje útil.

**Cómo se usa:** quita `resumen` de `02-commits.mdx`:

```bash
npm run build
```

```text
[InvalidContentEntryDataError] secciones → git/02-commits data does not match collection schema.
  resumen: Required
  Location:
    src/content/secciones/git/02-commits.mdx:0:0
```

- **Código 1 y ninguna página:** colección, entrada, campo y problema. Otros errores, uno cada vez, también con código 1:

```text
orden: "2"
  orden: Expected type "number", received "string"

resumen de 130 caracteres
  resumen: Too big: expected string to have <=120 characters

"nivel": "facil" en cursos.json
  nivel: Invalid option: expected one of "basico"|"intermedio"|"avanzado"

comilla sin cerrar en el frontmatter
  Missing closing "quote at line 2, column 17
```

<Callout type="risk">

- **Se detiene en el primer error:** con dos archivos mal, avisa de uno. La ubicación `0:0` apunta al archivo, no a la línea (con YAML roto sí dio `2:16`).
- **Un campo fuera del esquema se descarta en silencio** (`autor: Dani`): con `z.strictObject({ … })`, `Unrecognized key: "autor"`.
- **`astro dev` es menos estricto ya arrancado:** registra `Failed to reload` y sigue sirviendo la versión anterior con 200.

</Callout>

## Paso 6: lo que el build deja pasar

**Qué es:** la parte que no suele contarse: cinco errores que terminaron con **código 0**, un despliegue en verde.

**Cómo se usa:**

| Error                                | Qué ocurrió                                                         |
| ------------------------------------ | ------------------------------------------------------------------- |
| `curso: gti`, un curso que no existe | Un `[ERROR]` en el registro, y la sección desapareció del índice    |
| `seccion.data.titullo` en la página  | Publicó un `<h1></h1>` vacío en cada sección                        |
| `getCollection("seciones")`          | Un `[WARN]`, y ninguna página de sección: solo quedaron los índices |
| Dos archivos con el mismo `slug`     | Un `[WARN]`, y `01-que-es` perdió su contenido                      |
| Una carpeta `_borradores/`           | Con el patrón `**/[^_]*.mdx`, se publicó el borrador `03-idea`      |

- **`reference` se valida, pero no detiene el _build_:** se publicó hasta `/cursos/gti/02-commits`. Tres defensas, dos ya en tu código.
- **1. Comprueba `getEntry`:** el `throw` del Paso 4 lo convierte en un fallo real:

```text
Error: La sección git/02-commits apunta a un curso que no existe
```

- **Código 1;** sin esa línea, 0.
- **2. Varios patrones de exclusión:** el `glob` del Paso 2 deja fuera `_borradores/` y `_04-idea.mdx`; el clásico solo mira el nombre del archivo.
- **3. `astro check` antes del _build_,** lo que hace `npm run verificar` y debería hacer tu CI:

```text
src/pages/cursos/[curso]/[seccion].astro:21:19 - error ts(2551): Property 'titullo' does not exist
```

- **Con esa errata, `astro build` dio 0 y `verificar` 1.** `astro check` también vio `"seciones"`, y genera los tipos solo: tras borrar `.astro/`, 0 errores sin `astro sync`.

<Callout type="risk">

- **Lee los `[WARN]` y `[ERROR]` del _build_ en verde:** tres de los cinco casos solo se ven ahí.
- **Dos `slug` iguales siguen sin detectarse:** `verificar` dio 0 y el `throw` no lo ve.

</Callout>

## Paso 7: componentes dentro del contenido

**Qué es:** MDX es Markdown que admite componentes.

**Cómo se usa:** `src/components/Contador.tsx`:

```tsx
// Archivo: src/components/Contador.tsx
import { useState } from "react";

export default function Contador({ inicio = 0 }: { inicio?: number }) {
  const [n, setN] = useState(inicio);
  return <button onClick={() => setN(n + 1)}>Pulsado {n} veces</button>;
}
```

`src/components/Aviso.astro`:

```astro
---
// Archivo: src/components/Aviso.astro
const { tipo = "nota" } = Astro.props;
---

<aside data-tipo={tipo}><slot /></aside>
```

En la sección, importados bajo el _frontmatter_:

```mdx
import Contador from "../../../components/Contador.tsx";
import Aviso from "../../../components/Aviso.astro";

## Commits

<Aviso tipo="riesgo">Texto con **negrita** dentro.</Aviso>

<Contador inicio={3} client:load />
```

- **El Markdown de dentro de `Aviso` se convierte** (`<strong>negrita</strong>`), y la directiva decide el JavaScript:

| `Contador`        | Página con el contador       | Resto de páginas |
| ----------------- | ---------------------------- | ---------------- |
| Sin directiva     | 0 KB, y el botón no responde | 0 KB             |
| Con `client:load` | 3 archivos, 69 KB con gzip   | 0 KB             |

- **Casi todo es React (unos 66 KB);** el componente, 0,4 KB. Sin directiva hay HTML del botón, y parece funcionar hasta que lo pulsas.

Para un componente que aparece en muchas secciones, desde la página:

```astro
<Content components={{ Aviso, h2: Aviso }} />
```

- **`<Aviso>` funcionó sin importar** y cada `## título` se dibujó con `Aviso`. Esta plataforma lo hace así: los bloques de riesgo son un componente que ninguna sección importa.

<Callout type="risk">

- **`client:load` no funciona con `components`** (`Expected a matching import for component "Contador"`): una isla se importa en el MDX. Sin importar, `Expected component "Contador" to be defined`, un buen error.
- **`<` y `{` significan algo:** `a <b` y `{clave: 1}` fallan, y `{2 + 2}` publica un `4`. Ponlos en código con comillas invertidas.
- **El `.mdx` ejecuta código:** trátalo como código fuente y revisa el de desconocidos.

</Callout>

## Paso 8: cuántos archivos aguanta

**Qué es:** la escala: 500 secciones de seis apartados, sin caché.

**Cómo se usa:**

| Ajuste              | Tres builds            |
| ------------------- | ---------------------- |
| Normal              | 2,59 s, 2,09 s, 2,05 s |
| `deferRender: true` | 2,21 s, 1,94 s, 2,03 s |

- **Unos 2 s para 506 páginas:** `deferRender`, opción del `glob`, queda en el ruido. Solo si tu _build_ tarda de verdad, midiendo varias veces.
- **Estas colecciones se resuelven en el _build_:** para datos que cambian a cada momento (CMS, inventario), colecciones _live_ en `src/live.config.ts`, no probadas aquí y sin MDX.

## Paso 9: un ejemplo real

**Qué es:** esta plataforma se construye así, y su [`src/content.config.ts`](https://github.com/Daniel-Vasquez/dani-academy/blob/main/src/content.config.ts) es público. Esta lección es una entrada de la colección `sections`.

**Cómo se usa:**

```ts
const sections = defineCollection({
  // Ignora archivos que empiecen por "_" (borradores)
  loader: glob({ pattern: "**/[^_]*.mdx", base: "./src/content/sections" }),
  schema: z.object({
    sectionId: z.string().regex(SECTION_ID_REGEX),
    course: reference("courses"),
    title: z.string(),
    order: z.number().int().positive(),
    minutes: z.number().int().positive().default(60),
    summary: z.string().max(220),
  }),
});
```

- **Las evaluaciones son otra colección, en YAML:** `glob` no se limita a MDX. Su esquema exige un número exacto de preguntas con `.length()` y cuatro opciones por pregunta: una incompleta no puede publicarse, sin tabla en ninguna base.
- **Usa el patrón simple,** el que deja pasar carpetas con `_` (Paso 6): aquí no hay ninguna.

<Callout type="risk">

- **Si algún día se añade una carpeta con `_`,** este patrón la publicaría: el ejemplo real tiene la misma trampa que el Paso 6.
- **`.length()` hace del número de preguntas parte del contrato:** cambiarlo exige revisar todas las evaluaciones a la vez.

</Callout>

Solución, sobre el proyecto de esta lección:

1. Añade el curso a `src/content/cursos.json`:


2. Crea un archivo por sección en `src/content/secciones/linux/`, con su contenido en Markdown:

```mdx

minutos: 45

Texto.
```

3. Compila:

```bash

```

```text
10 page(s) built
cursos/linux/01-la-terminal  cursos/linux/02-archivos  cursos/linux/03-procesos  cursos/linux
```

- **De 6 a 10 páginas sin tocar `src/pages/`:** un curso nuevo es contenido, no código.

4. Rómpelo a propósito con `orden: "2"` en `02-archivos.mdx`:

<Callout type="mastery">

Tu contenido tiene un esquema, y un error en el _frontmatter_ rompe el build con un mensaje que dice el archivo, el campo y el problema. También sabes qué errores no lo rompen, y `npm run verificar` junto al `throw` de `getEntry` cubren los que puedes cubrir. Añadir un curso es añadir archivos.

</Callout>

## Resumen

- **`src/content.config.ts`:** `file()`, `glob()` y un esquema Zod de `astro/zod`.
- **Rompen el _build_,** de uno en uno: campo que falta, tipo, longitud, enumeración y YAML roto.
- **`getCollection`, `getEntry` y `render`;** ordena siempre tú, con comparador.
- **No lo rompen:** `reference` a nada, errata en `data`, colección mal escrita, `slug` repetido y carpeta `_`.
- **Defensas:** `throw` con `getEntry`, patrones de exclusión y `astro check`.
- **React en MDX:** 69 KB solo en esa página con `client:load`; `components` no lo admite.
- **500 secciones en unos 2 s.**
