Una función útil (dame el primero, búscalo por `id`, pagina esta lista) la necesitas para entrenos, cursos y notas. Copiarla, usar `any` o usar `unknown` son malas salidas; los **genéricos** son la buena: una sola función que **recuerda el tipo** de lo que le pasas. Al terminar leerás firmas como `map<U>(callbackfn: (value: T) => U): U[]`.

**Requisitos:** el proyecto `ts-playground` de B1 (con `strict` y `noUncheckedIndexedAccess`). Todo I1 se trabaja en una carpeta nueva:

```bash
cd ts-playground
mkdir src/i1
```

## Paso 1: el problema que resuelven

**Qué es:** tres intentos de escribir "dame el primer elemento" sin genéricos, y por qué ninguno sirve.

**Cómo se usa:** crea `src/i1/01-sin-genericos.ts`.

```ts
// Archivo: src/i1/01-sin-genericos.ts
// Tres intentos de escribir "dame el primer elemento" sin genéricos

// 1. Una función por tipo: funciona, pero hay que duplicarla para cada tipo
function primerNumero(lista: number[]): number | undefined {
  return lista[0];
}
function primerTexto(lista: string[]): string | undefined {
  return lista[0];
}

// 2. any: una sola función, pero TypeScript deja de comprobar el resultado
function primeroAny(lista: any[]): any {
  return lista[0];
}

// 3. unknown: segura, pero el resultado no sirve sin comprobarlo a mano
function primeroUnknown(lista: unknown[]): unknown {
  return lista[0];
}

const km = [5.2, 10, 21.1];

const a = primerNumero(km);
const b = primeroAny(km);
const c = primeroUnknown(km);

console.log(primerTexto(["fuerza", "running"]));
console.log(a?.toFixed(1));
console.log(b.toUpperCase()); // compila… y explota al ejecutar
console.log(c);
```

```bash
npm run typecheck
npm start -- src/i1/01-sin-genericos.ts
```

`typecheck` no da errores, pero al ejecutar:

```text
fuerza
5.2
TypeError: b.toUpperCase is not a function
```

- **Una función por tipo** (`primerNumero`, `primerTexto`) está bien tipada, pero el cuerpo es idéntico: diez tipos, diez copias.
- **Con `any`, TypeScript deja de comprobar:** `b` es un número, `b.toUpperCase()` compila y explota al ejecutar.
- **Con `unknown`, la función "olvida" el tipo.** Añade `console.log(c.toFixed(1));` al final y ejecuta `npm run typecheck` (luego bórralo):

```text
src/i1/01-sin-genericos.ts(32,13): error TS18046: 'c' is of type 'unknown'.
```

<Callout type="risk">

- **`any` es contagioso:** todo lo que toca también es `any`. Un solo `any` en una utilidad puede desactivar la comprobación en media aplicación.
- **`unknown` es correcto cuando de verdad no sabes qué llega** (un `JSON.parse`, el cuerpo de una petición; I1.4). El error es usarlo cuando sí sabes el tipo.

</Callout>

## Paso 2: tu primera función genérica

**Qué es:** **`<T>`** tras el nombre declara un **parámetro de tipo**: igual que `lista` recibe un valor, `T` recibe un tipo. La firma de `primero` dice "devuelvo uno de los elementos de la lista que me pasaste, o `undefined`".

**Cómo se usa:** crea `src/i1/01-genericos.ts`.

```ts
// Archivo: src/i1/01-genericos.ts

// <T> es un parámetro de TIPO: se decide en cada llamada, como un argumento normal
function primero<T>(lista: T[]): T | undefined {
  return lista[0];
}

const km = [5.2, 10, 21.1];
const tipos = ["fuerza", "running"];

const a = primero(km); // T = number  → number | undefined
const b = primero(tipos); // T = string  → string | undefined
const c = primero<string>([]); // T explícito: la lista vacía no da pistas

console.log(a?.toFixed(1));
console.log(b?.toUpperCase());
console.log(c ?? "(lista vacía)");

// Varios parámetros de tipo: el resultado combina los dos
function par<A, B>(primero: A, segundo: B): [A, B] {
  return [primero, segundo];
}

const p = par("running", 10); // [string, number]
console.log(p[0].length, p[1].toFixed(2));
```

```bash
npm run typecheck
npm start -- src/i1/01-genericos.ts
```

```text
5.2
FUERZA
(lista vacía)
7 10.00
```

- **Inferencia:** en `primero(km)`, TypeScript deduce `T = number` (pasa el ratón por `a`: `number | undefined`). Con `tipos`, `T = string`, y `b?.toUpperCase()` es válido.
- **Tipo explícito solo sin pistas:** `primero<string>([])`.
- **Varios parámetros:** `par<A, B>` devuelve `[A, B]`; en `par("running", 10)`, `p[0]` es `string` y `p[1]`, `number`.

<Callout type="risk">

- **No escribas `<T>` al llamar si se infiere:** `primero<number>(km)` es una línea más que actualizar si cambia `km`.
- **Un genérico que no conecta nada sobra:** `function log<T>(x: T): void` no gana nada frente a `(x: unknown)`. `T` vale la pena si une entrada y salida.
- **Los genéricos no existen al ejecutar:** dentro de `primero` no puedes preguntar si `T` es número.

</Callout>

## Paso 3: restricciones con `extends` y valores por defecto

**Qué es:** **`T extends { id: string }`** significa "T puede ser cualquier tipo, **siempre que** tenga un `id` de texto". Pone un **mínimo**, y el tipo completo viaja hasta el resultado. **`<T = string>`** da un valor por defecto.

**Cómo se usa:** crea `src/i1/01-restricciones.ts`.

```ts
// Archivo: src/i1/01-restricciones.ts

interface Entreno {
  id: string;
  tipo: "fuerza" | "running";
  minutos: number;
}

interface Curso {
  id: string;
  titulo: string;
}

// T puede ser cualquier tipo… siempre que tenga una propiedad id de tipo string
function porId<T extends { id: string }>(lista: T[], id: string): T | undefined {
  return lista.find((x) => x.id === id);
}

const entrenos: Entreno[] = [
  { id: "e1", tipo: "fuerza", minutos: 45 },
  { id: "e2", tipo: "running", minutos: 30 },
];
const cursos: Curso[] = [{ id: "B1", titulo: "TypeScript desde cero" }];

const entreno = porId(entrenos, "e2"); // Entreno | undefined (no { id: string })
const curso = porId(cursos, "B1"); // Curso | undefined

console.log(entreno?.tipo, entreno?.minutos);
console.log(curso?.titulo);

// Restricción con un tipo primitivo: cualquier cosa con .length
function masLargo<T extends { length: number }>(a: T, b: T): T {
  return b.length > a.length ? b : a;
}
console.log(masLargo("fuerza", "running"));
console.log(masLargo([1, 2], [1, 2, 3]));

// Valor por defecto del parámetro de tipo: si no se indica, T = string
interface Respuesta<T = string> {
  ok: boolean;
  datos: T;
}
const texto: Respuesta = { ok: true, datos: "guardado" };
const numero: Respuesta<number> = { ok: true, datos: 3 };
console.log(texto.datos.toUpperCase(), numero.datos + 1);
```

```bash
npm run typecheck
npm start -- src/i1/01-restricciones.ts
```

```text
running 30
TypeScript desde cero
running
[ 1, 2, 3 ]
GUARDADO 4
```

- **`porId(entrenos, "e2")` devuelve `Entreno | undefined`,** no `{ id: string } | undefined`: por eso lees `entreno?.minutos`.
- **`Respuesta` a secas es `Respuesta<string>`;** `Respuesta<number>` lo cambia.

Añade estas líneas para incumplir la restricción (y bórralas después):

```ts
const numeros = [1, 2, 3];
porId(numeros, "1");
masLargo(10, 20);
```

```text
src/i1/01-restricciones.ts(48,7): error TS2345: Argument of type 'number[]' is not assignable to parameter of type '{ id: string; }[]'.
  Type 'number' is not assignable to type '{ id: string; }'.
src/i1/01-restricciones.ts(49,10): error TS2345: Argument of type 'number' is not assignable to parameter of type '{ length: number; }'.
```

- **Los números no tienen `id` ni `length`:** el error sale **en la llamada**, diciendo qué falta.

<Callout type="risk">

- **`extends` aquí no es herencia:** significa "es asignable a". Lo cumple cualquier objeto con un `id` de texto.
- **Restringe lo mínimo:** `T extends Entreno` solo serviría para entrenos. Pide lo que la función usa.
- **En funciones, la inferencia gana al valor por defecto:** los valores por defecto sirven sobre todo en interfaces y tipos.

</Callout>

## Paso 4: interfaces y tipos genéricos

**Qué es:** las interfaces y los alias de tipo también tienen parámetros: describes **una vez** "una página de resultados" o "una operación que puede fallar", sea cual sea el dato.

**Cómo se usa:** crea `src/i1/01-tipos-genericos.ts`.

```ts
// Archivo: src/i1/01-tipos-genericos.ts

// Una página de resultados de CUALQUIER cosa: entrenos, cursos, notas…
interface Paginado<T> {
  items: T[];
  total: number;
  pagina: number;
  paginas: number;
}

// El resultado de una operación que puede fallar, con el dato tipado si sale bien
type Resultado<T> = { ok: true; datos: T } | { ok: false; error: string };

interface Entreno {
  id: string;
  tipo: "fuerza" | "running";
  minutos: number;
}

function paginar<T>(lista: T[], pagina: number, porPagina = 2): Paginado<T> {
  const inicio = (pagina - 1) * porPagina;
  return {
    items: lista.slice(inicio, inicio + porPagina),
    total: lista.length,
    pagina,
    paginas: Math.max(1, Math.ceil(lista.length / porPagina)),
  };
}

function buscar<T extends { id: string }>(lista: T[], id: string): Resultado<T> {
  const encontrado = lista.find((x) => x.id === id);
  return encontrado ? { ok: true, datos: encontrado } : { ok: false, error: `No existe ${id}` };
}

const entrenos: Entreno[] = [
  { id: "e1", tipo: "fuerza", minutos: 45 },
  { id: "e2", tipo: "running", minutos: 30 },
  { id: "e3", tipo: "running", minutos: 50 },
];

const pagina2 = paginar(entrenos, 2); // Paginado<Entreno>
console.log(`Página ${pagina2.pagina} de ${pagina2.paginas}:`, pagina2.items.map((e) => e.id));

for (const id of ["e3", "e9"]) {
  const r = buscar(entrenos, id); // Resultado<Entreno>
  if (r.ok) {
    console.log(`${id}: ${r.datos.tipo}, ${r.datos.minutos} min`); // r.datos solo existe si ok
  } else {
    console.log(`${id}: ${r.error}`);
  }
}
```

```bash
npm run typecheck
npm start -- src/i1/01-tipos-genericos.ts
```

```text
Página 2 de 2: [ 'e3' ]
e3: running, 50 min
e9: No existe e9
```

- **`Paginado<T>`:** cualquier endpoint que pagine devuelve la misma forma; `paginar(entrenos, 2).items` es `Entreno[]`.
- **`Resultado<T>`** es una unión discriminada (B1.6): dentro de `if (r.ok)`, `r.datos` existe y es un `Entreno`. Comprueba que el compilador obliga a mirar `ok` (y borra las líneas después):

```ts
const r = buscar(entrenos, "e1");
console.log(r.datos.minutos);
```

```text
src/i1/01-tipos-genericos.ts(54,15): error TS2339: Property 'datos' does not exist on type 'Resultado<Entreno>'.
  Property 'datos' does not exist on type '{ ok: false; error: string; }'.
```

- **Frente a devolver `null`,** el compilador no deja olvidar el error. Volverás a este patrón en I1.5.

<Callout type="risk">

- **Las uniones solo se escriben con `type`;** para formas de objeto, `interface` o `type` valen igual.
- **Paginar en memoria solo vale para listas pequeñas:** con miles de documentos, se pagina en la consulta (`skip` y `limit`, o por cursor). `Paginado<T>` no cambia.

</Callout>

## Paso 5: genéricos que ya usabas sin saberlo

**Qué es:** `Promise<T>`, `Array<T>`, `useState<T>` y `collection<T>` son genéricos: el tipo entre `< >` **protege todo lo que entra y sale**.

**Cómo se usa:** crea `src/i1/01-ya-los-usas.ts`.

```ts
// Archivo: src/i1/01-ya-los-usas.ts
// Genéricos de la librería estándar que usas a diario

// Array<T> es lo mismo que T[]
const minutos: Array<number> = [45, 30, 50];

// map<U> devuelve U[]: aquí U = string
const etiquetas = minutos.map((m) => `${m} min`);

// Map<K, V>: claves de un tipo y valores de otro
const porTipo = new Map<string, number>();
porTipo.set("running", 80);
porTipo.set("fuerza", 45);

// Promise<T>: una promesa que, al resolverse, contiene un T
function esperar<T>(valor: T, ms: number): Promise<T> {
  return new Promise((resolve) => setTimeout(() => resolve(valor), ms));
}

const total = await esperar(minutos.reduce((a, b) => a + b, 0), 100); // number

// Promise.all conserva el tipo de cada posición: [string, number]
const [nombre, km] = await Promise.all([esperar("Dani", 50), esperar(21.1, 80)]);

console.log(etiquetas);
console.log(porTipo.get("running") ?? 0);
console.log(`${nombre}: ${total} min, ${km.toFixed(1)} km`);
```

```bash
npm start -- src/i1/01-ya-los-usas.ts
```

```text
[ '45 min', '30 min', '50 min' ]
80
Dani: 125 min, 21.1 km
```

- **`Array<number>` es `number[]`;** `Map<string, number>` tiene un tipo para claves y otro para valores.
- **`await` sobre `Promise<T>` da un `T`,** y `Promise.all` conserva el tipo de cada posición: `nombre` es `string` y `km`, `number`.

Instala MongoDB y React solo para comprobar tipos:

```bash
npm install mongodb react
npm install --save-dev @types/react
```

Crea `src/i1/01-librerias.ts`:

```ts
// Archivo: src/i1/01-librerias.ts
// Solo para comprobar tipos (npm run typecheck): no se ejecuta
import type { Collection } from "mongodb";
import { useState } from "react";

interface Entreno {
  tipo: "fuerza" | "running";
  minutos: number;
  fecha: Date;
}

// MongoDB: collection<T> tipa lo que entra y lo que sale de la colección
export async function ultimoEntreno(col: Collection<Entreno>) {
  await col.insertOne({ tipo: "running", minutos: 30, fecha: new Date() });
  const doc = await col.findOne({ tipo: "running" }); // WithId<Entreno> | null
  return doc?.minutos;
}

// React: useState<T> tipa el estado y su función de actualización
export function useEntrenos() {
  const [lista, setLista] = useState<Entreno[]>([]);
  const añadir = (e: Entreno) => setLista((prev) => [...prev, e]);
  return { lista, añadir };
}
```

`npm run typecheck` pasa. Cambia `tipo: "running"` por `tipo: "natacion"` en `insertOne` y añade `setLista([{ tipo: "running", minutos: "30" }]);` bajo `añadir` (deshazlo después):

```text
src/i1/01-librerias.ts(14,25): error TS2322: Type '"natacion"' is not assignable to type '"fuerza" | "running"'.
src/i1/01-librerias.ts(23,32): error TS2322: Type 'string' is not assignable to type 'number'.
```

- **MongoDB rechaza el tipo inventado y el estado rechaza minutos como texto:** es lo que aportan `collection<Entreno>` y `useState<Entreno[]>`.

<Callout type="risk">

- **`useState([])` sin tipo infiere `never[]`:** al guardar algo, `is not assignable to type 'never'`. Con estado inicial vacío o `null`, `useState<Entreno[]>([])` o `useState<Entreno | null>(null)`.
- **`collection<T>` no valida la base de datos,** solo tu código. Un documento insertado desde Compass sale tipado como `Entreno` y miente: para eso `$jsonSchema` (B5) y Zod (I1.4).
- **`collection` sin tipo usa `Document`:** todo es `any`, y se pierde la comprobación de la capa de datos.

</Callout>

## Paso 6: leer la firma genérica de una librería

**Qué es:** el objetivo real de la sección: abrir los tipos de una librería y entenderlos.

**Cómo se usa:** `Cmd` + clic (o `Ctrl` + clic) sobre `.map` en `01-ya-los-usas.ts` abre `lib.es5.d.ts` en esta línea:

```ts
map<U>(callbackfn: (value: T, index: number, array: T[]) => U, thisArg?: any): U[];
```

- **`map<U>`** tiene su propio parámetro, `U`; `T` es el de los elementos, declarado en `interface Array<T>`.
- **`callbackfn: (value: T, ...) => U`** convierte cada `T` en un `U`, y **`: U[]`** devuelve la lista de `U`. Por eso ``minutos.map((m) => `${m} min`)`` es `string[]`.

Dos firmas más:

```ts
// React (@types/react): el estado S y su función de actualización
function useState<S>(initialState: S | (() => S)): [S, Dispatch<SetStateAction<S>>];

// MongoDB: TSchema debe ser un documento; si no lo indicas, es Document
collection<TSchema extends Document = Document>(name: string, options?: CollectionOptions): Collection<TSchema>;
```

- **`useState`** acepta un valor (o una función que lo calcula) y devuelve la tupla estado-actualizador. **`collection`** tiene restricción (`extends Document`) y valor por defecto (`= Document`), los dos del Paso 3.

<Callout type="risk">

- **Las firmas reales tienen ruido** (sobrecargas, `thisArg?: any`, `readonly`): busca primero lo que va entre `< >` y sigue por dónde entra y sale.
- **Pasar el ratón sobre una llamada** muestra la firma con los tipos ya sustituidos (`map<string>(…): string[]`): más fácil de leer.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Escribe `agruparPor<T, K extends keyof T>(lista: T[], clave: K): Record<string, T[]>` en `src/i1/01-ejercicio.ts`.
2. Úsala para agrupar una lista de entrenos por `tipo` y muestra, para cada grupo, cuántos entrenos hay y los minutos totales.
3. Agrúpalos también por `semana`, y usa la misma función con una lista de cursos agrupada por `nivel`.
4. Comprueba que `agruparPor(entrenos, "color")` no compila.

</Callout>

`K extends keyof T` adelanta la sección siguiente: `keyof T` es la unión de los nombres de las propiedades de `T`, así que `K` solo puede ser una que exista.

Solución completa, `src/i1/01-ejercicio.ts`:

```ts
// Archivo: src/i1/01-ejercicio.ts

interface Entreno {
  id: string;
  tipo: "fuerza" | "running" | "movilidad";
  minutos: number;
  semana: number;
}

/**
 * Agrupa una lista por el valor de una de sus propiedades.
 * K extends keyof T: la clave tiene que ser una propiedad que T tenga de verdad.
 */
function agruparPor<T, K extends keyof T>(lista: T[], clave: K): Record<string, T[]> {
  const grupos: Record<string, T[]> = {};
  for (const item of lista) {
    const valor = String(item[clave]); // item[clave] es de tipo T[K]; como clave de objeto, texto
    (grupos[valor] ??= []).push(item);
  }
  return grupos;
}

const entrenos: Entreno[] = [
  { id: "e1", tipo: "fuerza", minutos: 45, semana: 40 },
  { id: "e2", tipo: "running", minutos: 30, semana: 40 },
  { id: "e3", tipo: "running", minutos: 50, semana: 41 },
  { id: "e4", tipo: "movilidad", minutos: 20, semana: 41 },
  { id: "e5", tipo: "running", minutos: 35, semana: 41 },
];

const porTipo = agruparPor(entrenos, "tipo");
for (const [tipo, lista] of Object.entries(porTipo)) {
  const total = lista.reduce((suma, e) => suma + e.minutos, 0);
  console.log(`${tipo.padEnd(10)} ${lista.length} entrenos, ${total} min`);
}

const porSemana = agruparPor(entrenos, "semana");
console.log(Object.keys(porSemana)); // las claves de un objeto siempre son texto

// La misma función sirve para cualquier lista, sin escribirla otra vez
const cursos = [
  { id: "B1", nivel: "basico" },
  { id: "I1", nivel: "intermedio" },
  { id: "B2", nivel: "basico" },
];
console.log(agruparPor(cursos, "nivel"));
```

```bash
npm run typecheck
npm start -- src/i1/01-ejercicio.ts
```

```text
fuerza     1 entrenos, 45 min
running    3 entrenos, 115 min
movilidad  1 entrenos, 20 min
[ '40', '41' ]
{
  basico: [ { id: 'B1', nivel: 'basico' }, { id: 'B2', nivel: 'basico' } ],
  intermedio: [ { id: 'I1', nivel: 'intermedio' } ]
}
```

Con `agruparPor(entrenos, "color");` al final:

```text
src/i1/01-ejercicio.ts(47,22): error TS2345: Argument of type '"color"' is not assignable to parameter of type 'keyof Entreno'.
```

- **`item[clave]` es de tipo `T[K]`,** el de esa propiedad. Las claves de un objeto son texto, así que se convierte con `String()`: las semanas salen como `'40'` y `'41'`.
- **`(grupos[valor] ??= []).push(item)`** crea el grupo si falta; con `noUncheckedIndexedAccess`, `??=` resuelve el `undefined`.
- **La misma función agrupa entrenos y cursos** sin cambiar una línea.

<Callout type="risk">

- **`String()` mezcla valores:** `1` y `"1"` caen en el mismo grupo. Si importa, un `Map<T[K], T[]>`.
- **`Object.groupBy` ya existe** (con `"lib": ["ES2024"]`): en un proyecto real, usa la función estándar.
- **`Record<string, T[]>` dice que cualquier texto es clave,** pero `porTipo["natacion"]` no existe; `noUncheckedIndexedAccess` obliga a comprobarlo.

</Callout>

## Resumen

- `<T>` es un parámetro de tipo: la función recuerda el tipo en vez de perderlo (`any`) u ocultarlo (`unknown`).
- `T` se infiere de los argumentos; a mano solo sin pistas.
- `extends` pone un mínimo sin perder el tipo; `<T = string>`, un valor por defecto.
- `Paginado<T>` y `Resultado<T>`: interfaces y tipos genéricos.
- `Promise<T>`, `Map<K, V>`, `useState<S>` y `collection<T>` protegen lo que entra y sale.
