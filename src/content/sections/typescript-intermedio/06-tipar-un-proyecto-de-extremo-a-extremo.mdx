Un dato viaja del formulario al _endpoint_, a MongoDB y de vuelta, y en cada salto puede deformarse. Aquí construyes ese viaje con **un solo esquema** como fuente de verdad: si cambias un campo, el compilador te lleva por todos los sitios que deben cambiar.

**Requisitos:** I1.1–I1.5, un MongoDB (el de B5: Atlas o local) y las islas de React en Astro (B6.7).

## Paso 1: el proyecto y dónde vive cada tipo

**Qué es:** la organización de carpetas responde a **quién puede importar cada archivo**.

| Carpeta           | Contenido                             | Quién lo importa                                       |
| ----------------- | ------------------------------------- | ------------------------------------------------------ |
| `src/schemas/`    | Esquemas de Zod y tipos derivados     | Servidor **y** cliente: es el contrato compartido      |
| `src/server/`     | Acceso a MongoDB                      | Solo el servidor (_endpoints_, páginas)                |
| `src/lib/`        | Utilidades (`mongo.ts`, `errores.ts`) | `mongo.ts`, solo el servidor; `errores.ts`, cualquiera |
| `src/components/` | Componentes de React                  | El cliente (y Astro, al renderizar)                    |

**Cómo se usa:** crea el proyecto.

```bash
npm create astro@latest entrenos-app -- --template minimal --install --no-git --yes
cd entrenos-app
npx astro add react --yes
npm install mongodb zod
npm install --save-dev @types/node @astrojs/check typescript
mkdir -p src/schemas src/server src/lib src/components src/pages/api scripts
```

Y `src/lib/errores.ts`, el final de I1.5 (solo cambia el comentario de la primera línea):

```ts
// Archivo: src/lib/errores.ts (el de I1.5)
// Solo declaraciones: importar este módulo no ejecuta nada
import { z } from "zod";

// Clase base: un error con su código HTTP
export class HttpError extends Error {
  constructor(
    public readonly status: number,
    message: string,
    options?: ErrorOptions, // { cause }: el error original que lo provocó
  ) {
    super(message, options);
    this.name = new.target.name; // "NoEncontradoError", etc., sin repetirlo en cada subclase
  }
}

export class NoEncontradoError extends HttpError {
  constructor(recurso: string, id: string) {
    super(404, `${recurso} ${id} no existe`);
  }
}

export class NoAutorizadoError extends HttpError {
  constructor(message = "Inicia sesión para continuar") {
    super(401, message);
  }
}

export class ConflictoError extends HttpError {
  constructor(message: string, options?: ErrorOptions) {
    super(409, message, options);
  }
}

/** Datos que no cumplen el esquema: lleva los errores por campo para el formulario */
export class ValidacionError extends HttpError {
  constructor(
    public readonly campos: Record<string, string[] | undefined>,
    message = "Revisa los datos del formulario",
  ) {
    super(422, message);
  }

  static desdeZod(error: z.ZodError): ValidacionError {
    return new ValidacionError(z.flattenError(error).fieldErrors);
  }
}

/** Valida un dato externo y devuelve su tipo, o lanza un ValidacionError con los errores por campo */
export function validar<T>(esquema: z.ZodType<T>, dato: unknown): T {
  const resultado = esquema.safeParse(dato);
  if (!resultado.success) throw ValidacionError.desdeZod(resultado.error);
  return resultado.data;
}

/** El único punto que convierte cualquier error en una respuesta HTTP */
export function aRespuesta(e: unknown): Response {
  if (e instanceof ValidacionError) {
    return Response.json({ error: e.message, campos: e.campos }, { status: e.status });
  }
  if (e instanceof HttpError) {
    return Response.json({ error: e.message }, { status: e.status });
  }
  if (e instanceof z.ZodError) {
    // Un parse() que se escapó: también es culpa de los datos, no del servidor
    return aRespuesta(ValidacionError.desdeZod(e));
  }
  // Cualquier otra cosa es un fallo nuestro: se registra entero y al cliente no se le cuenta nada
  console.error("[api] Error no controlado:", e);
  return Response.json({ error: "Error interno" }, { status: 500 });
}
```

<Callout type="risk">

- **React nunca importa de `src/server/` ni de `mongo.ts`:** Astro enviaría el _driver_ al navegador, y en el peor caso tu cadena de conexión. `astro:env/server` hace fallar el build si un archivo del cliente lo importa.
- **`src/schemas/` debe ser puro:** solo Zod y tipos. Un esquema que importa `db` ya no sirve en el cliente.
- **El `.env` nunca va a Git:** el `.gitignore` de Astro lo excluye; compruébalo antes del primer commit (B2).

</Callout>

## Paso 2: el esquema compartido, el contrato

**Qué es:** **dos esquemas**, uno por dirección del viaje. **`EntrenoSchema`** es lo que **entra**: usa `z.coerce` porque los `<input>` dan texto y `vacioComoAusente` para que `""` no sea `0` (I1.4); su `.refine()` dice que solo el running lleva km. **`EntrenoDTOSchema`** es lo que **sale**: los mismos `campos` más `id` y `creado`. Un DTO (_Data Transfer Object_) es la forma pensada para viajar al cliente.

**Cómo se usa:** crea `src/schemas/entreno.ts`, del que se deriva todo lo demás.

```ts
// Archivo: src/schemas/entreno.ts
// La única fuente de verdad: la usan el formulario (cliente), el endpoint y la base de datos (servidor)
import { z } from "zod";

export const TIPOS_ENTRENO = ["fuerza", "running", "movilidad"] as const;

// Un campo de formulario vacío ("") significa "no lo he rellenado", no 0
const vacioComoAusente = (v: unknown) => (v === "" ? undefined : v);

// Campos comunes a la entrada y al DTO
const campos = {
  tipo: z.enum(TIPOS_ENTRENO, "Elige un tipo de entreno"),
  minutos: z.coerce.number("Indica los minutos").int("Minutos enteros").min(1, "Mínimo 1 minuto").max(600, "Máximo 600 minutos"),
  km: z.preprocess(vacioComoAusente, z.coerce.number().positive("Los km deben ser mayores que 0").max(100).optional()),
  fecha: z.coerce.date("Fecha no válida"),
  notas: z.preprocess(vacioComoAusente, z.string().trim().max(200, "Máximo 200 caracteres").optional()),
};

/** Lo que envía el formulario y valida el endpoint */
export const EntrenoSchema = z
  .object(campos)
  .refine((e) => e.tipo === "running" || e.km === undefined, {
    message: "Solo los entrenos de running llevan km",
    path: ["km"],
  });

/** Lo que devuelve la API: el entreno más su id y su fecha de creación */
export const EntrenoDTOSchema = z.object({
  ...campos,
  id: z.string(),
  creado: z.coerce.date(), // en el JSON llega como texto ISO; al validar vuelve a ser Date
});

export const ListaEntrenosSchema = z.object({ entrenos: z.array(EntrenoDTOSchema) });

// Los tipos se derivan; ninguno se escribe a mano
export type TipoEntreno = (typeof TIPOS_ENTRENO)[number];
export type EntrenoInput = z.output<typeof EntrenoSchema>;
export type EntrenoDTO = z.output<typeof EntrenoDTOSchema>;
/** Estado del formulario: los mismos campos, todos como texto (así los dan los <input>) */
export type EntrenoFormulario = Record<keyof EntrenoInput, string>;
```

| Tipo                | Qué es                                                     | Dónde se usa                        |
| ------------------- | ---------------------------------------------------------- | ----------------------------------- |
| `EntrenoInput`      | Un entreno validado (con `Date`, números…)                 | El servidor, al guardar             |
| `EntrenoDTO`        | Un entreno con `id` y `creado`, tal como lo usa el cliente | La respuesta de la API y el listado |
| `EntrenoFormulario` | Los mismos campos, todos como texto                        | El estado del formulario de React   |
| `TipoEntreno`       | `"fuerza" \| "running" \| "movilidad"`                     | Donde haga falta el tipo suelto     |

- **`EntrenoFormulario = Record<keyof EntrenoInput, string>`** combina `keyof` (I1.2) y `Record` (I1.3): un campo nuevo en el esquema lo exige al instante en el formulario.

<Callout type="risk">

- **Una fecha no sobrevive a JSON:** sale como texto. El DTO usa `z.coerce.date()` para que el cliente recupere un `Date`; sin eso, `e.fecha.toISOString()` fallaría con `toISOString is not a function`.
- **Las fechas sin hora se guardan a medianoche UTC:** en UTC−6 se verían el día **anterior**. Muéstralas en UTC (`toISOString().slice(0, 10)`) o guarda el día como texto.
- **`.refine()` solo se evalúa con los campos bien tipados:** con la fecha `"ayer"`, el error de km aparece cuando se corrige la fecha. Es correcto, pero sorprende.

</Callout>

## Paso 3: MongoDB y el paso de documento a DTO

**Qué es:** la capa de datos, el único sitio que sabe que existe MongoDB, y **`aDTO`**, donde se decide qué se publica.

**Cómo se usa:** crea `src/server/entrenos.ts`.

```ts
// Archivo: src/server/entrenos.ts
// Capa de datos: el único sitio que sabe que existe MongoDB
import type { ObjectId, WithId } from "mongodb";
import { db } from "../lib/mongo";
import type { EntrenoDTO, EntrenoInput } from "../schemas/entreno";

/** El documento tal como se guarda: lo validado más lo que pone el servidor */
export interface EntrenoDoc extends EntrenoInput {
  _id?: ObjectId;
  userId: string;
  creado: Date;
}

const entrenos = db.collection<EntrenoDoc>("entrenos");

/** Documento de BD → DTO para el cliente: _id pasa a id y userId no sale nunca */
export function aDTO(doc: WithId<EntrenoDoc>): EntrenoDTO {
  return {
    id: doc._id.toHexString(),
    tipo: doc.tipo,
    minutos: doc.minutos,
    km: doc.km,
    fecha: doc.fecha,
    notas: doc.notas,
    creado: doc.creado,
  };
}

export async function listarEntrenos(userId: string, limite = 20): Promise<EntrenoDTO[]> {
  const docs = await entrenos.find({ userId }).sort({ fecha: -1, creado: -1 }).limit(limite).toArray();
  return docs.map(aDTO);
}

export async function crearEntreno(userId: string, datos: EntrenoInput): Promise<EntrenoDTO> {
  const doc: EntrenoDoc = { ...datos, userId, creado: new Date() };
  const { insertedId } = await entrenos.insertOne(doc);
  return aDTO({ ...doc, _id: insertedId });
}
```

- **`EntrenoDoc extends EntrenoInput`:** lo validado más lo que pone el servidor (`_id`, `userId`, `creado`). Con **`collection<EntrenoDoc>`** (I1.1), `insertOne` exige un documento completo y `find` devuelve `WithId<EntrenoDoc>`.
- **`aDTO` construye campo a campo:** `userId` nunca sale (`Pick`, I1.3) y el `ObjectId` pasa a `id` como texto. El retorno `EntrenoDTO` obliga a incluir cada campo.
- **`crearEntreno` recibe un `EntrenoInput`,** que solo sale de Zod: nadie guarda sin validar.

<Callout type="risk">

- **`collection<EntrenoDoc>` describe lo que esperas, no lo que hay:** documentos de un esquema anterior salen con el tipo nuevo. Lo verás en el ejercicio; por eso el cliente valida la respuesta.
- **Cada campo publicado se añade a `aDTO` a propósito:** con `{ ...doc, id }`, cualquier campo interno futuro saldría en la API sin que nadie lo decida.
- **Con muchos datos, la ordenación necesita índice:** `{ userId: 1, fecha: -1 }` (B4.4).

</Callout>

## Paso 4: el endpoint

**Qué es:** un _endpoint_ corto porque el trabajo ya está repartido: `validar` (I1.5) convierte el cuerpo en `EntrenoInput` o lanza, `crearEntreno` guarda y `aRespuesta` traduce errores.

**Cómo se usa:** crea `src/pages/api/entrenos.ts`, arranca con `npm run dev` y pruébalo.

```ts
// Archivo: src/pages/api/entrenos.ts
import type { APIRoute } from "astro";
import { aRespuesta, validar } from "../../lib/errores";
import { EntrenoSchema } from "../../schemas/entreno";
import { crearEntreno, listarEntrenos } from "../../server/entrenos";

export const prerender = false;

// Sin autenticación todavía (curso I5): todos los entrenos son de un usuario de demostración
const USUARIO_DEMO = "u_demo";

export const GET: APIRoute = async () => {
  try {
    const entrenos = await listarEntrenos(USUARIO_DEMO);
    return Response.json({ entrenos });
  } catch (e) {
    return aRespuesta(e);
  }
};

export const POST: APIRoute = async ({ request }) => {
  try {
    const datos = validar(EntrenoSchema, await request.json().catch(() => null)); // EntrenoInput
    const creado = await crearEntreno(USUARIO_DEMO, datos);
    return Response.json(creado, { status: 201 });
  } catch (e) {
    return aRespuesta(e);
  }
};
```

Tus `id` y fechas de `creado` serán otros.

- **`"52"` y `"10"` entraron como texto y salieron como números** (`z.coerce`); las notas perdieron los espacios (`.trim()`). El POST inválido dio 422 sin tocar la base de datos.
- **`userId: "atacante"` y `_id: "x"` se descartaron** (I1.4): se guardó para `u_demo` con un `_id` de MongoDB. En la respuesta, solo `id` (`aDTO`).

En MongoDB, `fecha` y `creado` son `Date` de verdad, que se ordenan y filtran por rangos:

```text
{
  _id: ObjectId('6ac9d70ffb3dc052e01134a3'),
  tipo: 'running',
  minutos: 52,
  km: 10,
  fecha: 2026-10-08T00:00:00.000Z,
  notas: 'Rodaje suave',
  userId: 'u_demo',
  creado: 2026-10-10T06:11:27.650Z
}
```

<Callout type="risk">

- **`USUARIO_DEMO` es provisional:** con autenticación (I5), el `userId` sale **siempre de la sesión** (`locals.user.id`), nunca del cuerpo.
- **Si MongoDB no responde al arrancar,** el cliente guardado en `globalThis` puede quedar cerrado: `MongoTopologyClosedError: Topology is closed` hasta reiniciar `npm run dev`.
- **Los parámetros del `GET` también se validan:** con `?tipo=` o `?pagina=`, un esquema como el `FiltroSchema` de I1.4.

</Callout>

## Paso 5: el formulario y el listado en React

**Qué es:** el mismo `EntrenoSchema` que protege el servidor valida en el navegador, con los mismos mensajes, y el cliente **también valida lo que recibe**.

**Cómo se usa:** crea `src/components/Entrenos.tsx`.

```tsx
// Archivo: src/components/Entrenos.tsx
import { useEffect, useState, type FormEvent } from "react";
import { z } from "zod";
import {
  EntrenoDTOSchema,
  EntrenoSchema,
  ListaEntrenosSchema,
  TIPOS_ENTRENO,
  type EntrenoDTO,
  type EntrenoFormulario,
} from "../schemas/entreno";

type Errores = Partial<Record<keyof EntrenoFormulario, string[]>>;

/** "AAAA-MM-DD" de hoy en la zona horaria del navegador (el formato de <input type="date">) */
const hoy = () => new Date().toLocaleDateString("en-CA");

const VACIO: EntrenoFormulario = { tipo: "running", minutos: "", km: "", fecha: "", notas: "" };

export default function Entrenos() {
  const [formulario, setFormulario] = useState<EntrenoFormulario>(VACIO);
  const [errores, setErrores] = useState<Errores>({});
  const [entrenos, setEntrenos] = useState<EntrenoDTO[]>([]);
  const [estado, setEstado] = useState<"cargando" | "listo" | "error">("cargando");

  // Al montar: pedir la lista y VALIDAR la respuesta con el mismo esquema que usa el servidor
  useEffect(() => {
    // La fecha de hoy se pone al montar, en el navegador: así no difiere del HTML del servidor
    setFormulario((f) => ({ ...f, fecha: f.fecha || hoy() }));
    fetch("/api/entrenos")
      .then((res) => res.json())
      .then((json) => {
        setEntrenos(ListaEntrenosSchema.parse(json).entrenos);
        setEstado("listo");
      })
      .catch(() => setEstado("error"));
  }, []);

  const cambiar = (campo: keyof EntrenoFormulario, valor: string) =>
    setFormulario((f) => ({ ...f, [campo]: valor }));

  async function enviar(evento: FormEvent<HTMLFormElement>) {
    evento.preventDefault();
    // 1. Validación en el cliente: respuesta inmediata, sin ir al servidor
    const local = EntrenoSchema.safeParse(formulario);
    if (!local.success) {
      setErrores(z.flattenError(local.error).fieldErrors);
      return;
    }
    // 2. El servidor vuelve a validar (el cliente se puede saltar)
    const res = await fetch("/api/entrenos", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(local.data), // las Date viajan como texto ISO
    });
    const json: unknown = await res.json();
    if (res.status === 422) {
      setErrores(z.object({ campos: z.record(z.string(), z.array(z.string())) }).parse(json).campos);
      return;
    }
    if (!res.ok) {
      setEstado("error");
      return;
    }
    const nuevo = EntrenoDTOSchema.parse(json); // fecha y creado vuelven a ser Date
    setEntrenos((lista) => [nuevo, ...lista]);
    setFormulario({ ...VACIO, fecha: hoy() });
    setErrores({});
  }

  const error = (campo: keyof EntrenoFormulario) =>
    errores[campo]?.map((m) => (
      <p key={m} className="error" data-campo={campo}>
        {m}
      </p>
    ));

  return (
    <div>
      <form onSubmit={enviar} noValidate>
        <label>
          Tipo
          <select value={formulario.tipo} onChange={(e) => cambiar("tipo", e.target.value)}>
            {TIPOS_ENTRENO.map((t) => (
              <option key={t} value={t}>
                {t}
              </option>
            ))}
          </select>
        </label>
        {error("tipo")}
        <label>
          Minutos
          <input inputMode="numeric" value={formulario.minutos} onChange={(e) => cambiar("minutos", e.target.value)} />
        </label>
        {error("minutos")}
        <label>
          Km
          <input inputMode="decimal" value={formulario.km} onChange={(e) => cambiar("km", e.target.value)} />
        </label>
        {error("km")}
        <label>
          Fecha
          <input type="date" value={formulario.fecha} onChange={(e) => cambiar("fecha", e.target.value)} />
        </label>
        {error("fecha")}
        <label>
          Notas
          <input value={formulario.notas} onChange={(e) => cambiar("notas", e.target.value)} />
        </label>
        {error("notas")}
        <button type="submit">Guardar</button>
      </form>

      {estado === "cargando" && <p>Cargando…</p>}
      {estado === "error" && <p className="error">No se pudieron cargar los entrenos</p>}
      <ul id="lista">
        {entrenos.map((e) => (
          <li key={e.id}>
            {e.fecha.toISOString().slice(0, 10)} · {e.tipo} · {e.minutos} min
            {e.km !== undefined && ` · ${e.km} km`}
            {e.notas && ` · ${e.notas}`}
          </li>
        ))}
      </ul>
    </div>
  );
}
```

- **Los dos intentos inválidos no hicieron petición.** El estado es **`useState<EntrenoFormulario>`**, se valida con **`safeParse`** y los errores salen de **`z.flattenError(...).fieldErrors`**, que ya conoce los nombres de campo.
- **`ListaEntrenosSchema.parse` y `EntrenoDTOSchema.parse`** validan la respuesta y devuelven las fechas a `Date`: la API es frontera en las dos direcciones (I1.4).
- **La fecha de hoy va en un `useEffect`:** calculada al crear el estado, servidor y navegador podrían discrepar por zona horaria, con un error de hidratación.

<Callout type="risk">

- **El `<style>` de un `.astro` no llega a React:** tiene ámbito. Usa `is:global`, un CSS importado o clases en el componente.
- **La validación del cliente es comodidad:** con `curl` se salta. El servidor valida siempre.
- **Un `.parse()` de la respuesta que falla deja la lista vacía:** mejor que datos rotos, pero registra el error para enterarte.

</Callout>

## Paso 6: migrar JavaScript a TypeScript poco a poco

**Qué es:** un proyecto heredado en JavaScript no se reescribe entero: con **`// @ts-check`** y tipos en comentarios **JSDoc**, TypeScript revisa los `.js` uno a uno.

**Cómo se usa:** crea `src/lib/resumen.js`, código "antiguo" con dos erratas.

```js
// @ts-check
// Archivo: src/lib/resumen.js — código antiguo en JavaScript, revisado por TypeScript con JSDoc

/** @typedef {import("../schemas/entreno").EntrenoDTO} EntrenoDTO */

/**
 * Minutos totales y km de running de una lista de entrenos
 * @param {EntrenoDTO[]} entrenos
 * @returns {{ minutos: number; km: number }}
 */
export function resumen(entrenos) {
  let minutos = 0;
  let km = 0;
  for (const e of entrenos) {
    minutos += e.minuto;
    if (e.tipo === "runing") km += e.km ?? 0;
  }
  return { minutos, km };
}
```

- **No actives `checkJs` en todo el proyecto de golpe:** cientos de errores invitan a desactivarlo. Archivo a archivo.
- **JSDoc es un paso intermedio:** los tipos complejos son incómodos en comentarios.
- **Una migración no cambia comportamiento:** los bugs que aparezcan, en commits separados (B2).

```ts
// Archivo: src/schemas/entreno.ts
// La única fuente de verdad: la usan el formulario (cliente), el endpoint y la base de datos (servidor)
import { z } from "zod";

export const TIPOS_ENTRENO = ["fuerza", "running", "movilidad"] as const;

// Un campo de formulario vacío ("") significa "no lo he rellenado", no 0
const vacioComoAusente = (v: unknown) => (v === "" ? undefined : v);

// Campos comunes a la entrada y al DTO
const campos = {
  tipo: z.enum(TIPOS_ENTRENO, "Elige un tipo de entreno"),
  minutos: z.coerce.number("Indica los minutos").int("Minutos enteros").min(1, "Mínimo 1 minuto").max(600, "Máximo 600 minutos"),
  km: z.preprocess(vacioComoAusente, z.coerce.number().positive("Los km deben ser mayores que 0").max(100).optional()),
  fecha: z.coerce.date("Fecha no válida"),
  notas: z.preprocess(vacioComoAusente, z.string().trim().max(200, "Máximo 200 caracteres").optional()),
  sensacion: z.coerce.number().int().min(1, "De 1 a 5").max(5, "De 1 a 5"), // ← campo nuevo
};

/** Lo que envía el formulario y valida el endpoint */
export const EntrenoSchema = z
  .object(campos)
  .refine((e) => e.tipo === "running" || e.km === undefined, {
    message: "Solo los entrenos de running llevan km",
    path: ["km"],
  });

/** Lo que devuelve la API: el entreno más su id y su fecha de creación */
export const EntrenoDTOSchema = z.object({
  ...campos,
  id: z.string(),
  creado: z.coerce.date(), // en el JSON llega como texto ISO; al validar vuelve a ser Date
});

export const ListaEntrenosSchema = z.object({ entrenos: z.array(EntrenoDTOSchema) });

// Los tipos se derivan; ninguno se escribe a mano
export type TipoEntreno = (typeof TIPOS_ENTRENO)[number];
export type EntrenoInput = z.output<typeof EntrenoSchema>;
export type EntrenoDTO = z.output<typeof EntrenoDTOSchema>;
/** Estado del formulario: los mismos campos, todos como texto (así los dan los <input>) */
export type EntrenoFormulario = Record<keyof EntrenoInput, string>;
```

`src/server/entrenos.ts` completo:

```ts
// Archivo: src/server/entrenos.ts
// Capa de datos: el único sitio que sabe que existe MongoDB
import type { ObjectId, WithId } from "mongodb";
import { db } from "../lib/mongo";
import type { EntrenoDTO, EntrenoInput } from "../schemas/entreno";

/** El documento tal como se guarda: lo validado más lo que pone el servidor */
export interface EntrenoDoc extends EntrenoInput {
  _id?: ObjectId;
  userId: string;
  creado: Date;
}

const entrenos = db.collection<EntrenoDoc>("entrenos");

/** Documento de BD → DTO para el cliente: _id pasa a id y userId no sale nunca */
export function aDTO(doc: WithId<EntrenoDoc>): EntrenoDTO {
  return {
    id: doc._id.toHexString(),
    tipo: doc.tipo,
    minutos: doc.minutos,
    km: doc.km,
    fecha: doc.fecha,
    notas: doc.notas,
    sensacion: doc.sensacion,
    creado: doc.creado,
  };
}

export async function listarEntrenos(userId: string, limite = 20): Promise<EntrenoDTO[]> {
  const docs = await entrenos.find({ userId }).sort({ fecha: -1, creado: -1 }).limit(limite).toArray();
  return docs.map(aDTO);
}

export async function crearEntreno(userId: string, datos: EntrenoInput): Promise<EntrenoDTO> {
  const doc: EntrenoDoc = { ...datos, userId, creado: new Date() };
  const { insertedId } = await entrenos.insertOne(doc);
  return aDTO({ ...doc, _id: insertedId });
}
```

```tsx
// Archivo: src/components/Entrenos.tsx
import { useEffect, useState, type FormEvent } from "react";
import { z } from "zod";
import {
  EntrenoDTOSchema,
  EntrenoSchema,
  ListaEntrenosSchema,
  TIPOS_ENTRENO,
  type EntrenoDTO,
  type EntrenoFormulario,
} from "../schemas/entreno";

type Errores = Partial<Record<keyof EntrenoFormulario, string[]>>;

/** "AAAA-MM-DD" de hoy en la zona horaria del navegador (el formato de <input type="date">) */
const hoy = () => new Date().toLocaleDateString("en-CA");

const VACIO: EntrenoFormulario = {
  tipo: "running",
  minutos: "",
  km: "",
  fecha: "",
  notas: "",
  sensacion: "3",
};

export default function Entrenos() {
  const [formulario, setFormulario] = useState<EntrenoFormulario>(VACIO);
  const [errores, setErrores] = useState<Errores>({});
  const [entrenos, setEntrenos] = useState<EntrenoDTO[]>([]);
  const [estado, setEstado] = useState<"cargando" | "listo" | "error">("cargando");

  // Al montar: pedir la lista y VALIDAR la respuesta con el mismo esquema que usa el servidor
  useEffect(() => {
    // La fecha de hoy se pone al montar, en el navegador: así no difiere del HTML del servidor
    setFormulario((f) => ({ ...f, fecha: f.fecha || hoy() }));
    fetch("/api/entrenos")
      .then((res) => res.json())
      .then((json) => {
        setEntrenos(ListaEntrenosSchema.parse(json).entrenos);
        setEstado("listo");
      })
      .catch(() => setEstado("error"));
  }, []);

  const cambiar = (campo: keyof EntrenoFormulario, valor: string) =>
    setFormulario((f) => ({ ...f, [campo]: valor }));

  async function enviar(evento: FormEvent<HTMLFormElement>) {
    evento.preventDefault();
    // 1. Validación en el cliente: respuesta inmediata, sin ir al servidor
    const local = EntrenoSchema.safeParse(formulario);
    if (!local.success) {
      setErrores(z.flattenError(local.error).fieldErrors);
      return;
    }
    // 2. El servidor vuelve a validar (el cliente se puede saltar)
    const res = await fetch("/api/entrenos", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(local.data), // las Date viajan como texto ISO
    });
    const json: unknown = await res.json();
    if (res.status === 422) {
      setErrores(z.object({ campos: z.record(z.string(), z.array(z.string())) }).parse(json).campos);
      return;
    }
    if (!res.ok) {
      setEstado("error");
      return;
    }
    const nuevo = EntrenoDTOSchema.parse(json); // fecha y creado vuelven a ser Date
    setEntrenos((lista) => [nuevo, ...lista]);
    setFormulario({ ...VACIO, fecha: hoy() });
    setErrores({});
  }

  const error = (campo: keyof EntrenoFormulario) =>
    errores[campo]?.map((m) => (
      <p key={m} className="error" data-campo={campo}>
        {m}
      </p>
    ));

  return (
    <div>
      <form onSubmit={enviar} noValidate>
        <label>
          Tipo
          <select value={formulario.tipo} onChange={(e) => cambiar("tipo", e.target.value)}>
            {TIPOS_ENTRENO.map((t) => (
              <option key={t} value={t}>
                {t}
              </option>
            ))}
          </select>
        </label>
        {error("tipo")}
        <label>
          Minutos
          <input inputMode="numeric" value={formulario.minutos} onChange={(e) => cambiar("minutos", e.target.value)} />
        </label>
        {error("minutos")}
        <label>
          Km
          <input inputMode="decimal" value={formulario.km} onChange={(e) => cambiar("km", e.target.value)} />
        </label>
        {error("km")}
        <label>
          Fecha
          <input type="date" value={formulario.fecha} onChange={(e) => cambiar("fecha", e.target.value)} />
        </label>
        {error("fecha")}
        <label>
          Notas
          <input value={formulario.notas} onChange={(e) => cambiar("notas", e.target.value)} />
        </label>
        {error("notas")}
        <label>
          Sensación (1–5)
          <select value={formulario.sensacion} onChange={(e) => cambiar("sensacion", e.target.value)}>
            {[1, 2, 3, 4, 5].map((n) => (
              <option key={n} value={n}>
                {n}
              </option>
            ))}
          </select>
        </label>
        {error("sensacion")}
        <button type="submit">Guardar</button>
      </form>

      {estado === "cargando" && <p>Cargando…</p>}
      {estado === "error" && <p className="error">No se pudieron cargar los entrenos</p>}
      <ul id="lista">
        {entrenos.map((e) => (
          <li key={e.id}>
            {e.fecha.toISOString().slice(0, 10)} · {e.tipo} · {e.minutos} min
            {e.km !== undefined && ` · ${e.km} km`}
            {e.notas && ` · ${e.notas}`} · sensación {e.sensacion}/5
          </li>
        ))}
      </ul>
    </div>
  );
}
```

```text

'2026-10-10 · running · 35 min · 6.5 km · Series 6x400 · sensación 3/5',
```

- **Un campo, un cambio en el esquema;** el compilador señaló los dos sitios que pedían decisión. El selector no lo pidió: que falte **pintarlo** lo cubren las pruebas en el navegador (I8).
- **La migración da un valor neutro (3)** en vez de dejar el campo opcional para siempre: el tipo sigue diciendo la verdad.

<Callout type="risk">

- **Esquema y migración van juntos:** desplegar antes el código estricto deja "No se pudieron cargar los entrenos". El orden seguro: esquema tolerante (opcional o `.default(3)`), migración y luego esquema estricto.
- **Prueba la migración con una copia:** un filtro mal escrito (`{ sensacion: { $exists: true } }`) pisa los valores reales de todos.
- **Renombrar un campo** rompe el código, como buscas, pero los documentos guardados siguen con el nombre viejo: cada cambio de forma necesita su migración (A3).

</Callout>

<Callout type="mastery">

Cambiar un campo del esquema hace fallar al compilador en todos los sitios que deben actualizarse: tienes un único esquema de Zod en `src/schemas/` del que derivas los tipos del formulario, del _endpoint_, de la colección y de la respuesta; validas en las dos direcciones de la API; mapeas documentos a DTOs campo a campo, y acompañas cada cambio de forma con su migración de datos.

</Callout>

## Resumen

- Un esquema en `src/schemas/` es el contrato entre cliente y servidor; los tipos se derivan.
- Dos esquemas: entrada (coerción y reglas) y DTO (`id` y fechas como `Date`).
- `collection<EntrenoDoc>` y `aDTO` campo a campo: `_id` → `id`, nada interno sale.
- `validar()` y `aRespuesta()` en el _endpoint_; el cliente valida al enviar y al recibir.
- JS heredado con `// @ts-check`; datos con esquema tolerante, migración idempotente y esquema estricto.
