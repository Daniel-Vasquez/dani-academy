Si mil personas piden la misma página, no hace falta generarla mil veces: se guarda la respuesta y se entrega sin repetir el trabajo. Es lo que más rendimiento da por línea, y la forma más fácil de enseñarle a un usuario los datos de otro. Aquí pones una CDN delante de tu app, una caché en memoria con límites y una defensa con su _script_ para que nada privado se guarde.

**Requisitos:** la app desplegada con Nginx (A4) y el recolector de A6.1.

## Paso 1: una página que vale la pena guardar

**Qué es:** una página pública y cara de generar, y la cabecera `Cache-Control`, que dice quién puede guardarla y cuánto.

**Cómo se usa:** `src/pages/comunidad.astro` recorre toda la colección:

```astro
---
// Archivo: src/pages/comunidad.astro
// Pública y cara de generar: un resumen de toda la comunidad, sin datos de nadie en concreto
import Base from "../layouts/Base.astro";
import { repos } from "../repositories";
import { cacheDatos } from "../lib/cache-memoria";

export const prerender = false;

const filas = await cacheDatos.obtener("comunidad", () => repos.entrenos.comunidad());
const total = filas.reduce((suma, f) => suma + f.total, 0);
Astro.response.headers.set("Cache-Control", "public, s-maxage=60, stale-while-revalidate=600");
---

<Base titulo="Comunidad">
  <h1>La comunidad</h1>
  <p id="total">{total} entrenos registrados</p>
  <ul>{filas.map((f) => <li>{f.tipo}: {f.total} entrenos, {f.minutos} minutos</li>)}</ul>
  <p id="generada">HTML generado: {new Date().toISOString()}</p>
</Base>
```

En `src/repositories/entrenos.repo.ts`, la consulta, que nunca devuelve el `userId`:

```ts
/** Toda la comunidad, sin userId: recorre la colección entera, por eso es cara */
async comunidad(): Promise<{ tipo: string; total: number; minutos: number }[]> {
  return col
    .aggregate<{ tipo: string; total: number; minutos: number }>([
      { $group: { _id: "$tipo", total: { $sum: 1 }, minutos: { $sum: "$minutos" } } },
      { $project: { _id: 0, tipo: "$_id", total: 1, minutos: 1 } },
      { $sort: { tipo: 1 } },
    ])
    .toArray();
},
```

| Directiva                    | Significado                                                   |
| ---------------------------- | ------------------------------------------------------------- |
| `public`                     | La puede guardar cualquiera, incluida una caché compartida    |
| `private`                    | Solo el navegador de ese usuario                              |
| `no-store`                   | Nadie la guarda                                               |
| `max-age=60`                 | 60 s de validez, en el navegador                              |
| `s-maxage=60`                | 60 s de validez, en las cachés compartidas                    |
| `stale-while-revalidate=600` | Hasta 600 s más, sirve la copia vieja mientras trae una nueva |

- **`public, s-maxage=60, stale-while-revalidate=600`:** 60 s sirviendo la copia y hasta 10 minutos más sirviéndola mientras se actualiza detrás; nadie espera.
- **El navegador ignora `s-maxage`** y siempre pregunta a la CDN, así que puedes actualizarla sin depender de lo que guardó cada navegador.

<Callout type="risk">

- **`public` solo si el HTML es igual para todos:** con el nombre del usuario dentro, no es pública (Paso 4).
- **Una consulta que recorre toda la colección** se vuelve cara con el tiempo: la caché la esconde, no la arregla.

</Callout>

## Paso 2: una CDN en tu servidor

**Qué es:** una **CDN** es una caché compartida entre tus usuarios y tu servidor. Vercel la trae; en un VPS la hace Nginx.

**Cómo se usa:** la carpeta y `/etc/nginx/conf.d/cache.conf`:

```bash
sudo mkdir -p /var/cache/nginx/entrenos
sudo chown www-data /var/cache/nginx/entrenos
```

```nginx
# Archivo: /etc/nginx/conf.d/cache.conf
proxy_cache_path /var/cache/nginx/entrenos levels=1:2 keys_zone=cdn:10m max_size=200m inactive=1h use_temp_path=off;
```

`/etc/nginx/snippets/cdn.conf`:

```nginx
# Archivo: /etc/nginx/snippets/cdn.conf
proxy_cache cdn;
proxy_cache_lock on;                # con la caché vacía, solo una petición llega a Node
proxy_cache_background_update on;   # refresca en segundo plano, sin hacer esperar a nadie
proxy_cache_use_stale updating error timeout http_500 http_502 http_503 http_504;

# Un add_header propio anula todos los de server: hay que repetirlos
include snippets/cabeceras.conf;
add_header X-Cache $upstream_cache_status always; # HIT, MISS, STALE…
```

`include snippets/cdn.conf;` en `location /`, y una entrada para la página, sin el límite de A5.4 porque casi nada llegará a Node:

```nginx
location = /comunidad {
  include snippets/cdn.conf;
  proxy_cache_key $scheme$host$uri; # sin la query: ?utm=loquesea no esquiva la caché
  proxy_pass http://entrenos_app;
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
curl -sI https://academy.tudominio.com/comunidad
```

Con `s-maxage=10` y `stale-while-revalidate=30` para medir; la última columna es la hora en que se generó el HTML:

```text
MISS     81 ms  07:02:44.383Z
STALE     7 ms  07:02:44.383Z   ← 12 s después: copia vieja, y al instante
HIT       7 ms  07:02:56.352Z   ← un segundo más tarde, ya actualizada
```

| Estado     | Qué ha pasado                                        |
| ---------- | ---------------------------------------------------- |
| `MISS`     | No estaba: se generó en Node                         |
| `HIT`      | Servida desde la caché                               |
| `STALE`    | Copia caducada, servida mientras se actualiza        |
| `UPDATING` | Copia caducada, y ya hay una actualización en marcha |

- **En Vercel** (según su documentación, no medido), la cabecera es `x-vercel-cache`; una función solo se guarda con `s-maxage`, y esa directiva se quita antes del navegador.

<Callout type="risk">

- **La carpeta de la caché debe ser de `www-data`:** si no, Nginx no guarda nada y todo sale `MISS` sin error visible.
- **`max_size` e `inactive` acotan el disco:** sin ellos, la caché crece con cada URL distinta.

</Callout>

## Paso 3: lo que se gana

**Qué es:** la medida, con 300 000 entrenos de prueba y 1000 peticiones, 50 a la vez, por HTTPS desde el servidor, dos tandas de cada.

**Cómo se usa:**

```text
              Tiempo total    Mediana    Llegaron a Node
Sin caché     36,1 s          1637 ms    1000
Sin caché     32,8 s          1576 ms    1000
Con caché     3,0 s           60 ms      1
Con caché     3,0 s           59 ms      1
```

- **Once veces más rápido y una consulta en vez de mil.** Esos 60 ms son sobre todo de lanzar 50 `curl` a la vez; un `HIT` suelto tardó 7 ms.

La **avalancha**, caché vacía y 200 peticiones a la vez:

```text
proxy_cache_lock off:  llegaron a Node 27
proxy_cache_lock on:   llegó a Node 1
```

Y con Node caído:

```text
/comunidad      STALE, en 3 ms
/estadisticas   502
```

- **La página pública sigue con su última copia,** por `proxy_cache_use_stale error`.

<Callout type="risk">

- **La query entra en la clave por defecto:** `?utm=a` y `?utm=b` dieron `MISS` y cualquiera esquivaba la caché con `?x=` y un número. Con `proxy_cache_key`, todo `HIT`; pero si la página cambia con la query, debe seguir en la clave.
- **`stale-while-revalidate` no es estricto aquí:** se sirvió una copia de 44 s con `s-maxage=10` y `swr=30`, porque `proxy_cache_use_stale` manda. Y `max-age` también lo respeta Nginx y queda en cada navegador: por eso `s-maxage`.
- **La caché esconde errores** (Node caído sin enterarte, A6.4), un error guardado se multiplica, y si la página ya es rápida no compensa: mide antes.

</Callout>

## Paso 4: lo que nunca se guarda

**Qué es:** lo más importante de la sección. Una caché compartida no sabe quién eres: la clave es la URL, sin la _cookie_.

**Cómo se usa:** dos usuarias de prueba, Ana y Bea, y dos errores. **Error 1:** un `public` copiado en `/estadisticas`:

```text
Ana      /estadisticas  200  MISS  public, s-maxage=60  Estadísticas de Ana
Bea      /estadisticas  200  HIT   public, s-maxage=60  Estadísticas de Ana
anónimo  /estadisticas  200  HIT   public, s-maxage=60  Estadísticas de Ana
```

- **Bea ve los datos de Ana, y alguien sin sesión también:** Nginx responde antes de Node y el _middleware_ que protege la ruta (I5) ni se ejecuta.

**Error 2:** sin tocar la app, `proxy_cache_valid 200 1m;` en `cdn.conf` (que guarda lo que no trae cabecera):

```text
Ana      /api/entrenos  200  MISS  "tipo":"fuerza"
anónimo  /api/entrenos  200  HIT   "tipo":"fuerza"
```

- **Una API privada respondiendo sin sesión;** sin esa línea, el anónimo recibía su 401.

**Si tu código no dice nada, decide otro.** Al revés: todo privado salvo lo declarado público. En `src/middleware.ts`:

```ts
/** 3. Lo que genera el servidor es privado, salvo lo que se declare público y sea sin sesión */
const cacheSegura = defineMiddleware(async (ctx, next) => {
  const respuesta = await next();
  if (ctx.isPrerendered) return respuesta; // una página estática no lleva datos de nadie

  const esPublica = respuesta.headers.get("cache-control")?.includes("public");
  if (!esPublica || ctx.locals.usuario) respuesta.headers.set("Cache-Control", "private, no-store");
  return respuesta;
});

export const onRequest = sequence(registrar, cargarSesion, cacheSegura, proteger);
```

Antes de `proteger`, para cubrir sus redirecciones y sus 401. Con **los dos errores a la vez**:

```text
Ana      /estadisticas  200  MISS  private, no-store  Estadísticas de Ana
Bea      /estadisticas  200  MISS  private, no-store  Estadísticas de Bea
anónimo  /estadisticas  302  MISS  private, no-store
Ana      /api/entrenos  200  MISS  private, no-store  "tipo":"fuerza"
anónimo  /api/entrenos  401  MISS  private, no-store
```

- **La isla de sesión de A6.2 también lo pasó** (cada una su nombre, el anónimo «Sin sesión»): `/comunidad` se guarda aunque la barra muestre tu nombre, porque el HTML no lo lleva.

| Se puede guardar                 | Nunca                                    |
| -------------------------------- | ---------------------------------------- |
| Páginas iguales para todos       | Lo que depende de quién lo pide          |
| Recursos con _hash_ (`/_astro/`) | Respuestas con `Set-Cookie`              |
| Resúmenes sin datos de nadie     | Respuestas a un POST o PUT               |
| Respuestas públicas de una API   | Formularios con tokens o datos de sesión |

<Callout type="risk">

- **Tras una fuga, la caché sigue sirviendo el dato:** vacíala (`sudo find /var/cache/nginx/entrenos -type f -delete`); en Vercel, invalidar sirve la copia vieja mientras actualiza, hay que borrar.
- **Ni `Vary: Cookie`** (una copia por usuario, y Vercel la rechaza) **ni `proxy_ignore_headers Set-Cookie`,** que puede repartir la sesión de alguien. `private` no es seguro en un ordenador compartido: aquí, `no-store`.
- **Prueba con dos usuarios y sin sesión:** con uno solo todo parece correcto; la fuga salió en la segunda línea.

</Callout>

## Paso 5: caché en memoria

**Qué es:** la CDN solo guarda respuestas enteras y públicas. Para reutilizar un dato en tu código, la memoria del proceso.

**Cómo se usa:** `src/lib/cache-memoria.ts`:

```ts
// Archivo: src/lib/cache-memoria.ts
// Caché en la memoria de ESTE proceso: cada instancia tiene la suya y se pierde al reiniciar
interface Entrada {
  valor: Promise<unknown>;
  caduca: number;
}

export function crearCache(ttlMs: number, maxEntradas = 500) {
  const entradas = new Map<string, Entrada>();

  return {
    obtener<T>(clave: string, cargar: () => Promise<T>): Promise<T> {
      const entrada = entradas.get(clave);
      if (entrada && entrada.caduca > Date.now()) return entrada.valor as Promise<T>;

      // Con un límite: sin él, cada clave nueva se queda en memoria para siempre
      if (entradas.size >= maxEntradas) entradas.delete(entradas.keys().next().value as string);

      // Se guarda la promesa, no el resultado: 50 peticiones a la vez comparten una sola consulta
      const valor = cargar().catch((error: unknown) => {
        entradas.delete(clave); // un error no se queda guardado hasta que caduque
        throw error;
      });
      entradas.set(clave, { valor, caduca: Date.now() + ttlMs });
      return valor;
    },

    borrar(clave: string) {
      entradas.delete(clave);
    },
  };
}

export const cacheDatos = crearCache(60_000);
```

En `src/pages/comunidad.astro`:

```ts
import { cacheDatos } from "../lib/cache-memoria";

const filas = await cacheDatos.obtener("comunidad", () => repos.entrenos.comunidad());
```

- **La línea clave guarda la promesa:** con `const valor = await cargar(); entradas.set(...)`, hasta que termina la primera consulta las demás no encuentran nada. 50 peticiones a la vez con la caché vacía, tres veces:

```text
Guarda el resultado:  50, 7 y 20 consultas
Guarda la promesa:    1, 1 y 1 consulta
```

- **Depende del momento** (tres resultados distintos). Y con **blue** y **green** activas, creando un entreno en una:

```text
antes:      activa 300084 · otra 300084
al momento: activa 300085 · otra 300084
a los 30 s: otra 300084
a los 62 s: otra 300085
```

- **Cada proceso tiene su memoria:** la otra sigue con el dato viejo hasta los 60 s, y según quién responda ves un número u otro.

<Callout type="risk">

- **En _serverless_, cada instancia nace y muere sola:** solo para no repetir trabajo; compartir entre instancias exige Redis. Reiniciar la vacía, con su pequeña avalancha.
- **Sin límite crece hasta romper** (un millón de entradas, 170 MB: `maxEntradas`), y esta expulsión quita la más antigua, no la menos usada (`lru-cache` para algo serio).
- **Con datos privados, el usuario en la clave** (`totales:${usuario.id}`), o reproduces el Paso 4. Y el `catch` borra la entrada: sin él, un error se serviría 60 s.

</Callout>

## Paso 6: invalidar

**Qué es:** guardar es una decisión; saber cuándo deja de ser verdad exige conocer **todo lo que cambia ese dato**.

**Cómo se usa:** aquí toda escritura pasa por el servicio de I3 (_endpoints_ y _Actions_). En `src/services/entrenos.service.ts`, añade `alCambiar?: () => void` a `Dependencias`, recíbelo y llámalo tras cada cambio:

```ts
async function crear(userId: string, datos: EntrenoInput): Promise<EntrenoDTO> {
  const { permitido, reintentarEn } = await limites.contar(`crear-entreno:${userId}`, MAX_ENTRENOS_POR_HORA, 3600);
  if (!permitido) throw new DemasiadasPeticionesError(reintentarEn);
  const creado = await entrenos.crear(userId, datos);
  alCambiar?.();
  return creado;
}
```

Lo mismo en `editar` y `borrar`. En `src/services/index.ts`:

```ts
entrenos: crearServicioEntrenos({
  entrenos: repos.entrenos,
  limites: repos.limites,
  alCambiar: () => cacheDatos.borrar("comunidad"), // todos los cambios pasan por aquí
}),
```

- **Eso resuelve la memoria de esa instancia** (`300085` al momento). La CDN no se entera; con `s-maxage=10`:

```text
al crear el entreno:  CDN 300083 · HIT
a los 12 s:           CDN 300083 · STALE
a los 13 s:           CDN 300084 · HIT
```

- **Caducidad corta:** aceptas X segundos de retraso; la más simple, la de esta app.
- **URL nueva:** si cambia el contenido, cambia el nombre, como `/_astro/` con su _hash_ (A4), que dura un año.
- **Borrar por etiqueta:** avisas a la CDN al escribir (`Vercel-Cache-Tag` y `vercel cache invalidate --tag`); el Nginx gratuito no lo trae. Astro 7 tiene `Astro.cache` con etiquetas, con proveedores de CDN experimentales; aquí no se usa.

<Callout type="risk">

- **`swr=600` con poco tráfico** muestra al primer visitante una copia muy vieja: solo para datos que toleran retraso.
- **Invalidar en una instancia no alcanza a las demás,** ni a lo que guardó el navegador con `max-age` largo.
- **Cada caché es un sitio más donde algo puede estar mal:** empieza por la CDN con caducidad corta. Un servicio único (I3) evita olvidar una ruta.

</Callout>

## Ejercicio práctico

Solución. `/comunidad` ya lleva `s-maxage=60, stale-while-revalidate=600`. `/acerca` es estática y Node la sirve con `max-age=0`, así que la caducidad la pone Nginx, **solo en esa ruta**:

```nginx
# Página estática: Node responde max-age=0, así que aquí se decide cuánto se guarda
location = /acerca {
  include snippets/cdn.conf;
  proxy_ignore_headers Cache-Control;
  proxy_cache_valid 200 10m;
  proxy_pass http://entrenos_app;
}
```

```bash
curl -sI https://academy.tudominio.com/comunidad
```

```text
HTTP/2 200
cache-control: public, s-maxage=60, stale-while-revalidate=600
x-cache: HIT
```

Lo importante es el Paso 4. `scripts/comprobar-cache.sh` revisa las dos listas con la _cookie_ de un usuario de prueba:

```bash
#!/usr/bin/env bash
# Archivo: scripts/comprobar-cache.sh
# Las páginas públicas se guardan y las privadas nunca. Si algo falla, termina con código 1.
# Uso: COOKIE='nombre=valor' bash scripts/comprobar-cache.sh https://tudominio.com
URL=${1:?Falta la URL}
PUBLICAS=(/comunidad /acerca)
PRIVADAS=(/estadisticas /notas /api/entrenos)
fallos=0

cabecera() { tr -d '\r' | grep -i "^$1:" | cut -d' ' -f2-; }

for ruta in "${PUBLICAS[@]}"; do
  curl -sI "$URL$ruta" >/dev/null # la primera llena la caché
  respuesta=$(curl -sI "$URL$ruta")
  estado=$(cabecera x-cache <<<"$respuesta")
  if [[ $estado == HIT || $estado == STALE || $estado == UPDATING ]]; then
    echo "ok     $ruta · $estado"
  else
    echo "FALLO  $ruta · debería venir de la caché, y vino: $estado"
    fallos=$((fallos + 1))
  fi
done

for ruta in "${PRIVADAS[@]}"; do
  curl -sI -H "Cookie: $COOKIE" "$URL$ruta" >/dev/null
  respuesta=$(curl -sI -H "Cookie: $COOKIE" "$URL$ruta")
  estado=$(cabecera x-cache <<<"$respuesta")
  control=$(cabecera cache-control <<<"$respuesta")
  if [[ $estado != HIT && $estado != STALE && $control == *no-store* ]]; then
    echo "ok     $ruta · $estado · $control"
  else
    echo "FALLO  $ruta · RESPUESTA PRIVADA EN CACHÉ: $estado · $control"
    fallos=$((fallos + 1))
  fi
done

exit $((fallos > 0))
```

```bash
COOKIE='__Secure-better-auth.session_token=…' bash scripts/comprobar-cache.sh https://academy.tudominio.com
```

```text
ok     /comunidad · HIT
ok     /acerca · HIT
ok     /estadisticas · MISS · private, no-store
ok     /notas · MISS · private, no-store
ok     /api/entrenos · MISS · private, no-store
```

- **Código 0.** Con una ruta que se guarda en la lista de privadas:

```text
FALLO  /comunidad · RESPUESTA PRIVADA EN CACHÉ: HIT · public, s-maxage=60, stale-while-revalidate=600
```

- **Código 1.** `proxy_cache_valid` solo en rutas concretas (en `cdn.conf` es el Error 2), y cada ruta nueva entra en la lista.
- **En Vercel,** busca `x-vercel-cache`; una estática sale como `PRERENDER`.
- **Ya demostró su utilidad:** tras un despliegue dio `FALLO` en las tres privadas por una etiqueta reutilizada que desplegó una imagen sin el _middleware_. Una etiqueta distinta por versión.

<Callout type="mastery">

Nunca cacheas por error una respuesta privada: todo es privado salvo lo que declaras público, y lo compruebas con dos usuarios y sin sesión. Sabes que `s-maxage` es para la CDN, que la memoria de cada instancia es solo suya, y que guardar la promesa evita la avalancha. Antes de guardar algo, tienes la respuesta a cómo se actualizará.

</Callout>

## Resumen

- `public, s-maxage=60, stale-while-revalidate=600`: un minuto en la CDN y diez más actualizando detrás.
- **Nginx como CDN:** de 34 s a 3 s y de 1000 consultas a 1.
- **`proxy_cache_lock`:** de 27 peticiones a Node a 1.
- **`proxy_cache_use_stale error`:** la página pública sobrevive a Node caído.
- **La clave es la URL:** una línea de más entregó datos de Ana sin sesión.
- **Todo privado por defecto:** el _middleware_ aguantó los dos errores.
- **Memoria:** guarda la promesa, con límite; cada instancia tiene la suya.
- **Invalidar:** caducidad corta, URL nueva o etiquetas. `comprobar-cache.sh` falla si se guarda algo privado.
