Medir (A6.1) era el primer paso; ahora toca bajar los números sin perder tiempo en lo que no pesa ni en consejos que en tu caso no cambian nada. La regla de esta sección: **mide, cambia una cosa y vuelve a medir**. Aquí reduces un tercio el JavaScript con las mismas funciones y ajustas imágenes, fuentes y _prefetch_ donde de verdad ayudan.

**Requisitos:** la app con el recolector y el presupuesto de A6.1.

## Paso 1: mira qué envías

**Qué es:** el inventario del JavaScript que genera el _build_ y el que descarga **cada página**.

**Cómo se usa:** los archivos del _build_, con su tamaño comprimido:

```bash
npm run build
cd dist/client/_astro
for f in *.js; do printf "%7s %s\n" "$(gzip -c "$f" | wc -c)" "$f"; done | sort -rn | head -6
```

```text
  65735 client.XI9U0KhD.js
  25466 schemas.CaUk71cF.js
  12378 CampoTexto.uoz2kuvv.js
  11780 auth-client.DrxeVTVP.js
   3412 _astro_actions.DBkyQHVi.js
   3152 Vitales.astro_astro_type_script_index_0_lang.Ck8WY5Bw.js
```

`client` es React. Para saber qué hay en `schemas`, busca una palabra de la biblioteca:

```bash
grep -l ZodError *.js
```

- **Es Zod.** `scripts/peso-js.mjs` saca de los informes de Lighthouse de A6.1 lo que descarga cada página:

```js
// Archivo: scripts/peso-js.mjs
// JavaScript transferido por cada página, de informes JSON de Lighthouse.
// Uso: node scripts/peso-js.mjs informes/*.json
import { readFileSync } from "node:fs";

for (const archivo of process.argv.slice(2)) {
  const informe = JSON.parse(readFileSync(archivo, "utf8"));
  const peticiones = informe.audits["network-requests"].details.items;
  const js = peticiones
    .filter((p) => p.resourceType === "Script")
    .sort((a, b) => b.transferSize - a.transferSize);
  const total = js.reduce((suma, p) => suma + p.transferSize, 0);

  console.log(`${new URL(informe.finalDisplayedUrl).pathname.padEnd(16)} ${(total / 1024).toFixed(1).padStart(6)} KB en ${js.length} archivos`);
  for (const p of js.slice(0, 4)) {
    console.log(`  ${(p.transferSize / 1024).toFixed(1).padStart(6)} KB  ${new URL(p.url).pathname.split("/").pop()}`);
  }
}
```

Con sesión, salvo `/entrar`:

```text
/                 100.3 KB en 10 archivos
/entrar           109.9 KB en 10 archivos
/estadisticas      75.1 KB en 7 archivos
/notas            103.8 KB en 12 archivos
```

- **`/estadisticas` se pinta entera en el servidor y descarga 75 KB:** solo por el nombre del usuario y el botón «Salir» de la barra.

<Callout type="risk">

- **Lo que existe no es lo que se descarga:** un archivo grande puede no cargarse en ninguna página importante. Mide por página.
- **Buscar una palabra (`ZodError`) es una pista, no una prueba:** confirma qué módulo trae la biblioteca antes de tocarlo.

</Callout>

## Paso 2: quita lo que no necesitas

**Qué es:** la isla `SesionActual` carga React y el cliente de Better Auth en **todas** las páginas, pero el servidor ya sabe quién eres (`Astro.locals`). Una isla de servidor (I3.1) lo pinta y deja estáticas las páginas estáticas.

**Cómo se usa:** `src/components/SesionServidor.astro`:

```astro
---
// Archivo: src/components/SesionServidor.astro
// Quién ha iniciado sesión, pintado en el servidor: sin React ni el cliente de Better Auth
const { usuario } = Astro.locals;
---

{
  usuario ? (
    <span id="sesion">
      {usuario.nombre} · {usuario.zonaHoraria} <button type="button" data-salir>Salir</button>
    </span>
  ) : (
    <span id="sesion">Sin sesión</span>
  )
}

<script>
  document.addEventListener("click", async (evento) => {
    if (!(evento.target as Element).closest("[data-salir]")) return;
    await fetch("/api/auth/sign-out", {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: "{}",
    });
    window.location.assign("/");
  });
</script>
```

En `src/layouts/Base.astro`, en lugar de la isla de React:

```astro
<SesionServidor server:defer><span slot="fallback" id="sesion">…</span></SesionServidor>
```

Borra `src/components/SesionActual.tsx`. En el navegador muestra el nombre y «Salir» cierra la sesión.

```text
/estadisticas: de 75,1 KB a 3,1 KB
```

- **Un 96 % menos:** queda solo el recolector de A6.1. Quitar una isla vale más que cualquier compresión.

<Callout type="risk">

- **`server:defer` añade una petición:** el nombre aparece tras un «…», a cambio de que la página no lleve datos personales y pueda ir a caché.
- **Comprueba el flujo completo en un navegador:** que el nombre aparece y que «Salir» cierra la sesión, no solo que bajan los KB.

</Callout>

## Paso 3: carga más tarde lo que se usa poco

**Qué es:** en la portada, React se queda (hay un formulario), pero Zod solo hace falta **al enviar**. El plan: descargarlo la primera vez que alguien pulsa «Guardar».

**Cómo se usa:** lo obvio, `await import("zod")`, bajó la portada a 67 KB, pero `/notas`:

```text
/notas: de 92,3 KB a 141,2 KB   (zod.JDcFsRQu.js: 71,3 KB)
```

- **Subió:** importada entera de forma dinámica, Zod no se recorta (71 KB en vez de 22) y otro componente la seguía importando normal. Solo se ve midiendo **todas** las páginas.

Lo correcto es un módulo tuyo pequeño. `src/lib/validar-entreno.ts`:

```ts
// Archivo: src/lib/validar-entreno.ts
// Validación del formulario, en un módulo aparte para descargarlo solo al enviar.
// Nunca import("zod"): trae la biblioteca entera, sin eliminar lo que no se usa
import { z } from "zod";
import { EntrenoSchema, type EntrenoFormulario } from "../schemas/entreno";

export function validarEntreno(formulario: EntrenoFormulario) {
  const local = EntrenoSchema.safeParse(formulario);
  return local.success
    ? { datos: local.data }
    : { errores: z.flattenError(local.error).fieldErrors };
}
```

El `<select>` necesita la lista de tipos al pintar, y estaba junto a Zod. A un archivo sin dependencias, `src/schemas/tipos.ts`:

```ts
// Archivo: src/schemas/tipos.ts
// Sin Zod: el componente puede importarlo sin arrastrar la biblioteca al navegador
export const TIPOS_ENTRENO = ["fuerza", "running", "movilidad"] as const;
```

En `src/schemas/entreno.ts`, en lugar de la constante:

```ts
export { TIPOS_ENTRENO } from "./tipos";
import { TIPOS_ENTRENO } from "./tipos";
```

En `src/components/Entrenos.tsx`, los imports, la recuperación de fechas y la validación al enviar:

```tsx
import type { EntrenoDTO, EntrenoFormulario } from "../schemas/entreno"; // import type: no llega al navegador
import { TIPOS_ENTRENO } from "../schemas/tipos";

type EntrenoJson = Omit<EntrenoDTO, "fecha" | "creado"> & { fecha: string; creado: string };

/** La API es nuestra y ya valida: aquí solo se recuperan las fechas */
const aDTO = (e: EntrenoJson): EntrenoDTO => ({ ...e, fecha: new Date(e.fecha), creado: new Date(e.creado) });
```

```tsx
// Al cargar la lista
setEntrenos((json as { entrenos: EntrenoJson[] }).entrenos.map(aDTO));

// Al enviar: Zod se descarga aquí, la primera vez que se envía
const { validarEntreno } = await import("../lib/validar-entreno");
const local = validarEntreno(formulario);
if (local.errores) {
  setErrores(local.errores);
  return;
}
// … y el fetch envía local.datos

// Con la respuesta del servidor
setErrores((json as { campos: Errores }).campos); // en el 422
const nuevo = aDTO(json as EntrenoJson);          // en el 201
```

- **En un navegador real:** la portada no descarga Zod al cargar; con 0 minutos se descargan `schemas` y `validar-entreno` y aparece «Mínimo 1 minuto», y con 30 se guarda y sigue al recargar.

```text
/                  66.9 KB en 8 archivos
/estadisticas       3.1 KB en 1 archivos
/notas             92.3 KB en 10 archivos
```

| Página          | Antes    | Después  | Cambio |
| --------------- | -------- | -------- | ------ |
| `/`             | 100,3 KB | 66,9 KB  | −33 %  |
| `/estadisticas` | 75,1 KB  | 3,1 KB   | −96 %  |
| `/notas`        | 103,8 KB | 69,4 KB  | −33 %  |
| `/entrar`       | 109,9 KB | 106,9 KB | −3 %   |

- **`/notas` es el ejercicio; `/entrar` apenas baja** porque ahí React, _React Hook Form_, Zod y el cliente de Better Auth sí se usan. Es una decisión, no un descuido.
- **Lighthouse siguió en 100 y el LCP entre 0,8 y 0,9 s:** ya iban bien. Cambió lo que paga cada usuario: la portada, de 107 a 77 KB.

<Callout type="risk">

- **Quitar la validación de respuestas es un intercambio:** se sustituye por un _cast_, razonable porque API y cliente se despliegan juntos. **Mantenla con APIs de terceros,** y el servidor valida siempre.
- **`import()` puede fallar con mala cobertura:** `try/catch` y envía igual, que responda el servidor. La primera pulsación tarda algo más: sirve para acciones ocasionales, no al teclear.
- **Usa `import type`:** un `import` normal de un archivo con Zod la trae entera aunque solo uses un tipo.

</Callout>

## Paso 4: la directiva adecuada

**Qué es:** cuando una isla hace falta, la directiva decide cuándo se descarga.

**Cómo se usa:** con una isla al final de una página larga:

```text
               LCP      JS al cargar   JS tras bajar
client:load    192 ms   61 KB          61 KB
client:idle    192 ms   61 KB          61 KB
client:visible 200 ms   1 KB           61 KB
```

- **`client:load`** para lo que debe funcionar ya; **`client:idle`** espera a que el navegador esté libre (aquí descargó igual); **`client:visible`** para lo de abajo, que no paga quien no baja; **sin directiva**, solo HTML.
- **El LCP no cambia** (el contenido viene en el HTML): se ahorran descargas y trabajo. Y la mejor directiva es no necesitar ninguna (Paso 2).

<Callout type="risk">

- **`client:visible` en algo que se ve al cargar** descarga igual y llega más tarde: úsala solo bajo el primer pantallazo.
- **Una isla sin directiva no es interactiva:** si el componente tiene manejadores, quedarán muertos sin aviso.

</Callout>

## Paso 5: imágenes

**Qué es:** Astro optimiza las imágenes que importas de `src/`, con `sharp` instalado y la imagen en `src/assets/`, no en `public/`.

**Cómo se usa:**

```astro
---
import { Image, Picture } from "astro:assets";
import portada from "../assets/portada.jpg";
---

<Image src={portada} alt="Portada" widths={[400, 800, 1200]} sizes="100vw" priority />

<Picture src={portada} alt="Portada" formats={["avif", "webp"]} widths={[400, 800, 1200]} sizes="100vw" priority />
```

- **`widths` y `sizes` generan un `srcset`** y el móvil elige su medida; el HTML lleva `width` y `height`, sin salto (A6.1).

Con un JPG de 2400 × 1600 y el móvil lento de A6.1:

```text
                         LCP       Descarga
<img> con el JPG         1788 ms   294 KB  jpg
<Image>                  504 ms    29 KB   webp
<Image priority>         492 ms    29 KB   webp
<Picture> avif y webp    476 ms    27 KB   avif
```

- **El salto grande es pasar por Astro;** `<Picture>` apenas añadió. `priority` cambió poco con una sola imagen, pero pasa de `loading="lazy"` a `loading="eager"`, `decoding="sync"` y `fetchpriority="high"`.

<Callout type="risk">

- **`priority` solo en la principal,** y nunca `loading="lazy"` en ella (retrasa el LCP); el resto, _lazy_, como hace Astro.
- **`sizes` debe describir tu diseño:** `100vw` en media pantalla descarga el doble. Y cada ancho y formato es un archivo más de _build_ (en páginas de servidor, al pedirlas: no medido).
- **Esta imagen comprime especialmente bien,** y optimizar no sustituye a un buen `alt`.

</Callout>

## Paso 6: fuentes

**Qué es:** una fuente web es una descarga más. _Fontsource_ la aloja en tu servidor **dividida por alfabetos** (_subsetting_).

**Cómo se usa:**

```bash
npm install @fontsource-variable/source-serif-4
```

```astro
---
import "@fontsource-variable/source-serif-4";
---

<style is:global>
  body {
    font-family: "Source Serif 4 Variable", Arial, sans-serif;
  }
</style>
```

- **6 archivos, 188 KB, y el navegador descargó uno de 50 KB,** el latino. Con `font-display: swap` se pinta con Arial y cambia al llegar:

```text
                   Primer pintado   Descarga   La fuente aparece
Fuente del sistema 192 ms           0 KB       —
Web, con swap      196 ms           50 KB      a los 692 ms
Web, con preload   296 ms           50 KB      a los 595 ms
```

- **`preload` empeoró el primer pintado 100 ms** para adelantar la fuente otros 100, en dos páginas distintas. Una fuente del sistema cuesta 0 KB.
- **El cambio apenas movió el texto:** 0,004 de CLS en bruto, con las mismas líneas.

<Callout type="risk">

- **Una fuente más ancha que su respaldo cambia líneas y salta:** mide la tuya y elige un respaldo parecido. Chromium marcó este salto como excluido, y `web-vitals` dio CLS 0.
- **`font-display: block` esconde el texto** hasta que llega: solo para iconos. Con fuentes no variables, carga solo los pesos que uses.
- **Alójala en tu servidor:** el `default-src 'self'` de A5 bloquearía otro dominio.

</Callout>

## Paso 7: prefetch y View Transitions

**Qué es:** el _prefetch_ descarga la página siguiente antes del clic; **View Transitions** navega con una transición, sin recargar.

**Cómo se usa:** en `astro.config.mjs`:

```js
export default defineConfig({
  prefetch: { prefetchAll: false, defaultStrategy: "hover" },
  // …
});
```

Y en cada enlace:

```html
<a href="/estadisticas" data-astro-prefetch>Estadísticas</a>
```

Con un servidor de 400 ms, del clic a ver la página:

```text
                         Sin prefetch   Con prefetch
Cache-Control max-age=0  453 ms         460 ms
Cache-Control max-age=60 455 ms         47 ms
```

- **Sin caché, no sirve:** descarga al pasar el ratón, gasta datos y vuelve a pedir al hacer clic. Con caché corta, 47 ms. En una página con datos del usuario:

```astro
---
Astro.response.headers.set("Cache-Control", "private, max-age=60");
---
```

View Transitions:

```astro
---
import { ClientRouter } from "astro:transitions";
---

<head>
  <ClientRouter />
</head>
```

- **6,5 KB más y navegación sin recarga,** pero la consola en dos páginas:

```text
script-una-vez
page-load
page-load
```

- **Los `<script>` no se vuelven a ejecutar:** solo se repite `astro:page-load`. El recolector de A6.1 envía al ocultar la pestaña con la ruta de ese momento, y la visita entera quedaría bajo la última. Aquí no compensa y no se añade.

<Callout type="risk">

- **Comprueba que tu prueba usa caché:** la primera medida no mostraba diferencia porque Chromium no reutiliza la caché con `ignoreHTTPSErrors`. Si un dato no cuadra, busca la causa.
- **`max-age` con datos, siempre `private`,** aceptando 60 s de retraso. Y solo enlaces seguros: el _prefetch_ hace GET, y un `/salir` por GET se ejecutaría solo.
- **En móvil no hay `hover`** (`tap` o `viewport`, que descarga de más), `prefetchAll` gasta datos y carga el servidor, y `ClientRouter` activa el _prefetch_.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

Reduce el JavaScript enviado en tu página más pesada al menos un 30 %, y mide el antes y el después.

</Callout>

Solución, con `/notas`, que tras el Paso 3 seguía en 92,3 KB:

```text
/notas             92.3 KB en 10 archivos
    55.8 KB  client.XI9U0KhD.js
    22.5 KB  schemas.CaUk71cF.js
     3.3 KB  _astro_actions.DBkyQHVi.js
     3.1 KB  Vitales.astro_astro_type_script_index_0_lang.Ck
```

- **`schemas` es Zod,** traído por `NuevaNota` (la lista de categorías) y `NuevaNotaFetch` (eso y validar el error). La misma receta. En `src/schemas/tipos.ts`:

```ts
export const CATEGORIAS = ["trabajo", "personal", "salud", "estudio"] as const;
```

En `src/schemas/nota.ts`, en lugar de la constante:

```ts
export { CATEGORIAS } from "./tipos";
import { CATEGORIAS } from "./tipos";
```

`NuevaNota.tsx` importa `CATEGORIAS` de `../schemas/tipos`, y `src/components/NuevaNotaFetch.tsx` queda sin Zod:

```tsx
import { CATEGORIAS } from "../schemas/tipos";
import type { NotaDTO } from "../schemas/nota";

type RespuestaError = { error: string; campos?: Record<string, string[]> };

// Dentro de guardar()
const cuerpo = (await res.json().catch(() => null)) as RespuestaError | null;
if (res.status === 422 && cuerpo) return setMensaje(`Revisa: ${Object.values(cuerpo.campos ?? {}).flat().join(", ")}`);
setMensaje(res.status === 409 && cuerpo ? cuerpo.error : "No se pudo guardar");
```

```text
/notas: de 103,8 KB a 69,4 KB, un 33 % menos
```

- **En un navegador:** el título vacío da «Revisa: El título es obligatorio», uno válido se guarda y las `<select>` siguen con 4 opciones.
- **`/entrar`, la más pesada (109,9 KB), no llega al 30 %:** sacar Zod daría un 22 %, y más exigiría rehacer el formulario sin React. Anotarlo y dejarla puede ser lo correcto.
- **Añade el resultado a `docs/rendimiento.md`** con fecha, y ajusta `scripts/presupuesto.mjs` para no perder lo ganado.

<Callout type="mastery">

Cada kilobyte de JavaScript de tus páginas tiene una justificación: sabes de dónde sale, qué página lo paga y por qué sigue ahí. Quitas islas antes de optimizarlas, cargas más tarde lo que se usa poco, y mides todas las páginas después de cada cambio. Sabes que `preload` puede empeorar el primer pintado, y que el _prefetch_ no hace nada sin caché.

</Callout>

## Resumen

- **Mide antes,** con `gzip` sobre el _build_ y `peso-js.mjs` por página.
- **Quitar gana a optimizar:** `/estadisticas` de 75 a 3 KB.
- **Carga diferida con un módulo tuyo,** nunca `import("zod")` (71 KB, y otra página a 141).
- **`import type` y constantes aparte.**
- **`client:visible`** retrasó 60 KB; `client:idle` no ahorró nada.
- **`<Image>`:** LCP de 1,8 a 0,5 s, de 294 a 29 KB.
- **Fuentes:** 50 de 188 KB; `preload` retrasó 100 ms el primer pintado.
- **`prefetch`:** de 455 a 47 ms, solo con caché. `ClientRouter` no reejecuta `<script>`.
