Better Auth, la librería de esta plataforma, registra usuarios, guarda sus contraseñas (I5.1), gestiona sesiones y lo expone como API (`/api/auth/sign-up/email`…) y como cliente para el navegador. No tiene servidor propio: es una función de tu app que guarda en tu base de datos mediante un **adaptador**. Aquí la añades con MongoDB y ves qué escribe en cada paso.

**Requisitos:** la app `entrenos-app` de I3 con `scripts/i5/hash.ts` (I5.1), y un MongoDB _replica set_ (Atlas lo es; uno local, solo si lo arrancaste así, B5.2).

## Paso 1: instalar y configurar las variables

**Qué es:** **`BETTER_AUTH_SECRET`** firma las _cookies_ de sesión, para que nadie fabrique una válida (justo lo que permitía la sesión de I3.4). **`BETTER_AUTH_URL`** es la dirección de la app, para construir enlaces y comprobar el origen de las peticiones (Paso 3).

**Cómo se usa:**

```bash
npm install better-auth @better-auth/mongo-adapter
```

Declara las dos en `astro:env` (I3.6). Sustituye `astro.config.mjs`:

```js
// @ts-check
import { defineConfig, envField } from "astro/config";
import react from "@astrojs/react";

import node from "@astrojs/node";

export default defineConfig({
  integrations: [react()],

  env: {
    schema: {
      // Secretas del servidor: nunca llegan al navegador ni al HTML
      MONGODB_URI: envField.string({ context: "server", access: "secret", startsWith: "mongodb" }),
      MONGODB_DB: envField.string({ context: "server", access: "secret", default: "entrenos_lab" }),
      // Better Auth: el secreto firma las cookies de sesión (mínimo 32 caracteres) y la URL base de la app
      BETTER_AUTH_SECRET: envField.string({ context: "server", access: "secret", min: 32 }),
      BETTER_AUTH_URL: envField.string({ context: "server", access: "secret", url: true }),
      // Públicas del servidor: configuración que no es secreta (se puede incrustar en el build)
      OBJETIVO_SEMANAL_MINUTOS: envField.number({ context: "server", access: "public", int: true, gt: 0, default: 150 }),
      // Públicas del cliente: las pueden leer los componentes de React. NUNCA un secreto.
      PUBLIC_NOMBRE_APP: envField.string({ context: "client", access: "public", default: "Mi entreno" }),
    },
    // Comprueba también las secretas al arrancar `astro dev` y `astro build`
    validateSecrets: true,
  },

  adapter: node({
    mode: "standalone",
  }),
});
```

Genera un secreto y añade las dos líneas a tu `.env`:

```bash
openssl rand -base64 32
```

```bash
BETTER_AUTH_SECRET="el-resultado-de-openssl"
BETTER_AUTH_URL="http://localhost:4321"
```

Y documéntalas en `.env.example`, sin el valor del secreto:

<Callout type="risk">

- **Un secreto por entorno, nunca el de los ejemplos:** compartido, una _cookie_ de desarrollo valdría en producción. Si se filtra, cámbialo: todas las sesiones caducan a la vez.
- **`BETTER_AUTH_URL` debe ser la dirección real:** con otro puerto, Better Auth rechaza las peticiones (Paso 3). En producción, tu dominio con `https`.
- **`min: 32` lo comprueba `validateSecrets`:** un secreto corto para `npm run dev` y el _build_ con un mensaje claro (I3.6).

</Callout>

## Paso 2: el servidor, `src/lib/auth.ts`

**Qué es:** la configuración de Better Auth en el servidor: base de datos, método de acceso y campos propios del usuario.

**Cómo se usa:** crea `src/lib/auth.ts`.

```ts
// Archivo: src/lib/auth.ts
// La configuración de Better Auth en el servidor: base de datos, método de acceso y sesiones
import { betterAuth } from "better-auth";
import { mongodbAdapter } from "@better-auth/mongo-adapter";
import { BETTER_AUTH_SECRET, BETTER_AUTH_URL } from "astro:env/server";
import { db, mongoClient } from "./mongo";

export const auth = betterAuth({
  appName: "Mi entreno",
  baseURL: BETTER_AUTH_URL,
  secret: BETTER_AUTH_SECRET,
  // El mismo cliente de la app (B5.2). Pasarlo permite a Better Auth usar transacciones (requiere replica set)
  database: mongodbAdapter(db, { client: mongoClient }),
  emailAndPassword: {
    enabled: true,
    autoSignIn: true, // tras registrarse, la sesión queda iniciada
    minPasswordLength: 8,
    maxPasswordLength: 128, // I5.1: sin límite, una contraseña de megas obliga a ejecutar scrypt sobre ella
  },
  user: {
    // Campos propios del usuario, además de los de Better Auth (name, email, image…)
    additionalFields: {
      zonaHoraria: { type: "string", required: false, defaultValue: "America/Mexico_City" },
    },
  },
});

/** El tipo de la sesión, con los campos adicionales incluidos */
export type Sesion = typeof auth.$Infer.Session;
```

- **`mongodbAdapter(db, { client: mongoClient })`** usa la conexión de la app (B5.2) y, con el cliente, **transacciones**: usuario y cuenta se crean juntos o ninguno.
- **`emailAndPassword`** activa correo y contraseña, el único método de esta plataforma (Better Auth admite también Google, GitHub…).
- **`additionalFields`** añade la zona horaria (I3) al documento `user`, con su tipo en la sesión. **`Sesion = typeof auth.$Infer.Session`** tipará `locals` en I5.3.

<Callout type="risk">

- **Sin _replica set_, el registro falla:** un MongoDB suelto no admite transacciones. Atlas o `--replSet` (B5.2); si no, quita `{ client: mongoClient }`, con el riesgo de un usuario sin cuenta si algo falla a mitad.
- **`auth.ts` es solo de servidor:** si React lo importa, el _build_ falla con `ServerOnlyModule` (I3.6). Es una protección.
- **Los campos adicionales se pueden enviar desde el cliente:** para uno que el usuario no debe elegir (un rol), `input: false`. Según `node_modules/better-auth/dist/db/schema.mjs`, el registro usa el valor por defecto y la edición responde `FIELD_NOT_ALLOWED`.

</Callout>

## Paso 3: la ruta _catch-all_ y el primer registro

**Qué es:** toda la API vive bajo `/api/auth/`. Una sola ruta con **parámetro _rest_** (`[...all]`) recoge cualquier subruta y se la pasa a Better Auth.

**Cómo se usa:** crea `src/pages/api/auth/[...all].ts`.

```ts
// Archivo: src/pages/api/auth/[...all].ts
// Una sola ruta para todo Better Auth: /api/auth/sign-up/email, /api/auth/sign-in/email, /api/auth/get-session…
import type { APIRoute } from "astro";
import { auth } from "../../../lib/auth";

export const prerender = false;

export const ALL: APIRoute = (ctx) => auth.handler(ctx.request);
```

- **`export const ALL`** responde a cualquier método, y **`auth.handler(ctx.request)`** recibe un `Request` y devuelve un `Response` estándar: vale en Astro, Vercel o cualquier servidor.

Prueba a registrarte:

```bash
curl -s -X POST http://localhost:4321/api/auth/sign-up/email \
  -H "origin: http://localhost:4321" -H "content-type: application/json" \
  -d '{"name":"Ana","email":"ana@entrenos.test","password":"Gatito2019!"}'
```

```text
{"error":"Inicia sesión para continuar"} (401)
```

- **Es el _middleware_ de I3.4,** que protege todo `/api/`. Añade `/api/auth/` a las excepciones; en `src/middleware.ts` solo cambia `PUBLICAS` (en I5.3 se reescribe entero):

```ts
// Archivo: src/middleware.ts
// Se ejecuta ANTES de cada página o endpoint renderizado en el servidor
import { defineMiddleware, sequence } from "astro:middleware";
import { COOKIE_SESION, usuarioPorId } from "./lib/sesion";

const PRIVADAS = ["/estadisticas", "/notas", "/nuevo", "/api/", "/_actions/"];
const PUBLICAS = ["/api/sesion", "/api/auth/"]; // excepciones dentro de las privadas (Better Auth, I5.2)

/** 0. Registro: método, ruta, código y duración de cada petición (va el primero para medirlo todo) */
const registrar = defineMiddleware(async (ctx, next) => {
  if (ctx.isPrerendered) return next(); // en el build no hay peticiones que registrar
  const inicio = performance.now();
  try {
    const respuesta = await next();
    const ms = (performance.now() - inicio).toFixed(1);
    console.log(`${ctx.request.method} ${ctx.url.pathname} → ${respuesta.status} (${ms} ms)`);
    return respuesta;
  } catch (error) {
    // Un error no capturado más abajo: se registra y se deja seguir hasta Astro (que responde 500)
    console.error(`${ctx.request.method} ${ctx.url.pathname} → error (${(performance.now() - inicio).toFixed(1)} ms)`, error);
    throw error;
  }
});

/** 1. Carga la sesión en locals: lo que pongas aquí lo verán todas las páginas y endpoints */
const cargarSesion = defineMiddleware((ctx, next) => {
  // En el build (páginas prerenderizadas) no hay petición: ni cookies ni usuario
  ctx.locals.usuario = ctx.isPrerendered ? null : usuarioPorId(ctx.cookies.get(COOKIE_SESION)?.value);
  return next();
});

/** 2. Protege las rutas privadas: ninguna página tiene que comprobarlo por su cuenta */
const proteger = defineMiddleware((ctx, next) => {
  if (ctx.isPrerendered) return next(); // una página estática no se puede proteger: ver el aviso de la lección
  const { pathname, search } = ctx.url;
  const privada = PRIVADAS.some((p) => pathname.startsWith(p)) && !PUBLICAS.some((p) => pathname.startsWith(p));
  if (!privada || ctx.locals.usuario) return next();

  const esApi = pathname.startsWith("/api/") || pathname.startsWith("/_actions/");
  if (esApi) return Response.json({ error: "Inicia sesión para continuar" }, { status: 401 });
  return ctx.redirect(`/entrar?volver=${encodeURIComponent(pathname + search)}`);
});

export const onRequest = sequence(registrar, cargarSesion, proteger);
```

Repite el registro con el servidor en el 4600 y `BETTER_AUTH_URL` en el 4321:

```text
{"message":"Invalid origin","code":"INVALID_ORIGIN"} (403)
{"token":"iVZny8pL…","user":{"name":"Ana","email":"ana@entrenos.test","emailVerified":false,"createdAt":"2026-10-16T19:17:41.192Z","updatedAt":"2026-10-16T19:17:41.192Z","zonaHoraria":"America/Mexico_City","id":"6ad27855d30b651f5b07a3d8"}} (200) sin cabecera Origin
```

- **`INVALID_ORIGIN`:** Better Auth rechaza un `Origin` distinto de `BETTER_AUTH_URL` (o `trustedOrigins`). Es la protección contra CSRF (B3.4).
- **Sin cabecera `Origin`, pasa** (segunda línea): así entran `curl` o una app móvil, y los navegadores siempre la envían en un POST de otra web.
- **La respuesta trae el _token_ y el usuario,** con `zonaHoraria` por defecto. Con el puerto correcto, funciona igual.

<Callout type="risk">

- **Registro, login y `get-session` se llaman sin sesión:** deben ser públicas. Esta plataforma usa `PUBLIC_PREFIXES = ["/api/auth/", "/api/health"]` en `src/middleware.ts`.
- **`prerender = false` es obligatorio:** con salida estática (I3.1), la ruta no existiría en producción.
- **En desarrollo, el puerto cambia:** esta plataforma usa una función `trustedOrigins` que, **solo en desarrollo**, acepta el origen local real (`src/lib/auth.ts`); en producción, solo `BETTER_AUTH_URL`.

</Callout>

## Paso 4: las colecciones y el formato de la contraseña

**Qué es:** Better Auth crea cuatro colecciones en tu base de datos.

| Colección      | Qué guarda                                                                                                                   | Cuándo cambia                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `user`         | Un documento por persona: nombre, correo, `emailVerified`, imagen y los campos adicionales                                   | Al registrarse y al editar el perfil          |
| `session`      | Una por sesión abierta: `token`, `userId`, `expiresAt`, IP y navegador                                                       | Al iniciar sesión, al renovarla y al cerrarla |
| `account`      | Una por forma de entrar: `providerId: "credential"` (correo y contraseña) con el _hash_ en `password`, o `google`, `github`… | Al registrarse y al vincular otro proveedor   |
| `verification` | _Tokens_ temporales: verificar el correo, recuperar la contraseña                                                            | Al pedir uno de esos correos                  |

**Cómo se usa:** la contraseña está en `account`, con el formato de I5.1. `scripts/i5/02-compatible.ts` la verifica con **tu** función:

```ts
// Archivo: scripts/i5/02-compatible.ts
// El verificar() de I5.1 comprueba un hash guardado por Better Auth: es el mismo formato
// Uso: node --env-file=.env scripts/i5/02-compatible.ts
import { MongoClient } from "mongodb";
import { verificar } from "./hash.ts";

const cliente = await MongoClient.connect(process.env.MONGODB_URI!);
const db = cliente.db(process.env.MONGODB_DB);
const usuario = await db.collection("user").findOne({ email: "ana@entrenos.test" });
const cuenta = await db.collection("account").findOne({ userId: usuario!._id, providerId: "credential" });

console.log(`account.password: ${String(cuenta!.password).slice(0, 12)}…  (${String(cuenta!.password).length} caracteres)`);
console.log(`verificar("Gatito2019!"): ${await verificar("Gatito2019!", cuenta!.password)}`);
console.log(`verificar("gatito2019!"): ${await verificar("gatito2019!", cuenta!.password)}`);
console.log(`account.userId es ${cuenta!.userId.constructor.name}, igual que user._id: ${cuenta!.userId.equals(usuario!._id)}`);
await cliente.close();
```

```bash
node --env-file=.env scripts/i5/02-compatible.ts
```

```text
account.password: cac457b6399b…  (161 caracteres)
verificar("Gatito2019!"): true
verificar("gatito2019!"): false
account.userId es ObjectId, igual que user._id: true
```

- **El `verificar` de I5.1 acepta el _hash_ de Better Auth:** mismo algoritmo, parámetros y `sal:clave` de 161 caracteres.
- **`account.userId` es un `ObjectId`,** como `user._id`, pero las colecciones de la plataforma (`section_progress`, `quiz_attempts`) guardan el `userId` como **texto**. Al cruzarlas, cuidado con el tipo.

<Callout type="risk">

- **No escribas en estas colecciones a mano:** borrar un usuario en MongoDB deja huérfanas sus sesiones y cuentas. API de Better Auth (`auth.api.…`) o un _script_ que trate las cuatro.
- **Las sesiones caducadas de quien no vuelve se quedan:** un índice TTL sobre `expiresAt` (B5.6) las borra.
- **`user` tiene datos personales:** entra en los _backups_ (Tanda 10) y fuera de los registros.

</Callout>

## Paso 5: el cliente de React

**Qué es:** en el navegador no se importa `auth.ts` (tiene el secreto), sino un **cliente** que llama a `/api/auth/` por `fetch`.

**Cómo se usa:** crea `src/lib/auth-client.ts`.

```ts
// Archivo: src/lib/auth-client.ts
// El cliente de Better Auth para los componentes de React (se ejecuta en el navegador)
import { createAuthClient } from "better-auth/react";
import { inferAdditionalFields } from "better-auth/client/plugins";
import type { auth } from "./auth"; // import type: solo los tipos, el código del servidor no llega al navegador

export const authClient = createAuthClient({
  // Sin baseURL: usa el mismo origen que la página (http://localhost:4321)
  plugins: [inferAdditionalFields<typeof auth>()],
});
```

- **`import type { auth }`** trae solo los **tipos**: el cliente conoce `zonaHoraria` (con `inferAdditionalFields`) sin que `auth.ts` llegue al navegador. Sin `baseURL`, llama al mismo origen.

Un componente, `src/components/SesionActual.tsx`:

```tsx
// Archivo: src/components/SesionActual.tsx
// Quién ha iniciado sesión, leído en el navegador con el cliente de Better Auth
import { authClient } from "../lib/auth-client";

export default function SesionActual() {
  const { data, isPending } = authClient.useSession(); // pide /api/auth/get-session y se actualiza solo

  if (isPending) return <span id="sesion">…</span>;
  if (!data) return <span id="sesion">Sin sesión</span>;

  return (
    <span id="sesion">
      {data.user.name} · {data.user.zonaHoraria /* campo adicional, con su tipo */}{" "}
      <button type="button" onClick={() => authClient.signOut()}>
        Salir
      </button>
    </span>
  );
}
```

En Chrome, sin sesión, al entrar, al recargar y tras "Salir":

```text
sin sesión: Sin sesión
tras iniciar sesión: Ana · America/Mexico_City Salir
cookie: better-auth.session_token httpOnly: true sameSite: Lax secure: false JS la ve: false
tras pulsar Salir: Sin sesión

```

- **`useSession`** pide `/api/auth/get-session` al montarse y se actualiza solo: tras "Salir", pasa a "Sin sesión" sin recargar.
- **La _cookie_ `better-auth.session_token` es `httpOnly`:** `document.cookie` no la ve, ni un código inyectado (XSS, A5) podría robarla. `SameSite=Lax` impide su envío en POST de otras webs, y `secure: false` es solo por `http` en `localhost`.

<Callout type="risk">

- **`Invalid hook call` en la consola del servidor** tras añadir el componente: Vite optimizó `better-auth/react` en marcha y hay dos copias de React. `npm run dev -- --force`, como el `504` de I3.3.
- **La sesión del cliente pinta, no protege:** la protección está en cada _endpoint_ (I5.3).
- **`useSession` hace una petición por componente:** léelo una vez arriba y pásalo por _props_ (I2.4).

</Callout>

Solución con dos _scripts_, repetible. `scripts/i5/02-estado.ts` enseña las colecciones sin secretos completos:

```ts
// Archivo: scripts/i5/02-estado.ts
// Qué hay en las 4 colecciones de Better Auth (sin enseñar secretos completos)
// Uso: node --env-file=.env scripts/i5/02-estado.ts "título del paso"
import { MongoClient } from "mongodb";

const cliente = await MongoClient.connect(process.env.MONGODB_URI!);
const db = cliente.db(process.env.MONGODB_DB);
const corto = (v: unknown) => (typeof v === "string" && v.length > 16 ? `${v.slice(0, 8)}…(${v.length})` : v);
const hora = (d: unknown) => (d instanceof Date ? d.toISOString().slice(11, 19) : d);

console.log(`── ${process.argv[2] ?? "estado"}`);
for (const nombre of ["user", "session", "account", "verification"]) {
  const docs = await db.collection(nombre).find().toArray();
  console.log(`  ${nombre} (${docs.length})`);
  for (const d of docs) {
    const resumen =
      nombre === "user"
        ? { email: d.email, name: d.name, emailVerified: d.emailVerified, zonaHoraria: d.zonaHoraria }
        : nombre === "session"
          ? { userId: corto(String(d.userId)), token: corto(d.token), expiresAt: d.expiresAt?.toISOString().slice(0, 10), ip: d.ipAddress, userAgent: corto(d.userAgent) }
          : nombre === "account"
            ? { providerId: d.providerId, accountId: corto(String(d.accountId)), password: corto(d.password) }
            : { identifier: d.identifier, expiresAt: hora(d.expiresAt) };
    console.log(`    ${JSON.stringify(resumen)}`);
  }
}
await cliente.close();
```

`scripts/i5/02-flujo.sh` recorre el flujo con `curl` y llama al anterior en cada paso:

```bash
#!/bin/sh
# Archivo: scripts/i5/02-flujo.sh
# Registro → sesión → cerrar sesión → iniciar sesión → cerrar sesión, enseñando las colecciones en cada paso
B=http://localhost:4321
J=/tmp/entrenos-cookies.txt
rm -f "$J"
estado() { node --env-file=.env scripts/i5/02-estado.ts "$1"; }
pedir() { # método ruta [cuerpo]
  curl -s -b "$J" -c "$J" -o /tmp/entrenos-respuesta.json -w "  %{http_code} $1 $2\n" -X "$1" "$B$2" \
    -H "origin: $B" -H "content-type: application/json" ${3:+-d "$3"}
}

estado "0. antes de nada"
pedir POST /api/auth/sign-up/email '{"name":"Ana","email":"ana@entrenos.test","password":"Gatito2019!"}'
estado "1. tras registrarse"
pedir GET /api/auth/get-session
echo "  get-session: $(head -c 160 /tmp/entrenos-respuesta.json)…"
pedir POST /api/auth/sign-out '{}'
estado "2. tras cerrar sesión"
pedir POST /api/auth/sign-in/email '{"email":"ana@entrenos.test","password":"Gatito2019!"}'
estado "3. tras iniciar sesión"
```

- **Cerrar sesión borra la sesión,** no solo la _cookie_: una _cookie_ copiada antes ya no sirve.
- **Cada inicio crea una sesión nueva:** con dos dispositivos, dos documentos; cerrar uno no cierra el otro.
- **`verification` sigue vacía:** solo la usan la verificación de correo y la recuperación de contraseña, desactivadas aquí.

<Callout type="risk">

- **El _token_ es una contraseña temporal:** el _script_ enseña 8 caracteres. Completo, es la sesión: ni registros, ni _issues_, ni capturas.
- **Correos de prueba** (`@entrenos.test`), y bórralos al terminar. Los E2E de esta plataforma usan una base en memoria que se descarta.

</Callout>

## Resumen

- `betterAuth({ database: mongodbAdapter(db, { client }), emailAndPassword, user: { additionalFields } })`, solo de servidor.
- `src/pages/api/auth/[...all].ts` con `ALL = (ctx) => auth.handler(ctx.request)`, pública en el _middleware_.
- Un `Origin` distinto de `BETTER_AUTH_URL` da `INVALID_ORIGIN`.
- `user`, `session`, `account` (con el _hash_) y `verification`.
- `createAuthClient` con `inferAdditionalFields`; _cookie_ `httpOnly` y `SameSite=Lax`.
