Las estadísticas, los avisos a una hora y la búsqueda piden más que un CRUD. Cada uno usa una pieza avanzada de MongoDB: una agregación, una operación atómica sobre un índice parcial y un índice de texto.

**Requisitos:** P1.5, I4.4, I4.5 y A2. Medido con MongoDB 8.2.6 local y un Telegram falso: no se ha llamado a la API real.

## Paso 1: estadísticas con una agregación

**Qué es:** P7, las tareas hechas por semana y categoría, calculadas en MongoDB con un _pipeline_ (I4.4) en lugar de traer todas las tareas a Node.

**Cómo se usa:** crea el repositorio de la _feature_, lo que ofrece al resto y la página. El _layout_ gana un menú para las páginas privadas.

```ts
// Archivo: src/features/estadisticas/estadisticas.repo.ts
import type { Db } from "mongodb";

export interface FilaSemana {
  semana: string; // el lunes de esa semana, AAAA-MM-DD
  categoria: string;
  color: string;
  hechas: number;
}

export function crearRepoEstadisticas(db: Db) {
  const tareas = db.collection("tareas");
  return {
    /** P7: tareas hechas por semana (de lunes a domingo) y categoría, desde un día */
    hechasPorSemana: (userId: string, desde: string) =>
      tareas
        .aggregate<FilaSemana>([
          // Igualdad en userId y rango en dia: usa el índice userId_dia
          { $match: { userId, dia: { $gte: desde }, hecha: true } },
          {
            $group: {
              _id: {
                // dia es texto (ADR 0001): se convierte a fecha solo para agrupar
                semana: {
                  $dateTrunc: {
                    date: { $dateFromString: { dateString: "$dia" } },
                    unit: "week",
                    startOfWeek: "monday",
                  },
                },
                categoria: "$categoria.id", // por id: un cambio de nombre no parte el grupo
              },
              categoria: { $last: "$categoria.nombre" },
              color: { $last: "$categoria.color" },
              hechas: { $sum: 1 },
            },
          },
          { $sort: { "_id.semana": -1, hechas: -1, categoria: 1 } },
          {
            $project: {
              _id: 0,
              semana: { $dateToString: { date: "$_id.semana", format: "%Y-%m-%d" } },
              categoria: 1,
              color: 1,
              hechas: 1,
            },
          },
        ])
        .toArray(),
  };
}
```

Y en `src/pages/index.astro`, la portada usa el menú: `<Base title="Hoy" nav>`.

- **`$dateTrunc` con `startOfWeek: "monday"`:** agrupa de lunes a domingo; el valor por defecto empieza en domingo.
- **Se agrupa por `categoria.id` y se muestra el último nombre:** si el usuario renombra una categoría, sus semanas anteriores no se parten en dos filas.

<Callout type="risk">

- **El `$match` va primero, con `userId` y `dia`:** así usa el índice `userId_dia` y el resto del _pipeline_ trabaja solo con las tareas de un usuario. Un `$match` después del `$group` recorrería las de todos.
- **Se agrupa por el día planificado, no por cuándo se completó:** una tarea del lunes marcada el miércoles cuenta en la semana del lunes. Si importa cuándo se hizo, hace falta un campo `hechaEn`, y es una decisión para el ADR.

</Callout>

## Paso 2: _cron_, no _change streams_

**Qué es:** la decisión de cómo enviar un aviso a una hora. Un _change stream_ (A2) avisa cuando un documento cambia, pero un aviso no depende de un cambio: depende de que llegue una hora.

**Cómo se usa:** cada minuto, un _cron_ llama a una ruta protegida de la app, que envía los avisos vencidos usando el índice parcial `avisos_pendientes` de P1.2.

| Opción                          | A favor                                           | En contra                                                                          |
| ------------------------------- | ------------------------------------------------- | ---------------------------------------------------------------------------------- |
| _Change streams_                | Reacciona al instante a cada cambio               | No sabe de horas; necesita _replica set_ y un proceso siempre escuchando           |
| Un `setInterval` en el servidor | Sin piezas nuevas                                 | Vive en el proceso web: cada instancia, y cada recarga en desarrollo, arranca otro |
| _Cron_ que llama a una ruta     | La app tal cual, con un único reloj fuera de ella | Hasta un minuto de retraso; la ruta necesita su propio secreto                     |

- **El _cron_ lo programa P1.8 en el VPS:** aquí basta con la ruta y una forma de llamarla a mano.

<Callout type="risk">

- **Un aviso tiene que llegar una vez, aunque coincidan dos ejecuciones:** si una tarda más de un minuto, la siguiente empieza antes de que acabe. El Paso 4 lo resuelve con una operación atómica, y el test del Paso 5 lo comprueba.
- **Un minuto de retraso es parte del diseño:** el aviso sale 15 minutos antes, así que llegar a los 14 no incumple nada. Si el requisito fuera «a la hora exacta», el _cron_ no bastaría.

</Callout>

## Paso 3: vincular Telegram

**Qué es:** el usuario abre `t.me/<bot>?start=<código>` y pulsa «Iniciar». El bot recibe `/start <código>` y la app guarda su chat. El código dice qué usuario es y hasta cuándo vale, y va firmado para que nadie fabrique uno ajeno.

**Cómo se usa:** declara las variables, crea el código firmado y el cliente de la Bot API, guarda el chat en el usuario y muestra el enlace en Ajustes.

```ts
// Archivo: src/features/avisos/vinculo.ts
// El código del enlace t.me/<bot>?start=<código>: dice qué usuario es, hasta cuándo vale, y va firmado.
// Telegram solo admite A-Z, a-z, 0-9, _ y - en ese parámetro, y 64 caracteres como máximo.
import { createHmac, timingSafeEqual } from "node:crypto";

const VALIDEZ_MS = 15 * 60_000;

const firma = (texto: string, secreto: string) =>
  createHmac("sha256", secreto)
    .update(`vinculo-telegram:${texto}`) // otro propósito, otra firma, aunque el secreto se comparta
    .digest("base64url")
    .replaceAll("_", "") // el _ separa las partes del código
    .slice(0, 22);

export function crearCodigo(userId: string, secreto: string, ahora = Date.now()): string {
  const cuerpo = `${userId}_${(ahora + VALIDEZ_MS).toString(36)}`;
  return `${cuerpo}_${firma(cuerpo, secreto)}`;
}

/** El userId si el código es auténtico y no ha caducado; si no, null */
export function leerCodigo(codigo: string, secreto: string, ahora = Date.now()): string | null {
  const [userId, caduca, recibida, ...sobra] = codigo.split("_");
  if (!userId || !caduca || !recibida || sobra.length > 0) return null;
  const esperada = firma(`${userId}_${caduca}`, secreto);
  const igual =
    recibida.length === esperada.length &&
    timingSafeEqual(Buffer.from(recibida), Buffer.from(esperada));
  if (!igual || parseInt(caduca, 36) < ahora) return null;
  return userId;
}
```

```ts
// Archivo: src/features/avisos/telegram.ts
// Las dos llamadas a la Bot API que usa la app: https://core.telegram.org/bots/api

export interface Actualizacion {
  update_id: number;
  message?: { chat: { id: number }; text?: string };
}

export function crearTelegram({ url, token }: { url: string; token: string }) {
  async function llamar<T>(metodo: string, cuerpo: object): Promise<T> {
    const r = await fetch(`${url}/bot${token}/${metodo}`, {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify(cuerpo),
      signal: AbortSignal.timeout(10_000), // una API lenta no puede bloquear la ejecución entera
    });
    const datos = (await r.json()) as { ok: boolean; result: T; description?: string };
    if (!datos.ok) throw new Error(`Telegram ${metodo}: ${datos.description}`);
    return datos.result;
  }

  return {
    enviar: (chatId: string, texto: string) =>
      llamar("sendMessage", { chat_id: chatId, text: texto }),
    /** Los mensajes recibidos desde offset; los anteriores quedan confirmados y no vuelven */
    actualizaciones: (offset: number) =>
      llamar<Actualizacion[]>("getUpdates", { offset, timeout: 0, allowed_updates: ["message"] }),
  };
}

export type Telegram = ReturnType<typeof crearTelegram>;
```

- **`getUpdates` en vez de un _webhook_:** el _webhook_ necesita una URL pública con HTTPS, que no existe hasta P1.8. Leer las actualizaciones en cada ejecución del _cron_ funciona también en local.

- **Un enlace de vínculo sin caducidad es una llave permanente:** quien lo encuentre en un historial vincula su chat y recibe tus avisos. Por eso caduca a los 15 minutos y la firma cubre también la caducidad.

## Paso 4: enviar los avisos

**Qué es:** el servicio que, en cada ejecución, lee los `/start` recibidos y envía los avisos vencidos. Cada aviso se **reclama** quitando su `avisarEn` en la misma operación que lo encuentra.

**Cómo se usa:** crea el servicio, lo que ofrece la _feature_ y la ruta del _cron_, y abre esa ruta en el _middleware_.

```ts
// Archivo: src/features/avisos/avisos.service.ts
import { ObjectId, type Db } from "mongodb";
import type { Tarea } from "@/features/tareas/tareas.repo";
import { leerCodigo } from "./vinculo";
import type { Telegram } from "./telegram";

interface UsuarioConTelegram {
  _id: ObjectId; // la colección user de Better Auth guarda el id como ObjectId
  telegramChatId?: string;
}

export function crearServicioAvisos(deps: { db: Db; telegram: Telegram; secreto: string }) {
  const { db, telegram, secreto } = deps;
  const tareas = db.collection<Tarea>("tareas");
  const usuarios = db.collection<UsuarioConTelegram>("user");
  // En memoria: tras un reinicio, Telegram reenvía lo de las últimas 24 h, y vincular es idempotente
  let offset = 0;

  return {
    /** Lee los /start <código> recibidos por el bot y guarda el chat de cada usuario */
    async vincularPendientes(): Promise<number> {
      let vinculados = 0;
      for (const a of await telegram.actualizaciones(offset)) {
        offset = a.update_id + 1;
        const chatId = a.message?.chat.id;
        const texto = a.message?.text ?? "";
        if (!chatId || !texto.startsWith("/start ")) continue;

        const userId = leerCodigo(texto.slice("/start ".length).trim(), secreto);
        if (!userId || !ObjectId.isValid(userId)) {
          await telegram.enviar(
            String(chatId),
            "El enlace no es válido o ha caducado. Genera otro en Ajustes.",
          );
          continue;
        }
        await usuarios.updateOne(
          { _id: new ObjectId(userId) },
          { $set: { telegramChatId: String(chatId) } },
        );
        await telegram.enviar(
          String(chatId),
          "Listo: te avisaré aquí 15 minutos antes de cada tarea con hora.",
        );
        vinculados++;
      }
      return vinculados;
    },

    /** P6: envía los avisos vencidos, como mucho `maximo` por ejecución */
    async enviarVencidos(ahora = new Date(), maximo = 100): Promise<number> {
      let enviados = 0;
      for (let i = 0; i < maximo; i++) {
        // Reclamar quitando avisarEn, en una sola operación atómica (índice avisos_pendientes):
        // dos ejecuciones a la vez nunca se llevan la misma tarea
        const tarea = await tareas.findOneAndUpdate(
          { avisarEn: { $lte: ahora } },
          { $unset: { avisarEn: "" } },
          { sort: { avisarEn: 1 } },
        );
        if (!tarea) break;
        const usuario = await usuarios.findOne({ _id: new ObjectId(tarea.userId) });
        if (!usuario?.telegramChatId) continue; // sin Telegram vinculado: no hay a quién avisar
        try {
          await telegram.enviar(usuario.telegramChatId, `⏰ ${tarea.hora} · ${tarea.titulo}`);
          enviados++;
        } catch (error) {
          console.error("[avisos] No se pudo enviar", tarea._id.toHexString(), error);
        }
      }
      return enviados;
    },
  };
}

export type ServicioAvisos = ReturnType<typeof crearServicioAvisos>;
```

```ts
// Archivo: src/pages/api/avisos/ejecutar.ts
// La llama el cron cada minuto: curl -X POST -H "Authorization: Bearer $CRON_SECRET" …
import { createHash, timingSafeEqual } from "node:crypto";
import type { APIRoute } from "astro";
import { CRON_SECRET } from "astro:env/server";
import { servicioAvisos } from "@/features/avisos/server";

/** Compara en tiempo constante: con === el tiempo de respuesta delataría cuántos caracteres aciertan */
function autorizado(cabecera: string | null): boolean {
  const resumen = (texto: string) => createHash("sha256").update(texto).digest();
  return timingSafeEqual(resumen(cabecera ?? ""), resumen(`Bearer ${CRON_SECRET}`));
}

export const POST: APIRoute = async ({ request }) => {
  if (!autorizado(request.headers.get("authorization"))) {
    return Response.json({ error: "No autorizado" }, { status: 401 });
  }
  if (!servicioAvisos) return Response.json({ error: "Telegram no configurado" }, { status: 503 });
  const vinculados = await servicioAvisos.vincularPendientes();
  const enviados = await servicioAvisos.enviarVencidos();
  return Response.json({ vinculados, enviados });
};
```

```ts
const PREFIJOS_PUBLICOS = ["/api/auth/", "/api/health", "/api/avisos/ejecutar"];

export const onRequest = defineMiddleware(async (ctx, next) => {
  const { pathname, search } = ctx.url;
  ctx.locals.user = null;
  if (PREFIJOS_PUBLICOS.some((p) => pathname.startsWith(p))) return next();

  const sesion = await auth.api.getSession({ headers: ctx.request.headers });
  ctx.locals.user = sesion?.user ?? null;

  if (PAGINAS_DE_ACCESO.has(pathname)) return ctx.locals.user ? ctx.redirect("/") : next();
  if (ctx.locals.user) return next();

  if (pathname.startsWith("/api/")) {
    return Response.json({ error: "No autenticado" }, { status: 401 });
  }
  return ctx.redirect(`/login?redirect=${encodeURIComponent(pathname + search)}`);
});
```

- **Como mucho, una entrega:** si Telegram falla después de reclamar el aviso, el aviso se pierde y queda en el registro. Reenviarlo podría duplicarlo, y para un recordatorio es peor recibirlo dos veces que perder uno de vez en cuando.
- **La ruta pública es exacta, `/api/avisos/ejecutar`:** un prefijo como `/api/avisos/` abriría también cualquier ruta futura bajo él (P1.4).

<Callout type="risk">

- **Buscar y después marcar no es atómico:** con un `findOne` y un `updateOne` separados, dos ejecuciones encuentran la misma tarea antes de que ninguna la marque. En el test de concurrencia del Paso 5, así se enviaron 34 avisos de 20 tareas.
- **El secreto del _cron_ se compara en tiempo constante:** con `===`, la respuesta tarda un poco más cuantos más caracteres iniciales aciertan, y eso permite adivinarlo poco a poco. `timingSafeEqual` sobre los dos resúmenes tarda siempre lo mismo.

</Callout>

```ts
        },
```

```ts
        creada: { bsonType: "date" },
      },
    },

      { key: { userId: 1, dia: 1 }, name: "userId_dia" },

        name: "avisos_pendientes",
        partialFilterExpression: { avisarEn: { $exists: true } },
      },

        name: "userId_titulo_texto",
        default_language: "spanish",
      },

/** Crea o actualiza cada colección con su esquema e índices; devuelve una línea por colección */
export async function aplicarColecciones(db: Db): Promise<string[]> {
  const resultado: string[] = [];
  for (const c of COLECCIONES) {
    const opciones = {
      validator: { $jsonSchema: c.esquema },
      validationLevel: "strict",
      validationAction: "error",
    } as const;
    const existe = (await db.listCollections({ name: c.nombre }).toArray()).length > 0;
    if (existe) await db.command({ collMod: c.nombre, ...opciones });
    else await db.createCollection(c.nombre, opciones);
    const indices = await db.collection(c.nombre).createIndexes(c.indices);
    resultado.push(`${existe ? "actualizada" : "creada"}: ${c.nombre} (${indices.join(", ")})`);
  }
  return resultado;
}
```

```ts
// Archivo: src/features/tareas/tareas.repo.ts
import { ObjectId, type Db, type UpdateFilter } from "mongodb";

export interface Tarea {
  _id: ObjectId;
  userId: string;
  titulo: string;
  dia: string;
  hora?: string;
  hecha: boolean;
  categoria: { id: ObjectId; nombre: string; color: string };
  avisarEn?: Date;
  creada: Date;
}

const ID = /^[0-9a-f]{24}$/i;
const filtro = (userId: string, id: string) =>
  ID.test(id) ? { _id: new ObjectId(id), userId } : null;

/** Todas las consultas llevan el userId en el filtro: no hay forma de leer una tarea ajena */
export function crearRepoTareas(db: Db) {
  const col = db.collection<Tarea>("tareas");
  return {
    async crear(datos: Omit<Tarea, "_id">): Promise<Tarea> {
      const tarea = { ...datos, _id: new ObjectId() };
      await col.insertOne(tarea);
      return tarea;
    },

    // P1: índice userId_dia; las de sin hora, primero
    delDia: (userId: string, dia: string) =>
      col.find({ userId, dia }).sort({ hora: 1, creada: 1 }).toArray(),

    buscar(userId: string, id: string) {
      const f = filtro(userId, id);
      return f ? col.findOne(f) : Promise.resolve(null);
    },

    actualizar(userId: string, id: string, cambios: UpdateFilter<Tarea>) {
      const f = filtro(userId, id);
      return f ? col.findOneAndUpdate(f, cambios, { returnDocument: "after" }) : null;
    },

    async borrar(userId: string, id: string): Promise<boolean> {
      const f = filtro(userId, id);
      return f ? (await col.deleteOne(f)).deletedCount === 1 : false;
    },

    // P8: índice userId_titulo_texto; userId tiene que ir con igualdad para poder usarlo
    buscarTexto: (userId: string, texto: string) =>
      col
        .find({ userId, $text: { $search: texto } })
        .sort({ puntuacion: { $meta: "textScore" } })
        .limit(20)
        .toArray(),

    // P5: la copia del nombre y el color en cada tarea (ADR 0002)
    async recolorear(userId: string, categoria: { _id: ObjectId; nombre: string; color: string }) {
      const { modifiedCount } = await col.updateMany(
        { userId, "categoria.id": categoria._id },
        { $set: { "categoria.nombre": categoria.nombre, "categoria.color": categoria.color } },
      );
      return modifiedCount;
    },
  };
}
```

```ts
// Archivo: src/features/tareas/tareas.service.ts
// Las reglas de las tareas, sin HTTP ni MongoDB: reciben los repositorios (y se prueban con ellos)
import { MongoServerError } from "mongodb";
import type { CambioCategoria, RepoCategorias } from "@/features/categorias/server";
import { diaEn, instanteEn } from "@/lib/dia";
import { Conflicto, NoEncontrado } from "@/lib/errores";
import type { CambioTarea, NuevaTarea, TareaVista } from "./tarea.schema";
import type { RepoTareas, Tarea } from "./tareas.repo";

export const MINUTOS_DE_AVISO = 15;

export interface Usuario {
  id: string;
  zonaHoraria: string;
}

/** Cuándo avisar: 15 min antes de la hora, y nunca si la tarea ya ha pasado o no tiene hora */
export function calcularAviso(
  t: { dia: string; hora?: string; hecha: boolean },
  zona: string,
  ahora: Date,
): Date | undefined {
  if (!t.hora || t.hecha) return undefined;
  const instante = instanteEn(t.dia, t.hora, zona);
  if (instante <= ahora) return undefined;
  return new Date(instante.getTime() - MINUTOS_DE_AVISO * 60_000);
}

export function aVista(t: Tarea): TareaVista {
  return {
    id: t._id.toHexString(),
    titulo: t.titulo,
    dia: t.dia,
    ...(t.hora && { hora: t.hora }),
    hecha: t.hecha,
    categoria: { ...t.categoria, id: t.categoria.id.toHexString() },
  };
}

export function crearServicioTareas(repos: { tareas: RepoTareas; categorias: RepoCategorias }) {
  const { tareas, categorias } = repos;

  async function categoriaDe(usuario: Usuario, id: string) {
    const c = await categorias.buscar(usuario.id, id);
    if (!c) throw new NoEncontrado("Categoría no encontrada"); // también si es de otro usuario
    return { id: c._id, nombre: c.nombre, color: c.color };
  }

  return {
    async deHoy(usuario: Usuario, ahora = new Date()) {
      return (await tareas.delDia(usuario.id, diaEn(ahora, usuario.zonaHoraria))).map(aVista);
    },

    async buscar(usuario: Usuario, texto: string) {
      return (await tareas.buscarTexto(usuario.id, texto)).map(aVista);
    },

    async una(usuario: Usuario, id: string) {
      const tarea = await tareas.buscar(usuario.id, id);
      if (!tarea) throw new NoEncontrado("Tarea no encontrada");
      return aVista(tarea);
    },

    async crear(usuario: Usuario, datos: NuevaTarea, ahora = new Date()) {
      const { categoriaId, ...resto } = datos;
      const base = { ...resto, hecha: false };
      const avisarEn = calcularAviso(base, usuario.zonaHoraria, ahora);
      const tarea = await tareas.crear({
        ...base,
        userId: usuario.id,
        categoria: await categoriaDe(usuario, categoriaId),
        ...(avisarEn && { avisarEn }),
        creada: ahora,
      });
      return aVista(tarea);
    },

    async cambiar(usuario: Usuario, id: string, cambios: CambioTarea, ahora = new Date()) {
      const actual = await tareas.buscar(usuario.id, id);
      if (!actual) throw new NoEncontrado("Tarea no encontrada");

      const { categoriaId, hora, ...resto } = cambios;
      const final = {
        ...actual,
        ...resto,
        hora: hora === null ? undefined : (hora ?? actual.hora),
      };
      const avisarEn = calcularAviso(final, usuario.zonaHoraria, ahora);

      const $set: Partial<Tarea> = { ...resto, ...(final.hora && { hora: final.hora }) };
      if (categoriaId) $set.categoria = await categoriaDe(usuario, categoriaId);
      if (avisarEn) $set.avisarEn = avisarEn;
      const $unset = {
        ...(!final.hora && { hora: "" as const }),
        ...(!avisarEn && { avisarEn: "" as const }),
      };
      // MongoDB rechaza un $set o un $unset vacíos: solo se envía el que tiene algo
      const actualizada = await tareas.actualizar(usuario.id, id, {
        ...(Object.keys($set).length > 0 && { $set }),
        ...(Object.keys($unset).length > 0 && { $unset }),
      });
      if (!actualizada) throw new NoEncontrado("Tarea no encontrada");
      return aVista(actualizada);
    },

    async borrar(usuario: Usuario, id: string) {
      if (!(await tareas.borrar(usuario.id, id))) throw new NoEncontrado("Tarea no encontrada");
    },

    /** P5: cambia la categoría y la copia que guarda cada una de sus tareas (ADR 0002) */
    async cambiarCategoria(usuario: Usuario, id: string, cambios: CambioCategoria) {
      const actual = await categorias.buscar(usuario.id, id);
      if (!actual) throw new NoEncontrado("Categoría no encontrada");
      try {
        const categoria = await categorias.cambiar(usuario.id, actual._id, cambios);
        if (!categoria) throw new NoEncontrado("Categoría no encontrada");
        const tareasActualizadas = await tareas.recolorear(usuario.id, categoria);
        const { nombre, color } = categoria;
        return { id: categoria._id.toHexString(), nombre, color, tareasActualizadas };
      } catch (error) {
        // 11000: el índice único userId_nombre_unico ya tiene ese nombre para este usuario
        if (error instanceof MongoServerError && error.code === 11000) {
          throw new Conflicto("Ya tienes una categoría con ese nombre");
        }
        throw error;
      }
    },
  };
}

export type ServicioTareas = ReturnType<typeof crearServicioTareas>;
```

```ts
import type { APIRoute } from "astro";
import { nuevaTarea, servicioTareas } from "@/features/tareas/server";
import { leerCuerpo, responderError } from "@/lib/http";

/** Las de hoy, o las que coinciden con ?q= (de 2 a 100 caracteres) */
export const GET: APIRoute = async ({ locals, url }) => {
  if (!locals.user) return Response.json({ error: "No autenticado" }, { status: 401 });
  const q = url.searchParams.get("q")?.trim();
  if (q === undefined) return Response.json(await servicioTareas.deHoy(locals.user));
  if (q.length < 2 || q.length > 100) {
    return Response.json({ error: "Escribe de 2 a 100 caracteres" }, { status: 400 });
  }
  return Response.json(await servicioTareas.buscar(locals.user, q));
};

export const POST: APIRoute = async ({ locals, request }) => {
  if (!locals.user) return Response.json({ error: "No autenticado" }, { status: 401 });
  const datos = await leerCuerpo(request, nuevaTarea);
  if (datos instanceof Response) return datos;
  try {
    return Response.json(await servicioTareas.crear(locals.user, datos), { status: 201 });
  } catch (error) {
    return responderError(error);
  }
};
```

- **El índice empieza por `userId`:** en un índice de texto compuesto, los campos anteriores al de texto tienen que ir con igualdad en la consulta. Así cada búsqueda solo recorre las tareas de un usuario.

<Callout type="risk">

- **Un requisito incumplido se decide, no se esconde:** Atlas Search tolera errores de escritura, pero necesita un servicio que este despliegue no tiene, y añadirlo es una decisión de arquitectura. La otra salida es cambiar el criterio en `docs/requisitos.md` y dejar el motivo en un ADR.
- **Solo cabe un índice de texto por colección:** si mañana quieres buscar también en notas, hay que rehacer este con los dos campos. Elige bien qué campos entran.

</Callout>

<Callout type="mastery">

Aplicas conceptos avanzados de MongoDB a casos reales: una agregación que usa el índice y agrupa por semana, una operación atómica sobre un índice parcial para que un aviso salga una sola vez aunque coincidan dos ejecuciones, y un índice de texto con sus límites medidos. Cada uno tiene tests, y los avisos se prueban sin llamar a Telegram.

</Callout>

## Resumen

- Estadísticas: `$match` con el índice primero, `$group` por semana con `$dateTrunc`.
- Un aviso depende de una hora, no de un cambio: _cron_ y no _change streams_.
- El enlace de Telegram lleva usuario, caducidad y firma.
- Reclamar con `findOneAndUpdate` hace que cada aviso salga una sola vez.
- Telegram falso en los tests: nunca la API real.
- El índice de texto no tolera errores de escritura: medirlo obliga a decidir.
