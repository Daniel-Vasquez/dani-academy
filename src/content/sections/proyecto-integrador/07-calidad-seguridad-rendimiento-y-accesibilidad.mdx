Antes de publicar, la v2 se audita con datos: la lista de seguridad de A5, Lighthouse y axe. Cada hallazgo se mide antes, se corrige y se vuelve a medir, y el informe queda en el repositorio.

<Callout type="risk">

- **Revisar el código no basta para la configuración:** el límite de intentos estaba «configurado» por defecto y no funcionaba. Solo una petición real lo mostró.
- **El hallazgo 3 depende de cómo se despliega:** cualquiera que llegue directamente a Node puede enviar `X-Forwarded-For`. Se cierra en P1.8, cuando Nginx sobrescriba esa cabecera y la app no publique su puerto.

</Callout>

## Paso 2: cabeceras y CSP

**Qué es:** la CSP (A5) dice al navegador de dónde puede cargar cada cosa; las otras cabeceras impiden que la app se incruste en otra página, que se adivinen tipos de archivo o que se filtre la URL. Astro genera la CSP con los _hashes_ de sus propios _scripts_.

**Cómo se usa:** sustituye `astro.config.mjs`; las demás cabeceras las pone el _middleware_ del Paso 4. Añade también la variable de Sentry a `.env.example`.

```js
// @ts-check
// Archivo: astro.config.mjs
import { defineConfig, envField } from "astro/config";
import node from "@astrojs/node";
import react from "@astrojs/react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  output: "server", // todas las páginas son privadas salvo login y registro (P1.4)
  adapter: node({ mode: "standalone" }), // un servidor Node, para Docker en el VPS (P1.8)
  integrations: [react()],
  vite: { plugins: [tailwindcss()] },
  security: {
    // CSP en <meta> con los hashes de los scripts que genera Astro (solo en el build).
    // style-src lleva 'unsafe-inline' por los style="" del color de cada categoría (P1.3);
    // contra XSS, lo importante es script-src, que no lo lleva.
    csp: {
      directives: [
        "default-src 'self'",
        "img-src 'self' data:",
        "connect-src 'self'",
        "object-src 'none'",
        "base-uri 'self'",
        "form-action 'self'",
      ],
      styleDirective: { resources: ["'self'", "'unsafe-inline'"] },
    },
  },
  env: {
    schema: {
      MONGODB_URI: envField.string({ context: "server", access: "secret", startsWith: "mongodb" }),
      MONGODB_DB: envField.string({ context: "server", access: "secret", default: "planificador" }),
      BETTER_AUTH_SECRET: envField.string({ context: "server", access: "secret", min: 32 }),
      BETTER_AUTH_URL: envField.string({ context: "server", access: "secret", url: true }),
      // Avisos (P1.6): sin token, la app funciona y los avisos quedan desactivados
      CRON_SECRET: envField.string({ context: "server", access: "secret", min: 32 }),
      // Calidad (P1.7): el límite de intentos, activo salvo que se apague a propósito (tests E2E)
      RATE_LIMIT: envField.boolean({ context: "server", access: "secret", default: true }),
      SENTRY_DSN: envField.string({ context: "server", access: "secret", optional: true }),
      TELEGRAM_BOT_TOKEN: envField.string({ context: "server", access: "secret", optional: true }),
      TELEGRAM_BOT_USUARIO: envField.string({
        context: "server",
        access: "public",
        optional: true,
      }),
      TELEGRAM_API_URL: envField.string({
        context: "server",
        access: "public",
        url: true,

      }),
    },
  },
});
```

## Paso 3: el límite de intentos

**Qué es:** el límite de Better Auth, activado de forma explícita y no por `NODE_ENV`: 5 inicios de sesión por minuto y 5 registros por hora para cada IP.

**Cómo se usa:** sustituye `auth.ts` y apágalo solo en los tests E2E, que registran muchos usuarios seguidos desde la misma IP.

```ts
// Archivo: src/features/auth/auth.ts
import { betterAuth } from "better-auth";
import { mongodbAdapter } from "@better-auth/mongo-adapter";
import { BETTER_AUTH_SECRET, BETTER_AUTH_URL, RATE_LIMIT } from "astro:env/server";
import { repoCategorias } from "@/features/categorias/server";
import { db } from "@/lib/mongo";

export const auth = betterAuth({
  appName: "Planificador",
  baseURL: BETTER_AUTH_URL,
  secret: BETTER_AUTH_SECRET,
  database: mongodbAdapter(db), // crea y usa las colecciones user, session, account y verification
  emailAndPassword: {
    enabled: true,
    autoSignIn: true, // tras registrarse, la sesión queda iniciada
    minPasswordLength: 8,
  },
  session: {
    expiresIn: 60 * 60 * 24 * 30, // 30 días
    updateAge: 60 * 60 * 24, // renueva la caducidad como mucho una vez al día
  },
  // Sin esto, Better Auth solo limita con NODE_ENV=production, y node dist/server/entry.mjs no lo pone
  rateLimit: {
    enabled: RATE_LIMIT,
    window: 60,
    max: 100,
    customRules: {
      "/sign-in/email": { window: 60, max: 5 },
      "/sign-up/email": { window: 60 * 60, max: 5 },
    },
  },
  user: {
    // Preferencias dentro del usuario (P1.2): se leen en cada página junto con la sesión
    additionalFields: {
      zonaHoraria: {
        type: "string",
        required: true,
        defaultValue: "America/Mexico_City",
        input: false, // el registro no puede elegirla: se cambiará desde Ajustes
      },
      // Lo escribe el servicio de avisos al vincular (P1.6), nunca el usuario
      telegramChatId: { type: "string", required: false, input: false },
    },
  },
  databaseHooks: {
    user: {
      create: {
        // Cada usuario nuevo empieza con las cuatro categorías de B7
        after: async (user) => repoCategorias.crearPorDefecto(user.id),
      },
    },
  },
});

export type Sesion = typeof auth.$Infer.Session;
```

## Paso 4: registro, errores y reconexión

**Qué es:** una línea JSON por petición, los errores inesperados en Sentry y una conexión con MongoDB que se recupera sola. Esto último apareció al probar Sentry con MongoDB parado.

**Cómo se usa:** instala el SDK y crea el registro, Sentry, la conexión y el _middleware_ que los une.

```ts
// Archivo: src/lib/sentry.ts
// Los errores inesperados del servidor, en Sentry. Sin SENTRY_DSN no se envía nada.
import * as Sentry from "@sentry/node";
import { SENTRY_DSN } from "astro:env/server";

if (SENTRY_DSN) {
  Sentry.init({
    dsn: SENTRY_DSN,
    environment: import.meta.env.MODE,
    tracesSampleRate: 0, // solo errores: el rendimiento se mide con Lighthouse y los registros
    // Por defecto, la versión 11 envía la IP, cookies, cabeceras y cuerpos: aquí, nada de eso.
    // El userId (reportarError) basta para encontrar el caso
    dataCollection: {
      userInfo: false,
      cookies: false,
      httpHeaders: false,
      httpBodies: [],
      urlQueryParams: false,
      databaseQueryData: false,
    },
  });
}

export function reportarError(error: unknown, contexto: { ruta: string; userId?: string }) {
  if (!SENTRY_DSN) return;
  Sentry.withScope((scope) => {
    scope.setTag("ruta", contexto.ruta);
    if (contexto.userId) scope.setUser({ id: contexto.userId });
    Sentry.captureException(error);
  });
}
```

```ts
// Archivo: src/lib/mongo.ts
import { MongoClient, type Db } from "mongodb";
import { MONGODB_DB, MONGODB_URI } from "astro:env/server";

declare global {
  var __mongoClient: MongoClient | undefined;
}

/** Un único cliente por proceso; en desarrollo sobrevive a las recargas de Vite (B5.2) */
export const mongoClient: MongoClient =
  globalThis.__mongoClient ?? new MongoClient(MONGODB_URI, { serverSelectionTimeoutMS: 5_000 });
if (import.meta.env.DEV) globalThis.__mongoClient = mongoClient;

export const db: Db = mongoClient.db(MONGODB_DB);

/**
 * Si la PRIMERA conexión del driver falla, el cliente queda cerrado para siempre
 * (MongoTopologyClosedError), aunque MongoDB vuelva. Conectar de forma explícita, y olvidar
 * el intento fallido, hace que la siguiente petición lo repita con el mismo cliente.
 */
let conectando: Promise<unknown> | null = null;
export async function conectarMongo(): Promise<void> {
  conectando ??= mongoClient.connect().catch((error: unknown) => {
    conectando = null;
    throw error;
  });
  await conectando;
}
```

```ts
// Archivo: src/middleware.ts
// Todo es privado salvo lo que se declara público aquí
import { defineMiddleware, sequence } from "astro:middleware";
import { auth } from "@/features/auth/auth";
import { log } from "@/lib/log";
import { conectarMongo } from "@/lib/mongo";
import { reportarError } from "@/lib/sentry";

const PAGINAS_DE_ACCESO = new Set(["/login", "/registro"]);
// /api/avisos/ejecutar no tiene sesión: la protege su propio secreto (CRON_SECRET)
const PREFIJOS_PUBLICOS = ["/api/auth/", "/api/health", "/api/avisos/ejecutar"];

/** 1. Registro de cada petición, cabeceras de seguridad y errores inesperados a Sentry */
const registro = defineMiddleware(async (ctx, next) => {
  const inicio = performance.now();
  const ruta = ctx.url.pathname;
  let respuesta: Response;
  try {
    respuesta = await next();
  } catch (error) {
    reportarError(error, { ruta, userId: ctx.locals.user?.id });
    log("error", "Error inesperado", { ruta, error: String(error) });
    respuesta = Response.json({ error: "Error interno" }, { status: 500 });
  }
  const h = respuesta.headers;
  h.set("X-Content-Type-Options", "nosniff");
  h.set("X-Frame-Options", "DENY");
  h.set("Referrer-Policy", "strict-origin-when-cross-origin");
  h.set("Permissions-Policy", "camera=(), microphone=(), geolocation=()");
  if (import.meta.env.PROD) h.set("Strict-Transport-Security", "max-age=63072000");
  if (ctx.locals.user) h.set("Cache-Control", "private, no-store"); // datos de un usuario
  const ms = Math.round(performance.now() - inicio);
  log("info", "petición", { metodo: ctx.request.method, ruta, estado: respuesta.status, ms });
  return respuesta;
});

/** 2. La sesión y quién puede pasar */
const acceso = defineMiddleware(async (ctx, next) => {
  const { pathname, search } = ctx.url;
  ctx.locals.user = null;
  // Si MongoDB no responde, esta petición falla, pero la siguiente vuelve a intentarlo (mongo.ts)
  await conectarMongo().catch((error) =>
    log("error", "MongoDB no responde", { error: String(error) }),
  );
  if (PREFIJOS_PUBLICOS.some((p) => pathname.startsWith(p))) return next();

  const sesion = await auth.api.getSession({ headers: ctx.request.headers });
  ctx.locals.user = sesion?.user ?? null;

  if (PAGINAS_DE_ACCESO.has(pathname)) return ctx.locals.user ? ctx.redirect("/") : next();
  if (ctx.locals.user) return next();

  if (pathname.startsWith("/api/")) {
    return Response.json({ error: "No autenticado" }, { status: 401 });
  }
  return ctx.redirect(`/login?redirect=${encodeURIComponent(pathname + search)}`);
});

export const onRequest = sequence(registro, acceso);
```

```js
// Archivo: scripts/sentry-falso.mjs
// Un "Sentry" local para comprobar que llegan los errores, sin cuenta: escucha en el puerto 4397
// y muestra cada evento recibido. Uso: node scripts/sentry-falso.mjs
import { createServer } from "node:http";
import { gunzipSync } from "node:zlib";

createServer(async (req, res) => {
  const trozos = [];
  for await (const t of req) trozos.push(t);
  let cuerpo = Buffer.concat(trozos);
  if (req.headers["content-encoding"] === "gzip") cuerpo = gunzipSync(cuerpo);
  // Un "envelope" son líneas JSON: cabecera, cabecera del elemento y el evento
  for (const linea of cuerpo.toString().split("\n").slice(1)) {
    const evento = JSON.parse(linea || "{}");
    const excepcion = evento.exception?.values?.[0];
    if (excepcion) {
      console.log(`${req.url} → ${excepcion.type}: ${excepcion.value.slice(0, 60)}`);
      console.log(
        `   entorno=${evento.environment} etiquetas=${JSON.stringify(evento.tags)} usuario=${JSON.stringify(evento.user)}`,
      );
    }
  }
  res.end("{}");
}).listen(4397, () => console.log("Sentry falso en http://localhost:4397"));
```

«Topology is closed» llevó al hallazgo 5: con el `mongo.ts` de P1.3, si la app arranca antes que MongoDB, no se recupera nunca. Con el de este paso, sí:

```text
{"ok":false,"db":"down"} 503    ← MongoDB parado (con los dos mongo.ts)
{"ok":false,"db":"down"} 503    ← MongoDB ya arrancado, mongo.ts de P1.3: así hasta reiniciar
{"ok":true,"db":"up"} 200       ← MongoDB ya arrancado, mongo.ts de este paso
```

- **El _middleware_ captura lo que nadie más ha capturado:** responde un 500 genérico, sin detalles internos, y deja el error en Sentry y en el registro con la ruta y el usuario.

<Callout type="risk">

- **Un DSN mal escrito apaga Sentry sin avisar:** con `http://clave-publica@…`, el guion invalida la clave y el SDK no envía nada; solo lo dice con `debug: true`. Prueba el envío una vez con el servidor falso.
- **La versión 11 del SDK envía datos personales por defecto:** la primera prueba llegó con `"ip_address":"::1"`. `dataCollection` desactiva IP, _cookies_, cabeceras y cuerpos, y el `userId` basta para investigar.

## Paso 5: Lighthouse

**Qué es:** las cuatro categorías clásicas de Lighthouse (rendimiento, accesibilidad, buenas prácticas y SEO) con los Core Web Vitals que se pueden medir en laboratorio: LCP y CLS (A6).

**Cómo se usa:** mide cada página con la _cookie_ de sesión, y resume los informes con un _script_.

```bash
npx lighthouse http://localhost:4399/ --quiet --chrome-flags="--headless=new" \
  --only-categories=performance,accessibility,best-practices,seo \
  --extra-headers '{"Cookie":"better-auth.session_token=…"}' \
  --output=json --output-path=informes/hoy.json
```

```js
// Archivo: scripts/puntuaciones.mjs
// Resume informes JSON de Lighthouse: las cuatro categorías y las auditorías por debajo de 0,9.
// Uso: node scripts/puntuaciones.mjs informe1.json informe2.json …
import { readFileSync } from "node:fs";

for (const archivo of process.argv.slice(2)) {
  const r = JSON.parse(readFileSync(archivo, "utf8"));
  const notas = Object.values(r.categories).map((c) => `${c.title} ${Math.round(c.score * 100)}`);
  const lcp = r.audits["largest-contentful-paint"].displayValue;
  const cls = r.audits["cumulative-layout-shift"].displayValue;
  console.log(
    `${new URL(r.finalDisplayedUrl).pathname.padEnd(14)} ${notas.join(" · ")} · LCP ${lcp} · CLS ${cls}`,
  );
  for (const a of Object.values(r.audits)) {
    const puntuable = !["informative", "notApplicable", "manual"].includes(a.scoreDisplayMode);
    if (puntuable && a.score !== null && a.score < 0.9 && !a.id.endsWith("-insight")) {
      console.log(`   ✗ ${a.id}: ${a.title}`);
    }
  }
}
```

## Paso 6: accesibilidad con axe

**Qué es:** axe comprueba en cada página las reglas automatizables de WCAG 2.1 AA (contraste, etiquetas, roles). Como test E2E, se ejecuta en cada CI.

**Cómo se usa:** instala la integración con Playwright y crea el test, con datos en las páginas privadas.

```bash
npm install -D @axe-core/playwright
```

```ts
// Archivo: tests/e2e/accesibilidad.spec.ts
import AxeBuilder from "@axe-core/playwright";
import { expect, test, type Page } from "@playwright/test";
import { correo, registrar } from "./ayudas";

/** Las reglas de WCAG 2.1 A y AA; cada infracción, con los elementos que la tienen */
async function infracciones(page: Page) {
  const { violations } = await new AxeBuilder({ page })
    .withTags(["wcag2a", "wcag2aa", "wcag21a", "wcag21aa"])
    .analyze();
  return violations.map((v) => `${v.id}: ${v.nodes.map((n) => n.target.join(" ")).join(", ")}`);
}

test("las páginas públicas cumplen WCAG 2.1 AA", async ({ page }) => {
  for (const ruta of ["/login", "/registro"]) {
    await page.goto(ruta);
    expect(await infracciones(page), ruta).toEqual([]);
  }
});

test("las páginas privadas cumplen WCAG 2.1 AA, con datos", async ({ page }) => {
  await registrar(page, correo("axe"));
  await page.getByLabel("Nueva tarea").fill("Revisar el informe");
  await page.getByRole("button", { name: "Añadir" }).click();
  await page.getByLabel("Hecha: Revisar el informe").check();
  for (const ruta of ["/", "/estadisticas", "/ajustes"]) {
    await page.goto(ruta);
    expect(await infracciones(page), ruta).toEqual([]);
  }
});
```
