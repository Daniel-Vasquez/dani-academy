## Paso 1: la hora del usuario

**Qué es:** dos conversiones entre el instante (UTC) y el calendario del usuario. `diaEn` ya existía (P1.3); `instanteEn` hace lo contrario, y lo necesita el aviso de cada tarea (`avisarEn`, P1.2).

**Cómo se usa:** sustituye `src/lib/dia.ts` y su test.

```ts
// Archivo: src/lib/dia.ts
// El día de una tarea es texto AAAA-MM-DD en la zona del usuario (ADR 0001)

/** "AAAA-MM-DD" del instante, en la zona horaria indicada */
export function diaEn(instante: Date, zona: string): string {
  return instante.toLocaleDateString("en-CA", { timeZone: zona });
}

/** Milisegundos que la zona va por delante de UTC en ese instante (negativo en América) */
function desfase(instante: Date, zona: string): number {
  const partes = new Intl.DateTimeFormat("en-US", {
    timeZone: zona,
    hourCycle: "h23",
    year: "numeric",
    month: "2-digit",
    day: "2-digit",
    hour: "2-digit",
    minute: "2-digit",
    second: "2-digit",
  }).formatToParts(instante);
  const p = (tipo: string) => Number(partes.find((x) => x.type === tipo)?.value);
  const comoUtc = Date.UTC(
    p("year"),
    p("month") - 1,
    p("day"),
    p("hour"),
    p("minute"),
    p("second"),
  );
  return comoUtc - Math.floor(instante.getTime() / 1000) * 1000;
}

/** El instante en que es "dia hora" en la zona: 23:30 del 21 en México son las 05:30 UTC del 22 */
export function instanteEn(dia: string, hora: string, zona: string): Date {
  const comoUtc = Date.parse(`${dia}T${hora}:00Z`);
  let instante = comoUtc - desfase(new Date(comoUtc), zona);
  // Segunda vuelta: si entre medias hay un cambio de horario, el desfase correcto es el del resultado
  instante = comoUtc - desfase(new Date(instante), zona);
  return new Date(instante);
}
```

```ts
// Archivo: tests/unit/dia.test.ts
import { describe, expect, it } from "vitest";
import { diaEn, instanteEn } from "@/lib/dia";

describe("diaEn", () => {
  it("una tarea de las 23:30 en México sigue en su día, aunque en UTC ya sea el siguiente", () => {
    expect(diaEn(new Date("2026-11-22T05:30:00Z"), "America/Mexico_City")).toBe("2026-11-21");
  });

  it("el mismo instante es otro día en Madrid", () => {
    expect(diaEn(new Date("2026-11-22T05:30:00Z"), "Europe/Madrid")).toBe("2026-11-22");
  });
});

describe("instanteEn", () => {
  it("las 23:30 del 21 en México son las 05:30 UTC del 22", () => {
    expect(instanteEn("2026-11-21", "23:30", "America/Mexico_City").toISOString()).toBe(
      "2026-11-22T05:30:00.000Z",
    );
  });

  it("respeta el horario de verano: en Madrid, julio es UTC+2 y noviembre UTC+1", () => {
    expect(instanteEn("2026-07-10", "09:00", "Europe/Madrid").toISOString()).toBe(
      "2026-07-10T07:00:00.000Z",
    );
    expect(instanteEn("2026-11-10", "09:00", "Europe/Madrid").toISOString()).toBe(
      "2026-11-10T08:00:00.000Z",
    );
  });

  it("el día del cambio de hora: la 01:30 del 29 de marzo en Madrid aún es UTC+1", () => {
    // A las 01:00 UTC, Madrid pasa de UTC+1 a UTC+2: la primera estimación cae al otro lado
    expect(instanteEn("2026-03-29", "01:30", "Europe/Madrid").toISOString()).toBe(
      "2026-03-29T00:30:00.000Z",
    );
    expect(instanteEn("2026-03-29", "03:30", "Europe/Madrid").toISOString()).toBe(
      "2026-03-29T01:30:00.000Z",
    );
  });
});
```

- **Sin librerías de fechas:** `Intl.DateTimeFormat` conoce todas las zonas y sus cambios de horario, y el desfase sale de comparar la misma hora leída en las dos zonas.

<Callout type="risk">

- **La segunda vuelta no sobra:** sin ella, la 01:30 del día del cambio de hora en Madrid sale una hora antes, porque la primera estimación cae al otro lado del cambio. El test lo detecta:

  ```text
  Expected: "2026-03-29T00:30:00.000Z"
  Received: "2026-03-28T23:30:00.000Z"
  ```

- **`new Date("2026-11-21T23:30")` usa la zona del servidor:** sin `Z` ni desfase, JavaScript la interpreta en la hora local del proceso. En un VPS en UTC y en tu Mac en México, el mismo código daría instantes distintos.

</Callout>

## Paso 2: las colecciones, en un módulo

**Qué es:** el `$jsonSchema` y los índices de P1.2, movidos a `src/lib/colecciones.ts`. Así los usan el _script_ de despliegue y los tests de integración, y los tests prueban el mismo esquema que producción.

**Cómo se usa:** crea el módulo y sustituye el _script_ de P1.2 por uno que lo importa.

```ts
// Archivo: src/lib/colecciones.ts
// El $jsonSchema y los índices de P1.2, en un módulo que usan el script y los tests de integración
import type { Db, Document, IndexDescription } from "mongodb";

const DIA = "^\\d{4}-\\d{2}-\\d{2}$"; // AAAA-MM-DD: el día del usuario (ADR 0001)
const HORA = "^([01]\\d|2[0-3]):[0-5]\\d$";
const COLOR = "^#[0-9a-f]{6}$";

interface Coleccion {
  nombre: string;
  esquema: Document;
  indices: IndexDescription[];
}

export const COLECCIONES: Coleccion[] = [
  {
    nombre: "categorias",
    esquema: {
      bsonType: "object",
      required: ["userId", "nombre", "color"],
      additionalProperties: false,
      properties: {
        _id: { bsonType: "objectId" },
        userId: { bsonType: "string", minLength: 1 },
        nombre: { bsonType: "string", minLength: 1, maxLength: 40 },
        color: { bsonType: "string", pattern: COLOR },
      },
    },
    indices: [{ key: { userId: 1, nombre: 1 }, name: "userId_nombre_unico", unique: true }],
  },
  {
    nombre: "tareas",
    esquema: {
      bsonType: "object",
      required: ["userId", "titulo", "dia", "hecha", "categoria", "creada"],
      additionalProperties: false,
      properties: {
        _id: { bsonType: "objectId" },
        userId: { bsonType: "string", minLength: 1 },
        titulo: { bsonType: "string", minLength: 1, maxLength: 200 },
        dia: { bsonType: "string", pattern: DIA },
        hora: { bsonType: "string", pattern: HORA },
        hecha: { bsonType: "bool" },
        categoria: {
          bsonType: "object",
          required: ["id", "nombre", "color"],
          additionalProperties: false,
          properties: {
            id: { bsonType: "objectId" },
            nombre: { bsonType: "string", minLength: 1, maxLength: 40 },
            color: { bsonType: "string", pattern: COLOR },
          },
        },
        avisarEn: { bsonType: "date" },
        creada: { bsonType: "date" },
      },
    },
    indices: [
      { key: { userId: 1, dia: 1 }, name: "userId_dia" },
      {
        key: { avisarEn: 1 },
        name: "avisos_pendientes",
        partialFilterExpression: { avisarEn: { $exists: true } },
      },
    ],
  },
];

/** Crea o actualiza cada colección con su esquema e índices; devuelve una línea por colección */
export async function aplicarColecciones(db: Db): Promise<string[]> {
  const resultado: string[] = [];
  for (const c of COLECCIONES) {
    const opciones = {
      validator: { $jsonSchema: c.esquema },
      validationLevel: "strict",
      validationAction: "error",
    } as const;
    const existe = (await db.listCollections({ name: c.nombre }).toArray()).length > 0;
    if (existe) await db.command({ collMod: c.nombre, ...opciones });
    else await db.createCollection(c.nombre, opciones);
    const indices = await db.collection(c.nombre).createIndexes(c.indices);
    resultado.push(`${existe ? "actualizada" : "creada"}: ${c.nombre} (${indices.join(", ")})`);
  }
  return resultado;
}
```

<Callout type="risk">

- **Un esquema distinto en los tests no prueba nada del real:** si los tests de integración crearan las colecciones a su manera, un campo que el `$jsonSchema` rechaza pasaría en los tests y fallaría en producción.
- **El _script_ va antes de arrancar, en cada despliegue:** un índice nuevo que no se crea no da ningún error; solo hace lentas las consultas que lo esperaban.

</Callout>

## Paso 3: los repositorios

**Qué es:** las funciones que hablan con MongoDB, una por patrón de acceso. Cada una lleva el `userId` en el filtro, y reciben la base de datos como parámetro para poder probarlas con otra.

**Cómo se usa:** crea el repositorio de categorías y lo que ofrece su _feature_, y sustituye el de tareas de P1.4.

```ts
// Archivo: src/features/categorias/categorias.repo.ts
import { ObjectId, type Db } from "mongodb";

export interface Categoria {
  _id: ObjectId;
  userId: string;
  nombre: string;
  color: string;
}

/** Las cuatro con las que empieza cada usuario (B7) */
export const POR_DEFECTO = [
  { nombre: "Trabajo", color: "#0284c7" },
  { nombre: "Personal", color: "#d97706" },
  { nombre: "Salud", color: "#0d9488" },
  { nombre: "Estudio", color: "#f25c76" },
];

const ID = /^[0-9a-f]{24}$/i;

export function crearRepoCategorias(db: Db) {
  const col = db.collection<Categoria>("categorias");
  return {
    listar: (userId: string) => col.find({ userId }).sort({ nombre: 1 }).toArray(),

    buscar: (userId: string, id: string) =>
      ID.test(id) ? col.findOne({ _id: new ObjectId(id), userId }) : Promise.resolve(null),

    async crearPorDefecto(userId: string) {
      await col.insertMany(POR_DEFECTO.map((c) => ({ ...c, _id: new ObjectId(), userId })));
    },

    cambiar: (userId: string, id: ObjectId, cambios: { nombre?: string; color?: string }) =>
      col.findOneAndUpdate({ _id: id, userId }, { $set: cambios }, { returnDocument: "after" }),
  };
}

export type RepoCategorias = ReturnType<typeof crearRepoCategorias>;
```

```ts
// Archivo: src/features/tareas/tareas.repo.ts
import { ObjectId, type Db, type UpdateFilter } from "mongodb";

export interface Tarea {
  _id: ObjectId;
  userId: string;
  titulo: string;
  dia: string;
  hora?: string;
  hecha: boolean;
  categoria: { id: ObjectId; nombre: string; color: string };
  avisarEn?: Date;
  creada: Date;
}

const ID = /^[0-9a-f]{24}$/i;
const filtro = (userId: string, id: string) =>
  ID.test(id) ? { _id: new ObjectId(id), userId } : null;

/** Todas las consultas llevan el userId en el filtro: no hay forma de leer una tarea ajena */
export function crearRepoTareas(db: Db) {
  const col = db.collection<Tarea>("tareas");
  return {
    async crear(datos: Omit<Tarea, "_id">): Promise<Tarea> {
      const tarea = { ...datos, _id: new ObjectId() };
      await col.insertOne(tarea);
      return tarea;
    },

    // P1: índice userId_dia; las de sin hora, primero
    delDia: (userId: string, dia: string) =>
      col.find({ userId, dia }).sort({ hora: 1, creada: 1 }).toArray(),

    buscar(userId: string, id: string) {
      const f = filtro(userId, id);
      return f ? col.findOne(f) : Promise.resolve(null);
    },

    actualizar(userId: string, id: string, cambios: UpdateFilter<Tarea>) {
      const f = filtro(userId, id);
      return f ? col.findOneAndUpdate(f, cambios, { returnDocument: "after" }) : null;
    },

    async borrar(userId: string, id: string): Promise<boolean> {
      const f = filtro(userId, id);
      return f ? (await col.deleteOne(f)).deletedCount === 1 : false;
    },

    // P5: la copia del nombre y el color en cada tarea (ADR 0002)
    async recolorear(userId: string, categoria: { _id: ObjectId; nombre: string; color: string }) {
      const { modifiedCount } = await col.updateMany(
        { userId, "categoria.id": categoria._id },
        { $set: { "categoria.nombre": categoria.nombre, "categoria.color": categoria.color } },
      );
      return modifiedCount;
    },
  };
}

export type RepoTareas = ReturnType<typeof crearRepoTareas>;
```

- **`crearRepoTareas(db)` en vez de importar `db`:** el repositorio de P1.4 importaba la conexión de `@/lib/mongo`, la de `MONGODB_URI`. Con la base de datos como parámetro, `server.ts` le pasa la real y el test, una en memoria.

<Callout type="risk">

- **Un ID mal formado se queda en el repositorio:** `filtro` devuelve `null` en lugar de lanzar el `BSONError` de `new ObjectId("abc")`, y la ruta responde 404 en lugar de 500.
- **`findOneAndUpdate` devuelve el documento anterior por defecto:** sin `returnDocument: "after"`, la API respondería con la tarea sin el cambio que acaba de guardar, y la isla mostraría el estado viejo.

</Callout>

## Paso 4: el servicio y la validación

**Qué es:** el servicio aplica las reglas (la categoría tiene que ser del usuario, el aviso se calcula 15 minutos antes, una tarea hecha no avisa) sin saber nada de HTTP. Zod valida lo que llega antes de que el servicio lo vea.

**Cómo se usa:** crea el esquema, el error de «no encontrado», el servicio y el `server.ts` que lo conecta.

```ts
// Archivo: src/features/tareas/tarea.schema.ts
import { z } from "zod";

const id = z.string().regex(/^[0-9a-f]{24}$/i, "ID no válido");
const titulo = z.string().trim().min(1, "El título no puede estar vacío").max(200);
const dia = z.iso.date("Día no válido (AAAA-MM-DD)"); // también rechaza el 30 de febrero
const hora = z.string().regex(/^([01]\d|2[0-3]):[0-5]\d$/, "Hora no válida (HH:MM)");

export const nuevaTarea = z.object({ titulo, dia, hora: hora.optional(), categoriaId: id });

export const cambioTarea = z
  .object({ titulo, dia, hora: hora.nullable(), hecha: z.boolean(), categoriaId: id })
  .partial()
  .strict() // un campo desconocido, como userId, es un error y no se ignora
  .refine((c) => Object.keys(c).length > 0, "No hay nada que cambiar");

export type NuevaTarea = z.infer<typeof nuevaTarea>;
export type CambioTarea = z.infer<typeof cambioTarea>;

/** Lo que recibe el navegador: sin userId ni avisarEn, y con los ID como texto */
export interface TareaVista {
  id: string;
  titulo: string;
  dia: string;
  hora?: string;
  hecha: boolean;
  categoria: { id: string; nombre: string; color: string };
}
```

```ts
// Archivo: src/features/tareas/tareas.service.ts
// Las reglas de las tareas, sin HTTP ni MongoDB: reciben los repositorios (y se prueban con ellos)
import type { RepoCategorias } from "@/features/categorias/server";
import { diaEn, instanteEn } from "@/lib/dia";
import { NoEncontrado } from "@/lib/errores";
import type { CambioTarea, NuevaTarea, TareaVista } from "./tarea.schema";
import type { RepoTareas, Tarea } from "./tareas.repo";

export const MINUTOS_DE_AVISO = 15;

export interface Usuario {
  id: string;
  zonaHoraria: string;
}

/** Cuándo avisar: 15 min antes de la hora, y nunca si la tarea ya ha pasado o no tiene hora */
export function calcularAviso(
  t: { dia: string; hora?: string; hecha: boolean },
  zona: string,
  ahora: Date,
): Date | undefined {
  if (!t.hora || t.hecha) return undefined;
  const instante = instanteEn(t.dia, t.hora, zona);
  if (instante <= ahora) return undefined;
  return new Date(instante.getTime() - MINUTOS_DE_AVISO * 60_000);
}

export function aVista(t: Tarea): TareaVista {
  return {
    id: t._id.toHexString(),
    titulo: t.titulo,
    dia: t.dia,
    ...(t.hora && { hora: t.hora }),
    hecha: t.hecha,
    categoria: { ...t.categoria, id: t.categoria.id.toHexString() },
  };
}

export function crearServicioTareas(repos: { tareas: RepoTareas; categorias: RepoCategorias }) {
  const { tareas, categorias } = repos;

  async function categoriaDe(usuario: Usuario, id: string) {
    const c = await categorias.buscar(usuario.id, id);
    if (!c) throw new NoEncontrado("Categoría no encontrada"); // también si es de otro usuario
    return { id: c._id, nombre: c.nombre, color: c.color };
  }

  return {
    async deHoy(usuario: Usuario, ahora = new Date()) {
      return (await tareas.delDia(usuario.id, diaEn(ahora, usuario.zonaHoraria))).map(aVista);
    },

    async una(usuario: Usuario, id: string) {
      const tarea = await tareas.buscar(usuario.id, id);
      if (!tarea) throw new NoEncontrado("Tarea no encontrada");
      return aVista(tarea);
    },

    async crear(usuario: Usuario, datos: NuevaTarea, ahora = new Date()) {
      const { categoriaId, ...resto } = datos;
      const base = { ...resto, hecha: false };
      const avisarEn = calcularAviso(base, usuario.zonaHoraria, ahora);
      const tarea = await tareas.crear({
        ...base,
        userId: usuario.id,
        categoria: await categoriaDe(usuario, categoriaId),
        ...(avisarEn && { avisarEn }),
        creada: ahora,
      });
      return aVista(tarea);
    },

    async cambiar(usuario: Usuario, id: string, cambios: CambioTarea, ahora = new Date()) {
      const actual = await tareas.buscar(usuario.id, id);
      if (!actual) throw new NoEncontrado("Tarea no encontrada");

      const { categoriaId, hora, ...resto } = cambios;
      const final = {
        ...actual,
        ...resto,
        hora: hora === null ? undefined : (hora ?? actual.hora),
      };
      const avisarEn = calcularAviso(final, usuario.zonaHoraria, ahora);

      const $set: Partial<Tarea> = { ...resto, ...(final.hora && { hora: final.hora }) };
      if (categoriaId) $set.categoria = await categoriaDe(usuario, categoriaId);
      if (avisarEn) $set.avisarEn = avisarEn;
      const $unset = {
        ...(!final.hora && { hora: "" as const }),
        ...(!avisarEn && { avisarEn: "" as const }),
      };
      // MongoDB rechaza un $set o un $unset vacíos: solo se envía el que tiene algo
      const actualizada = await tareas.actualizar(usuario.id, id, {
        ...(Object.keys($set).length > 0 && { $set }),
        ...(Object.keys($unset).length > 0 && { $unset }),
      });
      if (!actualizada) throw new NoEncontrado("Tarea no encontrada");
      return aVista(actualizada);
    },

    async borrar(usuario: Usuario, id: string) {
      if (!(await tareas.borrar(usuario.id, id))) throw new NoEncontrado("Tarea no encontrada");
    },
  };
}

export type ServicioTareas = ReturnType<typeof crearServicioTareas>;
```

- **`ahora` es un parámetro con valor por defecto:** la ruta no lo pasa y usa la hora real; el test pasa una fija.
- **`TareaVista` no lleva `userId` ni `avisarEn`:** el navegador recibe solo lo que pinta.

<Callout type="risk">

- **Sin `.strict()`, Zod descarta en silencio lo que no conoce:** `{ "titulo": "Pan", "hehca": true }` guardaría el título, y el cliente creería que también la ha marcado. Con `.strict()` es un 400 que señala el campo mal escrito.
- **MongoDB rechaza un `$set` o un `$unset` vacíos:** completar una tarea sin hora solo tiene `$set`, y quitar la hora puede dejar el `$set` vacío. Por eso cada uno se envía solo si tiene algo.

</Callout>

## Paso 5: las rutas

**Qué es:** las rutas traducen HTTP: leen la sesión, validan el cuerpo, llaman al servicio y convierten sus errores en códigos de estado. Auth crea además las categorías de cada usuario nuevo.

**Cómo se usa:** crea las ayudas de HTTP y las rutas de tareas, y sustituye `auth.ts`.

```ts
// Archivo: src/lib/http.ts
// Las traducciones entre HTTP y el resto: cuerpo validado con Zod y errores con su código
import type { z } from "zod";
import { NoEncontrado } from "@/lib/errores";

/** El cuerpo JSON validado, o una respuesta 400 con el primer problema */
export async function leerCuerpo<T>(
  request: Request,
  esquema: z.ZodType<T>,
): Promise<T | Response> {
  const json: unknown = await request.json().catch(() => undefined);
  const r = esquema.safeParse(json);
  if (r.success) return r.data;
  const error = r.error.issues[0]?.message ?? "Datos no válidos";
  return Response.json({ error }, { status: 400 });
}

export function responderError(error: unknown): Response {
  if (error instanceof NoEncontrado) {
    return Response.json({ error: error.message }, { status: 404 });
  }
  throw error; // lo inesperado sigue siendo un 500, con su traza en el registro
}
```

## Paso 6: la isla con actualización optimista

**Qué es:** `useOptimistic` (React 19) muestra el cambio en cuanto el usuario lo hace, antes de que el servidor responda. Si la petición falla, al acabar la transición la vista vuelve al estado real.

**Cómo se usa:** crea la isla y sustituye la portada, que carga los datos en el servidor y se los pasa.

```tsx
// Archivo: src/features/tareas/components/ListaHoy.tsx
import { useOptimistic, useState, useTransition, type FormEvent } from "react";
import type { TareaVista } from "../tarea.schema";

interface Props {
  dia: string;
  inicial: TareaVista[];
  categorias: { id: string; nombre: string }[];
}

async function enviar(url: string, method: string, cuerpo: unknown): Promise<TareaVista> {
  const r = await fetch(url, {
    method,
    headers: { "content-type": "application/json" },
    body: JSON.stringify(cuerpo),
  });
  if (!r.ok) throw new Error(((await r.json()) as { error: string }).error);
  return r.json();
}

export default function ListaHoy({ dia, inicial, categorias }: Props) {
  const [tareas, setTareas] = useState(inicial);
  // Lo que se ve: el estado real más los cambios que aún esperan respuesta del servidor
  const [visibles, marcar] = useOptimistic(tareas, (lista, { id, hecha }: TareaVista) =>
    lista.map((t) => (t.id === id ? { ...t, hecha } : t)),
  );
  const [, startTransition] = useTransition();
  const [error, setError] = useState("");

  function alternar(tarea: TareaVista) {
    setError("");
    startTransition(async () => {
      marcar({ ...tarea, hecha: !tarea.hecha }); // se ve marcada al instante
      try {
        const guardada = await enviar(`/api/tareas/${tarea.id}`, "PATCH", { hecha: !tarea.hecha });
        // Tras un await, la actualización necesita su propia transición (React 19)
        startTransition(() =>
          setTareas((l) => l.map((t) => (t.id === guardada.id ? guardada : t))),
        );
      } catch {
        setError("No se pudo guardar el cambio."); // al acabar la transición, vuelve el estado real
      }
    });
  }

  async function crear(evento: FormEvent<HTMLFormElement>) {
    evento.preventDefault();
    const form = evento.currentTarget;
    const datos = new FormData(form);
    setError("");
    try {
      const nueva = await enviar("/api/tareas", "POST", {
        titulo: datos.get("titulo"),
        dia,
        ...(datos.get("hora") && { hora: datos.get("hora") }),
        categoriaId: datos.get("categoriaId"),
      });
      setTareas((l) => [...l, nueva]);
      form.reset();
    } catch (e) {
      setError((e as Error).message);
    }
  }

  return (
    <section className="mt-8">
      <form onSubmit={crear} className="grid gap-2 sm:grid-cols-[1fr_auto_auto_auto]">
        <input
          name="titulo"
          aria-label="Nueva tarea"
          placeholder="Nueva tarea"
          className="rounded border px-3 py-2"
        />
        <input name="hora" type="time" aria-label="Hora" className="rounded border px-3 py-2" />
        <select name="categoriaId" aria-label="Categoría" className="rounded border px-3 py-2">
          {categorias.map((c) => (
            <option key={c.id} value={c.id}>
              {c.nombre}
            </option>
          ))}
        </select>
        <button className="rounded bg-acento px-4 py-2 font-medium text-white">Añadir</button>
      </form>
      <p role="alert" className="mt-2 min-h-6 text-peligro">
        {error}
      </p>
      <ul className="mt-2 divide-y rounded border bg-superficie">
        {visibles.map((t) => (
          <li key={t.id} className="flex items-center gap-3 px-3 py-2">
            <input
              type="checkbox"
              checked={t.hecha}
              onChange={() => alternar(t)}
              aria-label={`Hecha: ${t.titulo}`}
            />
            <span
              className="size-3 rounded-full"
              style={{ backgroundColor: t.categoria.color }} // el color lo elige el usuario: no es un token
              title={t.categoria.nombre}
            />
            <span className={t.hecha ? "text-suave line-through" : ""}>{t.titulo}</span>
            {t.hora && <span className="ml-auto text-sm text-suave">{t.hora}</span>}
          </li>
        ))}
        {visibles.length === 0 && <li className="px-3 py-2 text-suave">Nada para hoy.</li>}
      </ul>
    </section>
  );
}
```

- **Solo marcar es optimista; crear, no:** al marcar, el resultado es seguro casi siempre. Una tarea nueva puede rechazarse (título vacío) y necesita el ID del servidor, así que espera la respuesta.

<Callout type="risk">

- **Tras un `await`, la actualización necesita su propio `startTransition`:** React 19 no puede asociar a la transición original lo que ocurre después de una espera, y la documentación de React pide envolverlo otra vez. Sin hacerlo, esa actualización se trata como urgente, fuera de la transición.

</Callout>

```ts
// Las traducciones entre HTTP y el resto: cuerpo validado con Zod y errores con su código
import type { z } from "zod";
import { Conflicto, NoEncontrado } from "@/lib/errores";

/** El cuerpo JSON validado, o una respuesta 400 con el primer problema */
export async function leerCuerpo<T>(
  request: Request,
  esquema: z.ZodType<T>,
): Promise<T | Response> {
  const json: unknown = await request.json().catch(() => undefined);
  const r = esquema.safeParse(json);
  if (r.success) return r.data;
  const error = r.error.issues[0]?.message ?? "Datos no válidos";
  return Response.json({ error }, { status: 400 });
}

export function responderError(error: unknown): Response {
  if (error instanceof NoEncontrado) {
    return Response.json({ error: error.message }, { status: 404 });
  }
  if (error instanceof Conflicto) {
    return Response.json({ error: error.message }, { status: 409 });
  }
  throw error; // lo inesperado sigue siendo un 500, con su traza en el registro
}
```

```ts
// Archivo: src/features/tareas/tareas.service.ts
// Las reglas de las tareas, sin HTTP ni MongoDB: reciben los repositorios (y se prueban con ellos)
import { MongoServerError } from "mongodb";
import type { CambioCategoria, RepoCategorias } from "@/features/categorias/server";
import { diaEn, instanteEn } from "@/lib/dia";
import { Conflicto, NoEncontrado } from "@/lib/errores";
import type { CambioTarea, NuevaTarea, TareaVista } from "./tarea.schema";
import type { RepoTareas, Tarea } from "./tareas.repo";

export const MINUTOS_DE_AVISO = 15;

export interface Usuario {
  id: string;
  zonaHoraria: string;
}

/** Cuándo avisar: 15 min antes de la hora, y nunca si la tarea ya ha pasado o no tiene hora */
export function calcularAviso(
  t: { dia: string; hora?: string; hecha: boolean },
  zona: string,
  ahora: Date,
): Date | undefined {
  if (!t.hora || t.hecha) return undefined;
  const instante = instanteEn(t.dia, t.hora, zona);
  if (instante <= ahora) return undefined;
  return new Date(instante.getTime() - MINUTOS_DE_AVISO * 60_000);
}

export function aVista(t: Tarea): TareaVista {
  return {
    id: t._id.toHexString(),
    titulo: t.titulo,
    dia: t.dia,
    ...(t.hora && { hora: t.hora }),
    hecha: t.hecha,
    categoria: { ...t.categoria, id: t.categoria.id.toHexString() },
  };
}

export function crearServicioTareas(repos: { tareas: RepoTareas; categorias: RepoCategorias }) {
  const { tareas, categorias } = repos;

  async function categoriaDe(usuario: Usuario, id: string) {
    const c = await categorias.buscar(usuario.id, id);
    if (!c) throw new NoEncontrado("Categoría no encontrada"); // también si es de otro usuario
    return { id: c._id, nombre: c.nombre, color: c.color };
  }

  return {
    async deHoy(usuario: Usuario, ahora = new Date()) {
      return (await tareas.delDia(usuario.id, diaEn(ahora, usuario.zonaHoraria))).map(aVista);
    },

    async una(usuario: Usuario, id: string) {
      const tarea = await tareas.buscar(usuario.id, id);
      if (!tarea) throw new NoEncontrado("Tarea no encontrada");
      return aVista(tarea);
    },

    async crear(usuario: Usuario, datos: NuevaTarea, ahora = new Date()) {
      const { categoriaId, ...resto } = datos;
      const base = { ...resto, hecha: false };
      const avisarEn = calcularAviso(base, usuario.zonaHoraria, ahora);
      const tarea = await tareas.crear({
        ...base,
        userId: usuario.id,
        categoria: await categoriaDe(usuario, categoriaId),
        ...(avisarEn && { avisarEn }),
        creada: ahora,
      });
      return aVista(tarea);
    },

    async cambiar(usuario: Usuario, id: string, cambios: CambioTarea, ahora = new Date()) {
      const actual = await tareas.buscar(usuario.id, id);
      if (!actual) throw new NoEncontrado("Tarea no encontrada");

      const { categoriaId, hora, ...resto } = cambios;
      const final = {
        ...actual,
        ...resto,
        hora: hora === null ? undefined : (hora ?? actual.hora),
      };
      const avisarEn = calcularAviso(final, usuario.zonaHoraria, ahora);

      const $set: Partial<Tarea> = { ...resto, ...(final.hora && { hora: final.hora }) };
      if (categoriaId) $set.categoria = await categoriaDe(usuario, categoriaId);
      if (avisarEn) $set.avisarEn = avisarEn;
      const $unset = {
        ...(!final.hora && { hora: "" as const }),
        ...(!avisarEn && { avisarEn: "" as const }),
      };
      // MongoDB rechaza un $set o un $unset vacíos: solo se envía el que tiene algo
      const actualizada = await tareas.actualizar(usuario.id, id, {
        ...(Object.keys($set).length > 0 && { $set }),
        ...(Object.keys($unset).length > 0 && { $unset }),
      });
      if (!actualizada) throw new NoEncontrado("Tarea no encontrada");
      return aVista(actualizada);
    },

    async borrar(usuario: Usuario, id: string) {
      if (!(await tareas.borrar(usuario.id, id))) throw new NoEncontrado("Tarea no encontrada");
    },

    /** P5: cambia la categoría y la copia que guarda cada una de sus tareas (ADR 0002) */
    async cambiarCategoria(usuario: Usuario, id: string, cambios: CambioCategoria) {
      const actual = await categorias.buscar(usuario.id, id);
      if (!actual) throw new NoEncontrado("Categoría no encontrada");
      try {
        const categoria = await categorias.cambiar(usuario.id, actual._id, cambios);
        if (!categoria) throw new NoEncontrado("Categoría no encontrada");
        const tareasActualizadas = await tareas.recolorear(usuario.id, categoria);
        const { nombre, color } = categoria;
        return { id: categoria._id.toHexString(), nombre, color, tareasActualizadas };
      } catch (error) {
        // 11000: el índice único userId_nombre_unico ya tiene ese nombre para este usuario
        if (error instanceof MongoServerError && error.code === 11000) {
          throw new Conflicto("Ya tienes una categoría con ese nombre");
        }
        throw error;
      }
    },
  };
}

export type ServicioTareas = ReturnType<typeof crearServicioTareas>;
```

```ts
// Archivo: src/pages/api/categorias/[id].ts
import type { APIRoute } from "astro";
import { cambioCategoria } from "@/features/categorias/server";
import { servicioTareas } from "@/features/tareas/server";
import { leerCuerpo, responderError } from "@/lib/http";

export const PATCH: APIRoute = async ({ locals, params, request }) => {
  if (!locals.user) return Response.json({ error: "No autenticado" }, { status: 401 });
  const datos = await leerCuerpo(request, cambioCategoria);
  if (datos instanceof Response) return datos;
  try {
    return Response.json(
      await servicioTareas.cambiarCategoria(locals.user, params.id ?? "", datos),
    );
  } catch (error) {
    return responderError(error);
  }
};
```

```ts
// Archivo: tests/integration/categorias.test.ts
import { describe, expect, it } from "vitest";
import { cambioCategoria } from "@/features/categorias/categoria.schema";
import { crearRepoCategorias } from "@/features/categorias/categorias.repo";
import { crearRepoTareas } from "@/features/tareas/tareas.repo";
import { crearServicioTareas } from "@/features/tareas/tareas.service";
import { Conflicto, NoEncontrado } from "@/lib/errores";
import { db } from "./mongo";

const ana = { id: "ana", zonaHoraria: "America/Mexico_City" };
const beto = { id: "beto", zonaHoraria: "America/Mexico_City" };

async function preparar() {
  const categorias = crearRepoCategorias(db);
  const servicio = crearServicioTareas({ tareas: crearRepoTareas(db), categorias });
  await categorias.crearPorDefecto(ana.id);
  await categorias.crearPorDefecto(beto.id);
  const id = async (u: string, nombre: string) =>
    (await categorias.listar(u)).find((c) => c.nombre === nombre)!._id.toHexString();
  const salud = await id(ana.id, "Salud");
  for (const titulo of ["Dentista", "Correr", "Médico"]) {
    await servicio.crear(ana, { titulo, dia: "2026-11-21", categoriaId: salud });
  }
  await servicio.crear(ana, {
    titulo: "Informe",
    dia: "2026-11-21",
    categoriaId: await id(ana.id, "Trabajo"),
  });
  await servicio.crear(beto, {
    titulo: "Gimnasio",
    dia: "2026-11-21",
    categoriaId: await id(beto.id, "Salud"),
  });
  return { servicio, salud };
}

describe("cambiar una categoría (P5)", () => {
  it("el nuevo color llega a todas sus tareas, y solo a las suyas", async () => {
    const { servicio, salud } = await preparar();
    const r = await servicio.cambiarCategoria(
      ana,
      salud,
      cambioCategoria.parse({ color: "#16A34A" }),
    );
    expect(r).toMatchObject({ nombre: "Salud", color: "#16a34a", tareasActualizadas: 3 });

    const colores = (await servicio.deHoy(ana, new Date("2026-11-21T18:00:00Z"))).map(
      (t) => `${t.titulo} ${t.categoria.color}`,
    );
    expect(colores).toEqual([
      "Dentista #16a34a",
      "Correr #16a34a",
      "Médico #16a34a",
      "Informe #0284c7",
    ]);
    const deBeto = await servicio.deHoy(beto, new Date("2026-11-21T18:00:00Z"));
    expect(deBeto[0]?.categoria.color).toBe("#0d9488");
  });

  it("un nombre repetido es un conflicto, y nada cambia", async () => {
    const { servicio, salud } = await preparar();
    await expect(
      servicio.cambiarCategoria(ana, salud, { nombre: "Trabajo" }),
    ).rejects.toBeInstanceOf(Conflicto);
    const hoy = await servicio.deHoy(ana, new Date("2026-11-21T18:00:00Z"));
    expect(hoy.filter((t) => t.categoria.nombre === "Salud")).toHaveLength(3);
  });

  it("la categoría de otro usuario no se puede cambiar", async () => {
    const { servicio, salud } = await preparar();
    await expect(
      servicio.cambiarCategoria(beto, salud, { color: "#000000" }),
    ).rejects.toBeInstanceOf(NoEncontrado);
  });
});
```

<Callout type="risk">

- **Dos escrituras sin transacción:** si el proceso muere entre cambiar la categoría y recolorear sus tareas, quedan con el color viejo. Repetir el mismo `PATCH` lo arregla, porque las dos operaciones se pueden repetir sin efectos extra; con un _replica set_, una transacción lo evitaría.
- **El conflicto lo detecta el índice único, no una consulta previa:** comprobar antes si el nombre existe deja un hueco entre la comprobación y la escritura. El error 11000 llega en la misma operación.

</Callout>

La funcionalidad principal funciona de punta a punta con tests: rutas delgadas, un servicio con las reglas, repositorios que filtran por usuario, validación con Zod y con `$jsonSchema`, y una isla que responde al instante y se corrige si el servidor falla. Cada capa tiene sus tests, y los de seguridad se han visto fallar sin su protección.

</Callout>

## Resumen

- `instanteEn` convierte la hora del usuario en un instante, con dos vueltas por el cambio de horario.
- El esquema vive en un módulo que usan el despliegue y los tests de integración.
- Ruta, servicio y repositorio: HTTP, reglas y MongoDB, cada uno por separado.
- Zod con `.strict()` en la entrada; `$jsonSchema` como última barrera.
- `useOptimistic` marca al instante y deshace si falla; crear espera al servidor.
- Unitarios, integración con MongoDB en memoria y E2E, cada uno donde es más barato.
