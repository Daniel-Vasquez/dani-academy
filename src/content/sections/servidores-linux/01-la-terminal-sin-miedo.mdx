Un servidor no tiene ventanas ni ratón, solo una terminal, y todo este curso empieza aquí. En lugar de hacer clic, escribes lo que quieres, y eso se puede repetir, combinar y automatizar. Aquí te mueves por carpetas, creas y borras archivos y lees y buscas en el registro de tu app, en el `zsh` del Mac y viendo sus diferencias con el `bash` de los servidores.

**Requisitos:** un Mac con iTerm2 o la app Terminal, y tu `entrenos-app` (I3) con un registro en `logs/app.log`. Para crearlo, arranca la app en segundo plano, navega un rato (con y sin sesión) y guarda las líneas del registro de I3.4:

```bash
cd ~/entrenos-app
npx astro dev --background
mkdir -p logs
npx astro dev logs | grep "→" > logs/app.log
```

## Paso 1: la _shell_ y las rutas

**Qué es:** la **terminal** es la ventana; la **_shell_**, el programa que ejecuta lo que escribes: **`zsh`** en macOS desde 2019 y **`bash`** en casi todos los servidores. Cada comando corre en la **carpeta actual**. Una **ruta absoluta** empieza por `/` (`/usr/bin`); una **relativa** parte de donde estás (`proyecto/src`). `.` es la carpeta actual, `..` la de arriba, `~` tu carpeta personal y `cd -` la anterior.

**Cómo se usa:** crea una carpeta de práctica y muévete por ella.

```bash
mkdir ~/practica-terminal
cd ~/practica-terminal
```

```text
$ echo $SHELL
/bin/zsh
$ pwd
/Users/tu-usuario/practica-terminal
$ cd .. && pwd
/Users/tu-usuario
$ cd ~ && pwd
/Users/tu-usuario
$ cd /usr/bin && pwd
/usr/bin
$ mkdir -p proyecto/src/components && cd proyecto/src && pwd
/Users/tu-usuario/practica-terminal/proyecto/src
$ cd proyecto/src && cd ../.. && pwd
/Users/tu-usuario/practica-terminal
```

- **`pwd`** dice dónde estás; ante la duda, ejecútalo. **`mkdir -p`** crea las intermedias y no falla si existen.
- **En la salida, cada `$` va seguido del comando** (convención del curso: el `$` no se escribe) y debajo, la respuesta.

La diferencia que más sorprende, una variable con espacios **sin comillas**:

```text
— en el Mac (zsh):
$ archivo="mi informe.txt"; touch $archivo; ls
mi informe.txt
— en el servidor (bash):
$ echo $SHELL
/bin/bash
$ archivo="mi informe.txt"; touch $archivo; ls
informe.txt
mi
$ archivo="mi informe.txt"; touch "$archivo"; ls
mi informe.txt
```

- **En `bash`, `$archivo` se parte por los espacios** y `touch` recibe `mi` e `informe.txt`; `zsh` no lo hace. En el servidor y en los _scripts_ de I6.6, **siempre entre comillas**: `"$archivo"`.

<Callout type="risk">

- **Tab completa nombres:** evita erratas y te dice si un archivo existe antes de que el comando falle.
- **Los espacios necesitan comillas:** `cd "Mis documentos"`. En tus proyectos, evítalos en los nombres.
- **Un comando pegado de Internet se ejecuta tal cual:** léelo antes. Un `cd` que falla seguido de un `rm` borra en la carpeta equivocada (Paso 2).

</Callout>

## Paso 2: crear, copiar, mover y borrar

**Qué es:** los comandos de archivos, que actúan sin pedir confirmación.

| Comando         | Qué hace                                            | Ejemplo                       |
| --------------- | --------------------------------------------------- | ----------------------------- |
| `touch`         | Crea un archivo vacío (o actualiza su fecha)        | `touch notas.txt`             |
| `ls` / `ls -la` | Lista la carpeta / con ocultos y detalles           | `ls -la`                      |
| `cp` / `cp -r`  | Copia un archivo / una carpeta con su contenido     | `cp -r docs docs-copia`       |
| `mv`            | Mueve **o** renombra (es lo mismo: cambiar la ruta) | `mv copia.txt renombrada.txt` |
| `rm` / `rm -r`  | Borra un archivo / una carpeta con su contenido     | `rm -r docs-copia`            |

**Cómo se usa:**

```text
$ touch notas.txt .oculto
$ ls
notas.txt
proyecto
$ ls -la
total 0
drwxr-xr-x@ 5 tu-usuario  wheel  160 16 oct 14:13 .
drwxr-xr-x@ 3 tu-usuario  wheel   96 16 oct 14:13 ..
-rw-r--r--@ 1 tu-usuario  wheel    0 16 oct 14:13 .oculto
-rw-r--r--@ 1 tu-usuario  wheel    0 16 oct 14:13 notas.txt
drwxr-xr-x@ 3 tu-usuario  wheel   96 16 oct 14:13 proyecto
$ cp notas.txt copia.txt && ls
copia.txt
notas.txt
proyecto
$ mv copia.txt renombrada.txt && ls
notas.txt
proyecto
renombrada.txt
$ mkdir docs && mv renombrada.txt docs/ && ls docs
renombrada.txt
$ cp -r docs docs-copia && ls
docs
docs-copia
notas.txt
proyecto
$ rm notas.txt && ls
docs
docs-copia
proyecto
$ rm docs-copia
rm: docs-copia: is a directory
$ rm -r docs-copia && ls
docs
proyecto
```

- **Lo que empieza por `.` está oculto:** `ls` no enseña `.oculto`; `ls -la` sí. Por eso `.env`, `.gitignore` y `.zshrc` no se ven.
- **`ls -la` da permisos, dueño, grupo, tamaño y fecha** (I6.2); en tu carpeta personal, el grupo es `staff`.
- **`rm` sin `-r` no borra carpetas:** responde `is a directory`.

<Callout type="risk">

- **`rm` no tiene papelera:** si dudas, `rm -i` o mueve a una carpeta temporal.
- **Nunca un `cd` que puede fallar con un `rm` de rutas relativas:** con `&&` el `rm` se para si el `cd` falla; con `;`, borra donde estabas. Esta plataforma tiene esa regla desde que un `cd` fallido sobrescribió un `.env`.
- **`cp` y `mv` pisan el destino sin avisar:** `-i` pregunta antes.

</Callout>

## Paso 3: leer archivos

**Qué es:** **`cat`** vuelca el archivo entero; **`less`** lo abre para leerlo con calma (espacio o flechas, `/texto` busca, `n` el siguiente, `q` sale); **`head`** y **`tail`** dan el principio y el final; **`wc -l`** cuenta líneas; y **`tail -f`** sigue el archivo y enseña cada línea nueva al llegar.

**Cómo se usa:** en la carpeta de tu app:

```bash
cd ~/entrenos-app
```

```text
$ head -n 3 logs/app.log
POST /api/auth/sign-in/email → 200 (65.5 ms)
GET /estadisticas → 200 (21.5 ms)
GET /api/entrenos → 200 (2.0 ms)
$ tail -n 2 logs/app.log
GET /estadisticas → 302 (0.1 ms)
GET /api/resumen → 200 (1.6 ms)
$ wc -l logs/app.log
      36 logs/app.log
```

- **36 peticiones,** y `less` es lo que usarás para leer configuraciones en el servidor.

El registro en directo, solo con los errores 4xx:

```bash
tail -n 0 -f logs/app.log | grep --line-buffered "→ 4"
```

```text
GET /api/entrenos/abc → 404 (0.3 ms)
POST /api/entrenos → 422 (0.8 ms)
```

- **Llegaron cuatro líneas y solo salen las dos 4xx.** Ctrl+C para salir.

<Callout type="risk">

- **`--line-buffered` detrás de `tail -f`:** sin él, `grep` acumula y parece que no llega nada.
- **Con `-n 0`, `tail -f` no enseña las líneas antiguas;** sin él, empieza por las 10 últimas.

</Callout>

## Paso 4: buscar, tuberías y redirecciones

**Qué es:** **`grep`** busca texto (`-r` en subcarpetas, `-n` con número de línea, `-c` cuenta, `-v` invierte, `-l` solo nombres); **`find`** busca archivos por nombre, tipo o fecha. La **tubería `|`** pasa la salida de un comando al siguiente, y las **redirecciones** la mandan a un archivo.

**Cómo se usa:**

```text
$ grep -rn "MONGODB_URI" src/
src/lib/mongo.ts:3:import { MONGODB_DB, MONGODB_URI } from "astro:env/server";
src/lib/mongo.ts:11:  new MongoClient(MONGODB_URI, {
$ grep -c "→ 401" logs/app.log
3
$ grep "→ 4" logs/app.log | head -n 3
GET /api/entrenos → 401 (0.1 ms)
GET /api/entrenos/no-existe → 404 (0.4 ms)
GET /api/entrenos → 422 (0.7 ms)
$ grep -v "→ 200" logs/app.log | wc -l
      10
$ find . -name "*.astro" -not -path "./node_modules/*" | wc -l
      11
$ find src -name "*.tsx" | head -n 3
src/components/Objetivo.tsx
src/components/Entrenos.tsx
src/components/NuevaNota.tsx
$ cut -d " " -f 4 logs/app.log | sort | uniq -c | sort -rn
  26 200
   3 422
   3 404
   3 401
   1 302
```

- **`-not -path "./node_modules/*"`** evita buscar entre miles de archivos ajenos.
- **La última línea encadena cuatro:** `cut` saca el código, `sort` ordena, `uniq -c` cuenta y `sort -rn` ordena por número. El resumen de errores de tu app en una línea.

```text
$ echo "primera línea" > salida.txt && cat salida.txt
primera línea
$ echo "segunda línea" >> salida.txt && cat salida.txt
primera línea
segunda línea
$ echo "lo pisa todo" > salida.txt && cat salida.txt
lo pisa todo
$ ls archivo-que-no-existe > lista.txt
ls: archivo-que-no-existe: No such file or directory
$ cat lista.txt | wc -c
       0
$ ls archivo-que-no-existe 2> errores.txt; cat errores.txt
ls: archivo-que-no-existe: No such file or directory
$ ls archivo-que-no-existe . > todo.txt 2>&1; cat todo.txt
ls: archivo-que-no-existe: No such file or directory
.:
docs
errores.txt
lista.txt
proyecto
salida.txt
todo.txt
$ ls archivo-que-no-existe 2> /dev/null; echo "código de salida: $?"
código de salida: 1
```

| Símbolo          | Qué hace                                                                         |
| ---------------- | -------------------------------------------------------------------------------- |
| `>`              | Escribe la salida en un archivo, **sustituyendo** lo que tuviera                 |
| `>>`             | La **añade** al final                                                            |
| `2>`             | Redirige los **errores** (los programas escriben los errores en un canal aparte) |
| `> archivo 2>&1` | Las dos cosas al mismo archivo                                                   |
| `2> /dev/null`   | Descarta los errores (`/dev/null` es un "agujero negro")                         |

- **Los errores no pasan por `>`:** con un archivo inexistente, el error sigue en pantalla y `lista.txt` queda en 0 bytes. Hace falta `2>`.
- **`$?`** es el código de salida del último comando: 0 si fue bien. Los _scripts_ de I6.6 lo usan.

<Callout type="risk">

- **`>` vacía el archivo al instante:** `echo algo > .env` deja solo `algo`; añadir era `>>`. En el servidor, `cp .env .env.bak` antes de tocar una configuración.
- **`grep` trata `.` y `*` como patrones:** para texto literal, `grep -F`.

</Callout>

## Paso 5: alias y `~/.zshrc`

**Qué es:** un **alias** es un nombre corto para un comando largo, y se guarda en **`~/.zshrc`**, que `zsh` lee al abrir cada terminal.

**Cómo se usa:** abre el archivo.

```bash
code ~/.zshrc
```

Añade al final:

```bash
# Archivo: ~/.zshrc (añade esto al final)
alias gs="git status -sb"
alias dev="npm run dev"
alias ll="ls -lah"
alias ..="cd .."
alias errores='grep -v "→ 200" logs/app.log'

# Una función: como un alias, pero con argumentos
buscar() {
  grep -rn "$1" src/
}
```

Y recarga en la terminal abierta (las nuevas lo leen solas):

```bash
source ~/.zshrc
```

```text
ll='ls -lah'
gs='git status -sb'
errores='grep -v "→ 200" logs/app.log'
buscar is a shell function from /Users/tu-usuario/.zshrc
GET /api/entrenos → 401 (0.1 ms)
GET /api/entrenos/no-existe → 404 (0.4 ms)
src/lib/mongo.ts:3:import { MONGODB_DB, MONGODB_URI } from "astro:env/server";
src/lib/auth.ts:5:import { BETTER_AUTH_SECRET, BETTER_AUTH_URL } from "astro:env/server";
src/services/index.ts:3:import { OBJETIVO_SEMANAL_MINUTOS } from "astro:env/server";
```

- **`alias`** lista los definidos; con un nombre, enseña ese. Una **función** (`buscar`) admite argumentos (`$1`).
- **`errores`** sirve en cualquier proyecto con `logs/app.log`: la ruta es relativa.

<Callout type="risk">

- **No reutilices nombres de comandos:** `ls="ls -la"` cambia `ls` en todas partes, incluidos los _scripts_. Por eso `ll`.
- **Un error en `~/.zshrc` afecta a todas las terminales:** cópialo antes (`cp ~/.zshrc ~/.zshrc.bak`).
- **En el servidor, `bash` lee `~/.bashrc`:** tus alias del Mac no existen allí.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Crea 5 alias útiles en tu `~/.zshrc` (por ejemplo, `gs` para `git status` y `dev` para `npm run dev`) y comprueba que funcionan en una terminal nueva.
2. Cuenta, con una sola línea de comandos, cuántos componentes de React tiene tu app.
3. Comprueba si todos los archivos `.tsx` son componentes con `export default function`, y averigua cuál no lo es.

</Callout>

Solución. Los alias son los del Paso 5 (`gs`, `dev`, `ll`, `..` y `errores`), más la función `buscar`. Para los componentes:

```text
$ find src -name "*.tsx" | wc -l
       9
$ grep -rl "export default function" src --include="*.tsx" | wc -l
       8
$ grep -rL "export default function" src --include="*.tsx"
src/components/CampoTexto.tsx
```

- **`find src -name "*.tsx" | wc -l`** da 9 archivos; desde la raíz, añade `-not -path "./node_modules/*"`.
- **`grep -rl` lista los que contienen el texto (8) y `grep -rL`, los que no:** `CampoTexto.tsx` (I5.5) se exporta con nombre y `forwardRef`. "Contar componentes" depende de la definición, y la terminal lo comprueba en segundos.

<Callout type="risk">

- **`wc -l` cuenta líneas, no archivos:** funciona porque `find` escribe uno por línea; un nombre con salto de línea lo descuadraría.
- **`--include="*.tsx"` necesita comillas:** sin ellas, `zsh` expande el `*` y da `no matches found`.

</Callout>

<Callout type="mastery">

Usas la terminal para tareas que antes hacías en Finder: te mueves con rutas absolutas y relativas, creas, copias, mueves y borras sabiendo que no hay papelera, lees y sigues registros con `less` y `tail -f`, buscas con `grep` y `find`, encadenas comandos con tuberías, guardas resultados con redirecciones y tienes tus propios alias.

</Callout>

## Resumen

- `zsh` en el Mac, `bash` en los servidores; `pwd` dice dónde estás.
- `cp`, `mv` y `rm` actúan sin avisar ni papelera; `-i` pregunta.
- `cat`, `less`, `head`, `tail` y `tail -f` para leer; `grep` y `find` para buscar.
- `|` encadena; `>` sustituye, `>>` añade, `2>` redirige errores.
- En `bash`, variables siempre entre comillas.
