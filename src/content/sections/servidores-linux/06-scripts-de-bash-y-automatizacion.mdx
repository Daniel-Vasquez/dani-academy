Lo que haces más de dos veces en un servidor debería ser un **_script_**, y lo que tiene que pasar sin que nadie se acuerde, como el _backup_ nocturno, se programa con **`cron`**. Un _script_ que falla en silencio es peligroso porque nadie lo mira: descubres que el _backup_ está vacío el día que lo necesitas. Aquí escribes _scripts_ que se paran al primer error, los programas, rotas sus registros y compruebas un _backup_ restaurándolo.

**Requisitos:** el servidor de I6.5 con `ssh academy`. Los comandos van en el servidor, como `deploy`.

## Paso 1: `set -euo pipefail`, que el _script_ se pare

**Qué es:** por defecto, Bash **sigue adelante** cuando un comando falla. `set -euo pipefail` lo para: **`-e`** en el primer comando que falla, **`-u`** con una variable sin definir y **`-o pipefail`** si falla cualquier comando de una tubería.

**Cómo se usa:** un _script_ que copia una carpeta con una errata en el nombre, `~/sin-set.sh`:

```bash
#!/usr/bin/env bash
# Archivo: ~/sin-set.sh — sin protección
ORIGEN="/opt/entrenos-con-errata"
tar czf /tmp/copia.tar.gz "$ORIGEN"
echo "Backup OK: /tmp/copia.tar.gz"
```

El mismo con una línea más, `~/con-set.sh`:

```bash
#!/usr/bin/env bash
# Archivo: ~/con-set.sh — con set -euo pipefail
set -euo pipefail
ORIGEN="/opt/entrenos-con-errata"
tar czf /tmp/copia.tar.gz "$ORIGEN"
echo "Backup OK: /tmp/copia.tar.gz"
```

Una variable mal escrita (`~/variables.sh`) y un fallo en medio de una tubería (`~/pipefail.sh`):

```bash
#!/usr/bin/env bash
# Archivo: ~/variables.sh — set -u con una variable mal escrita
set -euo pipefail
DESTINO="/var/backups/entrenos"
echo "Borrando copias antiguas en ${DESTIN0}"   # errata: un cero en lugar de una O
```

```bash
#!/usr/bin/env bash
# Archivo: ~/pipefail.sh — un fallo en medio de una tubería
set -eu
cat /no/existe.log | grep ERROR | wc -l
echo "sin pipefail: el script sigue, con un 0 que parece correcto"
set -o pipefail
cat /no/existe.log | grep ERROR | wc -l
echo "esta línea no se ejecuta"
```

```text
$ chmod +x sin-set.sh con-set.sh variables.sh pipefail.sh
$ ./sin-set.sh; echo "código de salida: $?"
tar: Removing leading `/' from member names
tar: /opt/entrenos-con-errata: Cannot stat: No such file or directory
tar: Exiting with failure status due to previous errors
Backup OK: /tmp/copia.tar.gz
código de salida: 0
$ ./con-set.sh; echo "código de salida: $?"
tar: Removing leading `/' from member names
tar: /opt/entrenos-con-errata: Cannot stat: No such file or directory
tar: Exiting with failure status due to previous errors
código de salida: 2
$ ./variables.sh; echo "código de salida: $?"
./variables.sh: line 5: DESTIN0: unbound variable
código de salida: 1
$ ./pipefail.sh; echo "código de salida: $?"
cat: /no/existe.log: No such file or directory
0
sin pipefail: el script sigue, con un 0 que parece correcto
cat: /no/existe.log: No such file or directory
0
código de salida: 1
```

- **Sin `set -e`, el _script_ miente:** `tar` falla, pero dice `Backup OK` y sale con **0**, que para `cron` es "todo bien". Con `-e`, para y devuelve el 2 de `tar`.
- **Con `-u`, `DESTIN0` (con un cero) no pasa:** habría sido una cadena vacía, y un `rm -rf "${DESTIN0}/"*` habría borrado desde la raíz.
- **Sin `pipefail`, una tubería solo informa del último comando:** `cat` falla, `wc -l` dice `0` y todo parece correcto.

<Callout type="risk">

- **Primera línea, `#!/usr/bin/env bash`,** y debajo `set -euo pipefail`. Sin el `#!`, lo ejecuta la _shell_ de quien lo lanza (en Ubuntu, `sh` es `dash`, que no entiende `[[` ni arrays).
- **`set -e` no para dentro de un `if` ni con `||` o `&&`:** es lo esperado, pero `comando || true` desactiva la protección a propósito.
- **Comillas en todas las variables** (I6.1): `"$ORIGEN"`.

</Callout>

## Paso 2: un _script_ de verdad, variables, condicionales, bucles y funciones

**Qué es:** un _backup_ comprimido de la carpeta de la app que conserva solo las 7 copias más recientes.

**Cómo se usa:** prepara las carpetas una vez, con `sudo`:

```bash
sudo mkdir -p /var/backups/entrenos /var/log/entrenos /opt/entrenos/scripts
sudo chown deploy:deploy /var/backups/entrenos /var/log/entrenos /opt/entrenos/scripts
sudo chmod 750 /var/backups/entrenos
```

Crea `/opt/entrenos/scripts/backup.sh`:

```bash
#!/usr/bin/env bash
# Archivo: /opt/entrenos/scripts/backup.sh
# Copia comprimida de la carpeta de la app y rotación: solo se guardan las últimas $CONSERVAR
set -euo pipefail

ORIGEN="/opt/entrenos"
DESTINO="/var/backups/entrenos"
CONSERVAR=7
FECHA=$(date +%F_%H%M%S)
ARCHIVO="$DESTINO/entrenos-$FECHA.tar.gz"

log() {
  echo "$(date '+%F %T') $*"
}

if [[ ! -d "$ORIGEN" ]]; then
  log "✗ No existe $ORIGEN"
  exit 1
fi

mkdir -p "$DESTINO"
# -C: entra en /opt para que el archivo contenga "entrenos/…" y no la ruta absoluta
tar czf "$ARCHIVO" --exclude="entrenos/dist" -C "$(dirname "$ORIGEN")" "$(basename "$ORIGEN")"
chmod 600 "$ARCHIVO" # lleva el .env dentro: solo para deploy
log "✓ Copia: $ARCHIVO ($(du -h "$ARCHIVO" | cut -f1))"

# Rotación: de más reciente a más antigua, se borran todas a partir de la $CONSERVAR
mapfile -t copias < <(ls -1t "$DESTINO"/entrenos-*.tar.gz)
for vieja in "${copias[@]:$CONSERVAR}"; do
  rm -- "$vieja"
  log "  borrada la antigua $(basename "$vieja")"
done
log "  copias guardadas: $(ls -1 "$DESTINO"/entrenos-*.tar.gz | wc -l)"
```

| Construcción            | En el _script_                                      | Qué hace                                              |
| ----------------------- | --------------------------------------------------- | ----------------------------------------------------- |
| Variable                | `DESTINO="/var/backups/entrenos"`                   | Sin espacios alrededor del `=`                        |
| Sustitución de comandos | `FECHA=$(date +%F_%H%M%S)`                          | Guarda la salida de un comando                        |
| Función                 | `log() { … }`                                       | Reutiliza un bloque; `$*` son sus argumentos          |
| Condicional             | `if [[ ! -d "$ORIGEN" ]]; then … fi`                | `-d` existe y es carpeta; `!` niega                   |
| Array                   | `mapfile -t copias < <(ls -1t …)`                   | Una lista con una línea de la salida en cada elemento |
| Bucle                   | `for vieja in "${copias[@]:$CONSERVAR}"; do … done` | Recorre los elementos a partir del 7.º                |

Ejecútalo varias veces:

$ /opt/entrenos/scripts/backup.sh

2026-10-16 14:34:26   borrada la antigua entrenos-2026-10-16_143359.tar.gz
2026-10-16 14:34:26   copias guardadas: 7

- **La fecha y la hora en el nombre** ordenan las copias y evitan que se pisen.
- **Siempre las 7 más recientes:** la octava borra la más antigua.
- **`chmod 600`,** porque la copia lleva el `.env`; y **`tar tzf`** lista sin descomprimir: `entrenos/` sin `dist`, que se reconstruye con `npm run build`.

<Callout type="risk">

- **Un _backup_ en el mismo servidor no protege del servidor:** si el disco falla, se van con él. Cópialas fuera (`rsync` a otra máquina, I6.3), como en la Tanda 10.
- **`rm` en un _script_ desatendido, con mucho cuidado:** este solo borra lo que `ls` encontró con un patrón concreto y usa `--` para que un nombre raro no sea una opción.

</Callout>

## Paso 3: programarlo con `cron`

**Qué es:** **`cron`** ejecuta comandos a horas fijas, con una tabla por usuario (_crontab_) y una línea por tarea.

**Cómo se usa:**

```text
┌───────── minuto (0-59)
│ ┌─────── hora (0-23)
│ │ ┌───── día del mes (1-31)
│ │ │ ┌─── mes (1-12)
│ │ │ │ ┌─ día de la semana (0-7, 0 y 7 son domingo)
│ │ │ │ │
0 3 * * *  /opt/entrenos/scripts/backup.sh >> /var/log/entrenos/backup.log 2>&1
```

`*` es "cualquiera", y `0 3 * * *` significa "a las 3:00, todos los días". Edita con `crontab -e` (`nano` es el editor más sencillo). Para probarlo, primero **cada minuto** (`* * * * *`); dos minutos después:

```text
$ crontab -l
* * * * * /opt/entrenos/scripts/backup.sh >> /var/log/entrenos/backup.log 2>&1
$ cat /var/log/entrenos/backup.log
2026-10-16 14:35:01 ✓ Copia: /var/backups/entrenos/entrenos-2026-10-16_143501.tar.gz (4.0K)
2026-10-16 14:35:01   borrada la antigua entrenos-2026-10-16_143400.tar.gz
2026-10-16 14:35:01   copias guardadas: 7
2026-10-16 14:36:01 ✓ Copia: /var/backups/entrenos/entrenos-2026-10-16_143601.tar.gz (4.0K)
2026-10-16 14:36:01   borrada la antigua entrenos-2026-10-16_143401.tar.gz
2026-10-16 14:36:01   copias guardadas: 7
$ sudo journalctl -u cron -n 2 --no-pager -o cat
(deploy) CMD (/opt/entrenos/scripts/backup.sh >> /var/log/entrenos/backup.log 2>&1)
pam_unix(cron:session): session closed for user deploy
```

- **`>> backup.log 2>&1`:** `cron` no tiene pantalla; sin redirección, salida y errores se pierden.
- **El diario de `cron`** (con `sudo`) registra cada ejecución, con comando y usuario.
- **Cuando funcione, vuelve a `0 3 * * *`:** cada minuto llenaría el disco.

<Callout type="risk">

- **`cron` usa la zona horaria del servidor:** en UTC, `0 3` son las 21:00 del día anterior en Ciudad de México. Compruébalo con `timedatectl`.
- **Que `cron` lo ejecute no es que funcione:** la prueba es el registro. Revísalo, o haz que el _script_ avise si falla.

</Callout>

## Paso 4: rotar los registros con `logrotate`

**Qué es:** `backup.log` crece sin fin. **`logrotate`**, que Ubuntu ejecuta a diario, lo renombra, comprime los antiguos y borra los muy viejos.

**Cómo se usa:** crea `/etc/logrotate.d/entrenos` (con `sudo`):

```bash
# Archivo: /etc/logrotate.d/entrenos
/var/log/entrenos/*.log {
    weekly
    rotate 8
    compress
    delaycompress
    missingok
    notifempty
    su deploy deploy
}
```

```text
$ sudo logrotate -d /etc/logrotate.d/entrenos 2>&1 | grep -E "rotating pattern|considering log|log needs rotating|log does not need" | head -n 4
rotating pattern: /var/log/entrenos/*.log weekly empty log files are not rotated, (8 rotations), old logs are removed
considering log /var/log/entrenos/backup.log
  log does not need rotating (log has already been rotated)
$ sudo logrotate -f /etc/logrotate.d/entrenos && ls -l /var/log/entrenos
total 4
-rw-rw-r-- 1 deploy deploy 422 Oct 16 14:36 backup.log.1
$ sudo -iu deploy bash -c '/opt/entrenos/scripts/backup.sh >> /var/log/entrenos/backup.log 2>&1' && sudo logrotate -f /etc/logrotate.d/entrenos && ls -l /var/log/entrenos
total 8
-rw-r--r-- 1 deploy deploy 211 Oct 16 14:37 backup.log.1
-rw-rw-r-- 1 deploy deploy 168 Oct 16 14:36 backup.log.2.gz
```

- **`weekly` y `rotate 8`:** una rotación semanal y 8 copias, dos meses. **`-d`** prueba sin tocar nada; **`-f`** fuerza una rotación.
- **`delaycompress`** deja la más reciente (`.1`) sin comprimir, por si algo aún escribe en ella; la anterior pasa a `.2.gz`.
- **`su deploy deploy`** rota como el dueño de la carpeta. Aquí (`755`) también funcionaría sin él, pero con una carpeta escribible por grupo u otros, `logrotate` se negaría por inseguro.

<Callout type="risk">

- **Sin `missingok`, un registro que aún no existe es un error diario;** `notifempty` evita rotar vacíos.
- **Los servicios de `systemd` no lo necesitan:** su salida va al diario (I6.4), con rotación propia. `logrotate` es para tus _scripts_.

</Callout>

## Ejercicio práctico

<Callout type="exercise">

1. Escribe un _script_ que haga el _backup_ de la base de datos de tu Planificador con `mongodump`, leyendo la conexión de `/opt/entrenos/.env` y borrando las copias de más de 7 días.
2. Comprueba que funciona en el entorno vacío de `cron`, y no solo desde tu terminal.
3. Prográmalo con `cron` y comprueba que la copia se puede **restaurar**.

</Callout>

Solución. Instala las MongoDB Database Tools (paquete oficial para Ubuntu, de mongodb.com/try/download/database-tools; 100.13.0 en la medición):

```bash
curl -fsSLO https://fastdl.mongodb.org/tools/db/mongodb-database-tools-ubuntu2404-arm64-100.13.0.deb
sudo apt install -y ./mongodb-database-tools-ubuntu2404-arm64-100.13.0.deb
```

(`arm64` para Apple Silicon; en un VPS Intel o AMD, `x86_64`.) La conexión va en `/opt/entrenos/.env` (`MONGODB_URI=…`, `600`); en la medición, `planificador` está en otra máquina, como Atlas respecto a tu VPS. Crea `/opt/entrenos/scripts/backup-bd.sh`:

```bash
#!/usr/bin/env bash
# Archivo: /opt/entrenos/scripts/backup-bd.sh
# Backup de la base de datos con mongodump, rotado por antigüedad. Pensado para cron.
set -euo pipefail

ENV_FILE="/opt/entrenos/.env"
DESTINO="/var/backups/planificador"
DIAS=7 # se borran las copias de más de 7 días

# cron no carga tu sesión: la conexión se lee del .env, no de la terminal
if [[ ! -r "$ENV_FILE" ]]; then
  echo "✗ No puedo leer $ENV_FILE" >&2
  exit 1
fi
set -a # exporta todo lo que se defina mientras está activo
source "$ENV_FILE"
set +a
: "${MONGODB_URI:?Falta MONGODB_URI en $ENV_FILE}" # para con un mensaje claro si no está

FECHA=$(date +%F_%H%M%S)
ARCHIVO="$DESTINO/planificador-$FECHA.archive.gz"
mkdir -p "$DESTINO"

mongodump --uri="$MONGODB_URI" --archive="$ARCHIVO" --gzip --quiet
chmod 600 "$ARCHIVO"
echo "$(date '+%F %T') ✓ $ARCHIVO ($(du -h "$ARCHIVO" | cut -f1))"

# Rotación por antigüedad: -mtime +7 son los modificados hace más de 7 días
find "$DESTINO" -name 'planificador-*.archive.gz' -mtime +"$DIAS" -print -delete | sed 's/^/  borrada la antigua /'
```

La trampa de `cron` es que **no carga tu sesión**: un _script_ que da por hecho `MONGODB_URI` (exportada en la terminal o en `~/.bashrc`) funciona a mano y falla en `cron`. `env -i` ejecuta con el entorno vacío, como `cron`:

```text
$ export MONGODB_URI="mongodb://192.168.64.1:27300/planificador"
$ /opt/entrenos/scripts/backup-bd-ingenuo.sh
✓ backup hecho
$ env -i /opt/entrenos/scripts/backup-bd-ingenuo.sh; echo "código de salida: $?"
/opt/entrenos/scripts/backup-bd-ingenuo.sh: line 4: MONGODB_URI: unbound variable
código de salida: 1
$ env -i /opt/entrenos/scripts/backup-bd.sh; echo "código de salida: $?"
2026-10-16 14:40:03 ✓ /var/backups/planificador/planificador-2026-10-16_144003.archive.gz (4.0K)
código de salida: 0
```

La rotación por antigüedad, con dos copias falsas de hace 10 y 3 días (`touch -d` cambia la fecha):

$ touch -d "10 days ago" /var/backups/planificador/planificador-2026-10-06_030000.archive.gz
$ touch -d "3 days ago" /var/backups/planificador/planificador-2026-10-13_030000.archive.gz

-rw-rw-r-- 1 deploy deploy    0 Oct  6 14:40 planificador-2026-10-06_030000.archive.gz

  borrada la antigua /var/backups/planificador/planificador-2026-10-06_030000.archive.gz
$ ls -lt /var/backups/planificador

Desde `cron`, primero cada minuto:

```text
$ crontab -l
0 3 * * * /opt/entrenos/scripts/backup.sh >> /var/log/entrenos/backup.log 2>&1
* * * * * /opt/entrenos/scripts/backup-bd.sh >> /var/log/entrenos/backup-bd.log 2>&1
$ cat /var/log/entrenos/backup-bd.log
2026-10-16 14:41:01 ✓ /var/backups/planificador/planificador-2026-10-16_144101.archive.gz (4.0K)
```

Un _backup_ nunca restaurado es una esperanza. Restáuralo en una base de datos **distinta** y cuenta lo que hay:

```text
$ ULTIMA=$(ls -1t /var/backups/planificador/planificador-*.archive.gz | head -n 1)
$ mongorestore --uri="mongodb://192.168.64.1:27300" --archive="$ULTIMA" --gzip --nsFrom='planificador.*' --nsTo='restaurado.*' 2>&1 | tail -n 1
2026-10-16T14:41:44.659-0600	122 document(s) restored successfully. 0 document(s) failed to restore.
$ mongodump --uri="mongodb://192.168.64.1:27300/restaurado" --archive=/dev/null 2>&1 | grep done
2026-10-16T14:41:44.668-0600	done dumping restaurado.categorias (2 documents)
2026-10-16T14:41:44.669-0600	done dumping restaurado.tareas (120 documents)
$ (crontab -l | grep -v backup-bd; echo "30 3 * * * /opt/entrenos/scripts/backup-bd.sh >> /var/log/entrenos/backup-bd.log 2>&1") | crontab - && crontab -l
0 3 * * * /opt/entrenos/scripts/backup.sh >> /var/log/entrenos/backup.log 2>&1
30 3 * * * /opt/entrenos/scripts/backup-bd.sh >> /var/log/entrenos/backup-bd.log 2>&1
```

- **`source` con `set -a`** carga y exporta el `.env`, y **`: "${MONGODB_URI:?…}"`** para con un mensaje claro si falta.
- **`find -mtime +7 -delete`** borra la de hace 10 días y deja la de hace 3.
- **`--nsFrom` y `--nsTo`** restauran `planificador.*` como `restaurado.*`: 122 documentos (120 tareas y 2 categorías), como el original. Después, borra `restaurado`. La tabla final lleva los dos _backups_ diarios, separados media hora.

<Callout type="risk">

- **El `.env` del servidor abre la base de datos:** `600` y, si puedes, un usuario de Atlas solo de lectura para el _backup_ (el `academy_backup` de la Tanda 10).
- **MongoDB 8.0 no arranca en núcleos Linux 6.19 o posteriores:** en Ubuntu 26.04 (núcleo 7.0), `mongod` sale con `Linux kernel versions 6.19 and newer has a known incompatibility with this version of MongoDB` (SERVER-121912). Con Atlas no pasa.
- **Un `mongodump` en el mismo servidor no basta** (Paso 2): cópialo fuera.

</Callout>

<Callout type="mastery">

Automatizas una tarea repetitiva con un _script_ en lugar de hacerla a mano: lo empiezas con `set -euo pipefail`, usas variables entre comillas, condicionales, bucles y funciones, lo programas con `cron` sin depender de tu sesión, rotas sus registros con `logrotate` y compruebas el resultado, porque el único _backup_ que vale es el que has restaurado.

</Callout>

## Resumen

- `#!/usr/bin/env bash` y `set -euo pipefail`: parar en errores, variables sin definir y tuberías rotas.
- Variables entre comillas, `$(…)`, funciones, `if [[ … ]]`, arrays y `for`.
- `crontab -e` con `minuto hora día mes día-semana`, `>> archivo.log 2>&1` y sin contar con tu entorno.
- `logrotate` en `/etc/logrotate.d/`; `-d` para probar.
- Un _backup_ se comprueba restaurándolo en otra base de datos y se guarda fuera del servidor.
