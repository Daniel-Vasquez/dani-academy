`{ titulo: /fuerza/i }` no encuentra "genéricos" con "genericos" ni "entrenamientos" con "entrenamiento", y no sabe qué resultado es más relevante. Una **búsqueda de texto** entiende el idioma: quita tildes, reduce palabras a su raíz (_stemming_), ignora palabras vacías y ordena por relevancia. Aquí mides el índice `text` de MongoDB, conoces Atlas Search y decides cuándo hace falta un motor aparte.

**Requisitos:** el proyecto `mongo-academy` con `src/a2/`. El índice `text` funciona en cualquier MongoDB; **Atlas Search necesita Atlas** (también el M0, con límites) o MongoDB con su componente de búsqueda, y su código del Paso 3 **no se ha ejecutado aquí**: solo se comprobó que compila.

## Paso 1: el índice `text`, en español

**Qué es:** un índice que guarda la **raíz** de cada palabra según un idioma y permite buscar con `$text`, ordenando por relevancia (`textScore`).

**Cómo se usa:** las notas de prueba de toda la sección, `src/a2/notas-busqueda.ts`:

```ts
// Archivo: src/a2/notas-busqueda.ts
```

La búsqueda, `src/a2/12-texto.ts`:

```ts
// Archivo: src/a2/12-texto.ts
// El índice text nativo, en español: qué encuentra y en qué orden
import type { MongoServerError } from "mongodb";
import { cliente } from "../db";
import { notas, sembrarNotas } from "./notas-busqueda";

await sembrarNotas();

// Sin índice text, $text no funciona
try {
  await notas.find({ $text: { $search: "fuerza" } }).toArray();
} catch (e) {
  console.log(
    `Sin índice: ${(e as MongoServerError).codeName}: ${(e as MongoServerError).message}`,
  );
}

// Un índice text sobre título y contenido, en español; el título pesa el triple
await notas.createIndex(
  { titulo: "text", contenido: "text" },
  {
    name: "busqueda",
    default_language: "spanish",
    weights: { titulo: 3, contenido: 1 },
  },
);

async function buscar(texto: string) {
  const res = await notas
    .find<{ titulo: string; puntuacion: number }>(
      { $text: { $search: texto } },
      { projection: { _id: 0, titulo: 1, puntuacion: { $meta: "textScore" } } },
    )
    .sort({ puntuacion: { $meta: "textScore" } })
    .toArray();
  const lista = res
    .map((r) => `${r.titulo} (${r.puntuacion.toFixed(2)})`)
    .join(" · ");
  console.log(
    `${JSON.stringify(texto).padEnd(26)} → ${res.length ? lista : "nada"}`,
  );
}

console.log("\nBúsquedas:");
await buscar("genericos"); // sin tilde
await buscar("GENÉRICOS"); // mayúsculas
await buscar("entrenamiento"); // singular: ¿encuentra "entrenamientos"?
await buscar("correr"); // ¿y "corriendo", "corrí"?
await buscar("fuerza"); // en el título de una nota y en el contenido de otra
await buscar("de la"); // solo palabras vacías
await buscar('"peso muerto"'); // una frase exacta
await buscar("fuerza -sentadilla"); // fuerza, pero sin sentadilla

await cliente.close();
```

```bash
npm start -- src/a2/12-texto.ts
```

```text
Sin índice: IndexNotFound: text index required for $text query
Búsquedas:
"genericos"                → Genéricos en TypeScript (2.85)
"GENÉRICOS"                → Genéricos en TypeScript (2.85)
"entrenamiento"            → Entrenamientos de la semana (2.82) · Movilidad diaria (0.60)
"correr"                   → Correr el domingo (3.19) · Entrenamientos de la semana (0.57)
"fuerza"                   → Plan de fuerza (2.81) · Entrenamientos de la semana (0.57)
"de la"                    → nada
"\"peso muerto\""          → Plan de fuerza (1.13)
"fuerza -sentadilla"       → Entrenamientos de la semana (0.57)
```

- **Sin índice `text`, `$text` falla con `IndexNotFound`:** no recorre la colección como un `find`.
- **Ignora mayúsculas, tildes, diéresis y la virgulilla:** "genericos" encuentra "Genéricos", "pinguino" encuentra "pingüino" y **"ano" encuentra "año"**, lo que en español puede sorprender.
- **Con `default_language: "spanish"`, busca por raíz:** "entrenamiento" encuentra "Entrenamientos" y "correr", "corriendo". "de la" no encuentra nada: son palabras vacías.
- **Con `weights`, el título cuenta el triple:** "Plan de fuerza" sale antes que "Entrenamientos de la semana". Y admite **comillas** para frases (`"peso muerto"`) y **guion** para excluir (`fuerza -sentadilla`).

<Callout type="risk">

- **El idioma se elige al crear el índice:** por defecto es el inglés, con sus raíces y palabras vacías (Paso 2). En español, `default_language: "spanish"` siempre.
- **`$text` no se combina con todo:** uno por consulta y sin `hint` (`text and hint not allowed in same query`). Para filtrar por otro campo, ponlo en el mismo índice (como `categoria` en el ejercicio).

</Callout>

## Paso 2: lo que el índice `text` no sabe hacer

**Qué es:** los límites del índice, medidos.

**Cómo se usa:** crea `src/a2/13-limites.ts`.

```ts
// Archivo: src/a2/13-limites.ts
// Lo que el índice text NO hace
import type { MongoServerError } from "mongodb";
import { cliente } from "../db";
import { notas, sembrarNotas } from "./notas-busqueda";

await sembrarNotas();
await notas.createIndex({ titulo: "text", contenido: "text" }, { name: "busqueda", default_language: "spanish" });

const titulos = async (texto: string) =>
  (await notas.find({ $text: { $search: texto } }).toArray()).map((n) => n.titulo).join(" · ") || "nada";

console.log("1. Erratas y trozos de palabra:");
for (const texto of ["genricos", "jenéricos", "gen", "entrena", "corrí"]) console.log(`   ${JSON.stringify(texto).padEnd(12)} → ${await titulos(texto)}`);

console.log("2. Un segundo índice text en la misma colección:");
try {
  await notas.createIndex({ categoria: "text" }, { name: "otro" });
} catch (e) {
  const err = e as MongoServerError;
  console.log(`   ${err.codeName}: ${err.message.split(", name:")[0]} …`); // la clave interna de TODO índice text
}

console.log("3. El mismo índice con el idioma por defecto (inglés):");
await notas.dropIndex("busqueda");
await notas.createIndex({ titulo: "text", contenido: "text" }, { name: "busqueda_en" }); // default_language: "english"
for (const texto of ["entrenamiento", "genericos", "de la"]) console.log(`   ${JSON.stringify(texto).padEnd(16)} → ${await titulos(texto)}`);

console.log("4. La alternativa habitual para prefijos, una expresión regular:");
for (const patron of [/^gen/i, /^genericos/i]) {
  console.log(`   ${String(patron).padEnd(14)} → ${(await notas.find({ titulo: patron }).toArray()).map((n) => n.titulo).join(" · ") || "nada"}`);

```

```text
1. Erratas y trozos de palabra:
   "genricos"   → nada
   "jenéricos"  → nada
   "gen"        → nada
   "entrena"    → Entrenamientos de la semana · Movilidad diaria
   "corrí"      → Correr el domingo · Entrenamientos de la semana
2. Un segundo índice text en la misma colección:
   IndexOptionsConflict: An equivalent index already exists with a different name and options. Requested index: { v: 2, key: { _fts: "text", _ftsx: 1 } …
3. El mismo índice con el idioma por defecto (inglés):
   "entrenamiento"  → Entrenamientos de la semana · Movilidad diaria
   "genericos"      → Genéricos en TypeScript
   "de la"          → Plan de fuerza · Entrenamientos de la semana · Lectura pendiente · Movilidad diaria · Repaso de transacciones · Genéricos en TypeScript · Correr el domingo · Índices en MongoDB
4. La alternativa habitual para prefijos, una expresión regular:
   /^gen/i        → Genéricos en TypeScript
   /^genericos/i  → nada
```

- **No tolera erratas:** "genricos" y "jenéricos" no encuentran nada.
- **No busca prefijos:** "gen" no encuentra "Genéricos"; "entrena" acierta por casualidad (comparte la raíz `entren`). No sirve para autocompletar.
- **Solo uno por colección:** todos comparten la clave interna `{ _fts: "text", _ftsx: 1 }`. Más campos, en el mismo índice.
- **Con el idioma equivocado, las palabras vacías cuentan:** en inglés, "de la" devuelve las ocho notas.
- **Una expresión regular no lo sustituye:** `/^gen/i` encuentra "Genéricos", pero `/^genericos/i` no (compara con tilde), y con `i` MongoDB aprovecha mal un índice normal.

<Callout type="risk">

- **El índice `text` ocupa mucho y ralentiza escrituras:** una entrada por raíz y documento, y con textos largos puede pesar más que los datos. Indexa solo lo que se busca.
- **Sin sinónimos ni corrección:** "pesas" no encuentra "fuerza". Eso es de un motor de búsqueda (Paso 3).

</Callout>

## Paso 3: Atlas Search

**Qué es:** un motor de búsqueda (Apache Lucene, como Elasticsearch y OpenSearch) integrado en Atlas. Los datos siguen en tu colección, Atlas mantiene a su lado un índice que se actualiza solo y se consulta con `$search` en un `aggregate`.

| Necesidad                                        | Índice `text`     | Atlas Search                                    |
| ------------------------------------------------ | ----------------- | ----------------------------------------------- |
| Ignorar tildes y mayúsculas, raíces en español   | Sí                | Sí (analizador `lucene.spanish`)                |
| Tolerar erratas                                  | No                | Sí (`fuzzy`)                                    |
| Autocompletar mientras se escribe                | No                | Sí (tipo `autocomplete`)                        |
| Devolver el fragmento que coincide, resaltado    | No                | Sí (`highlight`)                                |
| Varios índices por colección, sinónimos, facetas | No                | Sí                                              |
| Dónde funciona                                   | Cualquier MongoDB | Atlas (o MongoDB con su componente de búsqueda) |

**Cómo se usa:** contra el MongoDB local, `$search` y `createSearchIndex` responden:

```text
$search en local: SearchNotEnabled Using $search and $vectorSearch aggregation stages requires additional configuration. Please connect to Atlas or an AtlasCLI local deployment to enable.For more
createSearchIndex en local: SearchNotEnabled Using Atlas Search Database Commands and the $listSearchIndexes aggregation stage requires additional configuration. Please connect to Atlas or an AtlasCLI loca
```

El código para Atlas, **sin ejecutar en este laboratorio** (solo compilado con `npm run typecheck`): pruébalo en tu clúster, en una base de pruebas. `src/a2/15-atlas-search.ts`:

```ts
// Archivo: src/a2/15-atlas-search.ts
// La misma búsqueda con Atlas Search: tolerante a erratas, con autocompletado y fragmentos resaltados.
// Necesita un clúster de Atlas (o MongoDB con el componente de búsqueda mongot): no funciona contra un MongoDB local normal
import { cliente } from "../db";
import { notas, type Nota } from "./notas-busqueda";

// 1. El índice de búsqueda (se crea una vez; Atlas tarda unos segundos en construirlo)
await notas.createSearchIndex({
  name: "notas",
  definition: {
    mappings: {
      dynamic: false,
      fields: {
        titulo: [
          { type: "string", analyzer: "lucene.spanish" },
          { type: "autocomplete", analyzer: "lucene.spanish", tokenization: "edgeGram", minGrams: 2, maxGrams: 15 },
        ],
        contenido: { type: "string", analyzer: "lucene.spanish" },
        categoria: { type: "token" },
      },
    },
  },
});

/** Búsqueda tolerante a erratas (una letra de diferencia), filtrada por categoría y con el fragmento que coincide */
export function buscarNotas(texto: string, categoria?: Nota["categoria"]) {
  return notas
    .aggregate([
      {
        $search: {
          index: "notas",
          compound: {
            must: [{ text: { query: texto, path: ["titulo", "contenido"], fuzzy: { maxEdits: 1 } } }],
            ...(categoria && { filter: [{ equals: { path: "categoria", value: categoria } }] }),
          },
          highlight: { path: "contenido" },
        },
      },
      { $limit: 10 },
      { $project: { _id: 0, titulo: 1, puntuacion: { $meta: "searchScore" }, resaltado: { $meta: "searchHighlights" } } },
    ])
    .toArray();
}

/** Autocompletado del título mientras se escribe: "gen" → "Genéricos en TypeScript" */
export function sugerir(prefijo: string) {
  return notas
    .aggregate([
      { $search: { index: "notas", autocomplete: { query: prefijo, path: "titulo" } } },
      { $limit: 5 },
      { $project: { _id: 0, titulo: 1 } },
    ])
    .toArray();
}

console.log(await buscarNotas("genricos"), await sugerir("gen"));
await cliente.close();
```

- **El índice es un documento JSON:** campos y analizador. `titulo` se indexa como texto y como `autocomplete` con `edgeGram` (trozos iniciales de 2 a 15 letras).
- **`fuzzy: { maxEdits: 1 }`** acepta una letra de distancia: "genricos" encontraría "genéricos".
- **`compound`** separa lo que **debe** coincidir (`must`, suma relevancia) de lo que solo **filtra** (`filter`), y **`searchScore`** y **`searchHighlights`** se leen con `$meta`.

<Callout type="risk">

- **El índice se construye en segundo plano:** recién creado puede no devolver nada unos segundos; comprueba `listSearchIndexes`.
- **El M0 tiene límites:** pocos índices de búsqueda y recursos compartidos. Revísalos antes de diseñar alrededor.
- **Prueba `lucene.spanish` con tus palabras** en la interfaz de Atlas antes de depender de él.

</Callout>

## Paso 4: ¿cuándo un motor de búsqueda aparte?

**Qué es:** la elección según el tamaño y el papel de la búsqueda.

**Cómo se usa:**

| Situación                                                                                                     | Lo razonable                                                                                    |
| ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Buscar en las notas o los títulos de un usuario (decenas o cientos de documentos)                             | Índice `text` (o incluso una expresión regular sobre pocos documentos ya filtrados por usuario) |
| Una búsqueda pública con erratas, autocompletado y resaltado, con los datos en Atlas                          | Atlas Search: sin servidor aparte y sin sincronizar datos                                       |
| Millones de documentos, varias fuentes de datos, búsqueda en el centro del producto (una tienda, un buscador) | Un motor dedicado (Elasticsearch, OpenSearch, Meilisearch, Typesense)                           |

- **Un motor dedicado es otro sistema:** hay que mantenerlo, copiar los datos y sincronizarlos; si un cambio no llega, devuelve datos viejos. Con los datos en Atlas, Atlas Search evita ese problema.

Solución con el índice `text`, `src/a2/14-ejercicio.ts`:

```ts
// Archivo: src/a2/14-ejercicio.ts
// La búsqueda de notas del Planificador con el índice text: en español, por relevancia y con filtro
import { cliente } from "../db";
import { notas, sembrarNotas, type Nota } from "./notas-busqueda";

await sembrarNotas();
await notas.createIndex(
  { titulo: "text", contenido: "text", categoria: 1 },
  { name: "busqueda", default_language: "spanish", weights: { titulo: 3, contenido: 1 } },
);

interface Resultado {
  titulo: string;
  categoria: Nota["categoria"];
  puntuacion: number;
}

/** Busca en título y contenido; opcionalmente, solo en una categoría. Las mejores primero */
async function buscarNotas(texto: string, opciones: { categoria?: Nota["categoria"]; limite?: number } = {}): Promise<Resultado[]> {
  const termino = texto.trim();
  if (termino.length < 2) return []; // una letra suelta no es una búsqueda
  return notas
    .find<Resultado>(
      { $text: { $search: termino }, ...(opciones.categoria && { categoria: opciones.categoria }) },
      { projection: { _id: 0, titulo: 1, categoria: 1, puntuacion: { $meta: "textScore" } } },
    )
    .sort({ puntuacion: { $meta: "textScore" } })
    .limit(opciones.limite ?? 10)
    .toArray();
}

const mostrar = (titulo: string, r: Resultado[]) =>
  console.log(`${titulo.padEnd(38)} → ${r.map((n) => `${n.titulo} [${n.categoria}]`).join(" · ") || "nada"}`);

mostrar('"genericos"', await buscarNotas("genericos"));
mostrar('"entrenamiento"', await buscarNotas("entrenamiento"));
mostrar('"entrenamiento", solo entreno', await buscarNotas("entrenamiento", { categoria: "entreno" }));
mostrar('"repaso", solo estudio', await buscarNotas("repaso", { categoria: "estudio" }));
mostrar('"indices mongo"', await buscarNotas("indices mongo"));
mostrar('"x"', await buscarNotas("x"));
mostrar('"genricos" (con errata)', await buscarNotas("genricos"));

const plan = await notas.find({ $text: { $search: "fuerza" }, categoria: "entreno" }).explain("executionStats");
console.log(`plan con filtro de categoría: documentos examinados ${plan.executionStats.totalDocsExamined}, devueltos ${plan.executionStats.nReturned}`);

await cliente.close();
```

```text
"genericos"                            → Genéricos en TypeScript [estudio]
"entrenamiento"                        → Entrenamientos de la semana [entreno] · Movilidad diaria [entreno]
"entrenamiento", solo entreno          → Entrenamientos de la semana [entreno] · Movilidad diaria [entreno]
"repaso", solo estudio                 → Repaso de transacciones [estudio] · Genéricos en TypeScript [estudio]
"indices mongo"                        → Índices en MongoDB [estudio]
"x"                                    → nada
"genricos" (con errata)                → nada
plan con filtro de categoría: documentos examinados 2, devueltos 2
```

- **"genericos" encuentra "Genéricos en TypeScript"**, y "entrenamiento", las dos notas que lo mencionan.
- **La categoría va dentro del índice `text`** (`categoria: 1`, tras los campos de texto): la búsqueda filtrada examina 2 para devolver 2. Las búsquedas de una letra se descartan antes.
- **"genricos" no encuentra nada,** el límite del índice. La versión tolerante es la del Paso 3 (`fuzzy: { maxEdits: 1 }`), **sin ejecutar aquí**: pruébala en tu Atlas.

<Callout type="risk">

- **Nunca metas lo que escribe el usuario en una expresión regular sin escaparlo:** un `.*` o un paréntesis la cambia, y una mal formada puede tardar muchísimo. `$text` y `$search` lo tratan como texto.
- **"Sin resultados" necesita respuesta:** "No hay notas con «genricos»" y, si puedes, una sugerencia; con `fuzzy`, ese caso es mucho más raro.

</Callout>

<Callout type="mastery">

Tu buscador encuentra "genericos" cuando el texto dice "genéricos": usas el índice `text` con el idioma español (tildes, raíces, palabras vacías y relevancia con pesos), conoces lo que no hace (erratas, prefijos, un índice por colección) y sabes cuándo pasar a Atlas Search (erratas, autocompletado, resaltado) o a un motor dedicado, y lo que cuesta cada uno.

</Callout>

## Resumen

- `createIndex({ titulo: "text", contenido: "text" }, { default_language: "spanish", weights })`: sin tildes ni mayúsculas, por raíces y relevancia.
- `$text: { $search }` con frases entre comillas y exclusiones con `-`.
- Sin erratas ni prefijos, un índice por colección, y el idioma decide las palabras vacías.
- Atlas Search (`$search`): `fuzzy`, `autocomplete`, `highlight`; necesita Atlas.
- Un motor dedicado es otro sistema que sincronizar: solo si la búsqueda es el producto.
